Finds a user within the project by their `foreignId` — the external identifier you provided when creating or syncing the user. This endpoint only reads: a user that doesn't exist is `404` for every caller. To fetch a user or create them when missing, use [Fetch or Create User by Foreign ID](/v8/api-reference/users/fetch-or-create-user-by-foreign-id) (`POST`, service key only), which takes the profile in the request body.

<Note>
  If the profile owner has blocked the viewer — the signed-in user, or the user a service key names in `actingUserId` — this returns `404` — the
  same response as a user who does not exist. The reverse is not true: a user
  *you* have blocked stays visible, so you keep a way to find and unblock them. Requires the `moderation` bundle.
</Note>

## Query Parameters

### Acting user

<ParamField query="actingUserId" type="string">
  Service key only: the user to read as. The response is exactly what that user's own access token would get — a profile whose owner blocked them returns `404`. Leave it out for the anonymous view. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 user/acting-user-not-allowed`).
</ParamField>

<ParamField query="foreignId" type="string" required>
  The external identifier from your system. It is matched exactly as sent. A blank or whitespace-only value returns `400 user/invalid-query` (`foreignId: Foreign ID is required`).
</ParamField>

<ParamField query="include" type="string">
  Associations to include, as a comma-separated value or repeated params. The only value is:
  - `files` — the processed `avatarFile` and `bannerFile` objects

  Matching ignores case. An unknown value returns `400 user/invalid-query`.
</ParamField>

### Space-scoped reputation

This endpoint has no space in context, so the opt-in `spaceReputation` object accepts a `spaceId` of a space **`<uuid>`** or **`none`** only — `context` is rejected (400). It adds a `spaceReputation` field to each returned user, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation).

## Response

Returns HTTP `200` with the user object:

<ResponseField name="id" type="string">
  Unique user ID (UUID).
</ResponseField>

<ResponseField name="foreignId" type="string | null">
  The foreign ID you provided.
</ResponseField>

<ResponseField name="projectId" type="string">
  Project this user belongs to.
</ResponseField>

<ResponseField name="name" type="string | null">
  Display name.
</ResponseField>

<ResponseField name="username" type="string | null">
  Unique username within the project.
</ResponseField>

<ResponseField name="avatar" type="string | null">
  Avatar image URL.
</ResponseField>

<ResponseField name="bio" type="string | null">
  Short bio text.
</ResponseField>

<ResponseField name="metadata" type="object | null">
  Public custom key-value data.
</ResponseField>

<ResponseField name="reputation" type="number">
  Reputation score.
</ResponseField>

<ResponseField name="avatarFile" type="object | null">
  Processed avatar image with variants. Only present when `include=files` is
  requested.
</ResponseField>

<ResponseField name="bannerFile" type="object | null">
  Processed banner image with variants. Only present when `include=files` is
  requested.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of account creation.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="User Not Found — 404">
    ```json
    {
      "error": "User not found",
      "code": "user/not-found"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned for an invalid query: a missing or blank `foreignId` (`foreignId: Foreign ID is required`), or an unknown `include` value.

    ```json
    {
      "error": "include: Unknown include `avatar`. Allowed: files.",
      "code": "user/invalid-query"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `createIfNotFound` or a profile field (`name`, `username`, `avatar`, `bio`, `metadata`, `secureMetadata`). This endpoint only reads; creating a user is [`POST /users/by-foreign-id`](/v8/api-reference/users/fetch-or-create-user-by-foreign-id), with the profile in the body. Returned for every caller.

    ```json
    {
      "error": "`createIfNotFound` isn't supported on `GET /users/by-foreign-id` in v8: it only reads. To fetch or create a user, send `POST /users/by-foreign-id` with a service key, the profile in the body.",
      "code": "user/unsupported-param",
      "param": "createIfNotFound"
    }
    ```

    For a profile field, the message names it:

    ```json
    {
      "error": "`name` isn't supported on `GET /users/by-foreign-id` in v8: it only reads. To create a user with a profile, send it in the body of `POST /users/by-foreign-id` with a service key.",
      "code": "user/unsupported-param",
      "param": "name"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "user/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "user/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
