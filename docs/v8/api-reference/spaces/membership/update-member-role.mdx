---
title: "Update Member Role"
api: "PATCH /v8/:projectId/spaces/:spaceId/members/:userId/role"
description: "Update a member's role within a space"
---

Changes a member's role. Only space admins can perform this action. The role also applies in the space's child spaces. Raising someone's role gives it to them there too, but never lowers a role they already hold there: someone who is a regular member here and an admin of a child space stays an admin there when made a moderator here. Lowering someone's role lowers it there too: an admin made a moderator becomes a moderator in the child spaces, and a regular member loses `"admin"` and `"moderator"` there. Giving someone the role they already have changes nothing, here or in the child spaces.

The space creator always stays an admin of their space. Only the creator can promote or demote admins, so no one else can lower the creator's role, and the creator can't step down either: this route refuses their own id.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space.
</ParamField>

<ParamField path="userId" type="string" required>
  UUID of the member's user: their user id, not their membership id. Your own id is refused (`400 space/own-member-id`): your own membership is [`/spaces/:spaceId/members/me`](/v8/api-reference/spaces/membership/check-my-membership).
</ParamField>

## Body Parameters

<ParamField body="role" type="string" required>
  New role: `"admin"`, `"moderator"`, or `"member"`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Required with a service key: the user this request acts as. The request has exactly that user's permissions, so it is refused unless they are an admin of the space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message.
</ResponseField>

<ResponseField name="membership" type="object">
  Updated membership with `id`, `role`, `status`, `joinedAt`, and `userId`.
</ResponseField>

## Errors

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` or `userId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Own Member Id — 400">
    `userId` is the acting user (the token's user, or the user named by `actingUserId`). This route acts on another member; check your own membership with `GET /spaces/:spaceId/members/me` and leave with `DELETE /spaces/:spaceId/members/me`.
    ```json
    { "error": "`PATCH /spaces/:spaceId/members/:userId/role` acts on another member, not on yourself. Your own membership is at `/spaces/:spaceId/members/me`: GET to check it, DELETE to leave.", "code": "space/own-member-id" }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "space/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Wrong Location — 400">
    `actingUserId` was sent in the query string. On this endpoint every field, `actingUserId` included, goes in the request body.
    ```json
    { "error": "`actingUserId` goes in the request body on this endpoint.", "code": "space/wrong-location", "param": "actingUserId" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not an Admin — 403">
    The caller (or the user named by `actingUserId`) is not an admin of the space.
    ```json
    { "error": "Admin access required", "code": "space/admin-required" }
    ```
  </Accordion>
  <Accordion title="Membership Not Found — 404">
    `userId` has no membership in this space.
    ```json
    { "error": "Membership not found.", "code": "space/membership-not-found" }
    ```
  </Accordion>
  <Accordion title="Creator Required — 403">
    Someone other than the space creator promoting a member to, or demoting them from, `"admin"`.
    ```json
    { "error": "Only the space creator can promote or demote admins.", "code": "space/creator-required" }
    ```
  </Accordion>
  <Accordion title="Last Admin — 400">
    ```json
    { "error": "Cannot demote the last admin. Promote another member to admin first.", "code": "space/last-admin" }
    ```
    Lowering a role also lowers it in the child spaces, so it is refused too when the member is the last admin of one of them, named by `spaceId`:
    ```json
    { "error": "This member is the last admin of a child space. Promote another member to admin there first.", "code": "space/last-admin", "spaceId": "…" }
    ```
  </Accordion>
  <Accordion title="Member Banned — 409">
    Raising a member to `"moderator"` or `"admin"` while they are banned in this space or in one of its child spaces (the role also applies in the child spaces). Lowering a banned member's role is allowed. `bannedSpaceIds` lists where the bans are, so they can be lifted first with [Unban Member](/v8/api-reference/spaces/membership/unban-member).
    ```json
    { "error": "This member is banned in this space or one of its child spaces. Lift those bans before giving them a role.", "code": "space/member-banned", "bannedSpaceIds": ["…"] }
    ```
  </Accordion>
  <Accordion title="Member Not Active — 409">
    Raising a member to `"moderator"` or `"admin"` while their request is pending or was rejected.
    ```json
    { "error": "Only an active member can be given a role.", "code": "space/member-not-active" }
    ```
  </Accordion>
</AccordionGroup>

See also: [useUpdateMemberRole](/v8/hooks/spaces/use-update-member-role)
