## Overview

`useFetchComment` returns a function that fetches a single comment by ID.

<Note>
  With the `moderation` bundle installed, the comment comes back the way a thread shows it: in full with `isAuthorBlocked: true` when the signed-in user blocked its author, or as a [placeholder](/v8/data-models/comment#placeholders) with `isUnavailable: true` when the author blocked them. An embedded `parentComment` follows the same rules.

  When the **entity's** author has blocked the signed-in user, the request fails with `404 comment/not-found`, identical to a comment that doesn't exist — except for the user's own comments, which still load (with `entity` and `parentComment` set to `null` when requested) so they can be found and deleted. Replying to, reacting to and editing those are refused.
</Note>

## Usage Example

```tsx
import { useFetchComment } from "@sublay/react-js";

function DeepLinkComment({ commentId }: { commentId: string }) {
  const fetchComment = useFetchComment();

  const load = async () => {
    const comment = await fetchComment({
      commentId,
      include: ["user", "parent"],
    });
    console.log(comment);
  };

  return <button onClick={load}>Load Comment</button>;
}
```

## Parameters

<ParamField path="commentId" type="string" required>
  The ID of the comment to fetch.
</ParamField>

<ParamField path="include" type="string | string[]">
  Populate related data. Accepted values: `"user"`, `"entity"`, `"space"`, `"parent"`, `"grants"`.
</ParamField>

<SpaceReputationParams variant="context" field="path" />

## Returns

<ResponseField name="Comment" type="Comment">
  The fetched comment. When `"parent"` is included, `comment.parentComment` is populated. When `spaceReputation` is requested, the embedded author carries an added `spaceReputation` number. See [Comment data model](/v8/data-models/comment) and [Reputation](/v8/data-models/reputation).
</ResponseField>
