---
title: "Fetch Followers"
api: "GET /v8/:projectId/follows/followers"
description: "Get a paginated list of the authenticated user's followers"
---

Returns a paginated list of users who follow the authenticated user. Unlike the [user-scoped endpoint](/v8/api-reference/users/follows/get-followers), this route always returns data for the current authenticated user.

<Note>
  Users with a block between them and the acting user (the signed-in user, or the
  user a service key names in `actingUserId`), in either direction, are excluded
  from the results. Requires the `moderation` bundle.
</Note>

## Query Parameters

<ParamField query="page" type="number">
  Page number for pagination. Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Number of results per page. Defaults to `20`. Max `100`.
</ParamField>

<ParamField query="query" type="string">
  Optional search term. Filters the list to users whose username or name contains this text (case-insensitive). When omitted, no filtering is applied.
</ParamField>

<ParamField query="searchFields" type="string">
  Restricts which field `query` matches against — `username` or `name`. When omitted, `query` matches either field.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their followers are listed. A user token always acts as its own user and must not send it (`400 follow/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200` with a paginated response:

<ResponseField name="data" type="array">
  Array of follow entries.
  <Expandable title="item properties">
    <ResponseField name="followId" type="string">
      ID of the follow record.
    </ResponseField>
    <ResponseField name="user" type="object">
      Public profile of the follower user. Sensitive fields (email, hash, secureMetadata, etc.) are excluded.
    </ResponseField>
    <ResponseField name="followedAt" type="string">
      ISO timestamp of when the follow was created.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="pagination" type="object">
  Pagination metadata.
  <Expandable title="properties">
    <ResponseField name="page" type="number">
      Current page number.
    </ResponseField>
    <ResponseField name="pageSize" type="number">
      Number of items per page.
    </ResponseField>
    <ResponseField name="totalItems" type="number">
      Total number of followers.
    </ResponseField>
    <ResponseField name="totalPages" type="number">
      Total number of pages.
    </ResponseField>
    <ResponseField name="hasMore" type="boolean">
      Whether there are more pages after the current one.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "follow/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "follow/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "follow/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "follow/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "follow/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
