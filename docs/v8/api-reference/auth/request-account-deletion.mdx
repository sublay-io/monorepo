---
title: "Request Account Deletion"
api: "POST /v8/:projectId/auth/request-account-deletion"
description: "Email the authenticated user a one-time code to confirm self-service account deletion"
---

Starts the self-service account-deletion flow for the authenticated user. The server generates a one-time, 6-digit confirmation code, emails it to the user's registered address, and stores it for **10 minutes**. The user completes deletion by passing that code to the [Confirm Account Deletion](/v8/api-reference/auth/confirm-account-deletion) endpoint.

Requires the user's own access token; a service key is refused (`403 auth/user-token-required`). This step does **not** delete anything — it only sends the code.

<Warning>
  This flow only works for accounts with an email on file. Accounts without one
  (e.g. anonymous or foreign-id users) cannot self-serve deletion — delete them
  from your backend with [Delete User](/v8/api-reference/users/delete-user)
  (`users.deleteUser` in the [node SDK](/v8/node-sdk/users)).
</Warning>

## Body Parameters

This endpoint takes no body parameters.

## Response

<ResponseField name="success" type="boolean">
  `true` when the request is processed without a server error. The response is intentionally generic.
</ResponseField>

## Error Codes

| Code | Status | Description |
|------|--------|-------------|
| `auth/no-email-on-file` | 400 | The authenticated account has no email address, so a confirmation code cannot be delivered. Use a service key to delete it instead. |
| `auth/no-user-found` | 403 | The access token is valid but no matching user record exists (e.g. the account was already deleted). |
| `auth/unsupported-param` | 400 | The request sent `userId`, in the body or the query. These endpoints always act as the signed-in user: ``"`userId` isn't accepted here: these endpoints always act as the signed-in user."``, with `param: "userId"`. |
| `auth/user-token-required` | 403 | A service key called this endpoint, with or without `actingUserId`: `"This endpoint needs the user's own access token; a service key can't use it."` |
| `auth/acting-user-not-allowed` | 400 | A user token, or a request with no credentials, sent `actingUserId`: `"actingUserId is only accepted with a service key. A user's own token always acts as that user."` A user token always acts as its own user. |

<Note>
  Each call generates a fresh code and overwrites any pending one for that user.
  The code expires after 10 minutes.
</Note>
