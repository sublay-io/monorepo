---
title: "Set RSVP"
api: "POST /v8/:projectId/events/:eventId/rsvp"
description: "Set or change the caller's RSVP to an event"
---

Sets or changes the caller's RSVP. A new RSVP is created, or an existing one is switched, and the event's `rsvpCounts` are updated atomically. Requires authentication, and the caller must be able to [see the event](/v8/data-models/event#visibility) (otherwise `404`).

Transitions into `going` are capacity-checked under a row-level lock, so an event can never be oversold.

**Rules:**

- RSVPs close at `startTime`.
- A `cancelled` event rejects RSVPs.
- `"maybe"` is rejected when the event's `allowMaybe` is `false`.
- `"going"` (new or switched into) is rejected when `rsvpCounts.going` has reached `capacity`.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

## Body Parameters

<ParamField body="status" type="string" required>
  `"going"`, `"maybe"`, or `"not_going"`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose RSVP is set. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the [Event](/v8/data-models/event) with refreshed `rsvpCounts` and the caller's `userRsvp`.

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Not Found / No Access — 404">
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Event Cancelled — 409">
    ```json
    { "error": "This event has been cancelled.", "code": "event/cancelled" }
    ```
  </Accordion>
  <Accordion title="RSVPs Closed — 409">
    ```json
    { "error": "RSVPs are closed for this event.", "code": "event/rsvp-closed" }
    ```
  </Accordion>
  <Accordion title="Maybe Disabled — 409">
    ```json
    { "error": "This event does not allow a 'maybe' RSVP.", "code": "event/maybe-disabled" }
    ```
  </Accordion>
  <Accordion title="At Capacity — 409">
    ```json
    { "error": "This event is at capacity.", "code": "event/full" }
    ```
  </Accordion>
</AccordionGroup>
