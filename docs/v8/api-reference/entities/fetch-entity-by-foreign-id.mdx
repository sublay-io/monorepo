---
title: "Fetch Entity by Foreign ID"
api: "GET /v8/:projectId/entities/by-foreign-id"
description: "Get an entity by its foreign ID, optionally creating it if not found"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Returns an entity matching the given `foreignId` within the project. Optionally creates a blank entity if none exists — useful for automatically bootstrapping entities when a user first visits a page or URL in your application.

## Query Parameters

<ParamField query="foreignId" type="string" required>
  The foreign ID to look up. This is the identifier from your application (URL, slug, database ID, etc.).
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only: the user to read as. The response is exactly what that user's own access token would get — their own drafts, block filtering, `saved`, their own reaction and the top comments they may see — and the read counts as their view. Leave it out for the anonymous view: drafts return `404`, and the read doesn't count as a view. It shapes the read only: an entity made by `createIfNotFound` is always app-owned, with no author. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

<ParamField query="createIfNotFound" type="string">
  When `"true"`, creates a blank entity with this `foreignId` if no entity is found. The new entity has no title, content, or author (an app-owned entity), whoever asks. Defaults to `"false"`.

  Because the new entity has no author, the project's **Who can create entities without an author** setting decides who may create it:

  | Caller | Everyone (default) | Signed-in users only | No one from the client |
  |---|---|---|---|
  | Service key | Creates | Creates | Creates |
  | User token | Creates | Creates | `403` |
  | No credentials | Creates | `403` | `403` |

  A refused caller gets `403 entity/authorless-creation-not-allowed` and nothing is created. A user token that is expired or invalid counts as no credentials, so under **Signed-in users only** that caller is refused too. A suspended user can't create the entity: they get `403 user/suspended`, as on [Create Entity](/v8/api-reference/entities/create-entity). The setting only matters when the entity doesn't exist yet: reading an existing entity works for every caller. Requests that race to create the same `foreignId` all get the one entity that was created. A `foreignId` whose entity was deleted stays taken: the lookup answers `409 entity/foreign-id-taken` instead of creating a new entity. A project admin changes the setting in the dashboard under **Settings → General → SDK**.
</ParamField>

<ParamField query="include" type="string">
  Associations to include. Pass it as one comma-separated value (`include=user,space`) or as repeated params (`include=user&include=space`). Values:
  - `user` — the author's user profile
  - `space` — the space the entity belongs to
  - `topComments` — the entity's best top-level comments, as full [Comment](/v8/data-models/comment) objects (see [Top comments](/v8/data-models/entity#top-comments))
  - `saved` — whether the authenticated user has saved this entity
  - `files` — uploaded file/image attachments
  - `grants` — the [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary) for the entity
</ParamField>

<ParamField query="topCommentsLimit" type="number" default="1">
  With `include=topComments`: how many top comments per entity. A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`. Maximum `5` — larger values are treated as `5`.
</ParamField>

<ParamField query="topCommentsSortByReaction" type="string" default="upvote">
  With `include=topComments`: the reaction whose raw count ranks the top comments (ties newest first). One of `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`.
</ParamField>

`include` values are case-insensitive. An unknown value returns `400 entity/invalid-query`, as does sending `topCommentsLimit` or `topCommentsSortByReaction` without `include=topComments`. `topComments` lists real content only — deleted, removed and block-edged comments are left out — and is `[]` when nothing qualifies.

## Response

Returns an [Entity](/v8/data-models/entity) object.

<Note>
  This endpoint returns entities regardless of moderation status, so the client can display the appropriate moderation state. Draft entities are only returned to their author: a user token, or a service key naming the author in `actingUserId`.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid include — 400">
    Returned with code `entity/invalid-query` for an unknown `include` value, when `topCommentsLimit` is below `1` or not a whole number, or when `topCommentsLimit` / `topCommentsSortByReaction` is sent without `include=topComments`.

    ```json
    { "error": "include: Unknown include `comments`. Allowed: user, space, topComments, saved, files, grants.", "code": "entity/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Renamed include — 400">
    `include=topComment` is rejected with a pointer to its replacement.

    ```json
    {
      "error": "`include=topComment` was renamed to `topComments` (with `topCommentsLimit` / `topCommentsSortByReaction`).",
      "code": "entity/unsupported-param",
      "param": "include"
    }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Entity not found", "code": "entity/not-found" }
    ```
    Returned when no entity with this `foreignId` exists and `createIfNotFound` is not `"true"`.
  </Accordion>
  <Accordion title="Foreign ID Taken — 409">
    `createIfNotFound` was `"true"` and the entity with this `foreignId` was deleted. A `foreignId` is unique across the project's entities, deleted ones included, so a deleted entity's `foreignId` can't be reused. Nothing is created.

    ```json
    { "error": "An entity with this foreignId was deleted; its foreignId can't be reused.", "code": "entity/foreign-id-taken" }
    ```
  </Accordion>
  <Accordion title="Rejected by Validation Webhook — 400">
    ```json
    { "error": "Entities are created by server only", "code": "entity/webhook-validation-failed" }
    ```
    Returned when your `entity.created` [validation webhook](/v8/webhooks) rejects the entity that `createIfNotFound` would create. `error` carries the `message` your webhook returned. Nothing is stored.
  </Accordion>
  <Accordion title="Author-less Creation Not Allowed — 403">
    `createIfNotFound` was `"true"`, no entity with this `foreignId` exists, and the project's **Who can create entities without an author** setting doesn't let this caller create one: a request with no credentials under **Signed-in users only** or **No one from the client**, or a user token under **No one from the client**. The message names the caller.

    ```json
    { "error": "This project doesn't allow anonymous callers to create entities without an author. A project admin can change this in the dashboard: Settings → General → SDK.", "code": "entity/authorless-creation-not-allowed" }
    ```

    For a user token, the message reads `signed-in users` in place of `anonymous callers`.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
