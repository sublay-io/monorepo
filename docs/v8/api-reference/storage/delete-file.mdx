---
title: "Delete File"
api: "DELETE /v8/:projectId/storage/:fileId"
description: "Delete a file and all its variants from storage"
---

Deletes a file record and removes all associated storage objects. For image files, all generated variants are also deleted.

Requires authentication. **The owner deletes:** a file with an owner is deleted only as that user — with their own access token, or with a service key naming them in `actingUserId`, and the request then runs exactly as theirs (suspension included). An app-owned file (uploaded without an `actingUserId`) is deleted only by a service key naming nobody; a user token gets `403`.

**Rate limit**: 50 requests per 5 minutes.

## Path Parameters

<ParamField path="fileId" type="string" required>
  The UUID of the file to delete.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user this delete acts as. Required when the file has an owner: name the owner (naming anyone else gets `403`). Leave it out only for an app-owned file. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 storage/acting-user-not-allowed`).
</ParamField>

## Response

```json
{
  "message": "File deleted successfully",
  "fileId": "uuid",
  "deletedPaths": [
    "images/abc123/original.webp",
    "images/abc123/thumbnail_original.webp",
    "images/abc123/medium_original.webp"
  ]
}
```

`deletedPaths` lists all storage paths that were removed, including the original file and any image variants.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `fileId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid file id: expected a UUID.", "code": "storage/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "File not found", "code": "storage/file-not-found" }
    ```
  </Accordion>
  <Accordion title="Unauthorized — 403">
    Returned when the acting user doesn't own the file, or when a user token, or a service key naming a user, deletes an app-owned file.
    ```json
    { "error": "Unauthorized", "code": "storage/unauthorized" }
    ```
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId` for a file that has an owner. Name the owner: the request then runs exactly as their own.

    ```json
    { "error": "A service key must send actingUserId to change a record that has an author: the request then acts as that user.", "code": "storage/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "storage/acting-user-not-allowed" }
    ```
  </Accordion>
</AccordionGroup>
