---
title: "Fetch Event RSVPs"
api: "GET /v8/:projectId/events/:eventId/rsvps"
description: "List the named guest list (who RSVP'd) for an event"
---

Returns a paginated list of [EventRsvp](/v8/data-models/event-rsvp) records, each with the `user` populated — the **named** guest list. Results are ordered by `createdAt` descending.

Authentication is optional. The viewer is the signed-in user, or the user a service key names in `actingUserId`; a service key naming nobody is treated as anonymous, with no bypass. The event is first loaded behind the [visibility predicate](/v8/data-models/event#visibility), so a caller without access to the event gets `404`. The named list itself is then gated:

- **Hosts** can always see it.
- **Any viewer** (including anonymous) can see it when the event's `guestListVisible` is `true`.
- Otherwise the response is `403`.

Aggregate RSVP **counts** are always public via the event's `rsvpCounts` — this endpoint only governs the per-user list.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user to read as, exactly as their own access token: their event visibility and whether they host it. Leave it out for the anonymous view (a `public` event's list, and only when `guestListVisible` is `true`). A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 event/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page. Capped at `100`. Defaults to `10`.
</ParamField>

<ParamField query="status" type="string">
  Comma-separated RSVP statuses to filter by, e.g. `"going,maybe"`: any of `going`, `maybe` and `not_going`, matched exactly (another case returns `400 event/invalid-query`). When omitted, all statuses are returned.
</ParamField>

## Response

Returns a paginated response: `{ data: EventRsvp[], pagination: {...} }`.

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found / No Access — 404">
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Guest List Hidden — 403">
    ```json
    { "error": "This event's guest list is not visible.", "code": "event/guest-list-hidden" }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned for an invalid query value, such as a `status` entry that isn't exactly `going`, `maybe` or `not_going`. `error` starts with the field name.
    ```json
    { "error": "status.0: Invalid option: expected one of \"going\"|\"maybe\"|\"not_going\"", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
