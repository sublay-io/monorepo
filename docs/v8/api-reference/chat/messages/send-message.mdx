Creates a new message in a conversation. The caller must be an active member. At least one of `content`, `gif`, or a file attachment is required.

For space conversations with `postingPermission: "admins"`, only users with `admin` or `moderator` role in the parent Space can send messages.

This endpoint accepts `multipart/form-data` to support file attachments alongside message content.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation to send the message to.
</ParamField>

## Body Parameters

<ParamField body="content" type="string">
  Text content of the message. Optional if a GIF or file is provided.
</ParamField>

<ParamField body="gif" type="object">
  GIF attachment. Optional. See [GifData](/v8/data-models/chat-message#gifdata) for the expected shape.
</ParamField>

<ParamField body="mentions" type="array">
  Array of [Mention](/v8/data-models/chat-message#mention) objects for @mentions in the message content. Optional.
</ParamField>

<ParamField body="parentMessageId" type="string">
  ID of a message in this conversation to reply to in a thread. The referenced message must be a main-stream message (threads are one level deep only). Optional.
</ParamField>

<ParamField body="quotedMessageId" type="string">
  ID of a message to quote inline. The message stays in the main stream but renders the quoted content as a preview. Must be a message in this conversation. Optional.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data. Limited to 10 KB. Optional.
</ParamField>

<ParamField body="localId" type="string">
  Client-generated identifier for optimistic deduplication. The server echoes it back in the response but never stores it. Optional.
</ParamField>

<ParamField body="files" type="file[]">
  File attachments (multipart/form-data). Up to 10 files per message. Optional.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. The message author; must be an active member. On a multipart request, send it as a form field. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params, in the body with the other fields. They add a `spaceReputation` field to the message sender's `user`, alongside the always-present `reputation` total. In JSON, `spaceReputationDescendants` is a boolean; on a multipart request both are form fields, with `spaceReputationDescendants` as `"true"` or `"false"`. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

<SpaceReputationParams variant="context" field="body" />

<Note>
  Every field goes in the body (or the multipart form). A body field sent in the query string returns `400 chat/wrong-location`.
</Note>

## Response

Returns the created [ChatMessage](/v8/data-models/chat-message) object, fully populated with `user`, `quotedMessage`, `files`, `reactionCounts` (empty on creation), and `userReactions` (empty on creation). If `localId` was provided, it is echoed in the response.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Wrong Location — 400">
    A body field — `actingUserId`, `content`, `spaceReputationId`, `spaceReputationDescendants` or any other — was sent in the query string.
    ```json
    { "error": "`spaceReputationId` goes in the request body on this endpoint.", "code": "chat/wrong-location", "param": "spaceReputationId" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Empty Message — 400 Bad Request">
    ```json
    { "error": "Message must have content, a GIF, or at least one file.", "code": "chat/empty-message" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Invalid Parent — 400 Bad Request">
    ```json
    { "error": "Parent message not found, not in this conversation, already removed, or is itself a reply.", "code": "chat/invalid-parent" }
    ```
  </Accordion>
  <Accordion title="Invalid Quote — 400 Bad Request">
    The quoted message is not in this conversation, or was removed.
    ```json
    { "error": "Quoted message not found in this conversation.", "code": "chat/invalid-quote" }
    ```
  </Accordion>
</AccordionGroup>
