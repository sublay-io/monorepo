---
title: "Fetch Mutual Spaces"
api: "GET /v8/:projectId/spaces/mutual/:userId"
description: "Get spaces shared between the authenticated user and another user"
---

Returns a paginated list of spaces that both the authenticated user and another user are active members of — i.e. their spaces in common. Requires an authenticated user. Only spaces the authenticated user can see are listed; as an active member, they can see every space they share. Sub-spaces are counted in each space's `childSpacesCount` only when the user can see them.

## Path Parameters

<ParamField path="userId" type="string" required>
  The other user's Sublay ID. Mutual spaces are computed between this user and the authenticated user.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose spaces are compared with the user in the path. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number">
  Page number. Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page. Max `100`. Defaults to `20`.
</ParamField>

<ParamField query="include" type="string">
  Associations to include, as a comma-separated value or repeated params. The only value is:
  - `files` — the processed `avatarFile` and `bannerFile` objects on each space (requires the `files-images` bundle)

  Matching ignores case. An unknown value returns `400 space/invalid-query`.
</ParamField>

## Response

<ResponseField name="data" type="Space[]">
  The spaces both users are active members of. Computed fields such as `membersCount` and `isMember` are populated from the authenticated user's perspective.
</ResponseField>

<ResponseField name="pagination" type="object">
  Standard pagination metadata (`page`, `pageSize`, `totalPages`, `totalItems`, `hasMore`).
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `userId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid user id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid query — 400">
    Returned with code `space/invalid-query` for an unknown `include` value.

    ```json
    { "error": "include: Unknown include `members`. Allowed: files.", "code": "space/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
