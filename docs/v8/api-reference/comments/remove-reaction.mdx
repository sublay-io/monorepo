---
title: "Remove Comment Reaction"
api: "DELETE /v8/:projectId/comments/:commentId/reactions"
description: "Remove the authenticated user's reaction from a comment"
---

Removes the authenticated user's reaction from a comment. The comment's `reactionCounts` map is decremented for the removed reaction type.

**Authentication required.**

## Path Parameters

<ParamField path="commentId" type="string" required>
  The UUID of the comment to remove the reaction from.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose reaction is removed. A key has no user of its own, so leaving it out returns `400 comment/missing-user-id`. A user token always acts as its own user and must not send it (`400 comment/acting-user-not-allowed`).
</ParamField>

## Blocks

Removing your own reaction is undoing your own action, so a block doesn't stop it: as long as the comment is visible to you — in full, or as a placeholder — your reaction is removed. This includes a comment whose author blocked you, a comment its author deleted and a moderator-removed comment — even though neither of the last two [takes new reactions](/v8/api-reference/comments/add-reaction#deleted-and-removed-comments).

When the comment isn't visible to you at all — it sits on an entity whose author has blocked you — the request returns `404 comment/not-found` and nothing changes. The exception is your **own** comment on such an entity: it stays visible to you, so removing your reaction from it works.

## Response

Returns the [Comment](/v8/data-models/comment) as you'd see it after the change — in full, flagged with `isAuthorBlocked`, or as a [placeholder](/v8/data-models/comment#placeholders) — with the updated `reactionCounts`. If you had no reaction on the comment, the comment is returned unchanged.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Params — 400">
    Returned when `commentId` isn't a valid UUID.

    ```json
    { "error": "Invalid comment id: expected a UUID.", "code": "comment/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    Returned when a user token sends `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "comment/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "comment/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    Returned when the request sends `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "comment/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "comment/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    Returned when a service key sends no `actingUserId`.

    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "comment/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Comment not found.", "code": "comment/not-found" }
    ```
  </Accordion>
</AccordionGroup>
