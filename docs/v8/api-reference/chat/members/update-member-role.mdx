---
title: "Update Member Role"
api: "PATCH /v8/:projectId/chat/conversations/:conversationId/members/:userId/role"
description: "Change a member's role in a group conversation"
---

Updates the role of an active member in a group conversation. Only group conversations have roles — this endpoint returns a 400 for direct and space conversations.

The caller must be an active `admin`.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation.
</ParamField>

<ParamField path="userId" type="string" required>
  The ID of the member whose role is being changed. Your own id is refused (`400 chat/own-member-id`): an admin can't change their own role. Your own membership is [`/chat/conversations/:conversationId/members/me`](/v8/api-reference/chat/members/check-my-membership).
</ParamField>

## Body Parameters

<ParamField body="role" type="string" required>
  The new role. Accepted values: `"admin"`, `"member"`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be an active `admin` of the conversation. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [ConversationMember](/v8/data-models/conversation-member) record.

## Error Responses

<AccordionGroup>
  <Accordion title="Own Member Id — 400">
    `userId` is the acting user (the token's user, or the user named by `actingUserId`). This route acts on another member; check your own membership with `GET /chat/conversations/:conversationId/members/me` and leave with `DELETE /chat/conversations/:conversationId/members/me`.
    ```json
    { "error": "`PATCH /chat/conversations/:conversationId/members/:userId/role` acts on another member, not on yourself. Your own membership is at `/chat/conversations/:conversationId/members/me`: GET to check it, DELETE to leave.", "code": "chat/own-member-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Conversation not found.", "code": "chat/not-found" }
    ```
  </Accordion>
  <Accordion title="Invalid Type — 400 Bad Request">
    ```json
    { "error": "Roles can only be changed in group conversations.", "code": "chat/invalid-type" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "Only group admins can change member roles.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Member Not Found — 404">
    ```json
    { "error": "Member not found in this conversation.", "code": "chat/member-not-found" }
    ```
  </Accordion>
</AccordionGroup>
