Returns a paginated list of reports for spaces where the authenticated user has the `admin` or `moderator` role. If `spaceId` is omitted, reports from all spaces the user moderates are returned.

**Authentication required.** Must be a space admin or moderator.

## Query Parameters

<ParamField query="spaceId" type="string">
  Filter to a specific space. The user must be an admin or moderator of that space. When omitted, reports from all moderated spaces are returned.
</ParamField>

<ParamField query="targetType" type="string">
  Filter by content type. One of: `entity`, `comment`, `message`. Message
  reports appear in this queue only for conversations attached to a space —
  DM and group reports have no space, so they are project-level and surface in
  the Sublay dashboard instead.
</ParamField>

<ParamField query="status" type="string">
  Filter by report status. One of: `pending`, `on-hold`, `escalated`, `dismissed`, `actioned`.
</ParamField>

<ParamField query="sortBy" type='"createdAt"' default="createdAt">
  Reports are sorted by when they were created.
</ParamField>

<ParamField query="sortDir" type='"asc" | "desc"'>
  Direction of the `createdAt` sort, `"asc"` or `"desc"` (either case). Default `"desc"` (newest first).
</ParamField>

<ParamField query="page" type="number" default="1">
  Page number (1-indexed).
</ParamField>

<ParamField query="limit" type="number" default="20">
  Number of reports per page.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Reports are returned for the spaces this user moderates. A user token always acts as its own user and must not send it (`400 report/acting-user-not-allowed`).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to each reported content author's populated `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

## Response

```json
{
  "data": [
    {
      "id": "uuid",
      "targetId": "uuid",
      "targetType": "comment",
      "spaceId": "uuid",
      "status": "pending",
      "reporterCount": 3,
      "target": { ...Comment object... },
      "space": { ...Space object... },
      "userReports": [
        { "userId": "uuid", "reason": "spam", "details": "..." }
      ],
      "createdAt": "2025-01-01T00:00:00Z"
    }
  ],
  "pagination": {
    "page": 1,
    "pageSize": 20,
    "totalPages": 2,
    "totalItems": 35,
    "hasMore": true
  }
}
```

Each report includes the full reported content (`target`), the space it belongs to, and all individual user reports (`userReports`). `target.user` is the author's public [User](/v8/data-models/user) — no email or other private fields.

## Error Responses

<AccordionGroup>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "Moderator access required for this space", "code": "report/forbidden" }
    ```
    Returned when `spaceId` is provided but the user is not a moderator of that space.
  </Accordion>
  <Accordion title="Unsupported sort — 400">
    `sortBy=new` and `sortBy=old` are rejected with a pointer to their replacements: `sortBy=createdAt` (newest first by default) and `sortBy=createdAt&sortDir=asc`.

    ```json
    {
      "error": "`sortBy=old` isn't supported in v8. Use `sortBy=createdAt&sortDir=asc`.",
      "code": "report/unsupported-param",
      "param": "sortBy"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "report/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "report/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "report/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
