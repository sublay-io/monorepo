---
title: "Create Space"
api: "POST /v8/:projectId/spaces"
description: "Create a new community space"
---

Creates a new space. Its creator — the signed-in user, or the user a service key names in `actingUserId` — is automatically added as an admin. A space always has a creator, so a service key must name one. Supports optional avatar and banner image upload via multipart form data.

**Authentication required.** A request with no credentials returns `401`.

## Body Parameters

<ParamField body="name" type="string">
  Display name for the space. Must be 3–100 characters.
</ParamField>

<ParamField body="slug" type="string">
  Optional URL slug. Must be unique per project. Supports Unicode letters, numbers, hyphens, and underscores.
</ParamField>

<ParamField body="description" type="string">
  Optional description. Up to 1,000 characters.
</ParamField>

<ParamField body="readingPermission" type="string">
  Who can read content: `"anyone"` or `"members"`. Defaults to `"anyone"`.
</ParamField>

<ParamField body="postingPermission" type="string">
  Who can post entities: `"anyone"`, `"members"`, or `"admins"`. Defaults to `"members"`.
</ParamField>

<ParamField body="visibility" type="string">
  Whether the space is listed and discoverable: `"public"`, `"unlisted"`, or `"private"`. Defaults to `"public"`. Governs discoverability only — independent of `readingPermission`, which governs content. `"unlisted"` hides the space from discovery and search but keeps it reachable by direct link; `"private"` currently behaves like `"unlisted"`. See [Space visibility](/v8/data-models/space#visibility).
</ParamField>

<ParamField body="requireJoinApproval" type="boolean">
  Whether new joins require approval. Defaults to `true`.
</ParamField>

<ParamField body="metadata" type="object">
  Optional arbitrary key-value data. Up to 1 MB.
</ParamField>

<ParamField body="parentSpaceId" type="string">
  Optional UUID of a parent space. The caller must be an admin of the parent space; when a service key creates the space for a user (`actingUserId`), that user must be.
</ParamField>

<ParamField body="avatarFile" type="file">
  Optional avatar image. Multipart form field. Requires `avatarFile.options` when provided.
</ParamField>

<ParamField body="bannerFile" type="file">
  Optional banner image. Multipart form field. Requires `bannerFile.options` when provided.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who creates the space and becomes its admin, held to their own permissions. Leaving it out returns `400 space/missing-user-id`. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

Returns the created [Space](/v8/data-models/space) object with `membersCount`, `childSpacesCount`, and optional file associations.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId`. A space needs a creator.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "space/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "space/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Slug Taken — 409">
    ```json
    { "error": "A space with this slug already exists.", "code": "space/slug-taken" }
    ```
  </Accordion>
  <Accordion title="Parent Not Found — 404">
    ```json
    { "error": "Parent space not found.", "code": "space/parent-not-found" }
    ```
  </Accordion>
  <Accordion title="Parent Admin Required — 403">
    ```json
    { "error": "Only admins of the parent space can create child spaces.", "code": "space/parent-admin-required" }
    ```
  </Accordion>
  <Accordion title="Banned — 403">
    The creator was banned in the parent space (or above) while the child space was being created.
    ```json
    { "error": "You are banned from a parent of this space.", "code": "space/banned" }
    ```
  </Accordion>
  <Accordion title="Max Depth Exceeded — 400">
    ```json
    { "error": "Maximum nesting depth (10) exceeded.", "code": "space/max-depth-exceeded" }
    ```
  </Accordion>
  <Accordion title="File Too Large — 413">
    ```json
    { "code": "space/file-too-large", "message": "Avatar image exceeds 50MB limit." }
    ```
  </Accordion>
  <Accordion title="files-images Bundle Required — 403">
    Returned when an avatar or banner is uploaded on a project without the files-images bundle. `missingTables` lists the tables that aren't installed.
    ```json
    { "error": "Space avatar/banner uploads require the files-images bundle. Enable it for this project.", "code": "space/files-images-bundle-required", "missingTables": ["Files", "Images"] }
    ```
  </Accordion>
</AccordionGroup>

See also: [useCreateSpace](/v8/hooks/spaces/use-create-space)
