---
title: "Delete Follow"
api: "DELETE /v8/:projectId/follows/:followId"
description: "Remove a follow relationship by its follow ID"
---

Removes a follow relationship by the follow record ID. Only the follower (the user who created the follow) can delete it. Use [Unfollow User](/v8/api-reference/users/follows/unfollow-user) instead if you only have the target user's ID.

## Path Parameters

<ParamField path="followId" type="string" required>
  The ID (UUID) of the follow record to delete.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be the follower. A user token always acts as its own user and must not send it (`400 follow/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `204` with no body.

## Error Responses

<AccordionGroup>
  <Accordion title="Follow Not Found — 404">
    ```json
    {
      "error": "Follow relationship does not exist.",
      "code": "follow/not-found"
    }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    {
      "error": "You do not have permission to delete this follow relationship.",
      "code": "follow/forbidden"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "Missing user ID",
      "code": "follow/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "follow/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "follow/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
