---
title: "Fetch Event"
api: "GET /v8/:projectId/events/:eventId"
description: "Fetch a single event by ID, with visibility enforced"
---

Returns a single event by UUID. The [server-side visibility predicate](/v8/data-models/event#visibility) is applied: if the event does not exist **or** the caller cannot see it, the response is `404` (existence is never leaked).

The response always includes inline `rsvpCounts`. Authentication is optional; pass the `userRsvp` include with an authenticated caller to populate `userRsvp`.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

## Query Parameters

<ParamField query="include" type="string">
  Associations to expand, as a comma-separated value (`include=user,space`) or repeated params. Values:
  - `user` — the creator's user profile
  - `space` — the space the event belongs to (`null` when the viewer can't see that space; see [Space visibility](/v8/data-models/space#visibility))
  - `files` — the cover and gallery file objects
  - `userRsvp` — the caller's own RSVP status (needs a viewer; otherwise `null`)

  Matching ignores case. An unknown value returns `400 event/invalid-query`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only: the user to read as. The response is exactly what that user's own access token would get (visibility, `userRsvp`). Leave it out for the anonymous view: only a `public` event is returned, and any other answers `404`. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the [Event](/v8/data-models/event) object.

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned for an unknown `include` value.
    ```json
    { "error": "include: Unknown include `rsvps`. Allowed: user, space, files, userRsvp.", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Not Found / No Access — 404">
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
</AccordionGroup>
