---
title: "Create Event"
api: "POST /v8/:projectId/events"
description: "Create an event, optionally with a cover image, images and files"
---

Creates an event. The acting user (the token's own user, or the `actingUserId` a service key sends) becomes the event's **owner** (`userId`) and is automatically added to `hostIds`. See [Owner and hosts](/v8/data-models/event#owner-and-hosts). Supports inline upload of a cover (`coverFile`), images (`images`) and files (`files`) via `multipart/form-data`; on a multipart request every field is a string, so send `location`, `hostIds` and `metadata` as JSON strings.

The required location fields depend on `type`: `online` needs a `url`; `physical` needs an `address` or `location`; `hybrid` needs both a `url` and an `address`/`location`.

Requires authentication. Space-scoped events (`spaceId`) require the `spaces` bundle and active membership of the space, no ban in any space above it, and, in a space whose `postingPermission` is `"team"`, the admin or moderator role there — for a service key, the membership of the user it names in `actingUserId`, exactly as that user's own request. Every user in `hostIds` must be an active member of the space too. Image upload requires the `files-images` bundle.

## Body Parameters

<ParamField body="title" type="string" required>
  Event title. 1–300 characters.
</ParamField>

<ParamField body="startTime" type="string" required>
  ISO datetime when the event starts. RSVPs close at this moment.
</ParamField>

<ParamField body="type" type="string" required>
  `"online"`, `"physical"`, or `"hybrid"`. Controls which location fields are required.
</ParamField>

<ParamField body="description" type="string">
  Optional description.
</ParamField>

<ParamField body="endTime" type="string">
  Optional ISO datetime when the event ends.
</ParamField>

<ParamField body="timezone" type="string">
  Optional IANA timezone string, e.g. `"America/New_York"`.
</ParamField>

<ParamField body="url" type="string">
  Join/stream URL. Required for `online` and `hybrid` events.
</ParamField>

<ParamField body="venueName" type="string">
  Optional venue name.
</ParamField>

<ParamField body="address" type="string">
  Street address. Required (alone or with `location`) for `physical` and `hybrid` events.
</ParamField>

<ParamField body="location" type="{ latitude: number; longitude: number }">
  Geographic coordinates. Stored as a GeoJSON point and used for proximity search. On multipart requests, send as a JSON string.
</ParamField>

<ParamField body="spaceId" type="string">
  Optional UUID of a space to scope the event to. Requires the `spaces` bundle and active membership. Mandatory when `visibility` is `"members"`.
</ParamField>

<ParamField body="visibility" type="string">
  `"public"`, `"members"`, or `"invite"`. Defaults to `"public"`. `"members"` requires a `spaceId`.
</ParamField>

<ParamField body="capacity" type="number">
  Maximum number of `going` RSVPs. Positive integer. Omit for unlimited.
</ParamField>

<ParamField body="allowMaybe" type="boolean">
  Whether a `"maybe"` RSVP is allowed. Defaults to `true`.
</ParamField>

<ParamField body="guestListVisible" type="boolean">
  Whether everyone who can see the event can view the named guest list. When `false`, only hosts who are active members of the event's space and not banned in it or a space above it and the space's admins and moderators can. Defaults to `true`.
</ParamField>

<ParamField body="hostIds" type="string[]">
  Additional host user IDs. The creator is always added automatically. For an event in a space, each one must be an active member of that space (`409 event/host-not-member`); events with no space accept anyone. On multipart requests, send as a JSON string.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key-value data. Up to 1 MB.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who becomes the creator and first host, held to their own permissions. A user that doesn't exist returns `404 event/user-not-found`. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

<ParamField body="coverFile" type="file">
  Optional cover image (one image). Multipart file field. Requires `coverFile.options`. The cover is one of the event's `files`, and `coverImageId` points at it; it sorts before the event's other files (find it by `coverImageId`). See [Cover and files](/v8/data-models/event#cover-and-files).
</ParamField>

<ParamField body="coverFile.options" type="string">
  JSON-stringified image-processing options for the cover (the same discriminated union used by [Upload Image](/v8/api-reference/storage/upload-image)).
</ParamField>

<ParamField body="images" type="file[]">
  Optional images in the event's files, processed into sizes per `images.options`. Multipart file field. Requires `images.options`. A request takes at most 20 files over all its file fields together.
</ParamField>

<ParamField body="images.options" type="string">
  JSON-stringified image-processing options applied to every image in `images` (`mode` is required). The same options as [Upload Image](/v8/api-reference/storage/upload-image)'s `file.options`.
</ParamField>

<ParamField body="files" type="file[]">
  Optional files in the event's files, stored as uploaded. Multipart file field. Each file's `type` comes from its MIME type; an image sent here isn't processed, so it has no `image` data.
</ParamField>

<ParamField body="files.options" type="string">
  Optional JSON-stringified file options: `pathParts` (string[]) customizes the storage path.
</ParamField>

The event's files list the cover first, then the images, then the files, each in upload order. An `images.options` or `files.options` sent without its files is ignored.

## Response

Returns `201` with the created [Event](/v8/data-models/event) object, including inline `rsvpCounts`. When the `files-images` bundle is installed it also carries `files` (`[]` for none; the cover first, then its images and files, images with their variants) and the host's `user.avatarFile` / `user.bannerFile`; without the bundle there is no `files` key.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `cover.options` or `gallery.options`. The cover is uploaded as `coverFile`, with its options in `coverFile.options`, and the event's images as `images`, with their options in `images.options`.

    ```json
    {
      "error": "`cover.options` isn't supported in v8. Send the cover image as the `coverFile` file, with its options as `coverFile.options`.",
      "code": "event/unsupported-param",
      "param": "cover.options"
    }
    ```

    ```json
    {
      "error": "`gallery.options` isn't supported in v8. Send gallery images as the `images` files, with their options as `images.options`.",
      "code": "event/unsupported-param",
      "param": "gallery.options"
    }
    ```

    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "Online events require a `url`.", "code": "event/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Bundle Not Installed — 403">
    Returned when a cover, images or files are uploaded on a project without the files-images bundle, or when `spaceId` is sent on a project without the spaces bundle: `missingTables` lists the tables that aren't installed and `bundleId` the bundle to install. While the bundle is still being installed, the response is `503 database/tables-provisioning` instead. See [Bundles](/v8/bundles).
    ```json
    { "error": "Event cover images and files require the files-images bundle. Enable it for this project.", "code": "database/tables-not-available", "missingTables": ["Files", "Images"], "bundleId": "files-images", "dashboardUrl": "https://…/<projectId>/database" }
    ```
    ```json
    { "error": "Space-scoped events require the spaces bundle. Enable it for this project.", "code": "database/tables-not-available", "missingTables": ["Spaces", "SpaceMembers", "SpaceBans", "Rules"], "bundleId": "spaces", "dashboardUrl": "https://…/<projectId>/database" }
    ```
  </Accordion>
  <Accordion title="Space Not Found — 404">
    The `spaceId` names no space, or one the creator can't see (a private space they aren't an active member of, or a space under one). Checked before the membership check. See [Space visibility](/v8/data-models/space#visibility).
    ```json
    { "error": "Space not found", "code": "event/space-not-found" }
    ```
  </Accordion>
  <Accordion title="Not a Space Member — 403">
    The creator isn't an active member of the space — including anyone banned in the space itself.
    ```json
    { "error": "You must be an active member of this space to create an event in it.", "code": "event/not-space-member" }
    ```
  </Accordion>
  <Accordion title="Posting Not Allowed — 403">
    The creator is an active member, but is banned in a space above it, or the space's `postingPermission` is `"team"` and they aren't one of its admins or moderators. One body for every cause.
    ```json
    { "error": "You can't post or take part in this space.", "code": "space/posting-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Host Not a Member — 409">
    A user in `hostIds` isn't an active member of the event's space (not a member, pending or banned — the same body for each).
    ```json
    { "error": "This user isn't an active member of this space.", "code": "event/host-not-member" }
    ```
  </Accordion>
  <Accordion title="Image Too Large — 413">
    ```json
    { "error": "`coverFile` is over the 50 MB per-file limit.", "code": "event/file-too-large", "param": "coverFile" }
    ```
    A file is over 50 MB. `param` names its field.
  </Accordion>
  <Accordion title="Invalid Image — 422">
    ```json
    { "error": "Cover file is not a valid image.", "code": "event/invalid-image", "param": "coverFile" }
    ```
    The cover can't be read as an image. A file in `images` that can't be read gets the same code with `param: "images"`:
    ```json
    { "error": "File \"photo.jpg\" is not a valid image.", "code": "event/invalid-image", "param": "images" }
    ```
    An image over 10000 px on a side gets the same code. `error` gives its size:
    ```json
    { "error": "Cover file is 12000 x 800 px; an image can be at most 10000 px on each side.", "code": "event/invalid-image", "param": "coverFile" }
    ```
    A file in `images`:
    ```json
    { "error": "File \"photo.jpg\" is 12000 x 800 px; an image can be at most 10000 px on each side.", "code": "event/invalid-image", "param": "images" }
    ```
  </Accordion>
  <Accordion title="Missing Image Options — 400">
    A cover or `images` were uploaded without their options. `param` is `coverFile.options` or `images.options`.
    ```json
    { "error": "Image options are required when uploading a cover image. Must include mode property.", "code": "event/missing-image-options", "param": "coverFile.options" }
    ```
    For `images`:
    ```json
    { "error": "`images.options` is required when `images` are uploaded. Must include mode property.", "code": "event/missing-image-options", "param": "images.options" }
    ```
  </Accordion>
  <Accordion title="Invalid Image Options — 400">
    `coverFile.options` without `mode`, or with a `mode` that isn't one of the five (other options fields the same way, named in `error` and `param`):
    ```json
    { "error": "coverFile.options.mode: Invalid input", "code": "event/invalid-body", "param": "coverFile.options.mode" }
    ```
    In an aspect-ratio mode, a variant's computed side would be outside 1–10000 px. Checked once the image is read, before anything is stored. `param` names the option:
    ```json
    { "error": "`coverFile.options.widths.s` gives a height of 0 px at the 3:1 aspect ratio. Each side of a variant must be 1–10000 px.", "code": "event/invalid-body", "param": "coverFile.options.widths.s" }
    ```
    In `aspect-ratio-height-based` it names a `heights` option and gives a width. In `multi-aspect-ratio` it names a `sizes` option, and the ratio is the one in `aspectRatios` closest to the image, so the text reads "… at the 3:1 aspect ratio, the one in `aspectRatios` closest to this image. Each side of a variant must be 1–10000 px."
    More than 30 entries in `dimensions`, `widths`, `heights` or `sizes` (one variant each). `param` names the option:
    ```json
    { "error": "coverFile.options.sizes: An image can have at most 30 variants.", "code": "event/invalid-body", "param": "coverFile.options.sizes" }
    ```
  </Accordion>
  <Accordion title="Storage Quota Reached — 429">
    ```json
    {
      "error": "Quota reached for storageFileBytes. Current: …, Action size: …, Limit: …",
      "code": "project/quota-reached",
      "details": { "current": 0, "actionSize": 0, "limit": 0, "metric": "storageFileBytes" }
    }
    ```
    The uploaded files would take the project past its plan's file-storage limit. Nothing is created or stored.
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Upload Refused — 400 / 413">
    A file was refused as the body was read: `event/unsupported-file-type` or `event/unexpected-file-field` (a file in another field, the old `cover` and `gallery` included, or a second file in `coverFile`), with `param` naming the field when there is one, or `413 event/too-many-files` for more than 20 files in the request. A body over 250 MB gets `413 request/body-too-large`; one that can't be read at all gets `request/invalid-multipart` or `request/field-too-large`. See [Upload errors](/v8/api-reference/getting-started#upload-errors).
  </Accordion>
</AccordionGroup>
