---
title: "Set Entity NSFW"
api: "PATCH /v8/:projectId/spaces/:spaceId/entities/:entityId/nsfw"
description: "Set or clear the NSFW flag on an entity within a space"
---

Sets the `nsfw` flag on an entity in a space, including entities authored by other users. Requires the caller to be a moderator or admin of the space.

<Note>
  NSFW is a separate axis from moderation. This endpoint writes the entity's own `nsfw` field and never touches `moderationStatus` — labelling content does not hide it the way [Moderate Entity](/v8/api-reference/spaces/moderation/moderate-entity) with `"remove"` does. Effective NSFW is computed live on read, so a space's own NSFW setting still applies on top of this flag.
</Note>

Requires the `entities` bundle in addition to `spaces`.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space.
</ParamField>

<ParamField path="entityId" type="string" required>
  UUID of the entity to flag. Must belong to the space named in `spaceId`.
</ParamField>

## Body Parameters

<ParamField body="nsfw" type="boolean" required>
  `true` to flag the entity as NSFW, `false` to clear the flag.
</ParamField>

<ParamField body="actingUserId" type="string">
  Required with a service key: the user this request acts as. The request has exactly that user's permissions, so it is refused unless they are a moderator or admin of the space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message.
</ResponseField>

<ResponseField name="nsfw" type="boolean">
  The flag as it now stands on the entity.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` or `entityId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "space/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Wrong Location — 400">
    `actingUserId` was sent in the query string. On this endpoint every field, `actingUserId` included, goes in the request body.
    ```json
    { "error": "`actingUserId` goes in the request body on this endpoint.", "code": "space/wrong-location", "param": "actingUserId" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not a Moderator — 403">
    The caller (or the user named by `actingUserId`) is not a moderator or admin of the space.
    ```json
    { "error": "Moderator access required", "code": "space/moderator-required" }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "Invalid request body.", "code": "moderation/invalid-body" }
    ```
  </Accordion>

  <Accordion title="Entities Bundle Unavailable — 403">
    ```json
    {
      "error": "Entities bundle is not available for this project",
      "code": "database/tables-not-available"
    }
    ```
  </Accordion>

  <Accordion title="Entity Not Found — 404">
    ```json
    { "error": "Entity not found.", "code": "moderation/entity-not-found" }
    ```
  </Accordion>

  <Accordion title="Entity Not In Space — 404">
    The entity exists but belongs to a different space.

    ```json
    {
      "error": "Entity does not belong to this space.",
      "code": "moderation/entity-not-in-space"
    }
    ```
  </Accordion>

  <Accordion title="Server Error — 500">
    ```json
    {
      "error": "Failed to set entity NSFW flag.",
      "code": "moderation/server-error"
    }
    ```
  </Accordion>
</AccordionGroup>
