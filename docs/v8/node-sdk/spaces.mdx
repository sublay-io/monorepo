---
title: "Spaces"
description: "Create and manage spaces, navigate hierarchies, and look up spaces by slug or short ID"
---

The `spaces` module covers core space lifecycle management: creating spaces, fetching them by various identifiers, updating settings, navigating parent-child hierarchies, and checking slug availability.

For membership management see [Space Members](/v8/node-sdk/spaces-members), and for moderation and rules see [Space Moderation](/v8/node-sdk/spaces-moderation).

---

### createSpace

Creates a new space.

```typescript
const space = await sublay.spaces.createSpace({
  actingUserId: "usr_abc123",
  name: "Photography",
  slug: "photography",
  description: "A community for photographers",
  postingPermission: "members",
});
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as: the space creator, who becomes the initial admin, held to their own permissions. A space always has a creator: leaving it out returns `400 space/missing-user-id`.
</ParamField>

<ParamField body="name" type="string" required>
  Display name for the space.
</ParamField>

<ParamField body="slug" type="string">
  URL-friendly identifier. Must be unique within the project. Generated from `name` if omitted.
</ParamField>

<ParamField body="description" type="string">
  Short description of the space.
</ParamField>

<ParamField body="readingPermission" type="string">
  Who can read content: `"anyone"` (default) or `"members"`.
</ParamField>

<ParamField body="postingPermission" type="string">
  Who can post content: `"anyone"`, `"members"` (default), or `"admins"`.
</ParamField>

<ParamField body="visibility" type="string">
  Listing/discoverability: `"public"` (default), `"unlisted"`, or `"private"`. Independent of `readingPermission` (which governs content). `"unlisted"` hides the space from discovery and search but keeps it reachable by direct link; `"private"` currently behaves like `"unlisted"`.
</ParamField>

<ParamField body="requireJoinApproval" type="boolean">
  When `true`, join requests must be manually approved. Defaults to `false`.
</ParamField>

<ParamField body="nsfw" type="boolean">
  The space's own NSFW flag. Defaults to `false`. A space created under an NSFW parent is effectively NSFW regardless of this value. See [Space NSFW flagging](/v8/data-models/space#nsfw-flagging).
</ParamField>

<ParamField body="parentSpaceId" type="string">
  Makes this space a child of the specified parent space. The user the space is created for (`actingUserId`) must be an active admin of the parent space, or the request is refused with `403 space/parent-admin-required`.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary metadata attached to the space.
</ParamField>

**Returns** — `Promise<Space>`

### fetchSpace

Fetches a space by its Sublay ID, including member counts and permission details.

```typescript
const space = await sublay.spaces.fetchSpace({ spaceId: "spc_abc123" });
```

<ParamField body="spaceId" type="string" required>
  The Sublay space ID.
</ParamField>

<ParamField body="include" type="SpaceIncludeParam">
  A single value or an array. The only value is `"files"`, which populates the avatar and banner file objects.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to read as: exactly what their own access token would get (their role, `memberPermissions` and membership). Omit it for the anonymous view.
</ParamField>

**Returns** — `Promise<SpaceDetailed>`

### fetchManySpaces

Fetches a paginated list of public spaces (the space directory), with optional text search. For the spaces a user belongs to, whatever their visibility, use [fetchUserSpaces](#fetchuserspaces).

```typescript
const { data, pagination } = await sublay.spaces.fetchManySpaces({
  page: 1,
  limit: 20,
  query: "photo",
  searchFields: "name",
  sortBy: "members",
});
```

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

<ParamField body="sortBy" type="string">
  Sort order: `"createdAt"` (when the space was created), `"alphabetical"` (by name) or `"members"` (by active member count). Defaults to `"members"`.
</ParamField>

<ParamField body="sortDir" type="string">
  Direction, `"asc"` or `"desc"`, for any `sortBy`. Left out: A–Z for `"alphabetical"`, otherwise newest / most first.
</ParamField>

<ParamField body="query" type="string">
  Free-text search term, matched as a case-insensitive substring. Trimmed; a blank value returns `400 space/invalid-query`.
</ParamField>

<ParamField body="searchFields" type='"slug" | "name" | "description"'>
  The one field `query` is matched against. Leave it out to match the slug, the name or the description.
</ParamField>

<ParamField body="parentSpaceId" type='string | "none"'>
  A space id returns that space's public child spaces; this is how to page through a space's sub-spaces (add `sortBy: "alphabetical"` to order them A–Z by name). An id that matches no space returns an empty page, not a 404. `"none"` returns top-level spaces only. Left out: spaces at every level.
</ParamField>

<ParamField body="nsfwFilter" type='"include-all" | "exclude" | "only"'>
  Filter by each space's `nsfwEffective` (own flag OR any ancestor). `"include-all"` (default) adds no predicate; `"exclude"` drops effective-NSFW spaces; `"only"` returns only them. `"only"` may return an NSFW child whose safe parent is omitted. See [Space NSFW flagging](/v8/data-models/space#nsfw-flagging).
</ParamField>

<ParamField body="include" type="SpaceIncludeParam">
  A single value or an array. The only value is `"files"`, which populates the avatar and banner file objects.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to list as: exactly what their own access token would get (their membership on each space). Omit it for the anonymous view.
</ParamField>

**Returns** — `Promise<PaginatedResponse<Space>>`

### fetchUserSpaces

Fetches the spaces a specific user is a member of, whatever their visibility, with their membership on each. It can search within them and sort them.

```typescript
const result = await sublay.spaces.fetchUserSpaces({
  actingUserId: "usr_abc123",
  query: "design",
  sortBy: "alphabetical",
  page: 1,
  limit: 20,
});
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose spaces to list.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

<ParamField body="query" type="string">
  Free-text search term within the user's spaces, matched as a case-insensitive substring. Trimmed; a blank value returns `400 space/invalid-query`.
</ParamField>

<ParamField body="searchFields" type='"slug" | "name" | "description"'>
  The one field `query` is matched against. Leave it out to match the slug, the name or the description.
</ParamField>

<ParamField body="sortBy" type="string">
  Sort order: `"joinedAt"` (when the user joined), `"createdAt"` (when the space was created), `"alphabetical"` (by name) or `"members"` (by active member count). Defaults to `"joinedAt"`.
</ParamField>

<ParamField body="sortDir" type="string">
  Direction, `"asc"` or `"desc"`, for any `sortBy`. Left out: A–Z for `"alphabetical"`, otherwise newest / most first.
</ParamField>

<ParamField body="role" type="string">
  Filter by the user's role in the space. A single role or comma-separated list, e.g. `"admin,moderator"`.
</ParamField>

<ParamField body="status" type="string">
  Membership status to list: `"active"` (default), `"pending"`, or `"banned"`. Use `"pending"` to find join requests still awaiting approval.
</ParamField>

<ParamField body="all" type='"true" | "false"'>
  When `"true"`, returns the full set of spaces rather than only the paginated page.
</ParamField>

<ParamField body="include" type="SpaceIncludeParam">
  A single value or an array. The only value is `"files"`, which populates the avatar and banner file objects.
</ParamField>

**Returns** — `Promise<UserSpacesResponse>`

### fetchMutualSpaces

Fetches the spaces shared between two users — the spaces both are active members of.

```typescript
const result = await sublay.spaces.fetchMutualSpaces({
  userId: "usr_other",       // the other user
  actingUserId: "usr_self",  // the user to act as (service key required)
  page: 1,
  limit: 20,
});
```

<ParamField body="userId" type="string" required>
  The other user's Sublay ID. Mutual spaces are computed between this user and `actingUserId`.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user to act as. Because the SDK authenticates with a service key, you must name the acting user explicitly.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Max `100`. Defaults to `20`.
</ParamField>

<ParamField body="include" type="SpaceIncludeParam">
  A single value or an array. The only value is `"files"`, which populates the avatar and banner file objects.
</ParamField>

**Returns** — `Promise<PaginatedResponse<Space>>`

### updateSpace

Updates settings on an existing space.

```typescript
const space = await sublay.spaces.updateSpace({
  spaceId: "spc_abc123",
  actingUserId: "usr_admin123",
  name: "Photography Community",
  postingPermission: "admins",
  requireJoinApproval: true,
});
```

<ParamField body="spaceId" type="string" required>
  The Sublay space ID to update.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the request acts as: they must be an admin of the space, and the action is recorded as theirs.
</ParamField>

<ParamField body="name" type="string">
  New display name.
</ParamField>

<ParamField body="slug" type="string">
  New slug. Must be unique.
</ParamField>

<ParamField body="description" type="string">
  New description.
</ParamField>

<ParamField body="readingPermission" type="string">
  Updated reading permission: `"anyone"` or `"members"`.
</ParamField>

<ParamField body="postingPermission" type="string">
  Updated posting permission: `"anyone"`, `"members"`, or `"admins"`.
</ParamField>

<ParamField body="visibility" type="string">
  Updated visibility: `"public"`, `"unlisted"`, or `"private"`. Controls listing/discoverability, independent of `readingPermission`.
</ParamField>

<ParamField body="nsfw" type="boolean">
  Updated NSFW own-flag. Toggling it recomputes this space's effective NSFW and cascades it top-down to every descendant space (and, live, to their entities). See [Space NSFW flagging](/v8/data-models/space#nsfw-flagging).
</ParamField>

<ParamField body="metadata" type="object">
  Updated metadata. Merged with existing values.
</ParamField>

**Returns** — `Promise<Space>`

### deleteSpace

Permanently deletes a space and all its content.

```typescript
const result = await sublay.spaces.deleteSpace({
  spaceId: "spc_abc123",
  actingUserId: "usr_creator123",
});
```

<ParamField body="spaceId" type="string" required>
  The Sublay space ID to delete.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the request acts as, exactly as their own token would: only the space's creator may delete it, and not while banned from the space or from a space above it (`403 space/creator-required`, `403 space/banned`).
</ParamField>

**Returns** — `Promise<DeleteSpaceResponse>`

### fetchSpaceBreadcrumb

Returns the full ancestor chain from the root down to the specified space. Useful for rendering breadcrumb navigation.

```typescript
const breadcrumb = await sublay.spaces.fetchSpaceBreadcrumb({
  spaceId: "spc_abc123",
});
// [{ id: "root", name: "Root" }, { id: "spc_parent", name: "Parent" }, { id: "spc_abc123", name: "Photography" }]
```

<ParamField body="spaceId" type="string" required>
  The Sublay space ID to get the breadcrumb for.
</ParamField>

**Returns** — `Promise<SpaceBreadcrumb>`
