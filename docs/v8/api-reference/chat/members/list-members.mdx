---
title: "List Members"
api: "GET /v8/:projectId/chat/conversations/:conversationId/members"
description: "List the active members of a conversation"
---

import { SpaceReputationParams } from "/snippets/v8/space-reputation-params.mdx";

Returns a paginated list of active [ConversationMember](/v8/data-models/conversation-member) objects, each with the member's user profile included. The caller must be an active member: a former member (who left, was removed or was banned from the space) gets a 403.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation.
</ParamField>

## Query Parameters

<ParamField query="page" type="number">
  Page number (1-based). Defaults to 1.
</ParamField>

<ParamField query="limit" type="number">
  Number of members per page. Defaults to 50. Maximum 100.
</ParamField>

<ParamField query="role" type="string">
  Filter by role. Accepted values: `admin`, `member`. If omitted, all roles are returned.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be an active member of the conversation. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to each returned member's `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

<SpaceReputationParams variant="context" field="query" />

## Response

<ResponseField name="data" type="ConversationMember[]">
  Array of active membership records. Each includes a `user` field with `id`, `name`, `username`, `avatar`, and `metadata`.
</ResponseField>

<ResponseField name="pagination" type="object">
  <Expandable title="properties">
    <ResponseField name="page" type="number">Current page number.</ResponseField>
    <ResponseField name="pageSize" type="number">Items per page.</ResponseField>
    <ResponseField name="totalPages" type="number">Total number of pages.</ResponseField>
    <ResponseField name="totalItems" type="number">Total number of active members.</ResponseField>
    <ResponseField name="hasMore" type="boolean">Whether more pages exist.</ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
</AccordionGroup>
