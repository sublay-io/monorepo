---
title: "Ban Member"
api: "POST /v8/:projectId/spaces/:spaceId/members/:userId/ban"
description: "Ban a member from a space"
---

Sets a member's status to `"banned"`, in this space and the child spaces where they are an active member (a pending or rejected request in a child space is left as it is), and ends their membership of those spaces' chats, so they can no longer post to them, receive them or read their history (see [space conversations](/v8/data-models/conversation-member#space-conversations)). A request to join that is still pending can be banned too. Requires the caller to be a moderator or admin. Moderators can only ban regular members. Only the **space creator** can ban admins, and the last admin cannot be banned. The space creator can't be banned: they are an admin only they could ban, and this route refuses their own id.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space.
</ParamField>

<ParamField path="userId" type="string" required>
  UUID of the user to ban: the member's user id, not their membership id. Your own id is refused (`400 space/own-member-id`): your own membership is [`/spaces/:spaceId/members/me`](/v8/api-reference/spaces/membership/check-my-membership).
</ParamField>

## Body

<ParamField body="reason" type="string">
  Optional reason for the ban, kept with who banned them in the space's ban log.
</ParamField>

<ParamField body="actingUserId" type="string">
  Required with a service key: the user this request acts as. The request has exactly that user's permissions, so it is refused unless they are a moderator or admin of the space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message.
</ResponseField>

<ResponseField name="membership" type="object">
  The updated membership record with `status: "banned"`.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` or `userId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Own Member Id — 400">
    `userId` is the acting user (the token's user, or the user named by `actingUserId`). This route acts on another member; check your own membership with `GET /spaces/:spaceId/members/me` and leave with `DELETE /spaces/:spaceId/members/me`.
    ```json
    { "error": "`POST /spaces/:spaceId/members/:userId/ban` acts on another member, not on yourself. Your own membership is at `/spaces/:spaceId/members/me`: GET to check it, DELETE to leave.", "code": "space/own-member-id" }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "space/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Wrong Location — 400">
    `actingUserId` was sent in the query string. On this endpoint every field, `actingUserId` included, goes in the request body.
    ```json
    { "error": "`actingUserId` goes in the request body on this endpoint.", "code": "space/wrong-location", "param": "actingUserId" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not a Moderator — 403">
    The caller (or the user named by `actingUserId`) is not a moderator or admin of the space.
    ```json
    { "error": "Moderator access required", "code": "space/moderator-required" }
    ```
  </Accordion>
  <Accordion title="Membership Not Found — 404">
    `userId` has no membership in this space.
    ```json
    { "error": "Membership not found.", "code": "space/membership-not-found" }
    ```
  </Accordion>
  <Accordion title="Already Banned — 409">
    The member is already banned here. The ban is still re-applied to their active memberships in child spaces, under the same rules as a first ban, so a repeated ban can instead return one of the errors below.
    ```json
    { "error": "This member is already banned.", "code": "space/already-banned" }
    ```
  </Accordion>
  <Accordion title="Insufficient Permissions — 403">
    A moderator banning someone who is a moderator or admin in this space or in a child space the ban reaches. `spaceId` names that space.
    ```json
    { "error": "Moderators can only ban regular members.", "code": "space/insufficient-permissions", "spaceId": "…" }
    ```
  </Accordion>
  <Accordion title="Creator Required — 403">
    Someone other than the space creator banning a member who is an admin in this space or in a child space the ban reaches. `spaceId` names that space.
    ```json
    { "error": "Only the space creator can ban admins.", "code": "space/creator-required", "spaceId": "…" }
    ```
  </Accordion>
  <Accordion title="Last Admin — 400">
    The member is the last admin of this space or of a child space the ban reaches. `spaceId` names that space.
    ```json
    { "error": "Cannot ban the last admin. Promote another member to admin first.", "code": "space/last-admin", "spaceId": "…" }
    ```
  </Accordion>
</AccordionGroup>
