---
title: "Create Report"
api: "POST /v8/:projectId/reports"
description: "Submit a content report for an entity, comment, or chat message"
---

Submits a report on an entity, comment, or chat message. If an **open** report already exists for the target, the authenticated user's report is added to it (increments `reporterCount`). If the same user already reported that open report, a `200` is returned without creating a duplicate.

Resolved reports (`dismissed` / `actioned`) are closed: a later report of the same target creates a **new** report rather than reopening the old one. A target therefore has at most one open report at a time, alongside any number of resolved ones.

**Authentication required.** **Rate limit**: 25 requests per 5 minutes.

## Body Parameters

<ParamField body="targetId" type="string" required>
  The UUID of the entity, comment, or chat message being reported. For a
  message this is the message id — the conversation is resolved server-side,
  so no `conversationId` is needed.
</ParamField>

<ParamField body="targetType" type="string" required>
  The type of content being reported. One of: `entity`, `comment`, `message`. Values match exactly: another case (`"Entity"`) returns `400 report/invalid-body`.
</ParamField>

<ParamField body="reason" type="string" required>
  The reason for the report. Must be one of: `spam`, `inappropriateContent`,
  `harassment`, `misinformation`, `hateSpeech`, `violence`, `illegalActivity`,
  `selfHarm`, `other`. Any other value is rejected with `report/invalid-body` —
  use `other` plus `details` for anything the taxonomy doesn't cover.
</ParamField>

<ParamField body="details" type="string">
  Optional additional context or description provided by the reporter.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. This user is the reporter. A user token always acts as its own user and must not send it (`400 report/acting-user-not-allowed`).
</ParamField>

## Response

Returns `201 Created` when a new report is created:

```json
{ "message": "Report submitted successfully", "code": "report/created" }
```

Returns `200 OK` when an existing report is updated with a new reporter:

```json
{ "message": "Report updated successfully", "code": "report/updated" }
```

Returns `200 OK` when the user has already reported this target:

```json
{ "message": "Report already registered by this user", "code": "report/already-reported" }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Target Not Found — 404">
    ```json
    { "error": "<targetType> not found", "code": "report/target-not-found" }
    ```
    The error message reflects the reported type, e.g. `"entity not found"` or `"comment not found"`.
  </Accordion>

  <Accordion title="Self Report — 400">
    ```json
    { "error": "You cannot report your own <targetType>.", "code": "report/self-report" }
    ```
    A user cannot report content they authored.
  </Accordion>

  <Accordion title="Not a Conversation Member — 403">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
    Only members of a conversation may report a message in it. In a space chat, the
    reporter must also be able to see the space ([visibility](/v8/data-models/space#visibility)).
    Applies to `targetType: "message"` only.
  </Accordion>

  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "...", "code": "report/invalid-body" }
    ```
    Returned for a malformed `targetId`, an unknown `targetType` (including one
    in another case, such as `"Entity"`), or a `reason` outside the accepted set.
  </Accordion>

  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "report/missing-user-id" }
    ```
  </Accordion>

  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "report/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "report/user-not-found" }
    ```
  </Accordion>

  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "report/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "report/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
