---
title: "List Workspace Invites"
api: "GET /v8/:projectId/workspaces/:id/invites"
description: "List a workspace's live pending invites"
---

Returns the workspace's **live** pending invites (`status = 'pending' AND expiresAt > now` — effectively-expired rows are excluded). Requires the `invite` capability (or owner).

## Path Parameters

<ParamField path="id" type="string" required>
  The workspace UUID.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string" required>
  Service keys only — the user to act as. **Required with a service key:** a key that names nobody is refused with `400 workspace/missing-user-id`. Enforced: the `invite` capability (or ownership) is required *of the named user*. A user token always acts as its own user and must not send it (`400 workspace/acting-user-not-allowed`). See [Acting on behalf of a user](/v8/sdk/workspaces/overview#acting-on-behalf-of-a-user).
</ParamField>

## Response

```json
{ "data": [ /* WorkspaceInvitation[] */ ] }
```

Each item is a [WorkspaceInvitation](/v8/data-models/workspace-invitation) object.

This is a workspace's **outbox**. For the invites addressed **to** a user, see [List My Invites](/v8/api-reference/workspaces/invitations/list-my-invites).

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Path Parameter — 400">
    ```json
    { "error": "Invalid workspace id: expected a UUID.", "code": "workspace/invalid-params" }
    ```
    Every path id on the workspaces bundle is checked for UUID shape before the route runs, so a malformed one is a plain `400` rather than a `500` from the database.
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "workspace/missing-user-id" }
    ```
    A service key sent no `actingUserId`. The request has to act as somebody, and is held to exactly that user's standing on the workspace.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "workspace/acting-user-not-allowed" }
    ```
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
  </Accordion>
  <Accordion title="User Not Found — 404">
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "workspace/user-not-found" }
    ```
    Returned when a service key names an `actingUserId` that isn't a user in this project.
  </Accordion>
</AccordionGroup>
