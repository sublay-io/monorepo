---
title: "Unban Member"
api: "PATCH /v8/:projectId/spaces/:spaceId/members/:memberId/unban"
description: "Unban a previously banned member"
---

Sets a banned member's status back to `"active"`, in this space and in the child spaces where they are banned (a ban covers child spaces, and so does lifting it). A request that was pending or rejected in a child space before the ban stays as it was. Unbanning makes the person an active member of this space even if they were never approved, for example when their request was still pending at the time of the ban. The member gets each space's chat back the next time they open it. Requires the caller to be a moderator or admin. Moderators can only unban regular members, not other moderators or admins. Only the **space creator** can unban an admin, as only they can ban one.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space.
</ParamField>

<ParamField path="memberId" type="string" required>
  UUID of the membership record to unban.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Required with a service key: the user this request acts as. The request has exactly that user's permissions, so it is refused unless they are a moderator or admin of the space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message.
</ResponseField>

<ResponseField name="membership" type="object">
  The updated membership record with `status: "active"`.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` or `memberId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "space/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not a Moderator — 403">
    The caller (or the user named by `actingUserId`) is not a moderator or admin of the space.
    ```json
    { "error": "Moderator access required", "code": "space/moderator-required" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Banned membership not found.", "code": "space/membership-not-found" }
    ```
  </Accordion>
  <Accordion title="Banned in a Parent Space — 409">
    The member is still banned in a parent of this space. Lift that ban first; `bannedSpaceIds` lists where.
    ```json
    { "error": "This member is banned in a parent of this space. Lift that ban first.", "code": "space/banned-in-parent", "bannedSpaceIds": ["…"] }
    ```
  </Accordion>
  <Accordion title="Insufficient Permissions — 403">
    A moderator unbanning someone who is a moderator or admin in this space or in one of the child spaces the unban covers.
    ```json
    { "error": "Moderators can only unban regular members.", "code": "space/insufficient-permissions" }
    ```
  </Accordion>
  <Accordion title="Creator Required — 403">
    Unbanning someone who is an admin in this space or in one of the child spaces the unban covers, by anyone but the space creator.
    ```json
    { "error": "Only the space creator can unban admins.", "code": "space/creator-required" }
    ```
  </Accordion>
</AccordionGroup>
