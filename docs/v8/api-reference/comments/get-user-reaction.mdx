---
title: "Get User Reaction"
api: "GET /v8/:projectId/comments/:commentId/reactions/me"
description: "Get the authenticated user's reaction on a comment"
---

Returns the authenticated user's current reaction on the specified comment, or `null` if they have not reacted.

**Authentication required.**

## Path Parameters

<ParamField path="commentId" type="string" required>
  The UUID of the comment.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose reaction is returned. A key has no user of its own, so leaving it out returns `400 comment/missing-user-id`. A user token always acts as its own user and must not send it (`400 comment/acting-user-not-allowed`).
</ParamField>

## Response

```json
{ "reactionType": "like" }
```

or, if the user has no reaction:

```json
{ "reactionType": null }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Params — 400">
    Returned when `commentId` isn't a valid UUID.

    ```json
    { "error": "Invalid comment id: expected a UUID.", "code": "comment/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    Returned when a user token sends `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "comment/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "comment/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    Returned when the request sends `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "comment/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "comment/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    Returned when a service key sends no `actingUserId`.

    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "comment/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Returned when the comment doesn't exist, or is on an entity whose author has blocked the user (the user's own comments excepted).

    ```json
    { "error": "Comment not found.", "code": "comment/not-found" }
    ```
  </Accordion>
</AccordionGroup>
