# Quick Start Guide

This guide installs a Sublay component into your project and renders it: a comment section bound to a Sublay entity, or the notifications bell. It focuses on the components. For a whole app built on Sublay — sign-up, creating and listing entities, comments and reactions — start with [Build your first Sublay app](/v8/quick-start).

---

## Before You Begin

- ✅ Node.js 20.5+ installed
- ✅ A React, React Native, or Expo project
- ✅ A [Sublay project](https://dash.sublay.io) with the `entities` and `comments` bundles installed, plus `reactions` (votes and likes) and `moderation` (the report button files reports through it). See [Bundles](/v8/bundles).

---

## Step 1: Initialize the CLI

Run the init command in your project directory:

```bash
cd your-project
npx @sublay/cli init
```

### Answer the prompts:

<Steps>
  <Step title="Select Platform">
    ```
    ? Which platform are you using?
    ❯ React (Web)
      React Native
      Expo
    ```
  </Step>

  <Step title="Choose Styling">
    ```
    ? Which styling approach do you prefer?
    ❯ Tailwind CSS
      Inline Styles
    ```

    - Select **Tailwind CSS** if you use Tailwind
    - Select **Inline Styles** otherwise
  </Step>

  <Step title="Set Component Path">
    ```
    ? Where should components be installed? (src/components)
    ```

    Press Enter to use the default, or type a custom path.
  </Step>
</Steps>

The CLI creates a `sublay.json` configuration file and checks for required dependencies.

## Step 3: Add a Component

Pick a component and a language to get the command:

<AddCommandBuilder />

- **Threaded comments** — Reddit-style discussions with unlimited nesting, upvote/downvote, threading lines, and collapsible threads.
- **Social comments** — Instagram-style comments with single-level nesting, heart/like system, and Top/New/Old sorting.
- **Notifications** — a notification bell with a dropdown of the user's notifications.

The language applies to the comment components; see [Languages & Right-to-Left](/v8/components/customization/languages-rtl).

`--ref v8` reads the component from the `v8` branch of the registry, where the v8 components live.

The CLI copies about 40 source files into your project and shows a usage example. It also checks your `package.json` for the third-party packages the component needs (the Giphy packages for the GIF picker, for example) and offers to install the ones that are missing.

## Step 4: Set Up SublayProvider

Wrap your app (or the relevant section) with `SublayProvider`:

<Tabs>
  <Tab title="React (Web)">
    ```tsx
    // App.tsx
    import { SublayProvider } from '@sublay/react-js';

    function App() {
      return (
        <SublayProvider projectId="your-project-id">
          {/* Your app content */}
        </SublayProvider>
      );
    }
    ```
  </Tab>

  <Tab title="React Native / Expo">
    ```tsx
    // App.tsx
    import { GestureHandlerRootView } from 'react-native-gesture-handler';
    import { SublayProvider } from '@sublay/react-native'; // or '@sublay/expo'

    function App() {
      return (
        // The comment sections' sheets need the gesture handler root
        <GestureHandlerRootView style={{ flex: 1 }}>
          <SublayProvider projectId="your-project-id">
            {/* Your app content */}
          </SublayProvider>
        </GestureHandlerRootView>
      );
    }
    ```
  </Tab>
</Tabs>

To post, reply or vote, a user must be signed in. Sublay's [built-in auth](/v8/sdk/authentication/built-in) handles sign-up and sign-in for you; the [complete example](#complete-example) below adds a sign-in form.

<Note>
If your app already has its own authentication, see [External Authentication](/v8/sdk/authentication/external) to connect it to Sublay.
</Note>

## Step 5: Use the Component

Bind the comment section to a Sublay entity: pass its `entityId`, or the `entity` object itself. Entities are what your users create — with [`useCreateEntity`](/v8/hooks/entities/use-create-entity), for example — and what you load with [`useEntityList`](/v8/sdk/entity-lists/overview) or [`EntityProvider`](/v8/sdk/entities/provider-and-hook).

<Tabs>
  <Tab title="Threaded Comments">
    ```tsx
    // EntityPage.tsx
    import { ThreadedCommentSection } from './components/comments-threaded';

    function EntityPage({ entity }) {
      return (
        <div>
          <h1>{entity.title}</h1>
          <p>{entity.content}</p>
          <ThreadedCommentSection entityId={entity.id} />
        </div>
      );
    }
    ```

    On React Native and Expo, threaded comments are three components that your screen places: `ThreadedComments` wraps the screen, `ThreadedCommentSection` (Sort by and the comments) goes in its `ScrollView`, and `ThreadedCommentInput` (the comment box) is pinned below:

    ```tsx
    // EntityScreen.tsx
    import { KeyboardAvoidingView, Platform, ScrollView } from 'react-native';
    import {
      ThreadedComments,
      ThreadedCommentSection,
      ThreadedCommentInput,
    } from './components/comments-threaded';

    function EntityScreen({ entity }) {
      return (
        <ThreadedComments entityId={entity.id}>
          <KeyboardAvoidingView
            style={{ flex: 1 }}
            behavior={Platform.OS === 'ios' ? 'padding' : undefined}
          >
            <ScrollView keyboardShouldPersistTaps="handled">
              <YourEntity />
              <ThreadedCommentSection />
            </ScrollView>
            <ThreadedCommentInput />
          </KeyboardAvoidingView>
        </ThreadedComments>
      );
    }
    ```
  </Tab>

  <Tab title="Social Comments">
    ```tsx
    // EntityPage.tsx
    import { SocialCommentSection } from './components/comments-social';

    function EntityPage({ entity }) {
      return (
        <div>
          <p>{entity.content}</p>
          <SocialCommentSection entityId={entity.id} />
        </div>
      );
    }
    ```
  </Tab>
</Tabs>

That's it! Sublay stores each comment against the entity, and the section loads, posts, votes and reports through the SDK.

## Complete Example

A working page: a sign-in form, using [built-in auth](/v8/sdk/authentication/built-in), and a list of the newest entities, each with its own comment section. Users sign up with `signUpWithEmailAndPassword` the same way. Sublay doesn't require a username, but the comment components do: as installed, they stop a user without one from posting, replying, voting or reporting. Pass a `username` at sign-up, or change `usernameRequiredCallback` in `hooks/use-threaded-comments.tsx` (or `hooks/use-social-comments.tsx`).

```tsx
import { useEffect } from 'react';
import { SublayProvider, useAuth, useEntityList } from '@sublay/react-js';
import { ThreadedCommentSection } from './components/comments-threaded';

const PROJECT_ID = import.meta.env.VITE_PUBLIC_SUBLAY_PROJECT_ID;

function SignInForm() {
  const { initialized, accessToken, signInWithEmailAndPassword } = useAuth();

  // Hide the form until auth has loaded, and once the user is signed in
  if (!initialized || accessToken) return null;

  const handleSubmit = (e: React.FormEvent<HTMLFormElement>) => {
    e.preventDefault();
    const form = e.currentTarget;
    signInWithEmailAndPassword({
      email: form.email.value,
      password: form.password.value,
    }).catch(console.error);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" type="email" placeholder="Email" />
      <input name="password" type="password" placeholder="Password" />
      <button type="submit">Sign in</button>
    </form>
  );
}

function Feed() {
  const { entities, fetchEntities } = useEntityList({ listId: 'feed' });

  useEffect(() => {
    fetchEntities({}, { sortBy: 'createdAt', sortDir: 'desc' }, { limit: 10 }, { fetchImmediately: true });
  }, []);

  return (
    <>
      {entities.map((entity) => (
        <article key={entity.id}>
          <h2>{entity.title}</h2>
          <p>{entity.content}</p>
          <ThreadedCommentSection entity={entity} />
        </article>
      ))}
    </>
  );
}

function App() {
  return (
    <SublayProvider projectId={PROJECT_ID}>
      <div className="max-w-4xl mx-auto p-8">
        <SignInForm />
        <Feed />
      </div>
    </SublayProvider>
  );
}

export default App;
```

For social comments, import `SocialCommentSection` from `./components/comments-social` and use it the same way. To let users create the entities in the list, see [Build your first Sublay app](/v8/quick-start).

## Attach Comments to Records You Already Have

If what users comment on lives in your own database — an article in your CMS, a product in your catalog — you don't need to create its entity yourself. Pass your record's ID as `foreignId`, with `createIfNotFound`, and the section creates the entity the first time it loads and finds it by that ID afterwards:

<Tabs>
  <Tab title="Threaded Comments">
    ```tsx
    <ThreadedCommentSection foreignId={article.id} createIfNotFound />
    ```

    On React Native and Expo, pass the same props to `ThreadedComments`.
  </Tab>

  <Tab title="Social Comments">
    ```tsx
    <SocialCommentSection foreignId={article.id} createIfNotFound />
    ```
  </Tab>
</Tabs>

<Note>
  `createIfNotFound` creates the record's entity the first time its comment section loads. That entity has no author, and the project's **Who can create entities without an author** setting decides who may create one. The default, **Everyone**, lets any visitor's section create it; under **Signed-in users only** or **No one from the client**, see `createIfNotFound` for [threaded](/v8/components/components/threaded/props-api#createifnotfound) and [social](/v8/components/components/social/props-api#createifnotfound) comments.
</Note>

See [Link entities to records you already have](/v8/sdk/entities/overview#link-entities-to-records-you-already-have).

## Troubleshooting

<AccordionGroup>
  <Accordion title="Import errors after adding component" icon="triangle-exclamation">
    Make sure the import path matches your `paths.components` in `sublay.json`:

    ```tsx
    // paths.components = "src/components"
    import { ThreadedCommentSection } from './components/comments-threaded';

    // paths.components = "app/ui"
    import { ThreadedCommentSection } from './ui/comments-threaded';
    ```
  </Accordion>

  <Accordion title="Components not rendering" icon="eye-slash">
    1. Check that `<SublayProvider>` wraps the component
    2. Verify `projectId` is correctly set
    3. Check the browser console for errors
  </Accordion>

  <Accordion title="TypeScript errors" icon="code">
    Ensure your `tsconfig.json` includes the components directory:

    ```json
    { "include": ["src/**/*"] }
    ```
  </Accordion>

  <Accordion title="Dark mode not working (Tailwind)" icon="moon">
    **React:** make Tailwind's dark mode follow a `dark` class (Tailwind CSS 3: `darkMode: 'class'` in `tailwind.config.js`; Tailwind CSS 4: `@custom-variant dark (&:where(.dark, .dark *));` in your CSS), and add a `dark` class to a parent element:

    ```tsx
    <html className={isDark ? 'dark' : ''}>
    ```

    **React Native and Expo:** pass `theme="dark"` to the component. There is no Tailwind dark mode setup.
  </Accordion>
</AccordionGroup>
