---
title: "Remove Connection"
api: "DELETE /v8/:projectId/users/:userId/connection"
description: "Remove, withdraw, or decline a connection by user ID"
---

Removes the connection relationship between the authenticated user and the specified user. The behavior depends on the current connection state:

- **Pending (sent by current user)** — withdraws the request (record is deleted).
- **Pending (sent by other user)** — declines the request (status updated to `"declined"`).
- **Accepted** — disconnects both users (record is deleted).

<Note>
  **Requires the `connections` bundle.** A project without the connections bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the other user.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who removes the connection. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`.

**When withdrawn or disconnected:**

<ResponseField name="message" type="string">
  Human-readable description of the action taken.
</ResponseField>

<ResponseField name="action" type="string">
  `"withdraw"` or `"disconnect"`.
</ResponseField>

**When declined:**

<ResponseField name="id" type="string">
  Connection record ID.
</ResponseField>

<ResponseField name="status" type="string">
  `"declined"`.
</ResponseField>

<ResponseField name="respondedAt" type="string">
  ISO timestamp of when the request was declined.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Self-Disconnect — 400">
    ```json
    {
      "error": "Cannot disconnect from yourself",
      "code": "connection/self-disconnect"
    }
    ```
  </Accordion>
  <Accordion title="No Connection Found — 404">
    ```json
    {
      "error": "No connection found between these users that can be removed.",
      "code": "connection/not-found"
    }
    ```
  </Accordion>
</AccordionGroup>
