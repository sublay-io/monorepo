---
title: "Update My Membership"
api: "PATCH /v8/:projectId/workspaces/:workspaceId/members/me"
description: "Edit your own title on a workspace, and as its owner your metadata"
---

Edits the acting user's own profile on a workspace: the token's user, or the user a service key names in `actingUserId`. `me` in the path always means that user. It is self-service: **no capability is needed**.

What you can edit depends on who you are on the workspace:

- **A member** edits their own `title` only. A member's other fields (`metadata`, `capabilities`, `permissions`, `rank`, `relativeRank`) are edited by a member with the capability, through [Update Member](/v8/api-reference/workspaces/members/update-member). A member who sends `metadata` here is refused with `400 workspace/unsupported-param`.
- **The workspace's owner** edits their own `title` and `metadata`, either or both. This route is the only way to set them: [Update Member](/v8/api-reference/workspaces/members/update-member) refuses the owner as a target for everyone, ancestor owners included. A service key acting as the owner counts as the owner. The owner's title and metadata are profile only: the owner's authority comes from owning the workspace, and setting them changes nothing about it. They show on the owner's [roster](/v8/api-reference/workspaces/members/list-members) entry and [standing](/v8/api-reference/workspaces/members/fetch-my-membership).

Ownership is per workspace. An ancestor owner who holds a member row on a child workspace is a member there, and edits only their `title` on that child.

A user who only reaches in from an ancestor workspace and holds no member row here gets `404 workspace/not-found`. A user with no relation to the workspace at all gets the roster-visibility `404`.

<Note>
  **Your own membership is `/workspaces/:workspaceId/members/me`**: [`GET`](/v8/api-reference/workspaces/members/fetch-my-membership) to read it, `PATCH` to edit your profile, [`DELETE`](/v8/api-reference/workspaces/members/leave-workspace) to leave. The `/workspaces/:workspaceId/members/:userId` routes act on other members and refuse your own id with `400 workspace/own-member-id`.
</Note>

## Path Parameters

<ParamField path="workspaceId" type="string" required>
  The workspace UUID.
</ParamField>

## Body Parameters

<ParamField body="title" type="string | null">
  Your new title: trimmed, up to 100 characters. `null` clears it. A cosmetic label with no authority. Required for a member; the owner sends `title`, `metadata` or both. Leaving it out keeps the current title.
</ParamField>

<ParamField body="metadata" type="object">
  **The owner only.** Arbitrary JSON (up to 1 MB) that replaces the owner's current metadata. Leaving it out keeps the current metadata. A member who sends it is refused with `400 workspace/unsupported-param`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service keys only, and **required** with one: the user whose own profile is edited. A key that names nobody is refused with `400 workspace/missing-user-id`. A user token always acts as its own user and must not send it (`400 workspace/acting-user-not-allowed`). See [Acting on behalf of a user](/v8/sdk/workspaces/overview#acting-on-behalf-of-a-user).
</ParamField>

## Response

Returns the updated [WorkspaceMember](/v8/data-models/workspace-member) object, the same record [Update Member](/v8/api-reference/workspaces/members/update-member) returns.

```json
{
  "id": "6f1c2b0e-8d4a-4f7e-9b3a-2c5d1e0f9a87",
  "workspaceId": "ws_abc",
  "userId": "u_pat",
  "capabilities": ["view", "invite"],
  "permissions": ["deploy"],
  "rank": 3,
  "title": "Frontend Lead",
  "metadata": {},
  "joinedAt": "2026-11-01T09:00:00.000Z",
  "createdAt": "2026-11-01T09:00:00.000Z"
}
```

For the owner, it returns their [owner profile](/v8/data-models/workspace-member) record instead (`WorkspaceOwnerProfile` in the SDKs): the same fields, holding the profile only, with `rank` `null` and `capabilities` and `permissions` empty, because the owner's access comes from ownership, not from this record. Read the owner's access with [Fetch My Membership](/v8/api-reference/workspaces/members/fetch-my-membership).

```json
{
  "id": "0b9e4d71-3c2a-4e58-a6f1-7d8c9e0a1b23",
  "workspaceId": "ws_abc",
  "userId": "u_owner",
  "capabilities": [],
  "permissions": [],
  "rank": null,
  "title": "Founder",
  "metadata": { "timezone": "UTC" },
  "joinedAt": "2026-11-14T09:00:00.000Z",
  "createdAt": "2026-11-14T09:00:00.000Z"
}
```

## Error Responses

<AccordionGroup>
  <Accordion title="Field Not Editable Here — 400">
    ```json
    { "error": "`capabilities` can't be edited on your own membership: only your profile can (`title`, and `metadata` if you own the workspace). A member with the capability edits `capabilities` through `PATCH /workspaces/:workspaceId/members/:userId`.", "code": "workspace/unsupported-param", "param": "capabilities" }
    ```
    Sent for `capabilities`, `permissions`, `rank` or `relativeRank`, whoever sends it, the owner included; `param` names the field. Sent for `metadata` too when the acting user is not the workspace's owner:
    ```json
    { "error": "`metadata` can't be edited on your own membership: only `title` can. A member with the capability edits `metadata` through `PATCH /workspaces/:workspaceId/members/:userId`.", "code": "workspace/unsupported-param", "param": "metadata" }
    ```
    Nothing is written.
  </Accordion>
  <Accordion title="Invalid Body — 400">
    No editable field was sent:
    ```json
    { "error": "At least one field must be provided", "code": "workspace/invalid-body" }
    ```
    `title` is the wrong type or longer than 100 characters, or `metadata` is not an object or is over 1 MB:
    ```json
    { "error": "title: Too big: expected string to have <=100 characters", "code": "workspace/invalid-body" }
    ```
    Any other unknown key is refused too:
    ```json
    { "error": "Unrecognized key: \"nickname\"", "code": "workspace/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Invalid Path Parameter — 400">
    ```json
    { "error": "Invalid workspace id: expected a UUID.", "code": "workspace/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "workspace/missing-user-id" }
    ```
    A service key sent no `actingUserId`. `me` is the acting user, so the key must name one.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "workspace/acting-user-not-allowed" }
    ```
    A user token sent `actingUserId`, even naming its own user.
  </Accordion>
  <Accordion title="Wrong Location — 400">
    ```json
    { "error": "`actingUserId` goes in the request body on this endpoint.", "code": "workspace/wrong-location", "param": "actingUserId" }
    ```
    A field this endpoint reads from the body was sent in the query string.
  </Accordion>
  <Accordion title="User Not Found — 404">
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "workspace/user-not-found" }
    ```
    Returned when a service key names an `actingUserId` that isn't a user in this project.
  </Accordion>
  <Accordion title="Not Found — 404">
    The workspace doesn't exist, or the acting user has no relation to it:
    ```json
    { "error": "Workspace not found", "code": "workspace/not-found" }
    ```
    The acting user is not the owner and has no direct member row on this workspace (a user who only reaches in from an ancestor), including when the row was removed while this request was being handled:
    ```json
    { "error": "The target user is not a direct member of this workspace.", "code": "workspace/not-found" }
    ```
  </Accordion>
</AccordionGroup>
