---
title: "Connections"
description: "Query and respond to a user's mutual connections from your server"
---

The `connections` module reads and manages a user's mutual connections (bidirectional relationships, similar to "friends"). Use it to list accepted connections, inspect pending requests, and accept, decline, or remove connections.

<Note>
  Every function acts on behalf of a named user. Pass that user's Sublay ID as
  [`actingUserId`](/v8/node-sdk/overview#acting-on-behalf-of-a-user), the user your service key acts as.
</Note>

<Tip>
  To **send** a connection request, check a connection's status, or remove a
  connection by the other user's ID, use the nested routes on the
  [`users`](/v8/node-sdk/users) module (`requestConnection`,
  `fetchConnectionStatus`, `removeConnectionByUserId`).
</Tip>

---

### fetchConnections

Fetches a paginated list of a user's accepted connections.

```typescript
const { data, pagination } = await sublay.connections.fetchConnections({
  actingUserId: "usr_abc123",
  page: 1,
  limit: 20,
});
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose connections to fetch.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

<ParamField body="query" type="string">
  Optional search term. Filters the list to connections whose other user's username or name contains this text (case-insensitive). When omitted, no filtering is applied.
</ParamField>

<ParamField body="searchFields" type="string">
  Restricts which field `query` matches against — `username` or `name`. When omitted, `query` matches either field.
</ParamField>

**Returns** — `Promise<PaginatedResponse<AcceptedConnectionRow>>`, where [`AcceptedConnectionRow`](/v8/data-models/connection#acceptedconnectionrow) is `{ id, user, status: "accepted", createdAt, respondedAt }` and `user` is the other user in the connection.

### fetchConnectionsCount

Returns the number of accepted connections for a user.

```typescript
const { count } = await sublay.connections.fetchConnectionsCount({
  actingUserId: "usr_abc123",
});
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as.
</ParamField>

**Returns** — `Promise<{ count: number }>`

---

### fetchSentPendingConnections

Returns a paginated list of connection requests the user has sent that are still pending.

```typescript
const { data, pagination } =
  await sublay.connections.fetchSentPendingConnections({
    actingUserId: "usr_abc123",
    page: 1,
    limit: 20,
  });
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose sent requests to fetch.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

**Returns** — `Promise<PaginatedResponse<ConnectionRow>>`, where [`ConnectionRow`](/v8/data-models/connection#connectionrow) is `{ id, user, type, message, status, createdAt, respondedAt }`. Here `user` is the user the request was sent to, `type` is `"sent"`, `status` is `"pending"` and `respondedAt` is `null`.

### fetchReceivedPendingConnections

Returns a paginated list of pending connection requests the user has received.

```typescript
const { data, pagination } =
  await sublay.connections.fetchReceivedPendingConnections({
    actingUserId: "usr_abc123",
    page: 1,
    limit: 20,
  });
```

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose received requests to fetch.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

**Returns** — `Promise<PaginatedResponse<ConnectionRow>>`. Here `user` is the user who sent the request, `type` is `"received"`, `status` is `"pending"` and `respondedAt` is `null`.

### acceptConnection

Accepts a pending connection request received by the user.

```typescript
const result = await sublay.connections.acceptConnection({
  connectionId: "con_xyz789",
  actingUserId: "usr_abc123",
});
```

<ParamField body="connectionId" type="string" required>
  The ID of the pending connection request to accept.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as: the recipient accepting the request.
</ParamField>

**Returns** — `Promise<ConnectionRow>`: the accepted connection from the acting user's side (`user` is the requester, `type` is `"received"`, `status` is `"accepted"`). See [ConnectionRow](/v8/data-models/connection#connectionrow).

---

### declineConnection

Declines a pending connection request received by the user.

```typescript
const result = await sublay.connections.declineConnection({
  connectionId: "con_xyz789",
  actingUserId: "usr_abc123",
});
```

<ParamField body="connectionId" type="string" required>
  The ID of the pending connection request to decline.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as: the recipient declining the request.
</ParamField>

**Returns** — `Promise<ConnectionRow>`: the declined connection from the acting user's side (`user` is the requester, `type` is `"received"`, `status` is `"declined"`). See [ConnectionRow](/v8/data-models/connection#connectionrow).

---

### removeConnection

Removes a connection by its connection ID: withdraws a pending request the user sent, or disconnects an accepted connection (either user can).

```typescript
await sublay.connections.removeConnection({
  connectionId: "con_xyz789",
  actingUserId: "usr_abc123",
});
```

<ParamField body="connectionId" type="string" required>
  The connection ID to remove.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, on whose behalf the connection is removed.
</ParamField>

**Returns** — `Promise<void>`. It resolves with no value once the connection is removed (the server answers `204 No Content`).
