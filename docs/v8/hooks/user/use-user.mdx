## Overview

`useUser` is the primary hook for interacting with the currently authenticated user's profile. It provides the user's full data (as an `AuthUser`), loading and error states, an `updateUser` action, and derived [suspension](/v8/sdk/moderation/suspensions) state (`isSuspended` / `activeSuspension`).

Updates are applied optimistically — the UI reflects changes immediately, and reverts automatically if the server request fails.

## Usage Example

```tsx
import { useUser } from "@sublay/react-js";

function ProfileEditor() {
  const { user, updating, updateUser } = useUser();

  const handleSave = async () => {
    await updateUser({ name: "Jane Doe", bio: "Building cool things." });
  };

  if (!user) return null;

  return (
    <div>
      <p>{user.name}</p>
      <button onClick={handleSave} disabled={updating}>
        Save
      </button>
    </div>
  );
}
```

### Uploading an Avatar

```tsx
import { useUser } from "@sublay/react-js";

function AvatarUpload({ file }: { file: File }) {
  const { updateUser } = useUser();

  const handleUpload = async () => {
    await updateUser({
      avatarFile: {
        file,
        options: {
          mode: "exact-dimensions",
          dimensions: { small: { width: 64, height: 64 }, large: { width: 200, height: 200 } },
          fit: "cover",
        },
      },
    });
  };

  return <button onClick={handleUpload}>Upload Avatar</button>;
}
```

### Removing the Avatar

List the current file's id in `removeFileIds`. It clears the user's avatar file and deletes it.

```tsx
const { user, updateUser } = useUser();

if (user?.avatarFile) {
  await updateUser({ removeFileIds: [user.avatarFile.id] });
}
```

## Return Values

<ResponseField name="user" type="AuthUser | null">
  The authenticated user's full profile. Returns `null` while loading or when no user is authenticated. See [User data model](/v8/data-models/user).
</ResponseField>

<ResponseField name="loading" type="boolean">
  `true` while the user's profile is being fetched for the first time.
</ResponseField>

<ResponseField name="updating" type="boolean">
  `true` while an `updateUser` call is in progress.
</ResponseField>

<ResponseField name="error" type="SublayError | null">
  The error if an `updateUser` call fails. `null` when there is no error. A [`SublayError`](/v8/hooks/overview#sublayerror).
</ResponseField>

<ResponseField name="isSuspended" type="boolean">
  `true` while the authenticated user has an active [suspension](/v8/sdk/moderation/suspensions). Derived from the user's `suspensions` using the same effective definition as the server.
</ResponseField>

<ResponseField name="activeSuspension" type="UserSuspension | null">
  The user's effective (furthest-reaching) active suspension — one of `user.suspensions` (`{ id, userId, reason, startDate, endDate, createdBy, createdAt, updatedAt }`) — or `null` when they aren't suspended. `endDate: null` means the suspension is indefinite. Bind a "suspended until X" banner or a disabled composer to this. See [Suspensions](/v8/sdk/moderation/suspensions).
</ResponseField>

<ResponseField name="updateUser" type="(update: UpdateUserParams) => Promise<AuthUser>">
  Updates the authenticated user's profile. Applies optimistic updates immediately and reverts on failure.

  A `null` field can't travel with `avatarFile` or `bannerFile` (a multipart request): such an update throws before anything is sent, naming the field. Send the clear in a separate call without a file.

  <Expandable title="UpdateUserParams fields">
    <ResponseField name="name" type="string | null">
      Display name. Pass `null` (or an empty string) to clear it, on an update without files.
    </ResponseField>
    <ResponseField name="username" type="string">
      Unique username. Must be available.
    </ResponseField>
    <ResponseField name="bio" type="string | null">
      Short biography. Limited to 300 characters. Pass `null` (or an empty string) to clear it, on an update without files.
    </ResponseField>
    <ResponseField name="birthdate" type="string | Date">
      Date of birth: a `Date`, or a full UTC timestamp string such as `"1990-05-17T00:00:00.000Z"` (a date alone, like `"1990-05-17"`, is refused). Not applied optimistically: it isn't part of `AuthUser`.
    </ResponseField>
    <ResponseField name="avatar" type="string | null">
      Avatar image URL, stored as given. Pass `null` to clear it, on an update without files. Separate from `avatarFile`, which uploads an image.
    </ResponseField>
    <ResponseField name="avatarFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
      New avatar image to upload, replacing the current one (up to 50 MB). `file` is a `File` or `Blob`, or a React Native file `{ uri, name, type? }`; `options` must include `mode` (see [Upload Image](/v8/api-reference/storage/upload-image)). With a file, the update is sent as `multipart/form-data`.
    </ResponseField>
    <ResponseField name="bannerFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
      New banner image to upload, replacing the current one; same shape as `avatarFile`.
    </ResponseField>
    <ResponseField name="removeFileIds" type="string[]">
      Files to remove: the id of `user.avatarFile` and/or `user.bannerFile`. Removing one clears that image. Any other id refuses the whole update (`400 user/invalid-remove-file-ids`).
    </ResponseField>
    <ResponseField name="location" type="{ latitude: number; longitude: number }">
      User's geographic location.
    </ResponseField>
    <ResponseField name="metadata" type="Record<string, any>">
      Arbitrary project-specific data. Limited to 10 KB. Visible to other users (embedded in entity and comment data).
    </ResponseField>
    <ResponseField name="secureMetadata" type="Record<string, any>">
      Never present: custom fields excluded from every client-facing response, including the authenticated user's own profile. The user can still write them (at sign-up and when updating their profile), so don't use them for data your app needs to trust.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="clearError" type="() => void">
  Clears the current error state.
</ResponseField>

## Optimistic Updates

`updateUser` applies changes to local state before the server responds. This makes the UI feel instant. Fields that cannot be optimistically applied (file uploads, location, birthdate) wait for the server response.

If the server returns an error, the hook automatically reverts the user state to its pre-update value.

<Note>
  File uploads (`avatarFile`, `bannerFile`) and `removeFileIds` are not applied optimistically: the new file fields are known only once the server answers.
</Note>
