---
title: "Authorize OAuth"
api: "POST /v7/:projectId/oauth/authorize"
description: "Initiate an OAuth sign-in or sign-up flow"
---

Initiates an OAuth 2.0 authorization flow for unauthenticated users (sign-in or sign-up). Returns an authorization URL that the client should redirect the browser to. Sublay sends the browser on to the provider, and after the user authenticates there, back to the `redirectAfterAuth` URL with tokens in the URL fragment.

<Note>
  The OAuth provider must be configured and enabled in the Sublay dashboard
  before this endpoint can be used. The `redirectAfterAuth` URL must be in
  the provider's allowed redirect URI list.
</Note>

## Body Parameters

<ParamField body="provider" type="string" required>
  The OAuth provider to use. Must be one of: `"google"`, `"github"`, `"apple"`,
  `"facebook"`.
</ParamField>

<ParamField body="redirectAfterAuth" type="string" required>
  The URL to redirect the user to after authentication. Must be a valid URL
  and must be present in the provider's configured allowed redirect URIs.
</ParamField>

## Response

<ResponseField name="authorizationUrl" type="string">
  The URL to send the user's browser to, to begin the OAuth flow. It is a
  one-time Sublay URL that redirects to the provider; it expires after 10
  minutes.
</ResponseField>

<Note>
  Open `authorizationUrl` as-is, in the browser (or auth session) that should
  end up signed in. It points to Sublay first, which ties the sign-in to that
  browser and then sends it on to the provider. A sign-in that returns to a
  different browser is refused with `error=state_mismatch`, and so is the
  older of two sign-ins started at the same time in one browser.
</Note>

## Callback

After the user authorizes with the provider, they are redirected to `redirectAfterAuth` with one of:

**On success** — Tokens in the URL fragment:
```
https://yourapp.com/callback#accessToken=...&refreshToken=...
```

**On error** — Error details in query parameters:
```
https://yourapp.com/callback?error=access_denied&error_description=...
```

`error=state_mismatch` means the browser that returned from the provider isn't the one that opened `authorizationUrl` (for example, the return link was opened somewhere else), so the sign-in is refused. Start the sign-in again. `error=state_expired` means the sign-in took too long (10 minutes at the provider; for a link, at most 30 minutes in all).

`error=email_not_verified` means the provider's email belongs to an existing user but the provider hasn't verified it, so the sign-in can't be connected to that account. `error_description` says so in words you can show the user: verify the email with the provider, or sign in the way they originally signed up.

## Error Responses

<AccordionGroup>
  <Accordion title="Provider Not Configured — 400">
    ```json
    {
      "error": "OAuth provider 'google' is not configured or not enabled for this project",
      "code": "oauth/provider-not-configured"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Redirect URI — 400">
    ```json
    {
      "error": "redirectAfterAuth is not in the allowed redirect URIs for this project",
      "code": "oauth/invalid-redirect-uri"
    }
    ```
  </Accordion>
</AccordionGroup>
