---
title: "Is Entity Saved"
api: "GET /v8/:projectId/entities/is-entity-saved"
description: "Check whether an entity is saved in any of the current user's collections"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Returns whether the specified entity is saved in any collection belonging to the authenticated user, along with the list of matching collections.

## Query Parameters

<ParamField query="entityId" type="string" required>
  The ID of the entity to check.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose collections are checked. A user token always acts as its own user and must not send it (`400 collection/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="saved" type="boolean">
  `true` if the entity is saved in at least one collection.
</ResponseField>

<ResponseField name="collections" type="Array<{ id: string; name: string }>">
  List of collections (by ID and name) that contain this entity.
</ResponseField>

```json
{
  "saved": true,
  "collections": [
    { "id": "col_abc", "name": "To Read" },
    { "id": "col_xyz", "name": "Favorites" }
  ]
}
```

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "collection/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "collection/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "collection/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Internal server error.", "code": "collection/server-error" }
    ```
  </Accordion>
</AccordionGroup>
