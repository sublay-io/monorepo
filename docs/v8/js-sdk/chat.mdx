The `chat` module powers direct, group, and space conversations — sending and
editing messages (with file attachments), managing members, reacting, and tracking
read state. All actions are performed as the logged-in user.

<Note>
  **Two list endpoints page by cursor, not `page`/`limit`:**
  [`listConversations`](#listconversations) takes the opaque `cursor` the
  previous page returned, and [`listMessages`](#listmessages) pages `before` or
  `after` a message id. See each below.
</Note>

---

### listConversations

Lists the user's conversations, newest activity first, with cursor pagination.

```typescript
const { data: conversations, pagination } = await sublay.chat.listConversations({
  types: ["direct", "group"],
  limit: 20,
});

// Next page: pass pagination.nextCursor back as `cursor` (null on the last page).
if (pagination.hasMore) {
  const next = await sublay.chat.listConversations({
    types: ["direct", "group"],
    cursor: pagination.nextCursor,
  });
}
```

<ParamField body="types" type="ConversationType | ConversationType[]">
  Only conversations of these types: any of `"direct"`, `"group"`, `"space"`. Omitted, every type is listed.
</ParamField>

<ParamField body="cursor" type="string | null">
  `pagination.nextCursor` from the previous response, passed as returned; omit
  it (or pass `null`) for the first page. It is opaque: don't build or parse it.
  One the server can't read is rejected with `400 chat/invalid-cursor`.
</ParamField>

<ParamField body="limit" type="number">
  Page size. Defaults to `20`, max `50`.
</ParamField>

**Returns** — `Promise<CursorPaginatedResponse<ConversationPreview>>`: `{ data: ConversationPreview[]; pagination: { nextCursor: string | null; hasMore: boolean } }`. `nextCursor` is `null` when `hasMore` is `false`.

Each `ConversationPreview` includes `otherMembers` — up to 5 active members other than the current user (`id`, `name`, `username`, `avatar`) for `direct`/`group` conversations, so a DM/group can render the counterparty without a separate members fetch. Capped at 5 (use `memberCount` for the group total); empty for `space` conversations.

### createDirectConversation

Returns the 1:1 direct conversation with another user, or creates it when there is none. Props type: `CreateDirectConversationProps`.

```typescript
const { conversation, created } = await sublay.chat.createDirectConversation({
  userId: "usr_abc123",
});
```

<ParamField body="userId" type="string" required>
  The other participant's Sublay user ID.
</ParamField>

**Returns** — `Promise<CreateDirectConversationResult>`: `{ conversation: Conversation; created: boolean }`. `created` is `true` when this call created the conversation (HTTP `201`) and `false` when it already existed (HTTP `200`).

### checkMyConversationMembership

Reads the logged-in user's own membership in a conversation (`GET /chat/conversations/:conversationId/members/me`).

```typescript
const membership = await sublay.chat.checkMyConversationMembership({
  conversationId: "cnv_abc123",
});
```

<ParamField body="conversationId" type="string" required>
  The conversation ID.
</ParamField>

**Returns** — `Promise<CheckMyConversationMembershipResponse>`, a flat object where a field that doesn't apply is left out:

- an active member: `{ isMember: true, role, lastReadAt, mutedForever, mutedUntil }`
- a user who left or was removed: `{ isMember: false, leftAt }`
- a user with no membership yet (a space conversation they haven't opened): `{ isMember: false }`

A user who can't read the conversation gets the same error as reading it (`404 chat/not-found` or `403 chat/not-a-member`). See [Check My Membership](/v8/api-reference/chat/members/check-my-membership).

### listMessages

Lists messages in a conversation, a page at a time before or after a message.

```typescript
const { data: messages, pagination } = await sublay.chat.listMessages({
  conversationId: "cnv_abc123",
  limit: 50,
  sortDir: "desc",
});

// Older page: pass the oldest message's id as `before`
// (with "desc", the last item of the page).
if (pagination.hasMore) {
  const older = await sublay.chat.listMessages({
    conversationId: "cnv_abc123",
    before: messages[messages.length - 1].id,
  });
}

// Only messages that have thread replies.
const withReplies = await sublay.chat.listMessages({
  conversationId: "cnv_abc123",
  filters: { hasReplies: true },
});
```

<ParamField body="conversationId" type="string" required>
  The conversation ID.
</ParamField>

<ParamField body="parentMessageId" type="string">
  List this message's thread replies (thread view), oldest first by default.
</ParamField>

<ParamField body="before" type="string">
  A message id: return the `limit` messages just before it. Pass the oldest
  message you hold to load older ones. It must be a message of this conversation
  at the same thread level (`parentMessageId`), or the call is rejected with
  `400 chat/invalid-cursor`. Mutually exclusive with `after`.
</ParamField>

<ParamField body="after" type="string">
  A message id: return the `limit` messages just after it. Pass the newest
  message you hold to load newer ones. Same rules as `before`. Mutually
  exclusive with `before`.
</ParamField>

<ParamField body="limit" type="number">
  Page size. Defaults to `50`, max `100`.
</ParamField>

<ParamField body="sortDir" type='"asc" | "desc"'>
  The order of the page by creation time. Defaults to `"desc"` for the main
  stream and `"asc"` for a thread. With `before` or `after`, the anchor decides
  which messages are in the page; `sortDir` only orders them.
</ParamField>

<ParamField body="include" type="ChatMessageListIncludeParam">
  Associations to populate, as a single value or an array: `"files"` (message attachments) and `"grants"` (each message's [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary)). Pass `["files", "grants"]` for both.
</ParamField>

<ParamField body="filters" type="MessageFilters">
  Optional filters. `filters.hasReplies` (boolean): when `true`, returns only
  messages that have thread replies (`threadReplyCount > 0`); when `false`, only
  messages with none. Filters by thread replies, not quotings.

  Threads are one level deep, so `hasReplies: true` together with `parentMessageId`
  always returns an empty list — the response's `notice` field explains why.
</ParamField>

<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<{ data: ChatMessage[]; pagination: { hasMore: boolean }; notice?: string }>`. `hasMore` says whether more messages exist past this page in the direction of travel: older with `before`, newer with `after`; with neither, older for `"desc"` and newer for `"asc"`. See [List Messages › Paging](/v8/api-reference/chat/messages/list-messages#paging).

### sendMessage

Sends a message to a conversation, optionally with file attachments. When `files`
is provided the request is sent as `multipart/form-data` (pass browser `File` /
`Blob` objects); otherwise it is a plain JSON body.

```typescript
const input = document.querySelector('input[type="file"]');

const message = await sublay.chat.sendMessage({
  conversationId: "cnv_abc123",
  content: "Here's the doc 👇",
  files: Array.from(input.files), // up to 20 File/Blob attachments, 50 MB each
});
```

<ParamField body="conversationId" type="string" required>
  The conversation ID.
</ParamField>

<ParamField body="content" type="string">
  Message text.
</ParamField>

<ParamField body="gif" type="GifData | null">
  An attached GIF, or `null`.
</ParamField>

<ParamField body="mentions" type="Mention[]">
  User mentions embedded in the message.
</ParamField>

<ParamField body="parentMessageId" type="string">
  The message this is a threaded reply to.
</ParamField>

<ParamField body="quotedMessageId" type="string">
  A message being quoted.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key-value data attached to the message.
</ParamField>

<ParamField body="localId" type="string">
  A client-generated ID echoed back on the created message (for optimistic UI);
  not stored.
</ParamField>

<ParamField body="files" type="(Blob | File)[]">
  Up to 10 file attachments, as browser `File` / `Blob` objects. Triggers a
  `multipart/form-data` upload.
</ParamField>

<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<ChatMessage>`

### Reporting a message

Message reports go through the shared reports API, not a chat-specific
function — the same call that reports entities and comments.

```typescript
const report = await sublay.reports.createReport({
  targetType: "message",
  targetId: "msg_xyz789",
  reason: "spam",
});
```

`targetId` is the message id; the conversation is resolved server-side, so no
`conversationId` is needed. The reporter must be a member of the conversation
and cannot report their own message. See [createReport](/v8/js-sdk/reports).

**Returns** — `Promise<CreateReportResponse>` — the user's own report of the message (see [createReport](/v8/js-sdk/reports#createreport)).

### toggleReaction

Toggles (adds or removes) an emoji reaction on a message for the logged-in user. A [deleted or removed message](/v8/data-models/chat-message#deleted-and-removed-messages) takes no new reaction: adding one fails with `404 chat/message-not-found`, while taking back your own still works.

```typescript
const { reactionCounts, userReactions, delta } = await sublay.chat.toggleReaction({
  conversationId: "cnv_abc123",
  messageId: "msg_xyz789",
  emoji: "👍",
});
// delta is +1 if the reaction was added, -1 if removed.
```

<ParamField body="conversationId" type="string" required>
  The conversation ID.
</ParamField>

<ParamField body="messageId" type="string" required>
  The message ID.
</ParamField>

<ParamField body="emoji" type="string" required>
  The reaction emoji (1–10 characters).
</ParamField>

**Returns** — `Promise<{ reactionCounts: Record<string, number>; userReactions: string[]; delta: 1 | -1 }>`

### muteConversation

Sets or clears the signed-in user's mute on a conversation. Muting suppresses the `message` push for this conversation only; the message is still delivered and readable. See [Notification Preferences & Mute](/v8/notification-preferences).

```typescript
// Mute for 24 hours
await sublay.chat.muteConversation({
  conversationId: "cnv_abc123",
  duration: "24h",
});

// Unmute
await sublay.chat.muteConversation({
  conversationId: "cnv_abc123",
  duration: null,
});
```

<ParamField body="conversationId" type="string" required>
  The conversation to mute or unmute.
</ParamField>

<ParamField body="duration" type='"8h" | "24h" | "1w" | "forever" | null' required>
  The mute **duration choice**, or `null` to clear the mute. Send the choice, never a raw timestamp — the server resolves the window.
</ParamField>

**Returns** — `Promise<{ currentMember: ConversationMember }>` — the signed-in user's own member row.

<Info>
  **"Forever" is an explicit signal.** A `forever` mute returns `mutedForever: true` with `mutedUntil: null`; a timed mute returns `mutedForever: false` with a real ISO `mutedUntil`. Read the boolean — never string-match a far-future date.
</Info>
