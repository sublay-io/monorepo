---
title: "Delete File"
api: "DELETE /v8/:projectId/storage/:fileId"
description: "Delete a file and all its variants from storage"
---

Deletes a file record and removes all associated storage objects. For image files, all generated variants are also deleted.

Requires authentication. **The owner deletes:** a file with an owner is deleted only as that user — with their own access token, or with a service key naming them in `actingUserId`, and the request then runs exactly as theirs (suspension included). An app-owned file (uploaded without an `actingUserId`) is deleted only by a service key naming nobody; a user token gets `403`.

The owner can delete any of their files here except these, refused with `409 storage/file-attached`:

- a chat message's file: it's removed when the message is deleted;
- a user's or space's avatar or banner (the file its `avatarFileId` or `bannerFileId` points at): remove it with `removeFileIds` on [Update User](/v8/api-reference/users/update-user) or [Update Space](/v8/api-reference/spaces/update-space);
- a conversation's avatar (the file its `avatarFileId` points at): remove it with `removeFileIds` on [Update Conversation](/v8/api-reference/chat/conversations/update-conversation);
- an event's file, its cover included: remove it with `removeFileIds` on [Update Event](/v8/api-reference/events/update-event).

**Rate limit**: 50 requests per 5 minutes.

## Path Parameters

<ParamField path="fileId" type="string" required>
  The UUID of the file to delete.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user this delete acts as. Required when the file has an owner: name the owner (naming anyone else gets `403`). Leave it out only for an app-owned file. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 storage/acting-user-not-allowed`).
</ParamField>

## Response

`204 No Content` on success, with no body. The original file and every image variant made from it are removed from storage.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `fileId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid file id: expected a UUID.", "code": "storage/invalid-params", "param": "fileId" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "File not found", "code": "storage/file-not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    Returned when the acting user doesn't own the file, or when a user token, or a service key naming a user, deletes an app-owned file.
    ```json
    { "error": "Only the file's owner can delete it.", "code": "storage/forbidden" }
    ```
  </Accordion>
  <Accordion title="File Attached — 409">
    The file is a chat message's file, a user's or space's avatar or banner, a conversation's avatar, or an event's file (its cover included). `error` names which, and how to remove it. Checked after the owner check, so only the file's owner learns this.
    ```json
    { "error": "This file belongs to a user's avatar or banner, so it can't be deleted here. Remove it through the user's update: list its id in `removeFileIds`.", "code": "storage/file-attached" }
    ```
    An event's file or cover:
    ```json
    { "error": "This file belongs to an event, so it can't be deleted here. Remove it through the event's update: list its id in `removeFileIds`.", "code": "storage/file-attached" }
    ```
    A conversation's avatar:
    ```json
    { "error": "This file belongs to a conversation's avatar, so it can't be deleted here. Remove it through the conversation's update: list its id in `removeFileIds`.", "code": "storage/file-attached" }
    ```
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId` for a file that has an owner. Name the owner: the request then runs exactly as their own.

    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "storage/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "storage/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "storage/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Failed to delete file", "code": "storage/server-error" }
    ```
  </Accordion>
</AccordionGroup>
