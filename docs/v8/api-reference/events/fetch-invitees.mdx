---
title: "Fetch Invitees"
api: "GET /v8/:projectId/events/:eventId/invites"
description: "List an event's invited users (host-only)"
---

Returns a paginated list of [EventInvite](/v8/data-models/event-invite) records, each with the invited `user` populated. Open to the event's hosts — for an event in a space, while they are active members of it and not banned in it or a space above it — and to the space's active admins and moderators. Anyone else who can see the event receives `403`; a missing event, or one the caller can't see and doesn't host, receives `404`. A service key acts as the user it names in `actingUserId`. Results are ordered by `invitedAt` descending.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

## Query Parameters

<ParamField query="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page. Capped at `100`. Defaults to `10`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Required with a service key: the user this request acts as. It has exactly that user's powers, so it is refused unless they are a host of the event or an admin or moderator of its space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns a paginated response: `{ data: EventInvite[], pagination: {...} }`.

## Error Responses

<AccordionGroup>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Body Not Allowed — 400">
    The request carried a body. A GET takes no body: send `actingUserId` and every other field in the query string.
    ```json
    {
      "error": "A GET request takes no body: send its fields in the query string. Received: `actingUserId`.",
      "code": "event/body-not-allowed",
      "params": ["actingUserId"]
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    The event doesn't exist, or the caller can't [see it](/v8/data-models/event#visibility) and isn't one of its hosts.
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    The caller can see the event but isn't one of its hosts or an admin or moderator of its space.
    ```json
    { "error": "Only the event's hosts or an admin or moderator of its space may view its invite list.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Host Not an Active Member — 403">
    The caller is a host, but the event is in a space they aren't an active member of, or they are banned in it or a space above it. One body for every case.
    ```json
    { "error": "Hosts must be active members of this event's space, and not banned from it or a space above it, to do this.", "code": "event/not-space-member" }
    ```
  </Accordion>
</AccordionGroup>
