Returns a paginated list of reactions for a comment, each with the reacting user's profile. Useful for displaying "reacted by" lists or per-type reaction breakdowns.

Authentication is optional — the endpoint works without a token. When there is a viewer (the signed-in user, or the user a service key names in `actingUserId`), reactions from users with a block between them and the viewer, in either direction, are excluded from both the results and the count. Block filtering requires the `moderation` bundle.

## Path Parameters

<ParamField path="commentId" type="string" required>
  The UUID of the comment.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as, exactly as their own access token: their block filtering, and `404` for a comment on an entity whose author blocked them. Leave it out for the anonymous view. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 comment/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number" default="1">
  Page number (1-indexed). A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 comment/invalid-query`.
</ParamField>

<ParamField query="limit" type="number" default="20">
  Number of reactions per page. A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 comment/invalid-query`. Values above `100` are treated as `100`.
</ParamField>

<ParamField query="reactionType" type="string">
  Filter to a specific reaction type. One of: `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`. When omitted, all types are returned.
</ParamField>

<ParamField query="sortDir" type="string" default="desc">
  Sort by creation time, `"asc"` or `"desc"` (either case).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to each reactor's `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Params — 400">
    Returned when `commentId` isn't a valid UUID.

    ```json
    { "error": "Invalid comment id: expected a UUID.", "code": "comment/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned when `page` isn't a positive whole number, `limit` is below `1` or not a whole number, `reactionType` isn't one of the eight types, or `sortDir` isn't `asc` or `desc`.

    ```json
    { "error": "page: Page must be a positive integer", "code": "comment/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Returned when the comment doesn't exist, a moderator removed it, or it is on an entity whose author has blocked the caller (the caller's own comments excepted).

    ```json
    { "error": "Comment not found.", "code": "comment/not-found" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "comment/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "comment/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
