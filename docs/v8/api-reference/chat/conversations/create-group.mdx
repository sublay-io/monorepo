---
title: "Create Group Conversation"
api: "POST /v8/:projectId/chat/conversations"
description: "Create a new multi-member group conversation"
---

Creates a group conversation. The caller is automatically added as an `admin`. All provided `memberIds` are validated to belong to the project and added as `member`.

Send a JSON body, or `multipart/form-data` when uploading the group's avatar with it. On a multipart request every field is a string: send `memberIds` and `metadata` as JSON strings.

## Body Parameters

<ParamField body="type" type="string" required>
  Must be `"group"`.
</ParamField>

<ParamField body="name" type="string">
  Display name of the conversation. Maximum 200 characters. Optional.
</ParamField>

<ParamField body="description" type="string">
  Optional description for the conversation. Maximum 1000 characters.
</ParamField>

<ParamField body="memberIds" type="string[]">
  Array of user IDs to add to the conversation. Defaults to `[]`. The caller's own ID is ignored if included — they are always added as admin. All IDs must belong to the same project.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data to attach to the conversation. Optional.
</ParamField>

<ParamField body="avatarFile" type="file">
  The group's avatar image: JPEG, PNG or WebP, maximum 50 MB. Requires `avatarFile.options`. The image is processed into the variants the options ask for, and the conversation's `avatarFileId` points at it. Requires the `files-images` bundle.
</ParamField>

<ParamField body="avatarFile.options" type="string">
  JSON-encoded image-processing options for `avatarFile`: a `mode` and the fields it needs, for example `{ "mode": "original-aspect", "sizes": { "small": 64, "large": 256 } }`. See [Image Processing Modes](/v8/sdk/storage/overview#image-processing-modes).
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. They create the group and become its `admin`. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns the created [Conversation](/v8/data-models/conversation) object with HTTP `201`. When the `files-images` bundle is installed it includes `avatarFile`: the avatar's file, or `null` when the group was created without one.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter (avatarFileId) — 400">
    The request sent `avatarFileId`. The avatar is the image itself, uploaded as `avatarFile`; this endpoint never takes the id of a file uploaded elsewhere.

    ```json
    {
      "error": "`avatarFileId` isn't accepted: send the avatar image itself as the `avatarFile` file.",
      "code": "chat/unsupported-param",
      "param": "avatarFileId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Member — 400 Bad Request">
    ```json
    { "error": "User 'abc' does not belong to this project.", "code": "chat/invalid-member" }
    ```
    One or more provided user IDs do not exist in this project.
  </Accordion>
  <Accordion title="Bundle Not Installed — 403">
    Returned when an avatar is uploaded on a project without the files-images bundle. `missingTables` lists the tables that aren't installed and `bundleId` the bundle to install. While the bundle is still being installed, the response is `503 database/tables-provisioning` instead. See [Bundles](/v8/bundles).
    ```json
    { "error": "Conversation avatar uploads require the files-images bundle. Enable it for this project.", "code": "database/tables-not-available", "missingTables": ["Files", "Images"], "bundleId": "files-images", "dashboardUrl": "https://…/<projectId>/database" }
    ```
  </Accordion>
  <Accordion title="Image Too Large — 413">
    ```json
    { "error": "`avatarFile` is over the 50 MB per-file limit.", "code": "chat/file-too-large", "param": "avatarFile" }
    ```
  </Accordion>
  <Accordion title="Invalid Image — 422">
    The file can't be read as an image.
    ```json
    { "error": "Avatar file is not a valid image.", "code": "chat/invalid-image", "param": "avatarFile" }
    ```
    An image over 10000 px on a side gets the same code. `error` gives its size:
    ```json
    { "error": "Avatar file is 12000 x 800 px; an image can be at most 10000 px on each side.", "code": "chat/invalid-image", "param": "avatarFile" }
    ```
  </Accordion>
  <Accordion title="Missing Image Options — 400">
    `avatarFile` was uploaded without `avatarFile.options`.
    ```json
    { "error": "Image options are required when uploading an avatar. Must include mode property.", "code": "chat/missing-image-options", "param": "avatarFile.options" }
    ```
  </Accordion>
  <Accordion title="Invalid Image Options — 400">
    `avatarFile.options` isn't valid JSON, or isn't valid image options.
    ```json
    { "error": "Invalid JSON in avatarFile.options field.", "code": "chat/invalid-body", "param": "avatarFile.options" }
    ```
    `avatarFile.options` without `mode`, or with a `mode` that isn't one of the five (other options fields the same way, named in `error` and `param`):
    ```json
    { "error": "avatarFile.options.mode: Invalid input", "code": "chat/invalid-body", "param": "avatarFile.options.mode" }
    ```
    In an aspect-ratio mode, a variant's computed side would be outside 1–10000 px. Checked once the image is read, before anything is stored. `param` names the option:
    ```json
    { "error": "`avatarFile.options.widths.s` gives a height of 0 px at the 3:1 aspect ratio. Each side of a variant must be 1–10000 px.", "code": "chat/invalid-body", "param": "avatarFile.options.widths.s" }
    ```
    In `aspect-ratio-height-based` it names a `heights` option and gives a width. In `multi-aspect-ratio` it names a `sizes` option, and the ratio is the one in `aspectRatios` closest to the image, so the text reads "… at the 3:1 aspect ratio, the one in `aspectRatios` closest to this image. Each side of a variant must be 1–10000 px."
    More than 30 entries in `dimensions`, `widths`, `heights` or `sizes` (one variant each). `param` names the option:
    ```json
    { "error": "avatarFile.options.sizes: An image can have at most 30 variants.", "code": "chat/invalid-body", "param": "avatarFile.options.sizes" }
    ```
    A variant name that is empty or `original`, or that contains `/`, `\` or `..`. `param` names the option:
    ```json
    { "error": "avatarFile.options.sizes: Variant names can't be empty, `original`, or contain `/`, `\\` or `..`.", "code": "chat/invalid-body", "param": "avatarFile.options.sizes" }
    ```
  </Accordion>
  <Accordion title="Upload Refused — 400 / 413">
    A file was refused as the body was read: `chat/unsupported-file-type` or `chat/unexpected-file-field` (a file in another field, or a second file in `avatarFile`), with `param` naming the field when there is one. A body over 250 MB gets `413 request/body-too-large`; one that can't be read at all gets `request/invalid-multipart` or `request/field-too-large`. See [Upload errors](/v8/api-reference/getting-started#upload-errors).
  </Accordion>
</AccordionGroup>
