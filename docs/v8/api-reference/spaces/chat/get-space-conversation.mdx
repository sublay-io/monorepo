---
title: "Get Space Conversation"
api: "GET /v8/:projectId/spaces/:spaceId/conversation"
description: "Get or create the chat conversation for a space"
---

Returns the chat conversation associated with a space. If no conversation exists yet, one is created automatically. Requires authentication. The caller must be an active member of the space: a request still awaiting approval, a rejected request and a ban are all refused.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be an active member of the space. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns a [Conversation](/v8/data-models/conversation) object with two additional fields:

<ResponseField name="currentMember" type="object | null">
  The caller's `ConversationMember` record for this conversation. Created or re-activated on first call.
</ResponseField>

<ResponseField name="memberCount" type="number">
  Number of currently active members in the conversation.
</ResponseField>

<Note>Each space has at most one associated conversation. This endpoint is idempotent — calling it multiple times returns the same conversation.</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "chat/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Not a Member — 403">
    Also returned when the caller's request to join was rejected.

    ```json
    { "error": "You are not a member of this space.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Awaiting Approval — 403">
    ```json
    { "error": "Your request to join this space is awaiting approval.", "code": "chat/membership-pending" }
    ```
  </Accordion>
  <Accordion title="Banned — 403">
    ```json
    { "error": "You are banned from this space.", "code": "chat/banned" }
    ```
  </Accordion>
</AccordionGroup>
