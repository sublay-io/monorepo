Returns a paginated list of entities for the project. Supports rich filtering by source, space, user, keywords, metadata, title, content, location, and time. Excludes drafts — use [Fetch Drafts](/v8/api-reference/entities/fetch-drafts) for those.

## Query Parameters

### Acting user

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as. The page is exactly what that user's own access token would get — `followedOnly` and `blockedFilter` for them, their own removed entities when `userId` names them, `saved`, their own reactions and the top comments they may see — and the reads count as their views. Leave it out for the anonymous view (no follow or block filtering; the reads don't count as views). This is the viewer, not the author filter: that is `userId`. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

### Pagination

<ParamField query="page" type="number" default="1">
  Page number (1-indexed). A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`.
</ParamField>

<ParamField query="limit" type="number" default="10">
  Number of entities per page. A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`. Maximum `100` — larger values are treated as `100`.
</ParamField>

### Sorting

<ParamField query="sortBy" type="string" default="createdAt">
  Sort algorithm. One of:
  - `createdAt` — chronological by creation time (honors `sortDir`; newest first by default)
  - `top` — by reaction count (use `sortByReaction` to specify which type)
  - `hot` — by computed engagement score (decays over time)
  - `controversial` — high total votes with a close up/down split (entities with no votes sort last)
  - `metadata.<property>` — sort by a metadata field (e.g. `metadata.memberCount`)
</ParamField>

<ParamField query="sortDir" type="string" default="desc">
  Sort direction, `"asc"` or `"desc"` (either case). Not accepted with `"hot"` or `"controversial"`, which rank one way only (most first): sending it returns `400 entity/invalid-query`.
</ParamField>

<ParamField query="sortType" type="string" default="auto">
  When using `sortBy=metadata.*`, the type of the metadata field. One of `auto`, `numeric`, `text`, `boolean`, `timestamp`. `auto` infers the type at query time.
</ParamField>

<ParamField query="sortByReaction" type="string" default="upvote">
  When `sortBy=top`, which reaction type to rank by. One of `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`. Only accepted with `sortBy=top`; sending it with any other sort returns `400 entity/invalid-query`.
</ParamField>

### Filtering

<ParamField query="timeFrame" type="string">
  Restrict to entities created within the last period. One of `hour`, `day`, `week`, `month`, `year`.
</ParamField>

<ParamField query="sourceId" type="string">
  Only entities with this exact `sourceId`. `none` returns entities with no source. Left out, or sent empty, entities from any source (or none) are returned. `null` and `undefined` are refused with `400 entity/unsupported-param` (see [Saying "no value"](/v8/authentication#saying-no-value)).
</ParamField>

<ParamField query="spaceId" type="string">
  Only entities in this space. `none` returns entities in no space. Left out, or sent empty, entities in any space or in none are returned. `null` and `undefined` are refused with `400 entity/unsupported-param` (see [Saying "no value"](/v8/authentication#saying-no-value)).
</ParamField>

<ParamField query="userId" type="string">
  Filter by author: returns only entities whose `userId` is this user. Not the viewer: a service key names the viewer in `actingUserId`. When this matches the viewer (the signed-in user, or the user named in `actingUserId`), moderation-removed entities are also included (an author can see their own removed entities).
</ParamField>

<ParamField query="followedOnly" type="string">
  When `"true"`, only returns entities from users the viewer follows. Needs a viewer: the signed-in user, or the user a service key names in `actingUserId`; without one it has no effect.
</ParamField>

<ParamField query="blockedFilter" type="string" default="exclude">
  Controls how entities authored by users the viewer is [block-edged](/v8/sdk/moderation/overview#blocking) with are treated. `"exclude"` (default) hides those entities. `"include-outbound-blocked"` re-includes entities authored **only** by users the viewer themselves blocked (their own "view anyway" choice); it never surfaces content from users who blocked the viewer. Counts reflect what the viewer sees (computed post-filter). Has no effect when the `moderation` bundle is not installed.
</ParamField>

<ParamField query="keywordsFilters" type="object">
  Filter by keywords. Pass as a JSON string or bracket-notation query params:
  ```json
  { "includes": ["react", "typescript"], "doesNotInclude": ["vue"] }
  ```
</ParamField>

<ParamField query="titleFilters" type="object">
  Filter by title content:
  ```json
  {
    "hasTitle": "true",
    "includes": "tutorial",
    "doesNotInclude": "beginner"
  }
  ```
  - `hasTitle`: `"true"` or `"false"` — filter for presence/absence of a title
  - `includes`: substring(s) to match (case-insensitive)
  - `doesNotInclude`: substring(s) to exclude
</ParamField>

<ParamField query="contentFilters" type="object">
  Filter by content text. Same structure as `titleFilters` (`hasContent`, `includes`, `doesNotInclude`).
</ParamField>

<ParamField query="attachmentsFilters" type="object">
  Filter by attachment presence:
  ```json
  { "hasAttachments": "true" }
  ```
</ParamField>

<ParamField query="locationFilters" type="object">
  Filter to entities within a radius of a point:
  ```json
  { "latitude": "40.7128", "longitude": "-74.0060", "radius": "5000" }
  ```
  `radius` is in meters: a number greater than `0` and at most `20000000` (20,000 km, about half the Earth's circumference, which reaches any point). A value outside that range, or one that isn't a finite number (`Infinity`, `1e999`), returns `400 entity/invalid-query`.
</ParamField>

<ParamField query="metadataFilters" type="object">
  Filter by metadata values. Supports complex conditions:
  ```json
  {
    "includes": { "status": "published" },
    "includesAny": [{ "type": "video" }, { "type": "image" }],
    "doesNotInclude": { "hidden": true },
    "exists": ["category"],
    "doesNotExist": ["archivedAt"]
  }
  ```
  - `includes` — all key/value pairs must match (AND)
  - `includesAny` — at least one object must match (OR)
  - `doesNotInclude` — none of these key/value pairs may match
  - `exists` — keys that must be present
  - `doesNotExist` — keys that must be absent

  Keys and values can't contain a NUL character (`\u0000`), which metadata can never hold; one anywhere in `metadataFilters` returns `400 entity/invalid-query`.
</ParamField>

### Optional Associations

<ParamField query="include" type="string">
  Associations to include in each entity. Pass it as one comma-separated value (`include=user,space`) or as repeated params (`include=user&include=space`). Values:
  - `user` — the author's user profile
  - `space` — the space the entity belongs to (`null` when the viewer can't see that space; see [Space visibility](/v8/data-models/space#visibility))
  - `topComments` — the entity's best top-level comments, as full [Comment](/v8/data-models/comment) objects (see [Top comments](/v8/data-models/entity#top-comments))
  - `saved` — whether the authenticated user has saved this entity
  - `files` — uploaded file/image attachments
  - `grants` — the [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary) for the entity
</ParamField>

<ParamField query="topCommentsLimit" type="number" default="1">
  With `include=topComments`: how many top comments per entity. A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`. Maximum `5` — larger values are treated as `5`.
</ParamField>

<ParamField query="topCommentsSortByReaction" type="string" default="upvote">
  With `include=topComments`: the reaction whose raw count ranks the top comments (ties newest first). One of `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`.
</ParamField>

`include` values are case-insensitive. An unknown value returns `400 entity/invalid-query`, as does sending `topCommentsLimit` or `topCommentsSortByReaction` without `include=topComments`. `topComments` lists real content only — deleted, removed and block-edged comments are left out — and is `[]` when nothing qualifies.

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to each populated author `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

## Response

Returns a paginated response object:

```json
{
  "data": [ ...Entity[] ],
  "pagination": {
    "page": 1,
    "pageSize": 10,
    "totalPages": 5,
    "totalItems": 42,
    "hasMore": true
  }
}
```

Each item in `data` is an [Entity](/v8/data-models/entity) object. File URLs are signed and ready to use.

<Note>
  Viewing scores (`hot` sort) are updated asynchronously after each fetch. Scores decay at a rate set per project ([feed decay](/v8/sdk/entity-lists/fetch-entities#feed-decay)). Entities with equal scores are ordered newest first.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Unsupported sort — 400">
    `sortBy=new` is rejected with a pointer to its replacement, `sortBy=createdAt`.

    ```json
    {
      "error": "`sortBy=new` isn't supported in v8. Use `sortBy=createdAt`, which lists newest first by default.",
      "code": "entity/unsupported-param",
      "param": "sortBy"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported filter value — 400">
    `null` or `undefined` as the value of `sourceId`, `spaceId` or `spaceReputationId`. The `error` names the spelling to use instead; for `spaceId` it reads ``Use `spaceId=none` for entities in no space, or leave it out for any space.``

    ```json
    {
      "error": "`sourceId=null` isn't supported. Use `sourceId=none` for entities with no source, or leave it out for any source.",
      "code": "entity/unsupported-param",
      "param": "sourceId"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned when `page` or `limit` is below `1` or not a whole number, when `locationFilters.radius` isn't a number greater than `0` and at most `20000000`, or when `metadataFilters` contains a NUL character. `error` starts with the field name.

    ```json
    { "error": "page: Page must be a positive integer", "code": "entity/invalid-query" }
    ```
    ```json
    { "error": "locationFilters.radius: Radius must be a number greater than 0 and at most 20000000 (meters)", "code": "entity/invalid-query" }
    ```
    ```json
    { "error": "metadataFilters: Metadata filter keys and values can't contain a NUL character (\\u0000)", "code": "entity/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Invalid include — 400">
    Returned with code `entity/invalid-query` for an unknown `include` value, when `topCommentsLimit` is below `1` or not a whole number, or when `topCommentsLimit` / `topCommentsSortByReaction` is sent without `include=topComments`.

    ```json
    { "error": "include: Unknown include `comments`. Allowed: user, space, topComments, saved, files, grants.", "code": "entity/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Renamed include — 400">
    `include=topComment` is rejected with a pointer to its replacement.

    ```json
    {
      "error": "`include=topComment` was renamed to `topComments` (with `topCommentsLimit` / `topCommentsSortByReaction`).",
      "code": "entity/unsupported-param",
      "param": "include"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
