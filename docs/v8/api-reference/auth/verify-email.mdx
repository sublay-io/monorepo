---
title: "Verify Email"
api: "POST /v8/:projectId/auth/verify-email"
description: "Verify a user's email address with a code from a verification email"
---

Verifies a user's email address with a code. It confirms two kinds of code:

- **A code from [Send Verification Email](/v8/api-reference/auth/send-verification-email)** (`mode: "code"`), sent to a signed-in user. Send it in `token` alone. It lasts 5 minutes.
- **A sign-up code**, sent when the project requires email verification before sign-in and the app chose `emailVerification: { mode: "code" }` on [Sign Up](/v8/api-reference/auth/sign-up) or [Sign In](/v8/api-reference/auth/sign-in). Send it in `token` together with the `verificationId` that call returned. It lasts 24 hours.

On success, the user's `isVerified` field is set to `true` and the code is invalidated. Verifying doesn't sign anyone in: after confirming a sign-up code, the user signs in.

This endpoint is unauthenticated — the code itself proves identity.

## Body Parameters

<ParamField body="token" type="string" required>
  The code from the email. Must match exactly, including case.
</ParamField>

<ParamField body="verificationId" type="string">
  The `verificationId` returned with a sign-up code, by the `202` from Sign Up or the `403 auth/email-not-verified` from Sign In. Required for those codes: a sign-up code can't be confirmed without it. Leave it out for a code from Send Verification Email.
</ParamField>

## Response

<ResponseField name="success" type="boolean">
  `true` when the email was successfully verified.
</ResponseField>

## Sign-up codes

A sign-up code is 6 digits and allows 5 wrong tries. After the fifth wrong try it stops working, and so does its `verificationId`. Sending a new code (signing in again with the email and password) replaces the previous one, with a new `verificationId` and a fresh set of tries.

Keep the `verificationId` in memory on the screen that asks for the code. If the user loses it, runs out of tries, or a correct code is refused (a repeated sign-up answers with an ID that doesn't match the code already emailed), the way back is to sign in again with the same email and password, which sends a new code and returns a new `verificationId` — or to reset the password, which also confirms the email. Emails to one address are limited to one every 10 minutes, so a new code can take up to 10 minutes to arrive.

## Error Codes

| Code | Status | Description |
|------|--------|-------------|
| `auth/invalid-or-expired-token` | 400 | The code is wrong, was never issued, has expired, or has already been used. For a sign-up code it's also the answer for an unknown `verificationId` and for a code that ran out of tries. |

<Note>
  Codes are single-use. Once consumed, the same code returns a 400 error.
</Note>
