title: "Fetch Message"

description: "Fetch a single message by ID"
---

import { SpaceReputationParams } from "/snippets/v8/space-reputation-params.mdx";

Returns a single [ChatMessage](/v8/data-models/chat-message) by ID, fully populated with `user`, `quotedMessage`, `files`, `reactionCounts`, and `userReactions`. The caller must be a member of the conversation.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation.
</ParamField>

<ParamField path="messageId" type="string" required>
  The ID of the message to fetch.
</ParamField>

## Query Parameters

<ParamField query="include" type="string">
  Extra fields to include, as a comma-separated value or repeated params. The only value is:
  - `grants` — the [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary) for this message

  The message's `files` are always returned, so `files` is not an include here. Matching ignores case. An unknown value, `files` included, returns `400 chat/invalid-query`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be a member of the conversation. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to the message sender's `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

<SpaceReputationParams variant="context" field="query" />

## Response

Returns a [ChatMessage](/v8/data-models/chat-message) with all populated fields including `reactionCounts` and `userReactions` for the requesting user.

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned for an unknown `include` value, including `files`.
    ```json
    { "error": "include: Unknown include `files`. Allowed: grants.", "code": "chat/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Also returned to a former member (who left, was removed or was banned) for a message sent after they left.
    ```json
    { "error": "Message not found.", "code": "chat/message-not-found" }
    ```
  </Accordion>
</AccordionGroup>
