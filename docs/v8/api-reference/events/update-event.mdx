---
title: "Update Event"
api: "PATCH /v8/:projectId/events/:eventId"
description: "Edit an event's mutable fields and curate its images (host-only)"
---

Updates an event. **Host-only**: the caller must be the owner or in `hostIds`, and, for an event in a space, an active member of that space who isn't banned in it or a space above it. The space's admins and moderators can't edit events they don't host. A service key acts as the host it names in `actingUserId`. Every provided field is updated; omitted fields are left untouched. Type-conditional location validation is re-applied when `type` is present.

`hostIds`, `status`, and `spaceId` are **not** editable here — manage hosts via the [host endpoints](/v8/api-reference/events/add-host), cancel via [Cancel Event](/v8/api-reference/events/cancel-event); the space is immutable.

Images can be curated in one request: a new `coverFile` **replaces** the existing cover, `gallery` files are **appended** after the event's existing images, and `removeFileIds` deletes existing event files by File ID. Any image operation requires the `files-images` bundle.

When a time field (`startTime`/`endTime`/`timezone`) or a location field (`location`/`url`/`venueName`/`address`) actually changes, an `event-updated` notification is fanned out to the `going`/`maybe` RSVP holders who can still see the event (best-effort, requires the `notifications` bundle).

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event to update.
</ParamField>

## Body Parameters

<ParamField body="title" type="string">Event title. 1–300 characters.</ParamField>
<ParamField body="description" type="string">New description.</ParamField>
<ParamField body="startTime" type="string">New ISO start datetime.</ParamField>
<ParamField body="endTime" type="string">New ISO end datetime.</ParamField>
<ParamField body="timezone" type="string">New IANA timezone.</ParamField>
<ParamField body="type" type="string">`"online"`, `"physical"`, or `"hybrid"`. Re-triggers location validation.</ParamField>
<ParamField body="url" type="string">Join/stream URL.</ParamField>
<ParamField body="venueName" type="string">Venue name.</ParamField>
<ParamField body="address" type="string">Street address.</ParamField>
<ParamField body="location" type="{ latitude: number; longitude: number }">New coordinates. On multipart requests, send as a JSON string.</ParamField>
<ParamField body="visibility" type="string">`"public"`, `"members"`, or `"invite"`.</ParamField>
<ParamField body="capacity" type="number">New capacity (positive integer).</ParamField>
<ParamField body="allowMaybe" type="boolean">Whether `"maybe"` RSVPs are allowed.</ParamField>
<ParamField body="guestListVisible" type="boolean">Whether everyone who can see the event can view the guest list. When `false`, only hosts who are active members of the event's space and not banned in it or a space above it and the space's admins and moderators can.</ParamField>
<ParamField body="metadata" type="object">Arbitrary key-value data. Up to 1 MB.</ParamField>

<ParamField body="removeFileIds" type="string[]">
  Files to remove from the event: its gallery images and/or the current cover (`coverImageId`). Removing the cover clears it (`coverImageId` becomes `null`). Each file and its blobs are deleted. Works alone or with uploads in the same request; uploading a new cover while listing the old one is a plain replace. On a multipart request, send it as a JSON string (`'["<fileId>"]'`). Any id that isn't one of this event's files refuses the whole request with `400 event/invalid-remove-file-ids`.
</ParamField>

<ParamField body="coverFile" type="file">
  New cover image (replaces the current cover; the old cover file is deleted). Multipart file field. Requires `coverFile.options`. Adding a cover doesn't move the gallery images.
</ParamField>

<ParamField body="coverFile.options" type="string">
  JSON-stringified image-processing options for the new cover.
</ParamField>

<ParamField body="gallery" type="file[]">
  Gallery images to append (up to 20 in a request). Multipart file field. Requires `gallery.options`.
</ParamField>

<ParamField body="gallery.options" type="string">
  JSON-stringified image-processing options for the appended gallery images.
</ParamField>

<ParamField body="actingUserId" type="string">
  Required with a service key: the user this request acts as. It has exactly that user's powers, so it is refused unless they are a host of the event with active membership of its space, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Event](/v8/data-models/event) object.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "event/invalid-body", "param": "actingUserId" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Wrong Location — 400">
    `actingUserId` was sent in the query string. On this endpoint every field goes in the request body.
    ```json
    {
      "error": "`actingUserId` goes in the request body on this endpoint.",
      "code": "event/wrong-location",
      "param": "actingUserId"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `removeImageIds` or `cover.options`. Files are removed with `removeFileIds`, and the cover is uploaded as `coverFile` with its options in `coverFile.options`. `param` names the field.

    ```json
    {
      "error": "`removeImageIds` was renamed to `removeFileIds`.",
      "code": "event/unsupported-param",
      "param": "removeImageIds"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    The event doesn't exist, or the caller can't [see it](/v8/data-models/event#visibility) and isn't one of its hosts.
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden (not a host) — 403">
    ```json
    { "error": "Only a host of this event may update it.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Host Not an Active Member — 403">
    The caller is a host, but the event is in a space they aren't an active member of, or they are banned in it or a space above it. One body for every case.
    ```json
    { "error": "Hosts must be active members of this event's space, and not banned from it or a space above it, to do this.", "code": "event/not-space-member" }
    ```
  </Accordion>
  <Accordion title="Bundle Not Installed — 403">
    Returned when images are uploaded or `removeFileIds` is sent on a project without the files-images bundle. `missingTables` lists the tables that aren't installed and `bundleId` the bundle to install. While the bundle is still being installed, the response is `503 database/tables-provisioning` instead. See [Bundles](/v8/bundles).
    ```json
    { "error": "Event cover/gallery images require the files-images bundle. Enable it for this project.", "code": "database/tables-not-available", "missingTables": ["Files", "Images"], "bundleId": "files-images", "dashboardUrl": "https://…/<projectId>/database" }
    ```
  </Accordion>
  <Accordion title="Invalid File Ids — 400">
    `removeFileIds` names a file that isn't one of this event's files. `invalidIds` lists those ids. Checked before anything is uploaded, so nothing is stored or removed.
    ```json
    { "error": "Some removeFileIds do not belong to this event.", "code": "event/invalid-remove-file-ids", "param": "removeFileIds", "invalidIds": ["9b2f…"] }
    ```
    A `removeFileIds` that isn't an array of file ids gets `400 event/invalid-body` instead.
  </Accordion>
  <Accordion title="Image Too Large — 413">
    ```json
    { "error": "`coverFile` is over the 50 MB per-file limit.", "code": "event/file-too-large", "param": "coverFile" }
    ```
    A file is over 50 MB. `param` names its field.
  </Accordion>
  <Accordion title="Invalid Image — 422">
    ```json
    { "error": "File \"cover.jpg\" is not a valid image.", "code": "event/invalid-image", "param": "coverFile" }
    ```
    A cover or gallery file can't be read as an image. `param` is `coverFile` or `gallery`.
  </Accordion>
  <Accordion title="Missing Image Options — 400">
    A cover or gallery image was uploaded without its options. `param` is `coverFile.options` or `gallery.options`.
    ```json
    { "error": "`coverFile.options` is required when a cover image is uploaded.", "code": "event/missing-image-options", "param": "coverFile.options" }
    ```
  </Accordion>
  <Accordion title="Upload Refused — 400 / 413">
    A file was refused as the body was read: `event/unsupported-file-type` or `event/unexpected-file-field` (a file in another field, `cover` included, or a second file in `coverFile`), with `param` naming the field when there is one, or `413 event/too-many-files` for more than 20 files in the request. A body over 250 MB gets `413 request/body-too-large`; one that can't be read at all gets `request/invalid-multipart` or `request/field-too-large`. See [Upload errors](/v8/api-reference/getting-started#upload-errors).
  </Accordion>
</AccordionGroup>
