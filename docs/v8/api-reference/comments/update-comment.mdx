---
title: "Update Comment"
api: "PATCH /v8/:projectId/comments/:commentId"
description: "Edit a comment's content and/or metadata"
---

Updates a comment's content, its metadata, or both. Only the comment's author may update it: with their own access token, or with a service key naming them in `actingUserId` — the request then runs exactly as theirs, blocks included. A comment with no author belongs to your app: only a service key naming nobody may update it, and a user token gets `403`.

**Authentication required.**

## Path Parameters

<ParamField path="commentId" type="string" required>
  The UUID of the comment to update.
</ParamField>

## Body Parameters

`content` and `metadata` are individually optional, but **at least one must be provided**.

<ParamField body="content" type="string">
  The new text content for the comment. Leading and trailing whitespace is trimmed. Cannot be empty or only whitespace. Omit to leave the existing content untouched.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary JSON metadata, up to 10 KB (10,240 bytes) as JSON. **Replaces** the stored metadata wholesale rather than merging into it.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only: the user this edit acts as. Required when the comment has an author: name the author, and the request runs exactly as their own access token's (naming anyone else gets what their token gets). Leave it out only for an app-owned comment (no author). A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 comment/acting-user-not-allowed`).
</ParamField>

## Deleted and removed comments

A comment its author deleted, and a comment a moderator removed, can't be edited: the request returns `404 comment/not-found`. This includes the author of a moderator-removed comment, who still sees it in full.

## Blocks

Editing changes content in someone else's space, so when the `moderation` bundle is installed, editing is refused with `404 comment/not-found` when the author of the comment's entity, or the author of the comment it replies to, has blocked the comment's author. Deleting the comment is still allowed.

A comment on an entity whose author has blocked the caller is hidden from them, so when the caller isn't the comment's author, the edit is refused with `404 comment/not-found` — the same response as a missing comment, not a `403`. This check also applies only when the `moderation` bundle is installed. A service key acting as a user is subject to both checks exactly as that user.

## Response

Returns the updated [Comment](/v8/data-models/comment) object in full, as the caller sees it.

## Error Responses

<AccordionGroup>
  <Accordion title="Missing token — 401">
    No `Authorization` header was sent. The body is `text/plain` (`Unauthorized`), not JSON. An expired or invalid token returns `403` instead — see [Authentication](/v8/api-reference/authentication).
  </Accordion>
  <Accordion title="Invalid Params — 400">
    Returned when `commentId` isn't a valid UUID.

    ```json
    { "error": "Invalid comment id: expected a UUID.", "code": "comment/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    Returned when neither `content` nor `metadata` is supplied, when `content` is an empty string or only whitespace, when `metadata` isn't an object, or when `metadata` is larger than 10 KB.

    ```json
    { "error": "Either content or metadata must be provided", "code": "comment/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Rejected by Webhook — 400">
    Returned when your project's `comment.updated` [validation webhook](/v8/webhooks#validation-events-blocking) doesn't approve the edit. Nothing is changed. `error` is the `message` your webhook responded with, when it sent one.

    ```json
    { "error": "Validation rejected", "code": "comment/webhook-validation-failed" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Returned when the comment doesn't exist, when its author deleted it or a moderator removed it (see [Deleted and removed comments](#deleted-and-removed-comments)), or when a block refuses the edit — including when the caller isn't the comment's author and the author of the comment's entity has blocked them (see [Blocks](#blocks)).

    ```json
    { "error": "Comment not found", "code": "comment/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    Returned when the acting user isn't the comment's author, or when a user token, or a service key naming a user, edits a comment with no author.

    ```json
    { "error": "You do not have permission to update this comment.", "code": "comment/forbidden" }
    ```
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId` for a comment that has an author. Name the author: the request then runs exactly as their own.

    ```json
    { "error": "A service key must send actingUserId to change a record that has an author: the request then acts as that user.", "code": "comment/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "comment/acting-user-not-allowed" }
    ```
  </Accordion>
</AccordionGroup>
