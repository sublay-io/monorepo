The `comments` module provides full server-side control over comments on entities. Use it to seed content, build moderation pipelines, or integrate comment data into your backend logic.

---

### createComment

Creates a new comment on an entity.

```typescript
const comment = await sublay.comments.createComment({
  entityId: "ent_xyz789",
  userId: "usr_abc123",
  content: "Great post!",
});
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID to comment on.
</ParamField>

<ParamField body="userId" type="string" required>
  The Sublay user ID of the comment author.
</ParamField>

<ParamField body="content" type="string">
  The comment text content.
</ParamField>

<ParamField body="foreignId" type="string">
  Your application's identifier for this comment.
</ParamField>

<ParamField body="gif" type="object">
  A GIF to attach to the comment (`GifData`), or `null`.
</ParamField>

<ParamField body="mentions" type="array">
  User mentions embedded in the comment.
</ParamField>

<ParamField body="parentId" type="string">
  The Sublay comment ID of the parent, for creating a reply.
</ParamField>

<ParamField body="referencedCommentId" type="string">
  A comment being directly quoted or referenced.
</ParamField>

<ParamField body="attachments" type="array">
  File or media attachments on the comment.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary metadata attached to the comment.
</ParamField>

<ParamField body="createdAt" type="Date">
  A `Date` used to backdate the comment's creation time.
</ParamField>

<ParamField body="updatedAt" type="Date">
  A `Date` used to backdate the comment's last update time.
</ParamField>

**Returns** — `Promise<Comment>`

When the server refuses the comment, the call rejects with its error — among them `403 comment/parent-deleted` and `403 comment/parent-removed` for a reply to a deleted or removed comment, `403 comment/referenced-deleted` and `403 comment/referenced-removed` for a quote of one, and `409 comment/foreign-id-taken` for a `foreignId` already in use. See [Create Comment → Error Responses](/v8/api-reference/comments/create-comment#error-responses) for the full list.

### fetchManyComments

Fetches one level of a comment thread, cursor-paginated: an entity's top-level comments (`entityId`) or a comment's direct replies (`parentId`). Exactly one of the two is required; the props type refuses neither and both. Optionally nests a few levels of replies inside each returned comment. See [Fetch Many Comments](/v8/api-reference/comments/fetch-many-comments) for the full contract — placeholders, block flags and the request size limit.

```typescript
const { data, pagination } = await sublay.comments.fetchManyComments({
  entityId: "ent_xyz789",
  sortBy: "top",
  limit: 20,
  include: "user",
  replyDepth: 2, // also bring 2 levels of replies…
  replyLimit: 3, // …up to 3 per comment
});

// Next page
const next = await sublay.comments.fetchManyComments({
  entityId: "ent_xyz789",
  sortBy: "top",
  limit: 20,
  cursor: pagination.nextCursor,
});
```

For a user's comments across entities, use [`users.fetchCommentsByUserId`](/v8/node-sdk/users#fetchcommentsbyuserid).

<Note>
  Service-key reads have no signed-in viewer, so they are anonymous: `isAuthorBlocked` and `isUnavailable` are always `false`, `userReaction` isn't populated, and no block rule applies. Moderator-removed comments come back as placeholders.
</Note>

<ParamField body="entityId" type="string">
  Fetch this entity's top-level comments. Pass this or `parentId`, not both.
</ParamField>

<ParamField body="parentId" type="string">
  Fetch this comment's direct replies. Pass it without `entityId`: the parent decides the entity.
</ParamField>

<ParamField body="limit" type="number">
  How many comments at the level being fetched. Server default `10`, max `100`.
</ParamField>

<ParamField body="cursor" type="string | null">
  `pagination.nextCursor` from the previous response, passed as returned. Omit it, or pass `null`, for the first page. Send the same `sortBy`, `sortDir` and `sortByReaction` as the request that returned it.
</ParamField>

<ParamField body="sortBy" type='"createdAt" | "top" | "controversial"'>
  Sort for the level being fetched. `"top"` ranks by the raw count of `sortByReaction`. Server default `"createdAt"`.
</ParamField>

<ParamField body="sortDir" type='"asc" | "desc"'>
  Applies to `"createdAt"` and `"top"`; not accepted with `"controversial"`, which ranks one way only. Server default `"desc"`.
</ParamField>

<ParamField body="sortByReaction" type="ReactionType">
  With `sortBy: "top"` only: the reaction to rank by. Server default `"upvote"`.
</ParamField>

<ParamField body="replyDepth" type="number">
  Levels of replies to nest under each returned comment (`0`–`5`). Server default `0`.
</ParamField>

<ParamField body="replyLimit" type="number">
  Replies per comment in the nested levels (at least `1`). Server default `3`.
</ParamField>

<ParamField body="replySortBy" type='"createdAt" | "top" | "controversial"'>
  Sort for the nested levels. Defaults to `sortBy`.
</ParamField>

<ParamField body="replySortDir" type='"asc" | "desc"'>
  Sort direction for the nested levels. Defaults to `sortDir`. Not sent when the nested sort is `"controversial"`.
</ParamField>

<ParamField body="replySortByReaction" type="ReactionType">
  The reaction the nested levels rank by, when their sort is `"top"`.
</ParamField>

<ParamField body="include" type='"user" | "grants" | ("user" | "grants")[]'>
  Related data to populate, at every level.
</ParamField>

<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<CursorPaginatedResponse<Comment>>` — `{ data, pagination: { nextCursor, hasMore } }`. With `replyDepth` above `0`, each comment carries nested `replies` in the same shape.

### addReaction

Adds a reaction from a user to a comment.

```typescript
const comment = await sublay.comments.addReaction({
  commentId: "cmt_abc123",
  userId: "usr_abc123",
  reactionType: "like",
});
```

<ParamField body="commentId" type="string" required>
  The Sublay comment ID.
</ParamField>

<ParamField body="userId" type="string" required>
  The Sublay user ID of the reactor.
</ParamField>

<ParamField body="reactionType" type="ReactionType" required>
  One of: `"upvote"`, `"downvote"`, `"like"`, `"love"`, `"wow"`, `"sad"`, `"angry"`, `"funny"`.
</ParamField>

**Returns** — `Promise<Comment>` — the updated comment, as the reacting user sees it: `userReaction` and `reactionCounts` reflect the new reaction.

### removeReaction

Removes a user's existing reaction from a comment.

```typescript
const comment = await sublay.comments.removeReaction({
  commentId: "cmt_abc123",
  userId: "usr_abc123",
});
```

<ParamField body="commentId" type="string" required>
  The Sublay comment ID.
</ParamField>

<ParamField body="userId" type="string" required>
  The Sublay user ID whose reaction to remove.
</ParamField>

**Returns** — `Promise<Comment>` — the updated comment, as that user sees it. When the user has no reaction on the comment, the comment comes back unchanged.

### getUserReaction

Checks what reaction (if any) a specific user has left on a comment.

```typescript
const { reactionType } = await sublay.comments.getUserReaction({
  commentId: "cmt_abc123",
  userId: "usr_abc123",
});
// reactionType is "like" | "upvote" | ... | null
```

<ParamField body="commentId" type="string" required>
  The Sublay comment ID.
</ParamField>

<ParamField body="userId" type="string" required>
  The Sublay user ID to check.
</ParamField>

**Returns** — `Promise<{ reactionType: ReactionType | null }>`. Rejects with `404 comment/not-found` when the comment doesn't exist, or is on an entity whose author has blocked the user (the user's own comments excepted).
