---
title: "Fetch Spaces"
api: "GET /v8/:projectId/spaces"
description: "Get a paginated list of public spaces with filtering and sorting"
---

Fetches a paginated list of public spaces: the space directory. By default it lists top-level spaces (spaces with no parent); the `parentSpaceId` filter lists a space's sub-spaces or every level instead. Supports text search. Authentication is optional; when there is a viewer (the signed-in user, or the user a service key names in `actingUserId`), each space carries their `isMember` flag.

<Note>
  This is a discovery surface: only `public` spaces are listed, for every caller. Spaces with `visibility` of `"unlisted"` or `"private"` are never listed here, not even to their members (they stay reachable by direct link via [Fetch Space by Slug](/v8/api-reference/spaces/fetch-space-by-slug) or [by Short ID](/v8/api-reference/spaces/fetch-space-by-short-id)). To list the spaces a user is a member of, whatever their visibility, use [Fetch User Spaces](/v8/api-reference/spaces/fetch-user-spaces). See [Space visibility](/v8/data-models/space#visibility).
</Note>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as. The page is exactly what that user's own access token would get (their membership on each space). Leave it out for the anonymous view. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 space/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number">
  Page number. Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page.
</ParamField>

<ParamField query="sortBy" type="string">
  Sort order: `"createdAt"` (when the space was created), `"alphabetical"` (by name) or `"members"` (by active member count). Defaults to `"members"`.
</ParamField>

<ParamField query="sortDir" type="string">
  Direction, `"asc"` or `"desc"` (either case), for any `sortBy`. Left out: A–Z for `"alphabetical"`, otherwise newest / most first.
</ParamField>

<ParamField query="query" type="string">
  Free-text search term, matched as a case-insensitive substring. Trimmed; a blank value returns `400 space/invalid-query`. Leave it out for no text filtering.
</ParamField>

<ParamField query="searchFields" type="string">
  The one field `query` is matched against: `"slug"`, `"name"` or `"description"`. Left out, `query` matches the slug, the name or the description. Values match exactly; any other value returns `400 space/invalid-query`.
</ParamField>

<ParamField query="parentSpaceId" type="string">
  Which level of the space tree to list:
  - Left out, sent empty, or `none`: top-level spaces only (spaces with no parent). This is the default.
  - A space id: that space's public direct sub-spaces. This is how to page through a space's sub-spaces (add `sortBy=alphabetical` to order them A–Z by name). An id that matches no space returns an empty page, not a 404.
  - `any`: spaces at every level.

  `null` and `undefined` are refused with `400 space/unsupported-param` (see [Saying "no value"](/v8/authentication#saying-no-value)). `none` and `any` match exactly (`ANY` is refused). Any other value that isn't a space id returns `400 space/invalid-query`.
</ParamField>

<ParamField query="nsfwFilter" type="string">
  Filter by each space's `nsfwEffective` (its own flag or any ancestor's): `"include-all"` (default) lists every space, `"exclude"` leaves effective-NSFW spaces out, and `"only"` lists only them. See [Space NSFW flagging](/v8/data-models/space#nsfw-flagging).
</ParamField>

<ParamField query="include" type="string">
  Associations to include, as a comma-separated value or repeated params. The only value is:
  - `files` — the processed `avatarFile` and `bannerFile` objects on each space (requires the `files-images` bundle)

  Matching ignores case. An unknown value returns `400 space/invalid-query`.
</ParamField>

## Response

<ResponseField name="data" type="Space[]">
  Array of [Space](/v8/data-models/space) objects.
</ResponseField>

<ResponseField name="pagination" type="object">
  <Expandable title="properties">
    <ResponseField name="page" type="number">Current page.</ResponseField>
    <ResponseField name="pageSize" type="number">Results per page.</ResponseField>
    <ResponseField name="totalPages" type="number">Total number of pages.</ResponseField>
    <ResponseField name="totalItems" type="number">Total matching spaces.</ResponseField>
    <ResponseField name="hasMore" type="boolean">Whether more pages exist.</ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Unsupported sort — 400">
    `sortBy=newest` is rejected with a pointer to its replacement, `sortBy=createdAt`.

    ```json
    {
      "error": "`sortBy=newest` isn't supported in v8. Use `sortBy=createdAt`, which lists newest first by default.",
      "code": "space/unsupported-param",
      "param": "sortBy"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported parentSpaceId value — 400">
    `parentSpaceId=null` and `parentSpaceId=undefined` are rejected with the spelling to use instead.

    ```json
    {
      "error": "`parentSpaceId=null` isn't supported. Use `parentSpaceId=none` for top-level spaces (the default), or `parentSpaceId=any` for every level.",
      "code": "space/unsupported-param",
      "param": "parentSpaceId"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported memberOf — 400">
    `memberOf`, in any form, is rejected with a pointer to [Fetch User Spaces](/v8/api-reference/spaces/fetch-user-spaces), which lists the spaces a user is a member of.

    ```json
    {
      "error": "`memberOf` isn't supported in v8. To list the spaces a user is a member of, use `GET /spaces/user-spaces`.",
      "code": "space/unsupported-param",
      "param": "memberOf"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported child-spaces route — 400">
    `GET /spaces/:spaceId/children` is not a route. It answers with a pointer to this endpoint's `parentSpaceId` filter.

    ```json
    {
      "error": "`GET /spaces/:spaceId/children` isn't supported in v8. List a space's sub-spaces with `GET /spaces?parentSpaceId=<spaceId>`, adding `sortBy=alphabetical` to order them A–Z by name.",
      "code": "space/unsupported-route"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported search parameter — 400">
    `searchSlug`, `searchName`, `searchDescription` and `searchAny` are rejected with a pointer to `query` and `searchFields`. `param` names the parameter sent.

    ```json
    {
      "error": "`searchName` isn't supported in v8. Search with `query` and `searchFields=name`.",
      "code": "space/unsupported-param",
      "param": "searchName"
    }
    ```

    The `error` names the replacement for each:
    - `searchSlug`: `query` with `searchFields=slug`
    - `searchName`: `query` with `searchFields=name`
    - `searchDescription`: `query` with `searchFields=description`
    - `searchAny`: `query` without `searchFields`, which matches the slug, name and description
  </Accordion>
  <Accordion title="Invalid query — 400">
    Returned with code `space/invalid-query` for invalid values — for example an unknown `sortBy`, `sortDir`, `searchFields` or `include` value, or a blank `query`. `error` names the first problem found.

    ```json
    { "error": "include: Unknown include `members`. Allowed: files.", "code": "space/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>

See also: [useFetchManySpaces](/v8/hooks/spaces/use-fetch-many-spaces)
