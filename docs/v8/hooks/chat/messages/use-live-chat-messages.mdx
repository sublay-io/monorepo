## Overview

The live, canonical view of a conversation's messages. Results are stored in Redux and kept in sync by `ChatProvider` socket events, so new messages, edits, reactions and reply-count changes appear in real time, and state is shared with `useSendMessage` (optimistic inserts), unread tracking and reconnect catch-up. Can be used for the main message stream or for a specific thread (by passing `parentMessageId`).

<Note>Requires `ChatProvider` in the component tree.</Note>

<Tip>For a read-only or **filtered** query (e.g. "only messages that have replies") that should not be touched by live socket traffic, use [`useFetchManyChatMessages` / `useFetchManyChatMessagesWrapper`](/v8/hooks/chat/messages/use-fetch-many-chat-messages) instead. The live hook intentionally does not take a `filters` prop.</Tip>

## Usage Example

```tsx
import { useLiveChatMessages } from "@sublay/react-js";

function MessageList({ conversationId }: { conversationId: string }) {
  const { messages, loading, hasMore, loadMore } = useLiveChatMessages({
    conversationId,
  });

  return (
    <div>
      {hasMore && (
        <button onClick={loadMore} disabled={loading}>
          Load older messages
        </button>
      )}
      {messages.map((msg) => (
        <div key={msg.id}>
          {msg.moderationStatus === "removed" && !msg.user ? (
            <em>Message removed</em>
          ) : (
            <>
              <strong>{msg.user?.name ?? "Deleted user"}</strong>:{" "}
              {msg.userDeletedAt ? <em>Message deleted</em> : msg.content}
            </>
          )}
        </div>
      ))}
    </div>
  );
}
```

## Props

<ParamField body="conversationId" type="string" required>
  The ID of the conversation to load messages for.
</ParamField>

<ParamField body="parentMessageId" type="string | null">
  When provided, loads thread replies for this parent message ID instead of the main stream. Replies are sorted ascending (oldest first); `loadMore` fetches newer replies.
</ParamField>

<ParamField body="limit" type="number">
  Number of messages per page. Defaults to `50`.
</ParamField>

<ParamField body="include" type="ChatMessageListIncludeParam">
  Fields to add to each message, as a single value or an array:
  - `"files"` — the `files` field. Left out by default to keep payloads small.
  - `"grants"` — the [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary) at `message.grants`: `{ total, count, viewerTotal }` over positive grants. Populated by the `reputation` bundle; on a project without it the summary comes back zero-filled rather than missing.
</ParamField>

## Returns

<ResponseField name="messages" type="ChatMessage[]">
  The loaded messages in ascending order (oldest first). See [ChatMessage](/v8/data-models/chat-message).
</ResponseField>

<ResponseField name="loading" type="boolean">
  `true` while a fetch is in progress.
</ResponseField>

<ResponseField name="error" type="Error | null">
  The last load failure, or `null`. Cleared when the next load starts; `loadMore()` retries it. Shared by every mounted hook showing the same conversation (or the same thread).
</ResponseField>

<ResponseField name="hasMore" type="boolean">
  `true` while `loadMore()` has something to fetch: a next page, or a load that failed.
</ResponseField>

<ResponseField name="loadMore" type="() => Promise<void>">
  Loads the next page in reading order. For the main stream: messages older than the oldest currently loaded. For threads (`parentMessageId` set): the next page of newer replies.
  Retries the load that failed instead, when there is one (a failed first page included). Does nothing while a page is loading or when there is nothing more. Never rejects: a failure lands in `error`.
</ResponseField>

<ResponseField name="refetch" type="() => Promise<void>">
  Reloads from the first page. For the main stream: the latest page replaces the loaded messages, keeping optimistic messages and newer live ones. For threads: starts over from the thread's first reply. Never rejects: a failure lands in `error`.
</ResponseField>

## Notes

- New messages that arrive via the socket (`message:created`) are added to the store automatically — no manual refetch needed. Thread replies go to their thread, never to the main stream.
- After the socket reconnects, a thread loads the replies sent while it was offline. The main stream's catch-up is done by `ConversationProvider` (see [Missed Messages After a Reconnect](/v8/sdk/chat/real-time#missed-messages-after-a-reconnect)).
- For integration guidance, see [Chat: Messages](/v8/sdk/chat/messages).
