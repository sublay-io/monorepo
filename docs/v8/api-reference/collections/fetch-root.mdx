---
title: "Fetch Root Collection"
api: "GET /v8/:projectId/collections/root"
description: "Get or create the current user's root collection"
---

Returns the root collection for the authenticated user. If no root collection exists yet, one is created automatically with the name `"root"`.

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their root collection is returned. A user token always acts as its own user and must not send it (`400 collection/acting-user-not-allowed`).
</ParamField>

## Response

Returns a [Collection](/v8/data-models/collection) object with `parentId: null` and `isRoot: true`.

<Note>
  This endpoint is the entry point for the collections system. Call it once on load to initialize the user's collection tree. Sub-collections are fetched separately via the sub-collections endpoint.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Server error", "code": "collection/server-error" }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "collection/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "collection/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "collection/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "collection/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "collection/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
