## Overview

`useUpdateSpace` returns a callable function for updating a space. Only space admins can update a space. Supports replacing the avatar and banner images (`avatarFile`, `bannerFile`) and removing them (`removeFileIds`).

<Note>When using `SpaceProvider`, prefer calling `updateSpace` from `useSpace` — it handles state updates automatically.</Note>

## Usage Example

```tsx
import { useUpdateSpace } from "@sublay/react-js";

function SpaceSettings({ spaceId }: { spaceId: string }) {
  const updateSpace = useUpdateSpace();

  const handleSave = async (name: string, description: string) => {
    const updated = await updateSpace({
      spaceId,
      update: { name, description },
    });
    console.log("Updated:", updated.name);
  };

  const removeAvatar = async (avatarFileId: string) => {
    await updateSpace({ spaceId, update: { removeFileIds: [avatarFileId] } });
  };
}
```

## Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space to update.
</ParamField>

<ParamField path="update" type="object" required>
  Fields to update. All fields are optional.

  <Expandable title="update fields">
    <ParamField path="name" type="string">
      New display name (3–100 characters after trimming). Leave it out to keep the current name; a name can't be removed.
    </ParamField>
    <ParamField path="slug" type="string | null">
      New URL slug. Pass `null` to remove it.
    </ParamField>
    <ParamField path="description" type="string | null">
      New description. Pass `null` to remove it.
    </ParamField>
    <ParamField path="readingPermission" type='"anyone" | "members"'>
      Updated reading permission.
    </ParamField>
    <ParamField path="postingPermission" type='"anyone" | "members" | "team"'>
      Updated posting permission: `"anyone"`, `"members"` (active members), or `"team"` (the space's active admins and moderators).
    </ParamField>
    <ParamField path="visibility" type='"public" | "unlisted" | "private"'>
      Updated visibility: who can find and see the space (and the spaces under it). Independent of `readingPermission`. See [Space visibility](/v8/data-models/space#visibility).
    </ParamField>
    <ParamField path="nsfw" type="boolean">
      Updated NSFW own-flag. Toggling it recomputes this space's effective NSFW and cascades it top-down to every descendant space (and, live, to their entities) in the same transaction. See [Space NSFW flagging](/v8/data-models/space#nsfw-flagging).
    </ParamField>
    <ParamField path="requireJoinApproval" type="boolean">
      Updated join approval requirement.
    </ParamField>
    <ParamField path="metadata" type="Record<string, any>">
      Updated metadata.
    </ParamField>
    <ParamField path="avatarFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
      New avatar image, replacing the current one. `file` is a `File` or `Blob`, or a React Native file `{ uri, name, type? }`; `options` must include `mode` (see [Upload Image](/v8/api-reference/storage/upload-image)). With an image, the request is sent as `multipart/form-data`.
    </ParamField>
    <ParamField path="bannerFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
      New banner image, replacing the current one; same shape as `avatarFile`.
    </ParamField>
    <ParamField path="removeFileIds" type="string[]">
      Files to remove: the space's `avatarFileId` and/or `bannerFileId`. Removing one clears that image. Any other id refuses the whole update (`400 space/invalid-remove-file-ids`).
    </ParamField>
  </Expandable>
</ParamField>

<Warning>
  With `avatarFile` or `bannerFile`, the request is `multipart/form-data`, which can't carry `null`. A `null` field next to a file throws before anything is sent (`` `slug: null` can't be sent with a file ``); clear the field in a separate call without a file.
</Warning>

## Returns

Returns the updated [Space](/v8/data-models/space) object plus `memberPermissions`: what the user may do in the space after the update (see [SpaceMemberPermissions](/v8/data-models/space#spacememberpermissions)). It carries no `parentSpace` or `childSpaces`. Inside a `SpaceProvider` for the same space, the provider's space takes the update and the new `memberPermissions`, keeping its hierarchy.
