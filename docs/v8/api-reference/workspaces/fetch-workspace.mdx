---
title: "Fetch Workspace"
api: "GET /v8/:projectId/workspaces/:id"
description: "Read a single workspace, visibility-filtered"
---

Returns a single [Workspace](/v8/data-models/workspace), filtered by the caller's reach-visibility — a caller never sees a node their authority doesn't reach. A caller with no user — anonymous, or a service key that names nobody — always gets `404`.

## Path Parameters

<ParamField path="id" type="string" required>
  The workspace UUID.
</ParamField>

## Query Parameters

<ParamField query="include" type="string">
  Include flags, as a comma-separated value or repeated params. The only value is `memberCount`: it adds the workspace's **direct** member count as `memberCount` on the object. Matching ignores case; an unknown value returns `400 workspace/invalid-query`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service keys only — the user to act as. Enforced: visibility resolves against the named user, so a key acting as someone with no relation to this workspace gets the same `404` that user would. Omit it and the key gets exactly the anonymous view: `404`. `actingUserId: ""` or `null` is a `400`, an attempt to name someone that names no one. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 workspace/acting-user-not-allowed`). See [Acting on behalf of a user](/v8/sdk/workspaces/overview#acting-on-behalf-of-a-user).
</ParamField>

## Response

Returns the [Workspace](/v8/data-models/workspace) object.

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found / Not Visible — 404">
    ```json
    { "error": "Workspace not found.", "code": "workspace/not-found" }
    ```
    The workspace does not exist, or the caller (or the user named by `actingUserId`) has no relation to it. Always returned to an anonymous request and to a service key that names nobody.
  </Accordion>
  <Accordion title="Invalid Path Parameter — 400">
    ```json
    { "error": "Invalid workspace id: expected a UUID.", "code": "workspace/invalid-params" }
    ```
    Every path id on the workspaces bundle is checked for UUID shape before the route runs, so a malformed one is a plain `400` rather than a `500` from the database.
  </Accordion>
  <Accordion title="Unknown Include — 400">
    ```json
    { "error": "include: Unknown include `members`. Allowed: memberCount.", "code": "workspace/invalid-query" }
    ```
    An `include` value outside `memberCount`. Matching ignores case.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "workspace/acting-user-not-allowed" }
    ```
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
  </Accordion>
  <Accordion title="Body Not Allowed — 400">
    ```json
    { "error": "A GET request takes no body: send its fields in the query string. Received: `actingUserId`.", "code": "workspace/body-not-allowed", "params": ["actingUserId"] }
    ```
    A `GET` takes every field, `actingUserId` included, in the query string, so any request body is refused: a JSON object with keys, a non-empty array, or a non-JSON payload such as multipart (then `params` is omitted). An absent body and `{}` pass.
  </Accordion>
  <Accordion title="User Not Found — 404">
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "workspace/user-not-found" }
    ```
    Returned when a service key names an `actingUserId` that isn't a user in this project.
  </Accordion>
</AccordionGroup>
