---
title: "Withdraw RSVP"
api: "DELETE /v8/:projectId/events/:eventId/rsvp"
description: "Remove the caller's RSVP from an event"
---

Removes the caller's RSVP. The RSVP row is deleted and the matching `rsvpCounts` entry is decremented. Requires authentication, and the caller must be able to [see the event](/v8/data-models/event#visibility) (otherwise `404`).

Withdrawing is idempotent — withdrawing when there is no RSVP succeeds and changes nothing.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose RSVP is withdrawn. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the [Event](/v8/data-models/event) with refreshed `rsvpCounts`.

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Not Found / No Access — 404">
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
</AccordionGroup>
