---
title: "Request Connection"
api: "POST /v8/:projectId/users/:userId/connection"
description: "Send a connection request to a user"
---

Sends a connection request from the authenticated user to the specified user. An optional message can be included. A notification is sent to the receiving user.

<Note>
  **Requires the `connections` bundle.** A project without the connections bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the user to send a connection request to.
</ParamField>

## Body Parameters

<ParamField body="message" type="string">
  Optional message to include with the connection request.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who sends the connection request. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `201` with the created connection record:

<ResponseField name="id" type="string">
  Unique connection record ID (UUID).
</ResponseField>

<ResponseField name="status" type="string">
  Always `"pending"` for a new request.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of when the request was sent.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Self-Request — 400">
    ```json
    {
      "error": "A user cannot send a connection request to themselves.",
      "code": "connection/self-request"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    A service key named an `actingUserId` that isn't a user in this project:

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```

    Otherwise, the user to connect with doesn't exist:

    ```json
    {
      "error": "One or both users involved in the connection do not exist.",
      "code": "connection/user-not-found"
    }
    ```
  </Accordion>
  <Accordion title="Already Pending — 409">
    ```json
    {
      "error": "A connection request is already pending between these users.",
      "code": "connection/request-pending"
    }
    ```
  </Accordion>
  <Accordion title="Already Connected — 409">
    ```json
    {
      "error": "Users are already connected.",
      "code": "connection/already-connected"
    }
    ```
  </Accordion>
  <Accordion title="Request Previously Declined — 409">
    ```json
    {
      "error": "Connection request was declined. Only the receiver can initiate a new request.",
      "code": "connection/request-declined"
    }
    ```
  </Accordion>
</AccordionGroup>
