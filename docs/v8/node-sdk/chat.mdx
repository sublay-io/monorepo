The `chat` module is the server-side client for Sublay's messaging: direct and group conversations, messages (with GIFs, mentions, threads, quotes, and file attachments), membership, reactions, read state, and reporting.

## Acting on behalf of a user

Your service key has no implicit session user, so **every** chat call takes the user it acts as, in `actingUserId`. Where a function also takes a `userId` (`createDirectConversation`, `addMember`, `removeMember`, `changeMemberRole`), that `userId` is the *target* user. See [Acting on behalf of a user](/v8/node-sdk/overview#acting-on-behalf-of-a-user).

<Warning>
  **Membership is enforced against the acting user (resolve-then-check).** Sublay
  resolves the named user first, then runs the normal conversation checks against
  *that* user. So you can only act as a user who is genuinely a member of the
  conversation, and admin-only actions (delete/update conversation, add/remove
  members, change roles) require that user to be a group **admin**. A service key
  cannot post into a conversation as a user who isn't in it.
</Warning>

<Note>
  Omitting `actingUserId` returns `400 chat/missing-user-id`.
</Note>

## Conversations

### listConversations

Lists the acting user's conversations, newest activity first. Uses **cursor pagination** — pass `pagination.nextCursor` from the previous page as `cursor` to get the next one.

```typescript
const { data: conversations, pagination } = await sublay.chat.listConversations({
  actingUserId: "usr_abc123",
  types: ["direct", "group"],
  limit: 20,
});

// Next page (nextCursor is null on the last page):
if (pagination.hasMore) {
  const next = await sublay.chat.listConversations({
    actingUserId: "usr_abc123",
    types: ["direct", "group"],
    cursor: pagination.nextCursor,
  });
}
```

<ParamField body="actingUserId" type="string" required>
  The user whose conversations are listed.
</ParamField>
<ParamField body="types" type="ConversationType | ConversationType[]">
  Only conversations of these types: any of `"direct"`, `"group"`, `"space"`. Omitted, every type is listed.
</ParamField>
<ParamField body="cursor" type="string | null">
  `pagination.nextCursor` from the previous response, passed as returned; omit it (or pass `null`) for the first page. It is opaque: don't build or parse it. One the server can't read is rejected with `400 chat/invalid-cursor`.
</ParamField>
<ParamField body="limit" type="number">
  Page size, 1–50. Defaults to `20`.
</ParamField>

**Returns** — `Promise<CursorPaginatedResponse<ConversationPreview>>`: `{ data: ConversationPreview[]; pagination: { nextCursor: string | null; hasMore: boolean } }`. `nextCursor` is `null` when `hasMore` is `false`.

A `ConversationPreview` is the conversation's own fields plus:

- `unreadCount` and `memberCount` (active members).
- `mutedUntil` and `mutedForever`: the acting user's mute on the conversation (see [muteConversation](#muteconversation)).
- `otherMembers` — up to 5 active members other than the acting user (`id`, `name`, `username`, `avatar`) for `direct`/`group` conversations, so a DM/group can render the counterparty without a separate members fetch. Capped at 5 (use `memberCount` for the group total); empty for `space` conversations.
- `lastMessage` (`ConversationPreviewLastMessage | null`): a preview of the newest top-level message — `id`, `conversationId`, `content` (cut to 100 characters), `gif`, `userId`, `moderationStatus`, `userDeletedAt`, `createdAt`, `files`, and `user` (`{ id, name, username, avatar, reputation }`, on `group` and `space` rows only; `null` on `direct` rows). It has no mentions, quotes or reactions. A deleted or removed last message is its [placeholder](/v8/data-models/chat-message#deleted-and-removed-messages).

### createDirectConversation

Returns the one-to-one conversation between the acting user and a target user, or creates it when there is none. Props type: `CreateDirectConversationProps`.

```typescript
const { conversation, created } = await sublay.chat.createDirectConversation({
  actingUserId: "usr_abc123",
  userId: "usr_def456",
});
```

<ParamField body="userId" type="string" required>
  The other participant (the target).
</ParamField>
<ParamField body="actingUserId" type="string" required>
  The user initiating the DM.
</ParamField>

**Returns** — `Promise<CreateDirectConversationResult>`: `{ conversation: Conversation; created: boolean }`. `created` is `true` when this call created the conversation (HTTP `201`) and `false` when it already existed (HTTP `200`).

### createGroupConversation

Creates a group conversation; the acting user becomes its admin.

```typescript
const conversation = await sublay.chat.createGroupConversation({
  actingUserId: "usr_abc123",
  name: "Project Falcon",
  memberIds: ["usr_def456", "usr_ghi789"],
});
```

<ParamField body="actingUserId" type="string" required>
  The acting user (becomes the group admin).
</ParamField>
<ParamField body="name" type="string">Group name.</ParamField>
<ParamField body="description" type="string">Group description.</ParamField>
<ParamField body="memberIds" type="string[]">Initial members to add.</ParamField>
<ParamField body="metadata" type="object">Custom key-value data.</ParamField>
<ParamField body="avatarFile" type="{ file: Uint8Array | Blob; filename?: string; mimeType?: string; options: ImageOptions }">
  The group's avatar image, up to 50 MB. Raw bytes carry no type, so pass `mimeType` with a `Uint8Array` (`image/jpeg`, `image/png` or `image/webp`; without it the file goes as `application/octet-stream` and is refused with `400 chat/unsupported-file-type`); a `Blob` keeps its own type. `options` says how to process the image and must include `mode` (see [Upload Image](/v8/api-reference/storage/upload-image)). With an image, the request is sent as `multipart/form-data`. Requires the `files-images` bundle.
</ParamField>

```typescript
import { readFile } from "node:fs/promises";

const group = await sublay.chat.createGroupConversation({
  actingUserId: "usr_abc123",
  name: "Project Falcon",
  avatarFile: {
    file: new Uint8Array(await readFile("./falcon.png")),
    filename: "falcon.png",
    mimeType: "image/png",
    options: { mode: "exact-dimensions", dimensions: { small: { width: 64, height: 64 } } },
  },
});
```

**Returns** — `Promise<Conversation>`

### checkMyConversationMembership

Reads the acting user's own membership in a conversation (`GET /chat/conversations/:conversationId/members/me`).

```typescript
const membership = await sublay.chat.checkMyConversationMembership({
  conversationId: "cnv_abc123",
  actingUserId: "usr_abc123",
});
```

<ParamField body="conversationId" type="string" required />
<ParamField body="actingUserId" type="string" required>The user whose membership is checked: the request acts as them.</ParamField>

**Returns** — `Promise<CheckMyConversationMembershipResponse>`, a flat object where a field that doesn't apply is left out:

- an active member: `{ isMember: true, role, lastReadAt, mutedForever, mutedUntil }`

## Messages

### listMessages

Lists messages in a conversation. Pages are anchored on a message — pass a message id as `before` to page backwards, or as `after` to page forwards (`before`/`after` are mutually exclusive).

```typescript
const { data: messages, pagination } = await sublay.chat.listMessages({
  conversationId: "cnv_abc123",
  actingUserId: "usr_abc123",
  limit: 50,
});

// Next (older) page: newest first by default, so the oldest message is the last one.
if (pagination.hasMore) {
  const older = await sublay.chat.listMessages({
    conversationId: "cnv_abc123",
    actingUserId: "usr_abc123",
    before: messages[messages.length - 1].id,
  });
}

// Only messages that have thread replies.
const withReplies = await sublay.chat.listMessages({
  conversationId: "cnv_abc123",
  actingUserId: "usr_abc123",
  filters: { hasReplies: true },
});
```

<ParamField body="conversationId" type="string" required />
<ParamField body="actingUserId" type="string" required>The acting user (must be a member).</ParamField>
<ParamField body="parentMessageId" type="string">List this message's thread replies (thread view), oldest first by default.</ParamField>
<ParamField body="before" type="string">A message id: the `limit` messages just before it. Pass the oldest message you hold to load older ones. It must be a message of this conversation at the same thread level (`parentMessageId`), or the call is rejected with `400 chat/invalid-cursor`. Mutually exclusive with `after`.</ParamField>
<ParamField body="after" type="string">A message id: the `limit` messages just after it. Pass the newest message you hold to load newer ones. Same rules as `before`. Mutually exclusive with `before`.</ParamField>
<ParamField body="limit" type="number">1–100, defaults to `50`.</ParamField>
<ParamField body="sortDir" type='"asc" | "desc"'>The order of the page by creation time. Defaults to `"desc"` for the main stream and `"asc"` for a thread. With `before` or `after`, the anchor decides which messages are in the page; `sortDir` only orders them.</ParamField>
<ParamField body="include" type="ChatMessageListIncludeParam">Associations to populate, as a single value or an array: `"files"` (the message's images and files) and `"grants"` (each message's [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary)). Pass `["files", "grants"]` for both.</ParamField>
<ParamField body="filters" type="MessageFilters">Optional filters. `filters.hasReplies` (boolean): when `true`, returns only messages that have thread replies (`threadReplyCount > 0`); when `false`, only messages with none. Filters by thread replies, not quotings. Threads are one level deep, so `hasReplies: true` together with `parentMessageId` always returns an empty list — the response's `notice` field explains why.</ParamField>
<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<{ data: ChatMessage[]; pagination: { hasMore: boolean }; notice?: string }>`. `hasMore` says whether more messages exist past this page in the direction of travel: older with `before`, newer with `after`; with neither, older for `"desc"` and newer for `"asc"`. See [List Messages › Paging](/v8/api-reference/chat/messages/list-messages#paging).

### sendMessage

Sends a message as the acting user. A message must have content, a GIF, or at least one image or file. When `images` or `files` are attached the request is sent as `multipart/form-data`; otherwise it's a JSON body.

```typescript
// Text + mention
const message = await sublay.chat.sendMessage({
  conversationId: "cnv_abc123",
  actingUserId: "usr_abc123",
  content: "Welcome aboard!",
  mentions: [{ type: "user", id: "usr_def456", username: "dana" }],
});

// With an image (processed into sizes)
import { readFile } from "node:fs/promises";
const buffer = await readFile("./diagram.png");

await sublay.chat.sendMessage({
  conversationId: "cnv_abc123",
  actingUserId: "usr_abc123",
  content: "See attached",
  images: {
    files: [{ file: new Uint8Array(buffer), filename: "diagram.png", mimeType: "image/png" }],
    options: { mode: "original-aspect", sizes: { full: 1080 } },
  },
});
```

<ParamField body="conversationId" type="string" required />
<ParamField body="actingUserId" type="string" required>The message author (must be a member).</ParamField>
<ParamField body="content" type="string">Up to 4000 characters.</ParamField>
<ParamField body="gif" type="GifData | null">An attached GIF object.</ParamField>
<ParamField body="mentions" type="Mention[]">User/space mentions.</ParamField>
<ParamField body="parentMessageId" type="string">Reply within a thread.</ParamField>
<ParamField body="quotedMessageId" type="string">Quote another message.</ParamField>
<ParamField body="metadata" type="object">Custom key-value data.</ParamField>
<ParamField body="localId" type="string">Client-generated id echoed back on the created message (not stored).</ParamField>
<ParamField body="images" type="{ files: { file: Uint8Array | Blob; filename?: string; mimeType?: string }[]; options: ImageOptions }">
  Images, 50 MB each, processed per `options` (`mode` is required); each comes back with `image` and its variants. Pass `mimeType` with a `Uint8Array`; a part without a `filename` is named `image`. A request takes at most 20 files in all. Requires the `files-images` bundle.
</ParamField>
<ParamField body="files" type="{ files: { file: Uint8Array | Blob; filename?: string; mimeType?: string }[]; options?: { pathParts?: string[] } }">
  Files, 50 MB each, stored as uploaded (`image` is `null`, an image sent here included). A part without a `filename` is named `file`. Requires the `files-images` bundle.
</ParamField>
<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<SendMessageResponse>`: the created message as a `SentChatMessage` (a `ChatMessage` without `reactionCounts`, `userReactions` and `grants`), with `localId` when you passed one.

### Reporting a message

Message reports go through the shared reports API, not a chat-specific
function — the same call that reports entities and comments.

```typescript
await sublay.reports.createReport({
  targetType: "message",
  targetId: "msg_xyz",
  actingUserId: "usr_abc123",
  reason: "harassment",
  details: "Targeted insults",
});
```

`targetId` is the message id; the conversation is resolved server-side, so no
`conversationId` is needed. The reporter must be a member of the conversation
and cannot report their own message. See [createReport](/v8/node-sdk/reports).

### muteConversation

Sets or clears a user's mute on a conversation. Muting suppresses the `message` push for this conversation only; the message is still delivered. See [Notification Preferences & Mute](/v8/notification-preferences).

```typescript
// Mute for a week
await sublay.chat.muteConversation({
  conversationId: "cnv_abc123",
  duration: "1w",
  actingUserId: "usr_abc123",
});

// Unmute
await sublay.chat.muteConversation({
  conversationId: "cnv_abc123",
  duration: null,
  actingUserId: "usr_abc123",
});
```

<Note>
  Like every other `chat` call, the Node SDK names the acting user with `actingUserId`. The user must be a member of the conversation, and the returned `currentMember` is that user's own row. End-user-token clients (the React hooks, the browser JS SDK) act on the signed-in user and send no `actingUserId`.
</Note>

<ParamField body="conversationId" type="string" required />
<ParamField body="duration" type='"8h" | "24h" | "1w" | "forever" | null' required>
  The mute **duration choice**, or `null` to clear the mute. Send the choice, never a raw timestamp.
</ParamField>
<ParamField body="actingUserId" type="string" required>The user whose mute is set (must be a member).</ParamField>

**Returns** — `Promise<{ currentMember: ConversationMember }>` — that user's own member row.

```typescript
interface ConversationMember {
  // ...
  mutedForever?: boolean;    // true when muted indefinitely
  mutedUntil?: string | null; // ISO timestamp for a timed mute; null otherwise
}
```

<Info>
  **"Forever" is an explicit signal.** A `forever` mute returns `mutedForever: true` with `mutedUntil: null`. A timed mute returns `mutedForever: false` with a real ISO `mutedUntil`. Read the boolean — never string-match a far-future date.
</Info>

## Space conversations

Each space has a single built-in conversation. These three live on **`client.spaces`** (they're `/spaces/...` routes), not on `client.chat`.

### spaces.getSpaceConversation

Fetches-or-creates a space's conversation and joins the acting user to it. The acting user must be an active member of the space; a pending or rejected request, or a ban, is refused.

```typescript
const conversation = await sublay.spaces.getSpaceConversation({
  spaceId: "spc_abc123",
  actingUserId: "usr_abc123",
});
```

<ParamField body="spaceId" type="string" required />
<ParamField body="actingUserId" type="string" required>The acting user (must be an active member of the space).</ParamField>

**Returns** — `Promise<Conversation>`, with `memberCount` and `currentMember` (the acting user's own member row).

---

### spaces.moderateSpaceChatMessage

Removes a message in a space conversation.

<Note>
  On the space moderation routes, `actingUserId` is required: the request has
  exactly that user's moderation permissions and is refused if they cannot
  moderate the space.
</Note>

```typescript
await sublay.spaces.moderateSpaceChatMessage({
  spaceId: "spc_abc123",
  messageId: "msg_xyz",
  action: "remove",
  reason: "Off-topic",
  actingUserId: "usr_mod123",
});
```

<ParamField body="spaceId" type="string" required />
<ParamField body="messageId" type="string" required />
<ParamField body="action" type='"remove"' required>The moderation action. Chat messages are never held for approval, so `"remove"` is the only value.</ParamField>
<ParamField body="reason" type="string">The reason for the removal. Trimmed; up to 1,000 characters.</ParamField>
<ParamField body="actingUserId" type="string" required>The moderator the request acts as: they must be a moderator or admin of the space, and the action is recorded as theirs.</ParamField>

**Returns** — `Promise<{ moderationStatus: "removed" | null }>`: `null` for a message its author deleted (and nobody removed), which is left as it was.

---

### Handling chat message reports

A report against a space-conversation message is handled with [`spaces.handleSpaceReport`](/v8/node-sdk/spaces-moderation#handlespacereport), the one function for every report type in a space. A chat message report takes the actions `"remove-message"`, `"ban-user"` and `"dismiss"`, and requires a `summary` like every other report type.
