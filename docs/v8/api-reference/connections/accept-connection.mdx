---
title: "Accept Connection"
api: "PATCH /v8/:projectId/connections/:connectionId/accept"
description: "Accept a pending connection request"
---

Accepts a pending connection request. Only the receiver of the original request can accept it. A notification is sent to the original requester.

## Path Parameters

<ParamField path="connectionId" type="string" required>
  The ID (UUID) of the pending connection record to accept.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be the receiver of the request. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`:

<ResponseField name="id" type="string">
  Connection record ID.
</ResponseField>

<ResponseField name="status" type="string">
  `"accepted"`.
</ResponseField>

<ResponseField name="respondedAt" type="string">
  ISO timestamp of when the connection was accepted.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found — 404">
    ```json
    {
      "error": "Pending connection request not found.",
      "code": "connection/not-found"
    }
    ```
  </Accordion>
  <Accordion title="Unauthorized — 403">
    ```json
    {
      "error": "Only the receiver can accept a connection request.",
      "code": "connection/unauthorized"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "connection/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "connection/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
