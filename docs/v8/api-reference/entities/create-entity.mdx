---
title: "Create Entity"
api: "POST /v8/:projectId/entities"
description: "Create a new entity, with optional file upload support"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Creates a new entity in your project. Supports optional file uploads via `multipart/form-data`. When no files are attached, use `application/json`. The entity's author is the signed-in user, or the user a service key names in `actingUserId`; the create then runs under that user's own checks, such as suspension. A service key naming nobody creates an app-owned entity with no author, which only a service key naming nobody can later edit, publish or delete.

## Body Parameters

<ParamField body="foreignId" type="string">
  Your application's identifier for this entity (URL, slug, database ID, etc.). Used to fetch or create entities without knowing the Sublay ID.
</ParamField>

<ParamField body="sourceId" type="string">
  Groups entities by source. Use a topic ID or page ID to scope feeds to a specific context.
</ParamField>

<ParamField body="spaceId" type="string">
  The ID of the space this entity belongs to. The space must exist in the same project.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only: the user this request acts as, who authors the entity. Leave it out to create an app-owned entity with no author. A user that doesn't exist returns `404 entity/user-not-found`. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

<ParamField body="title" type="string">
  A title or headline for the entity.
</ParamField>

<ParamField body="content" type="string">
  The main body text of the entity.
</ParamField>

<ParamField body="attachments" type="object[]">
  An array of generic attachment objects. Each item is a free-form JSON object — structure is defined by your application.
</ParamField>

<ParamField body="keywords" type="string[]">
  Tags or keywords associated with this entity. Used for keyword-based filtering in the list endpoint.
</ParamField>

<ParamField body="mentions" type="object[]">
  Users or spaces mentioned in this entity. Each object is a discriminated union:
  - `{ type: "user", id: string, username: string, foreignId?: string }`
  - `{ type: "space", id: string, slug: string }`

  Each mentioned user receives one in-app notification, however many times they are mentioned. A space mention sends no notification, and an author mentioning themselves is not notified. When a service key creates the entity on a user's behalf, that user is the notification's initiator. An entity without an author sends no mention notifications.
</ParamField>

<ParamField body="location" type="object">
  Geographic coordinates for this entity. Enables proximity-based filtering.

  ```json
  { "latitude": 40.7128, "longitude": -74.0060 }
  ```
</ParamField>

<ParamField body="metadata" type="object">
  A free-form JSON object for any custom data your application needs alongside the entity. Supports rich filtering via `metadataFilters` in the list endpoint.
</ParamField>

<ParamField body="isDraft" type="boolean">
  When `true`, the entity is saved as a draft and excluded from public feeds. Publish it later via the [Publish Entity](/v8/api-reference/entities/publish-entity) endpoint. A draft needs an owner: send it with a user token, or with a service key and `actingUserId`. Otherwise it returns `400 entity/draft-requires-user`.
</ParamField>

<ParamField body="requireUser" type="boolean">
  When `true`, the entity must have an author: a request with no credentials, or a service key naming nobody, returns `401 entity/user-required`. A service key with `actingUserId` passes.
</ParamField>

<ParamField body="createdAt" type="string">
  ISO 8601 datetime to backfill a creation timestamp. **Service key only**, also with `actingUserId` (importing content with its original authors and dates). Ignored from a user token.
</ParamField>

<ParamField body="updatedAt" type="string">
  ISO 8601 datetime for `updatedAt`. Requires `createdAt` to also be set. Must be ≥ `createdAt`. **Service key only**, also with `actingUserId`. Ignored from a user token.
</ParamField>

### File Uploads (multipart/form-data)

When uploading files, send the request as `multipart/form-data`. All JSON fields above are sent as form fields.

Form fields can only carry strings, so the object and array fields — `attachments`, `keywords`, `mentions`, `location` and `metadata` — must be JSON-stringified. Booleans are sent as `"true"` / `"false"`. Plain strings such as `title` and `content` are sent as-is.

```js
const form = new FormData();
form.append("title", "Sunset over the bay");
form.append("keywords", JSON.stringify(["sunset", "bay"]));
form.append("location", JSON.stringify({ latitude: 40.7128, longitude: -74.006 }));
form.append("metadata", JSON.stringify({ category: "photo" }));
form.append("nsfw", "false");
form.append("images.files", file);
form.append("images.options", JSON.stringify({ mode: "original-aspect", sizes: { full: 1080 } }));
```

<Note>
  The SDKs handle this for you — [`useCreateEntity`](/v8/hooks/entities/use-create-entity) switches to `multipart/form-data` and stringifies these fields automatically as soon as you pass `images` or `files`.
</Note>

<ParamField body="images.files" type="file[]">
  Image files to attach. Maximum 10 images, 50 MB each. Must be valid images. Requires `images.options`.
</ParamField>

<ParamField body="images.options" type="string">
  Stringified JSON describing how to process uploaded images. Must include a `mode` field:
  - `"exact-dimensions"` — resize to specific pixel dimensions per variant
  - `"aspect-ratio-width-based"` — resize by width maintaining aspect ratio
  - `"aspect-ratio-height-based"` — resize by height maintaining aspect ratio
  - `"original-aspect"` — preserve original ratio, resize by max dimension
  - `"multi-aspect-ratio"` — generate crops at multiple aspect ratios

  Optional fields: `quality` (1–100), `format` (`webp`, `jpeg`, `png`, `original`), `stripExif` (boolean), `pathParts` (string[]).
</ParamField>

<ParamField body="files.files" type="file[]">
  Generic files to attach. Maximum 10 files, 50 MB each.
</ParamField>

<ParamField body="files.options" type="string">
  Stringified JSON for file options. Optional `pathParts` (string[]) customizes the storage path.
</ParamField>

## Response

Returns the created [Entity](/v8/data-models/entity) object. When files are uploaded, the entity includes a `files` array with signed URLs for each attachment.

<Note>
  Draft entities are invisible to everyone but their author until published. Use [Fetch Drafts](/v8/api-reference/entities/fetch-drafts) to list an author's unpublished drafts.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="User Required — 401">
    ```json
    { "error": "Authentication required to create this entity.", "code": "entity/user-required" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "entity/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "entity/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Rejected by Validation Webhook — 400">
    ```json
    { "error": "Entities are created by server only", "code": "entity/webhook-validation-failed" }
    ```
    Returned when your `entity.created` [validation webhook](/v8/webhooks) rejects the request. `error` carries the `message` your webhook returned. Nothing is stored.
  </Accordion>
  <Accordion title="Space Not Found — 404">
    ```json
    { "error": "Space not found", "code": "entity/space-not-found" }
    ```
  </Accordion>
  <Accordion title="Invalid Timestamp — 400">
    ```json
    { "error": "Cannot set updatedAt without also setting createdAt.", "code": "entity/invalid-timestamp" }
    ```
    Also returned when `updatedAt` is earlier than `createdAt`:
    ```json
    { "error": "updatedAt must be the same or after createdAt.", "code": "entity/invalid-timestamp" }
    ```
  </Accordion>
  <Accordion title="File Too Large — 413">
    ```json
    { "code": "entity/file-too-large", "message": "Image \"photo.jpg\" exceeds 50MB limit." }
    ```
  </Accordion>
  <Accordion title="Invalid Image — 422">
    ```json
    { "code": "entity/invalid-image", "message": "File \"doc.txt\" is not a valid image: ..." }
    ```
  </Accordion>
  <Accordion title="Removed Parameter — 400">
    The request sent `excludeUserId`. To create an entity with no author, use a service key without `actingUserId`.

    ```json
    { "error": "`excludeUserId` isn't accepted: to create an entity with no author, use a service key without actingUserId.", "code": "entity/unsupported-param", "param": "excludeUserId" }
    ```
  </Accordion>
  <Accordion title="Draft Requires User — 400">
    `isDraft` was `true` with no author: a request with no credentials, or a service key naming nobody. A draft needs an owner.

    ```json
    { "error": "A draft needs an owner: create it with a user's token, or with a service key and actingUserId.", "code": "entity/draft-requires-user" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
