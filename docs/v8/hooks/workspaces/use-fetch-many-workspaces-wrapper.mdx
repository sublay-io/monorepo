## Overview

`useFetchManyWorkspacesWrapper` follows the **Wrapper pattern** (mirroring `useFetchManyEntitiesWrapper`). It manages page state, accumulates results, and exposes a `loadMore`. There is **no** Redux slice — this is the house-style list hook for workspaces.

## Usage Example

```tsx
import { useFetchManyWorkspacesWrapper } from "@sublay/react-js";

function WorkspaceList() {
  const { workspaces, loading, hasMore, loadMore } =
    useFetchManyWorkspacesWrapper({ limit: 10, include: ["memberCount"] });

  return (
    <div>
      {workspaces.map((w) => (
        <div key={w.id}>{w.name} — {w.memberCount} members</div>
      ))}
      {hasMore && <button disabled={loading} onClick={loadMore}>Load more</button>}
    </div>
  );
}
```

## Parameters

<ParamField path="limit" type="number">
  Page size. Defaults to `10`.
</ParamField>

<ParamField path="parentWorkspaceId" type='string | "none" | "any" | null'>
  Narrows the list by where each workspace sits in the tree. `"none"`: top-level workspaces only. A workspace id: the caller's workspaces directly under that workspace. `"any"`, left out or `null`: workspaces at every level (the default). Changing it refetches from page 1.
</ParamField>

<ParamField path="include" type="WorkspaceIncludeParam">
  A single value or an array. The only value is `"memberCount"`: it adds each accumulated workspace's **direct** member count; omit it and the field is absent.
</ParamField>

## Returns

| Field | Type | Description |
|-------|------|-------------|
| `workspaces` | `Workspace[]` | Accumulated list. |
| `loading` | `boolean` | Whether a fetch is in flight. |
| `hasMore` | `boolean` | Whether more pages remain. |
| `loadMore` | `() => void` | Fetch the next page. |
