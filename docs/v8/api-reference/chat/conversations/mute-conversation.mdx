---
title: "Mute Conversation"
api: "POST /v8/:projectId/chat/conversations/:conversationId/mute"
description: "Set or clear the authenticated user's mute on a conversation"
---

Sets or clears the acting user's mute on a conversation. Muting suppresses the `message` push for this conversation only — the message is still delivered, socket-emitted, and readable. Timed mutes expire lazily (push resumes once the window passes).

Requires authentication. **Acting-user-scoped:** an end-user token (`Authorization: Bearer <accessToken>`) mutes its own membership. A service key acts on behalf of a named user via the body `actingUserId`, which it must send; an end-user token must not send it (both consistent with every other per-user write). Requires the `chat` bundle.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation to mute or unmute.
</ParamField>

## Body Parameters

<ParamField body="duration" type="string | null" required>
  The mute **duration choice** — send the choice, never a raw timestamp. One of:

  - `"8h"` — mute for 8 hours from now
  - `"24h"` — mute for 24 hours from now
  - `"1w"` — mute for 1 week from now
  - `"forever"` — mute indefinitely
  - `null` — clear the mute (unmute)

  The server resolves the window from its own clock, so client clock skew can't distort it.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their membership is muted. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns `200` with the acting user's own (self-serialized) member row under `currentMember`. The `mutedUntil` / `mutedForever` fields reflect the new state.

```json
{
  "currentMember": {
    "id": "mbr_abc123",
    "conversationId": "cnv_abc123",
    "userId": "usr_abc123",
    "role": "member",
    "mutedForever": true,
    "mutedUntil": null,
    "isActive": true
  }
}
```

<Warning>
  **"Forever" is an explicit signal.** A `forever` mute returns `mutedForever: true` with `mutedUntil: null` — the far-future storage sentinel is never exposed as a date. A timed mute returns `mutedForever: false` with a real ISO `mutedUntil`. An unmuted conversation returns `mutedForever: false`, `mutedUntil: null`. Read the boolean; never string-match a date.
</Warning>

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User ID — 400">
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
    Returned when a service key omits the required `actingUserId` (it has no implicit session user).
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Conversation not found.", "code": "chat/not-found" }
    ```
  </Accordion>
  <Accordion title="Not a Member — 400">
    ```json
    { "error": "You are not an active member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "...", "code": "chat/invalid-body" }
    ```
    Returned when `duration` is not one of the accepted choices (or `null`).
  </Accordion>
</AccordionGroup>
