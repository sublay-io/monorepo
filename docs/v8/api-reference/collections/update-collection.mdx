---
title: "Update Collection"
api: "PATCH /v8/:projectId/collections/:collectionId"
description: "Rename a collection"
---

Updates the name of a sub-collection. The root collection cannot be renamed (it has `parentId: null`, which this endpoint rejects).

## Path Parameters

<ParamField path="collectionId" type="string" required>
  The ID of the collection to update.
</ParamField>

## Body Parameters

<ParamField body="name" type="string" required>
  The new name for the collection. Must be a non-empty string.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must own the collection. A user token always acts as its own user and must not send it (`400 collection/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Collection](/v8/data-models/collection) object.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Body — 400">
    Returned when `name` is missing or an empty string. The `error` message names the offending field.
    ```json
    { "error": "name: Invalid input: expected string, received undefined", "code": "collection/invalid-body" }
    ```
  </Accordion>
  <Accordion title="Collection Not Found — 404">
    Returned when the collection doesn't exist, doesn't belong to the user, or is the root collection (which cannot be renamed).
    ```json
    { "error": "Collection not found", "code": "collection/not-found" }
    ```
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Server error", "code": "collection/server-error" }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "collection/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "collection/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "collection/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
