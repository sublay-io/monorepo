## Overview

`useFetchManyComments` returns a function that fetches one level of a comment thread ([`GET /comments`](/v8/api-reference/comments/fetch-many-comments)): an entity's top-level comments (`entityId`) or a comment's direct replies (`parentId`). It's the fetch function behind `useEntityComments` and `useReplies`. Use it directly when you need full control over a thread request.

For a user's comments across entities, use [`useFetchCommentsByUserId`](/v8/hooks/comments/use-fetch-comments-by-user-id).

## Usage Example

```tsx
import { useFetchManyComments, type Comment } from "@sublay/react-js";
import { useEffect, useState } from "react";

function TopComments({ entityId }: { entityId: string }) {
  const fetchComments = useFetchManyComments();
  const [comments, setComments] = useState<Comment[]>([]);
  const [cursor, setCursor] = useState<string | null>(null);

  useEffect(() => {
    fetchComments({
      entityId,
      sortBy: "top",
      limit: 10,
      include: "user",
      replyDepth: 1, // also bring each comment's first replies
      replyLimit: 2,
    }).then((res) => {
      setComments(res.data);
      setCursor(res.pagination.nextCursor);
    });
  }, [entityId]);

  const loadMore = async () => {
    if (!cursor) return;
    const res = await fetchComments({ entityId, sortBy: "top", limit: 10, cursor, include: "user" });
    setComments((prev) => [...prev, ...res.data]);
    setCursor(res.pagination.nextCursor);
  };

  return (
    <>
      <ul>{comments.map((c) => <li key={c.id}>{c.content}</li>)}</ul>
      {cursor && <button onClick={loadMore}>Load more</button>}
    </>
  );
}
```

## Parameters

One of `entityId` or `parentId` is required.

<ParamField path="entityId" type="string">
  Fetch this entity's top-level comments.
</ParamField>

<ParamField path="parentId" type="string">
  Fetch this comment's direct replies.
</ParamField>

<ParamField path="limit" type="number">
  How many comments at the level being fetched. Server default `10`, max `100`.
</ParamField>

<ParamField path="cursor" type="string | null">
  `pagination.nextCursor` from the previous response. Omit for the first page. Send the same sort as the request that returned it.
</ParamField>

<ParamField path="sortBy" type="CommentsSortByOptions">
  `"createdAt"`, `"top"` (raw count of `sortByReaction`) or `"controversial"`. Server default `"createdAt"`.
</ParamField>

<ParamField path="sortDir" type='"asc" | "desc"'>
  Applies to `"createdAt"` and `"top"`; not accepted with `"controversial"`, which ranks one way only. Server default `"desc"`.
</ParamField>

<ParamField path="sortByReaction" type="ReactionType">
  With `sortBy: "top"` only: the reaction to rank by. Server default `"upvote"`.
</ParamField>

<ParamField path="replyDepth" type="number">
  Levels of replies to nest under each returned comment (`0`–`5`). Server default `0`.
</ParamField>

<ParamField path="replyLimit" type="number">
  Replies per comment in the nested levels (at least `1`). Server default `3`.
</ParamField>

<ParamField path="replySortBy" type="CommentReplySortByOptions">
  Sort for the nested levels: `"createdAt"`, `"top"` or `"controversial"`. Defaults to `sortBy`.
</ParamField>

<ParamField path="replySortDir" type='"asc" | "desc"'>
  Sort direction for the nested levels. Defaults to `sortDir`. Not sent when the nested sort is `"controversial"`.
</ParamField>

<ParamField path="replySortByReaction" type="ReactionType">
  The reaction the nested levels rank by, when their sort is `"top"`.
</ParamField>

<ParamField path="include" type='"user" | "grants" | ("user" | "grants")[]'>
  Related data to populate, at every level.
</ParamField>

<SpaceReputationParams variant="context" field="path" />

A request can return at most 500 comments, nested replies included — see [Request size limit](/v8/api-reference/comments/fetch-many-comments#request-size-limit).

## Returns

A `Promise<CursorPaginatedResponse<Comment>>`:

<ResponseField name="data" type="Comment[]">
  The comments at the requested level. With `replyDepth` above `0`, each carries nested `replies` (`{ data, pagination }`). When `spaceReputation` is requested, each embedded author carries an added `spaceReputation` number. See [Reputation](/v8/data-models/reputation).
</ResponseField>

<ResponseField name="pagination.nextCursor" type="string | null">
  Pass as `cursor` to get the next page. `null` when there's nothing more.
</ResponseField>

<ResponseField name="pagination.hasMore" type="boolean">
  Whether more comments exist after this page.
</ResponseField>

See [Fetch Many Comments](/v8/api-reference/comments/fetch-many-comments) for placeholders, block flags and how to continue nested replies.
