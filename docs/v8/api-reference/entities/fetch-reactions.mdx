<Note>

</Note>

import { SpaceReputationParams } from "/snippets/v8/space-reputation-params.mdx";

Returns a paginated list of reactions for an entity, each with the reacting user's profile. Useful for displaying "liked by" lists or reaction breakdowns.

Authentication is optional — the endpoint works without a token. When there is a viewer (the signed-in user, or the user a service key names in `actingUserId`), reactions from users with a block between them and the viewer, in either direction, are excluded from both the results and the count. Block filtering requires the `moderation` bundle.

## Path Parameters

<ParamField path="entityId" type="string" required>
  The UUID of the entity.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as, with their block filtering, exactly as their own access token. Leave it out for the anonymous view (no block filtering). A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number" default="1">
  Page number (1-indexed). A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`.
</ParamField>

<ParamField query="limit" type="number" default="20">
  Number of reactions per page. A whole number of at least `1` — `0`, a negative number or a non-integer value returns `400 entity/invalid-query`. Maximum `100` — larger values are treated as `100`.
</ParamField>

<ParamField query="reactionType" type="string">
  Filter to a specific reaction type. One of: `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`. When omitted, all reaction types are returned.
</ParamField>

<ParamField query="sortDir" type="string" default="desc">
  Sort by creation time, `"asc"` or `"desc"` (either case).
</ParamField>

### Space-scoped reputation

This endpoint has a space in context, so it accepts the opt-in reputation params. They add a `spaceReputation` field to each reactor's `user`, alongside the always-present `reputation` total. Requires the `reputation` bundle. See the [Reputation data model](/v8/data-models/reputation) for the full contract.

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Query — 400">
    Returned when `page` or `limit` is below `1` or not a whole number, `reactionType` isn't one of the eight types, or `sortDir` isn't `asc` or `desc`.

    ```json
    { "error": "page: Page must be a positive integer", "code": "entity/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Entity not found.", "code": "entity/not-found" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
</AccordionGroup>
