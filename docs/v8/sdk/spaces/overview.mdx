Spaces are groups where users can gather, post content, and interact under customizable rules. Each space has its own membership system, permission levels, moderation tools, and optionally an integrated chat conversation.

<Note>
  **Requires the `spaces` bundle.** Spaces are only available when the `spaces` bundle is installed on your project (space-level chat additionally needs the `chat` bundle). See [Bundles](/v8/bundles) to add it.
</Note>

## Core Architecture

Spaces follow the provider + hook pattern used throughout Sublay. Wrap your space UI with a `SpaceProvider` and access everything via `useSpace`.

```tsx
import { SpaceProvider, useSpace } from "@sublay/react-js";

function SpacePage() {
  return (
    <SpaceProvider spaceId="space-uuid">
      <SpaceContent />
    </SpaceProvider>
  );
}

function SpaceContent() {
  const { space, isMember, canPost, joinSpace } = useSpace();

  if (!space) return <div>Loading...</div>;

  return (
    <div>
      <h1>{space.name}</h1>
      {!isMember && (
        <button onClick={joinSpace}>Join Space</button>
      )}
    </div>
  );
}
```

## Permission Model

Each space has two independent permission settings:

- **`readingPermission`** — `"anyone"` or `"members"`. Controls who can see content.
- **`postingPermission`** — `"anyone"`, `"members"`, or `"admins"`. Controls who can post.

When the current user is authenticated and is a member, `useSpace` exposes their resolved permissions (`canPost`, `canRead`, `canModerate`, `isAdmin`, `isModerator`).

Separately, each space has a **`visibility`** setting — `"public"` (default), `"unlisted"`, or `"private"` — that controls who can find and see the space, independent of the permission model above:

- `"unlisted"` keeps a space out of the directory, search and sub-space previews, but anyone who can see the space above it reaches it by id, short id or slug.
- `"private"` makes a space seen only by its active members. Everyone else — including users with a pending, banned or rejected membership, and a service key without `actingUserId` — gets `404`, as if it didn't exist, and so do the spaces under it (unless they are a member of one of those). A private space can't be joined: its moderators and admins add its members with [`useAddMember`](/v8/hooks/spaces/use-add-member).
- Listings show a space only if it and every space above it are `"public"`. Where a space the viewer can't see would be embedded (`parentSpace`, an entity's `space`), it is `null`.

See the [Space data model](/v8/data-models/space#visibility) for the full rule.

## Hierarchy

Spaces can be nested up to 10 levels deep. A child space is created by passing a `parentSpaceId` to `useCreateSpace`. Only admins of the parent space can create child spaces. Parent admins and moderators are automatically cascaded into new child spaces with their existing roles.

The space directory lists top-level spaces by default. Pass a space id as `parentSpaceId` to list that space's direct sub-spaces, or `"any"` to list spaces at every level. See [Space Lists](/v8/sdk/spaces/space-lists).
