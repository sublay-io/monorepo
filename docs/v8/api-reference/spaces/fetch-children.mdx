---
title: "Fetch Space Children"
api: "GET /v8/:projectId/spaces/:spaceId/children"
description: "Get the direct child spaces of a parent space"
---

Returns a paginated list of child spaces for a given parent space. Authentication is optional — when there is a viewer (the signed-in user, or the user a service key names in `actingUserId`), each child carries an `isMember` flag for them.

Only children with `visibility: "public"` are listed, for every caller. Unlike [Fetch Spaces](/v8/api-reference/spaces/fetch-spaces), authenticating does not surface unlisted or private children the caller belongs to.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the parent space.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as. The page is exactly what that user's own access token would get (`isMember` on each child space). Leave it out for the anonymous view. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 space/acting-user-not-allowed`).
</ParamField>

<ParamField query="page" type="number">
  Page number. Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page.
</ParamField>

<ParamField query="sortBy" type="string">
  Sort order: `"createdAt"` (when the space was created), `"alphabetical"` (by name) or `"members"` (by active member count). Defaults to `"alphabetical"`.
</ParamField>

<ParamField query="sortDir" type="string">
  Direction, `"asc"` or `"desc"` (either case), for any `sortBy`. Left out: A–Z for `"alphabetical"`, otherwise newest / most first.
</ParamField>

## Response

<ResponseField name="data" type="Space[]">
  Array of child [Space](/v8/data-models/space) objects.
</ResponseField>

<ResponseField name="pagination" type="object">
  Standard pagination metadata.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Parent space not found.", "code": "space/not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported sort — 400">
    `sortBy=newest` is rejected with a pointer to `sortBy=createdAt` (newest child spaces first) or to leaving `sortBy` out (the default, A–Z by name).

    ```json
    {
      "error": "`sortBy=newest` isn't supported in v8. Use `sortBy=createdAt` to list the newest child spaces first, or leave `sortBy` out for the default, A–Z by name.",
      "code": "space/unsupported-param",
      "param": "sortBy"
    }
    ```
  </Accordion>
  <Accordion title="Invalid query — 400">
    Returned with code `space/invalid-query` for invalid values — for example an unknown `sortBy` or `sortDir`. `error` names the first problem found.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "space/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
