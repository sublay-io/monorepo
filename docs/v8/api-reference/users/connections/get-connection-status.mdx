---
title: "Get Connection Status"
api: "GET /v8/:projectId/users/:userId/connection"
description: "Check the connection status between the authenticated user and another user"
---

Returns the connection status between the authenticated user and the specified user. The response shape varies depending on whether there is no connection, a pending request, an accepted connection, or a declined request.

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the other user.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose connection with the user in the path is checked. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`. The shape depends on the connection state:

**No connection:**

<ResponseField name="status" type="string">
  `"none"`.
</ResponseField>

**Pending request:**

<ResponseField name="status" type="string">
  `"pending"`.
</ResponseField>

<ResponseField name="type" type="string">
  `"sent"` if the authenticated user sent the request; `"received"` if they received it.
</ResponseField>

<ResponseField name="connectionId" type="string">
  ID of the connection record.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of when the request was sent.
</ResponseField>

**Accepted (connected):**

<ResponseField name="status" type="string">
  `"connected"`.
</ResponseField>

<ResponseField name="connectionId" type="string">
  ID of the connection record.
</ResponseField>

<ResponseField name="connectedAt" type="string">
  ISO timestamp of when the connection was accepted.
</ResponseField>

<ResponseField name="requestedAt" type="string">
  ISO timestamp of the original request.
</ResponseField>

**Declined:**

<ResponseField name="status" type="string">
  `"declined"`.
</ResponseField>

<ResponseField name="type" type="string">
  `"sent"` or `"received"` — perspective of the authenticated user.
</ResponseField>

<ResponseField name="connectionId" type="string">
  ID of the connection record.
</ResponseField>

<ResponseField name="respondedAt" type="string">
  ISO timestamp of when the request was declined.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Self-Check — 400">
    ```json
    {
      "error": "Cannot check connection status with yourself",
      "code": "connection/self-check"
    }
    ```
  </Accordion>
</AccordionGroup>
