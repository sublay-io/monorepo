---
title: "Fetch Workspace"
api: "GET /v8/:projectId/workspaces/:id"
description: "Read a single workspace, visibility-filtered"
---

Returns a single [Workspace](/v8/data-models/workspace), filtered by the caller's reach-visibility — a caller never sees a node their authority doesn't reach.

## Path Parameters

<ParamField path="id" type="string" required>
  The workspace UUID.
</ParamField>

## Query Parameters

<ParamField query="include" type="string">
  Comma-separated include flags. `memberCount` adds the workspace's **direct** member count as `memberCount` on the object.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service keys only — the user to act as. Enforced: visibility resolves against the named user, so a key acting as someone with no relation to this workspace gets the same `404` that user would. Omit it to read as the app itself (unbounded) — where "omit" means **absent**: `actingUserId: ""` or `null` is a `400`, not a fall-through to that mode. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 workspace/acting-user-not-allowed`). See [Acting on behalf of a user](/v8/sdk/workspaces/overview#acting-on-behalf-of-a-user).
</ParamField>

## Response

Returns the [Workspace](/v8/data-models/workspace) object.

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found / Not Visible — 404">
    ```json
    { "error": "Workspace not found.", "code": "workspace/not-found" }
    ```
  </Accordion>
  <Accordion title="Invalid Path Parameter — 400">
    ```json
    { "error": "Invalid workspace id: expected a UUID.", "code": "workspace/invalid-params" }
    ```
    Every path id on the workspaces bundle is checked for UUID shape before the route runs, so a malformed one is a plain `400` rather than a `500` from the database.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "workspace/acting-user-not-allowed" }
    ```
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
  </Accordion>
</AccordionGroup>

See also: [useFetchWorkspace](/v8/hooks/workspaces/use-fetch-workspace)
