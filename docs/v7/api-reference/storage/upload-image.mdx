---
title: "Upload Image"
api: "POST /v7/:projectId/storage/images"
description: "Upload an image with server-side processing and named variant generation"
---

Uploads an image, processes it with Sharp, and stores the original plus all requested variants. Returns proxy URLs for all variants immediately.

This endpoint accepts `multipart/form-data`. Requires an authenticated user.

**Rate limit**: 20 requests per 5 minutes.

## Body Parameters

<ParamField body="file" type="file" required>
  The image file to upload. Must be a valid image format recognized by Sharp (JPEG, PNG, WebP, AVIF, TIFF, GIF, SVG). Maximum 50 MB.
</ParamField>

<ParamField body="mode" type="string" required>
  Processing mode. One of: `exact-dimensions`, `aspect-ratio-width-based`, `aspect-ratio-height-based`, `original-aspect`, `multi-aspect-ratio`.
</ParamField>

<ParamField body="dimensions" type="object">
  Required for `exact-dimensions` mode. An object mapping variant names to `{ width, height }` pairs.

  ```json
  { "thumbnail": { "width": 64, "height": 64 }, "card": { "width": 400, "height": 300 } }
  ```
</ParamField>

<ParamField body="aspectRatio" type="object">
  Required for `aspect-ratio-width-based` and `aspect-ratio-height-based` modes. `{ width, height }` ratio.
</ParamField>

<ParamField body="widths" type="object">
  Required for `aspect-ratio-width-based` mode. An object mapping variant names to pixel widths.
</ParamField>

<ParamField body="heights" type="object">
  Required for `aspect-ratio-height-based` mode. An object mapping variant names to pixel heights.
</ParamField>

<ParamField body="sizes" type="object">
  Required for `original-aspect` and `multi-aspect-ratio` modes. An object mapping variant names to longest-edge pixel sizes.
</ParamField>

<ParamField body="aspectRatios" type="array">
  Required for `multi-aspect-ratio` mode. Array of `{ width, height }` aspect ratio objects.
</ParamField>

<ParamField body="fit" type="string">
  Sharp fit strategy. Defaults to `cover`. Valid values depend on the mode:
  - `exact-dimensions`, `aspect-ratio-width-based`, `aspect-ratio-height-based`, `multi-aspect-ratio`: `cover`, `contain`, `inside`, or `outside`
  - `original-aspect`: `inside` or `outside` only (`cover`/`contain` are not valid for this mode)
</ParamField>

<ParamField body="quality" type="number">
  Output quality (1–100). Applies to JPEG and WebP. Defaults to `85`.
</ParamField>

<ParamField body="format" type="string">
  Output format: `webp`, `jpeg`, `png`, or `original`. Defaults to `webp`.
</ParamField>

<ParamField body="stripExif" type="boolean">
  Remove EXIF metadata from output. Defaults to `true`.
</ParamField>

<ParamField body="pathParts" type="array">
  Folder segments for the stored image, as a JSON-encoded array. The new file's id is always added after them, so the image and its sizes are stored under `<pathParts>/<fileId>/`. Example: `["avatars", "user-123"]` → `avatars/user-123/<fileId>/<filename>`. Defaults to `["images"]`. A part that is, or contains, a `.` or `..` folder (also written `%2e%2e`), or that contains `?`, `#` or an encoded slash (`%2f`, `%5c`), is refused with `400 storage/invalid-image-body`.
</ParamField>

<ParamField body="entityId" type="string">
  Associates the file with an entity for cascade deletion. Only the entity's author can attach to it (a service key can attach to any entity).
</ParamField>

<ParamField body="commentId" type="string">
  Associates the file with a comment for cascade deletion. Only the comment's author can attach to it (a service key can attach to any comment).
</ParamField>

<ParamField body="spaceId" type="string">
  Associates the file with a space. Only an active admin of the space can attach to it (a service key can attach to any space).
</ParamField>

<ParamField body="eventId" type="string">
  Associates the image with an event. Only one of the event's hosts can attach to it (a service key can attach to any event). Requires the `events` bundle: without it the upload is refused with `403 storage/events-bundle-required`.
</ParamField>

<ParamField body="userId" type="string">
  Attribute the upload to a specific user. With a user token the upload is
  already attributed to the caller; only **service keys** may name a
  different user. Omit for a backend/project-owned file (no owning user).
</ParamField>

## Response

```json
{
  "fileId": "uuid",
  "type": "image",
  "originalPath": "/internal/files/...",
  "originalSize": 204800,
  "originalWidth": 1920,
  "originalHeight": 1080,
  "variants": {
    "thumbnail": {
      "publicPath": "/internal/files/...",
      "width": 64,
      "height": 64,
      "size": 3200,
      "format": "webp"
    }
  },
  "format": "webp",
  "quality": 85,
  "createdAt": "2025-01-01T00:00:00.000Z"
}
```

## Error Responses

<AccordionGroup>
  <Accordion title="No File — 400 Bad Request">
    ```json
    { "error": "No file provided", "code": "storage/no-file" }
    ```
  </Accordion>
  <Accordion title="File Too Large — 413">
    ```json
    { "error": "File size exceeds the allowed limit of 50MB", "code": "storage/file-too-large" }
    ```
  </Accordion>
  <Accordion title="Invalid Image — 422">
    ```json
    { "error": "Invalid image file", "code": "storage/invalid-image" }
    ```
  </Accordion>
  <Accordion title="Not Allowed To Attach — 403">
    ```json
    { "error": "Not authorized to attach a file to this entity.", "code": "storage/unauthorized" }
    ```
    The caller can't update the record named by `entityId`, `commentId`, `spaceId` or `eventId`: they aren't the entity's or comment's author, an active admin of the space, or a host of the event. The message names the record type. Nothing is stored.
  </Accordion>
  <Accordion title="Record Not Found — 404">
    ```json
    { "error": "Entity not found", "code": "storage/entity-not-found" }
    ```
    The record named by `entityId`, `commentId`, `spaceId` or `eventId` doesn't exist, or counts as missing: a deleted record, an entity removed by moderation, a comment its author deleted, and a space the caller can't see (a private space they aren't in, for example) all answer 404. The code is `storage/entity-not-found`, `storage/comment-not-found`, `storage/space-not-found` or `storage/event-not-found`. Nothing is stored.
  </Accordion>
</AccordionGroup>
