---
title: "Remove Host"
api: "DELETE /v8/:projectId/events/:eventId/hosts/:userId"
description: "Revoke a user's host privileges on an event (host-only)"
---

Removes a user from the event's `hostIds`. A service key acts as the user it names in `actingUserId`. The mutation runs under a row-level lock.

- **Removing another host** is **owner-only**: the caller must be the event's [owner](/v8/data-models/event#owner-and-hosts), and, for an event in a space, an active member of that space who isn't banned in it or a space above it.
- **Stepping down** (the path's `userId` is the caller): any host other than the owner may step down, active member of the event's space or not. The owner is always one of the event's hosts and can't step down or be removed (`409 event/owner-is-host`).
- On an event whose owner's account was deleted, nobody can remove another host, and its last remaining host can't step down (`409 event/last-host`); they can [cancel](/v8/api-reference/events/cancel-event) the event instead.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

<ParamField path="userId" type="string" required>
  The host to remove. A malformed id returns `400 event/invalid-params`.
</ParamField>

## Query Parameters

A DELETE takes no body: every field besides the path goes in the query string.

<ParamField query="actingUserId" type="string">
  Required with a service key: the user this request acts as. It has exactly that user's powers, so it is refused unless they are the event's owner (or, when stepping down, a host), and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Event](/v8/data-models/event) with the new `hostIds`. A host who stepped down from an event they can no longer [see](/v8/data-models/event#visibility) gets only:

```json
{ "id": "<eventId>" }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Body Not Allowed — 400">
    The request carried a body. A DELETE takes no body: the host goes in the path and `actingUserId` in the query string.
    ```json
    {
      "error": "A DELETE request takes no body: send its fields in the query string. Received: `actingUserId`.",
      "code": "event/body-not-allowed",
      "params": ["actingUserId"]
    }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    The event doesn't exist, or the caller can't [see it](/v8/data-models/event#visibility) and isn't one of its hosts.
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden (not a host) — 403">
    The caller tried to step down from an event they don't host.
    ```json
    { "error": "Only a host of this event may manage its hosts.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Forbidden (not the owner) — 403">
    The caller isn't the event's owner. Other hosts can't add or remove hosts; on an event whose owner's account was deleted, nobody can.
    ```json
    { "error": "Only the event's owner may add or remove hosts.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Host Not an Active Member — 403">
    The caller is the owner, removing another host, but the event is in a space they aren't an active member of, or they are banned in it or a space above it. One body for every case.
    ```json
    { "error": "Hosts must be active members of this event's space, and not banned from it or a space above it, to do this.", "code": "event/not-space-member" }
    ```
  </Accordion>
  <Accordion title="Owner Is Host — 409">
    The owner tried to step down. The owner can't be removed.
    ```json
    { "error": "The event's owner is always one of its hosts.", "code": "event/owner-is-host" }
    ```
  </Accordion>
  <Accordion title="Last Host — 409">
    The last remaining host of an event whose owner's account was deleted tried to step down.
    ```json
    { "error": "An event must have at least one host.", "code": "event/last-host" }
    ```
  </Accordion>
  <Accordion title="Unsupported Route — 400">
    `DELETE /v8/:projectId/events/:eventId/hosts`, with the host in a request body, is not a v8 route. Once the request passes the checks that run ahead of it (such as the bundle check and id validation), it gets this error, with or without a body.
    ```json
    {
      "error": "`DELETE /events/:eventId/hosts` isn't supported in v8. Remove a host with `DELETE /events/:eventId/hosts/:userId`, with the host's user id in the path.",
      "code": "event/unsupported-route"
    }
    ```
  </Accordion>
</AccordionGroup>

See also: [useRemoveHost](/v8/hooks/events/use-remove-host)
