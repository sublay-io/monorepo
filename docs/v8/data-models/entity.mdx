title: "Entity"

An entity is the central content unit in Sublay — it can represent a post, article, product listing, video, or any other piece of content in your application. Entities support reactions, comments, votes, file attachments, geo-location, and more.

<Note>
  Entities are provided by the optional **`entities`** bundle. A project without it returns `403 database/tables-not-available` for entity endpoints. See [Bundles](/v8/bundles).
</Note>

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | Unique entity identifier (UUID). |
| `foreignId` | `string \| null` | Your system's content ID, if this entity maps to existing data. Can also be a static identifier like `"about-page"`. Unique within the project, including deleted entities: a deleted entity's `foreignId` can't be reused (`409 entity/foreign-id-taken`). |
| `shortId` | `string` | Auto-generated short identifier, useful for sharing links. |
| `projectId` | `string` | The project this entity belongs to. |
| `sourceId` | `string \| null` | Groups entities by content type within a project. Useful when one project hosts multiple distinct categories of content (e.g. `"user-post"` vs `"blog-post"`), allowing you to filter and separate them without creating separate projects. `null` means no source. The strings `"none"`, `"null"` and `"undefined"` are reserved and can't be stored. |
| `spaceId` | `string \| null` | The space this entity belongs to, if any. |
| `space` | `Space \| null` | Populated space object when `include` contains `"space"`. An entity in a space the viewer can't read isn't returned at all (see [Who can read content](/v8/data-models/space#who-can-read-content)); the one exception is your own drafts in [Fetch Drafts](/v8/api-reference/entities/fetch-drafts), where `space` is `null` when you can't see the space (`spaceId` still names it). |
| `userId` | `string \| null` | The author: the user whose token created it, or the user a service key named in `actingUserId`. `null` for an app-owned entity — created by a service key naming nobody, by a request with no credentials, or by [`createIfNotFound`](/v8/api-reference/entities/fetch-entity-by-foreign-id) (who may create one is the project's **Who can create entities without an author** setting) — and for a published entity whose author was deleted; only a service key naming nobody may edit or delete it. |
| `user` | `User \| null` | The author. Populated when `include` contains `"user"`. |
| `title` | `string \| null` | Optional title. |
| `content` | `string \| null` | Optional text content. |
| `mentions` | `Mention[]` | Array of user mentions embedded in the content. |
| `attachments` | `Record<string, any>[]` | Flexible array of media/attachment metadata objects. |
| `files` | `File[]` | System-managed file associations. Populated when `include` contains `"files"`. |
| `keywords` | `string[]` | Tags used for filtering and discovery. |
| `upvotes` | `string[]` | Legacy v6 field — array of user IDs that upvoted. Use `reactionCounts` instead. |
| `downvotes` | `string[]` | Legacy v6 field — array of user IDs that downvoted. Use `reactionCounts` instead. |
| `reactionCounts` | `ReactionCounts` | Counts for all 8 reaction types. See [Reaction](/v8/data-models/reaction). |
| `userReaction` | `ReactionType \| null` | The current user's reaction. Only present when the user is authenticated and has reacted to this entity. |
| `commentsCount` | `number` | How many comments the entity has, at any depth. Counts everything its thread contains — deleted, removed and unavailable comments included, since they stay in the thread as [placeholders](/v8/data-models/comment#placeholders) — so it's the same number for every user. |
| `sharesCount` | `number` | Share counter stored on the entity. `0` by default. |
| `views` | `number` | View count. Auto-incremented on every fetch by a person: a signed-in user, an anonymous caller, or a service key naming a user in `actingUserId` (a service key naming nobody doesn't count). Can also be incremented manually via the service-key-only `POST /entities/:entityId/increment-views` endpoint. |
| `score` | `number` | Computed "hotness" score based on engagement activity. |
| `scoreUpdatedAt` | `Date` | When the score was last recalculated. |
| `location` | `GeoPoint \| null` | Optional geo-location stored as a GeoJSON point. |
| `metadata` | `Record<string, any>` | Custom key-value data (max 10 KB). |
| `topComments` | `Comment[]` | The entity's best top-level comments, as full [Comment](/v8/data-models/comment) objects. Populated when `include` contains `"topComments"`; `[]` when none qualify. See [Top comments](#top-comments). |
| `saved` | `EntitySaved` | Whether the current user has saved this entity, and in which of their collections. Populated when `include` contains `"saved"`. See [Saved state](#saved-state). |
| `grants` | `GrantSummary \| undefined` | Per-item [reputation-grant](/v8/data-models/reputation-grant) summary — `{ total, count, viewerTotal }` over **positive** grants. Populated when `include` contains `"grants"`. Zero-filled rather than omitted on a project with no grants, so `undefined` always means "nobody asked". |
| `isDraft` | `boolean \| null` | Whether this entity is in draft state. A draft is created with an author (a user token, or a service key with `actingUserId`), and only its author sees it. Deleting the author deletes their drafts. A draft with no author is answered as not found (`404`), like a missing entity. |
| `nsfw` | `boolean` | The entity's **own** NSFW flag. `false` by default. Set on create/update by the owner (a service key acting as the author, or naming nobody for an app-owned entity), or by a space moderator via the [set-NSFW endpoint](/v8/hooks/spaces/use-set-space-entity-nsfw). See [NSFW flagging](#nsfw-flagging). |
| `nsfwEffective` | `boolean` | **Computed live, read-only.** `true` when the entity's own `nsfw` is `true` **or** its space is effectively NSFW: `entity.nsfw OR (space?.nsfwEffective ?? false)`. This is the value the `nsfwFilter` query param keys off. See [NSFW flagging](#nsfw-flagging). |
| `moderationStatus` | `"approved" \| "removed" \| null` | Current space moderation status. Visible to everyone. |
| `moderatedAt` | `Date \| null` | When the moderation action was taken. |
| `moderatedById` | `string \| null` | ID of who took the action: the space moderator's user ID when `moderatedByType` is `"user"`, the dashboard account's ID when it is `"client"`. Visible only to some requesters — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `moderatedByType` | `"client" \| "user" \| null` | `"user"` when a space moderator took the action (through a report or directly); `"client"` when it was taken from the dashboard. Visible only to some requesters — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `moderationReason` | `string \| null` | Reason provided for moderation. Visible only to some requesters, including the entity's author — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `createdAt` | `Date` | When the entity was created. |
| `updatedAt` | `Date` | When the entity was last updated. |
| `deletedAt` | `Date \| null` | Soft-delete timestamp. `null` for active entities. |

## Moderation fields

`moderationStatus` is returned to everyone. The other three moderation fields are returned only to some requesters, on every entity response; everyone else gets `null`. The requester is the signed-in user, or the user a service key names in `actingUserId` (the key then gets exactly that user's view); a service key naming nobody is treated as signed out:

| Requester | `moderationReason` | `moderatedById`, `moderatedByType` |
|---|---|---|
| An active admin or moderator of the entity's space | ✓ | ✓ |
| A user whose project [`role`](/v8/data-models/user) is `admin` or `moderator` | ✓ | ✓ |
| The entity's author | ✓ | — |
| Anyone else, including signed-out requests and a service key naming nobody | — | — |

An entity with no space has no space moderators: only project-role admins and moderators and the entity's author qualify.

## Nested Types

### GeoPoint

| Property | Type | Description |
|----------|------|-------------|
| `type` | `"Point"` | GeoJSON geometry type. Always `"Point"`. |
| `coordinates` | `[number, number]` | Longitude and latitude, in that order. |

### EntitySaved

| Property | Type | Description |
|----------|------|-------------|
| `isSaved` | `boolean` | `true` when the entity is in at least one of the current user's collections. |
| `collections` | `{ id: string; name: string }[]` | The current user's collections that hold the entity, in the order it was saved into them. `[]` when it isn't saved. |

## NSFW flagging

An entity carries its own `nsfw` boolean and exposes a live-computed `nsfwEffective`:

- **`nsfw`** — the entity's own flag. It defaults to `false` and is what the owner or a space moderator toggles.
- **`nsfwEffective`** — never stored on the entity. It is computed on **every** read as:

  ```
  nsfwEffective = entity.nsfw OR COALESCE(space.nsfwEffective, false)
  ```

  So an entity reads as effectively NSFW when either its own flag is set **or** the space it lives in is effectively NSFW (which itself folds in the space's whole ancestor chain — see [Space → NSFW flagging](/v8/data-models/space#nsfw-flagging)). A space-less entity (`spaceId` is `null`) falls back to its own flag; on a project without the spaces bundle, the space contribution is simply absent and `nsfwEffective` equals `entity.nsfw`.

The effect is a live OR: clearing an entity's own `nsfw` **cannot** make it read safe while its space chain is still NSFW, and flagging a space instantly cascades to every entity inside it without stamping or backfilling entity rows.

To filter a list by effective NSFW, pass `nsfwFilter` to [Fetch many entities](/v8/hooks/entities/use-fetch-many-entities) (`include-all` default / `exclude` / `only`).

<Note>
  Sublay only **labels** (`nsfw`) and **filters** (`nsfwFilter`) content. It does **not** blur, age-gate, add interstitials, or store a per-viewer "show mature content" preference — how NSFW-flagged content is presented is entirely the consuming app's responsibility.
</Note>

## Saved state

`include=saved` adds `saved`, the current user's saved state for each entity: whether it is saved, and the collections it is in. It works the same on a single fetch and on a list, so a feed can show which of the user's collections hold each entity without another request.

```json
"saved": {
  "isSaved": true,
  "collections": [
    { "id": "0b1c4e1a-6c1f-4a8e-9d55-1f2a3b4c5d6e", "name": "Favorites" },
    { "id": "7f8e9d0c-1b2a-4c3d-8e4f-5a6b7c8d9e0f", "name": "Recipes" }
  ]
}
```

Only the current user's own collections are listed. With no current user (a request with no credentials, or a service key without `actingUserId`), `saved` is `{ "isSaved": false, "collections": [] }`. A service key that names a user in `actingUserId` gets that user's saved state. On a project without the `collections` bundle, `saved` is also `{ "isSaved": false, "collections": [] }`.

In the React and React Native SDKs, adding an entity to a collection or removing it from one through `useCollections` or `useCollectionsActions` updates `saved` on the entity in every entity list that carries it; lists fetched without `include=saved` don't gain the field. Renaming a collection through `updateCollection` updates its name in `saved` the same way, and deleting a collection through `deleteCollection` drops it, and every collection under it, from `saved.collections`; `isSaved` stays `true` only while another collection is listed. These updates, like those for reactions, edits and comment counts, reach lists loaded with [`useEntityList`](/v8/hooks/entity-lists/use-entity-list), and an `EntityProvider` given one of their entities. They don't reach an `EntityProvider` that fetched the entity itself, or entities held by [`useFetchManyEntitiesWrapper`](/v8/hooks/entities/use-fetch-many-entities-wrapper); fetch those again to see the change.

## Top comments

`include=topComments` adds a preview of the entity's best comments — for example, the top comment under each entity in a feed, or a few rotating ones.

- Each item is a full [Comment](/v8/data-models/comment), with its author (`user`) always included.
- Only **top-level** comments, ranked by the raw count of one reaction (`topCommentsSortByReaction`, default `upvote`), ties newest first.
- `topCommentsLimit` sets how many per entity: a whole number of at least `1`, default `1`, maximum `5` (larger values are treated as `5`). `0`, a negative number or a non-integer value returns `400`.
- **Real content only:** deleted and moderator-removed comments are left out (for everyone, the author included), and so are comments whose author is block-edged with the requesting user, in either direction. So `isAuthorBlocked` and `isUnavailable` are always `false` here.
- `[]` when no comment qualifies, on a project without the `comments` bundle, and on an entity whose author has blocked the requesting user (for example, one they saved to a collection before the block).

Sending `topCommentsLimit` or `topCommentsSortByReaction` without `include=topComments` returns `400`.

To render a full discussion — including placeholders, so replies stay in place — use [Fetch Many Comments](/v8/api-reference/comments/fetch-many-comments).

## Includes

Pass `include` to populate optional fields. Each endpoint accepts its own list; an unknown value returns `400`.

| Include value | Populates | Entity fetches and lists | Collection entities | Drafts |
|--------------|-----------|:---:|:---:|:---:|
| `"user"` | `user` — the entity author | ✓ | ✓ | ✓ |
| `"space"` | `space` — the associated space | ✓ | ✓ | ✓ |
| `"topComments"` | `topComments` — the best top-level comments | ✓ | ✓ | |
| `"saved"` | `saved` — whether the current user saved this entity, and in which collections | ✓ | | |
| `"files"` | `files` — managed file records | ✓ | ✓ | ✓ |
| `"grants"` | `grants` — the reputation-grant summary | ✓ | ✓ | ✓ |

"Entity fetches and lists" are [Fetch Entity](/v8/api-reference/entities/fetch-entity), [by foreign ID](/v8/api-reference/entities/fetch-entity-by-foreign-id), [by short ID](/v8/api-reference/entities/fetch-entity-by-short-id) and [Fetch Many Entities](/v8/api-reference/entities/fetch-many-entities). Collection entities don't take `"saved"`: every entity listed there is in that collection.
