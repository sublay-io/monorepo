# Social Comments Features

Instagram-style comment system features.

---

## Core Features

### Single-Level Nesting

Maximum 2 levels: comments and replies. Keeps conversations simple and easy to follow.

```
Comment 1
  └─ Reply to Comment 1
  └─ Another reply

Comment 2
  └─ Reply to Comment 2
```

---

### Heart/Like System

Positive-only engagement with heart icons.

- Heart button with like count display
- One like per user per comment
- Unlike at any time
- No downvotes — positive community focus

---

### Loading Replies

Replies load on demand: a "View more replies (N)" button ("View N more replies" on React Native) under each comment loads them in place, then the next batch while there are more, and "Hide replies" collapses them once all are loaded. The count subtracts the replies the user just posted, which are already shown.

Top-level comments load 10 at a time — with a **Load more comments** button on web, and as the list scrolls on React Native.

---

### Blocked Users

When the `moderation` bundle is installed, comments involving a block render as compact rows instead of disappearing, so the replies under them stay in place:

- **"This comment is unavailable"** — the comment's author blocked the user. No author, content, reply or reaction controls are shown. If the user had reacted before, they can still remove their reaction.
- **"Comment from a user you blocked"** — the user blocked this author. The row starts collapsed with a **Show anyway** button; once shown, the comment can be replied to and reacted to as usual.

Edit the row text in `comment.tsx`. See [Comment → Blocked authors](/v8/data-models/comment#blocked-authors) for the underlying flags.

---

### Deleted & Removed Comments

A comment its author deleted shows `[deleted]` in place of the author name and the text; a comment a moderator removed shows `[removed]`. The row has no reply, reaction or menu controls, and the replies under it stay in place. Replying to a reply goes to its top-level comment, so the replies under a deleted or removed comment have no Reply button either. The author of a removed comment still sees it in full, with a muted note under the text — `Removed by a moderator · only you can see this`, or `Removed by a moderator: <reason> · only you can see this` when the moderator gave a reason. Their row keeps delete, but has no Reply or like button, since the server refuses both. A comment whose author blocked the user shows as **"This comment is unavailable"** instead, even when it is also deleted or removed — and the replies under it have no Reply button, for the same reason.

Edit the row text in `comment.tsx`. See [Comment → Placeholders](/v8/data-models/comment#placeholders) for the underlying fields.

---

### Sorting

Built-in Top/New/Old sorting that users can switch on the fly. The section opens on **Top**.

- **Top** — Most liked comments first: ranked by the `like` reaction, which is what the heart records
- **New** — Newest comments first
- **Old** — Oldest comments first

Replies follow the section's sort, so under **Top** they are ranked by likes too.

---

### @ Mentions

Tag users with `@username`.

- Autocomplete suggestions as you type
- Clickable mentions link to user profiles (via `otherUserClickCallback`)
- Mentioned users receive notifications (if enabled)
- Works in both comments and replies

---

### Delete

Comment authors can delete their own comments.

- **Delete:** "Remove" in the comment menu ("Delete" on React Native), then a confirmation; the comment shows as `[deleted]`, keeping its replies in place

---

### Reporting

Built-in reporting for inappropriate content.

- Click "Report" from the action menu
- Select a reason and submit
- Reports appear in the [Sublay Dashboard](https://dash.sublay.io) for admin review

---

### Loading States

Skeleton loaders while fetching comments — prevents layout shift and provides visual feedback.

---

### Empty States

Friendly placeholder when no comments exist. Customize `no-comments-placeholder.tsx` to change messaging or add illustrations.

---

### Error States

When a load fails, the component shows a retry instead of a wrong or stuck state:

- **First load fails** — "Couldn't load comments" with a **Try again** button, in place of the empty state.
- **The entity can't be loaded** — the same "Couldn't load comments" with **Try again**. This is the case when the section looks the entity up from `entityId`, `foreignId` or `shortId` and the lookup fails or finds nothing. A `foreignId` that has no entity yet finds nothing unless the section is given [`createIfNotFound`](/v8/components/components/social/props-api#createifnotfound).
- **Loading more top-level comments fails** — "Couldn't load more · Try again" in place of the **Load more comments** button on web, and at the bottom of the list on React Native.
- **Loading replies fails** — the same "Couldn't load more · Try again" in place of the "View more replies" button.

**Try again** calls the same `loadMore()` that failed, which re-sends the failed request. When the entity couldn't be loaded, it looks the entity up again first, and the comments load once it is found. Edit the text in `comments-feed.tsx` (and `comments-footer-component.tsx` on React Native) and `comment/replies/show-hide-button.tsx`.

When posting a comment or a reply fails, a short muted message appears by the comment form — under the input on web, above it on React Native:

- **Replying to a comment that was deleted in the meantime** — "This comment was deleted, so you can't reply to it."
- **Replying to a comment a moderator removed in the meantime** — "This comment was removed, so you can't reply to it."
- **Any other failure** — "Couldn't post your comment. Try again."

The text you typed stays in the input, and the message goes away when you edit the text or send again. A GIF that fails to post keeps the text and mentions in the input too. In the first two cases the comment also turns into its `[deleted]` / `[removed]` row (or, for its author, the removed-note row), which has no Reply. The "Replying to …" banner stays, as after any failed reply; close it to post the text as a top-level comment instead.

The messages are chosen in `utils/comment-create-error.ts`, worded in `utils/strings.ts` and rendered in `new-comment-form.tsx`, from the section's [`createError`](/v8/sdk/comments/comment-section#usecommentsection-return-values).

---

### Real-Time Updates

Comments automatically update when other users post. No configuration required — powered by `@sublay/react-js` subscriptions.

---

### Dark Mode

Full dark mode support.

**Inline Styles Variant:**
```tsx
<SocialCommentSection
  entityId={entity.id}
  theme={isDark ? 'dark' : 'light'}
/>
```

**Tailwind Variant on React:**
```tsx
<html className={isDark ? 'dark' : ''}>
  <SocialCommentSection entityId={entity.id} />
</html>
```

On React Native and Expo, the Tailwind variant takes `theme` the same way as the inline styles variant.

---

### GIF Support (Optional)

GIFs come from Giphy and need a Giphy API key, read from your app's environment. The key is read in `utils/env.ts`, inside the component's folder, which `add` writes for your framework (it looks for `next`, `vite` or `react-scripts` in your `package.json`):

| Framework | Environment variable |
|-----------|----------------------|
| Next.js | `NEXT_PUBLIC_GIPHY_API_KEY` |
| Vite | `VITE_GIPHY_API_KEY` |
| Create React App | `REACT_APP_GIPHY_API_KEY` |
| Expo | `EXPO_PUBLIC_GIPHY_API_KEY` |
| Other web frameworks, React Native without Expo | None: `utils/env.ts` reads nothing until you edit it to read your key. On other web frameworks it also can't tell development from production, so until you edit it the GIF button, and without a key the alert, show in production too |

To use a different variable, change its name in `utils/env.ts`. Without a key, the GIF button shows only in development, and clicking it shows an alert naming the variable to set. In production the button is hidden until there is a key (on other web frameworks, once `isDevelopment` in `utils/env.ts` reads your framework's development flag).
