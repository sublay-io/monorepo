## Overview

`useCreateSpace` returns a callable function for creating a new space. The request can include an avatar and a banner image (`avatarFile`, `bannerFile`). The creator is automatically added as an admin.

## Usage Example

```tsx
import { useCreateSpace } from "@sublay/react-js";

function CreateSpaceForm() {
  const createSpace = useCreateSpace();

  const handleSubmit = async () => {
    const space = await createSpace({
      name: "Design Community",
      slug: "design-community",
      description: "A place for designers to share work and ideas.",
      readingPermission: "anyone",
      postingPermission: "members",
      requireJoinApproval: false,
    });
    console.log("Created:", space.id);
  };
}
```

With an avatar:

```tsx
const space = await createSpace({
  name: "Design Community",
  avatarFile: {
    file, // e.g. from an <input type="file">
    options: { mode: "exact-dimensions", dimensions: { small: { width: 64, height: 64 }, large: { width: 256, height: 256 } } },
  },
});
```

## Parameters

<ParamField path="name" type="string" required>
  Display name for the space. 3–100 characters.
</ParamField>

<ParamField path="slug" type="string">
  Optional URL slug. Must be unique per project. Supports letters, numbers, hyphens, and underscores (Unicode allowed).
</ParamField>

<ParamField path="description" type="string">
  Optional description. Up to 1,000 characters.
</ParamField>

<ParamField path="avatarFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
  Optional avatar image to upload, up to 50 MB. `file` is a `File` or `Blob`, or a React Native file `{ uri, name, type? }`. `options` controls how the image is processed and must include `mode` (see [Upload Image](/v8/api-reference/storage/upload-image)). With an image, the request is sent as `multipart/form-data`.
</ParamField>

<ParamField path="bannerFile" type="{ file: UploadFileInput; options: UploadImageOptions }">
  Optional banner image to upload; same shape as `avatarFile`.
</ParamField>

<ParamField path="readingPermission" type='"anyone" | "members"'>
  Who can read content. Defaults to `"anyone"`.
</ParamField>

<ParamField path="postingPermission" type='"anyone" | "members" | "team"'>
  Who can post entities: `"anyone"`, `"members"` (active members), or `"team"` (the space's active admins and moderators). Defaults to `"members"`.
</ParamField>

<ParamField path="visibility" type='"public" | "unlisted" | "private"'>
  Who can find and see the space. Defaults to `"public"`. Independent of `readingPermission` (which governs content). `"unlisted"` keeps the space out of the directory and search, and out of sub-space lists for non-members, but reachable by id, short id or slug; `"private"` makes it seen only by its active members (everyone else gets `404`), and it can't be joined: members are [added](/v8/api-reference/spaces/membership/add-member) by its moderators and admins. See [Space visibility](/v8/data-models/space#visibility).
</ParamField>

<ParamField path="nsfw" type="boolean">
  The space's own NSFW flag. Defaults to `false`. If the space is created under an NSFW parent, its effective NSFW status is `true` regardless of this value (a live rollup — see [Space NSFW flagging](/v8/data-models/space#nsfw-flagging)). Sublay labels and filters NSFW content; it does not blur or age-gate it.
</ParamField>

<ParamField path="requireJoinApproval" type="boolean">
  Whether new members must be approved. Defaults to `true`.
</ParamField>

<ParamField path="metadata" type="Record<string, any>">
  Optional custom metadata. Up to 1 MB.
</ParamField>

<ParamField path="parentSpaceId" type="string">
  Optional UUID of a parent space. The creator must be an admin of the parent space.
</ParamField>

## Returns

Returns the created [Space](/v8/data-models/space) object plus `memberPermissions`: what the creator may do in the new space (see [SpaceMemberPermissions](/v8/data-models/space#spacememberpermissions)).

<Note>When creating a child space, all admins and moderators of the parent space are automatically added to the new child space with their same roles.</Note>
