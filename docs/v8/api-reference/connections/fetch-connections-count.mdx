---
title: "Fetch Connections Count"
api: "GET /v8/:projectId/connections/count"
description: "Get the number of accepted connections for the authenticated user"
---

Returns the total number of accepted connections for the authenticated user.

<Note>
  Users with a block between them and you, in either direction, are excluded
  from the count. Requires the `moderation` bundle.
</Note>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their accepted connections are counted. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`:

<ResponseField name="count" type="number">
  Total number of accepted connections for the authenticated user.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "Missing user ID",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "connection/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
