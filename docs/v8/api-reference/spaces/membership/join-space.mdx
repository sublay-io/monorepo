---
title: "Join Space"
api: "POST /v8/:projectId/spaces/:spaceId/join"
description: "Join a space or submit a membership request"
---

Joins a space. If the space has `requireJoinApproval: true`, the membership is created with `status: "pending"` until approved. Otherwise it is immediately `active`.

## Path Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space to join.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who joins the space. A user token always acts as its own user and must not send it (`400 space/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="message" type="string">
  Confirmation message.
</ResponseField>

<ResponseField name="membership" type="object">
  <Expandable title="properties">
    <ResponseField name="id" type="string">Membership record UUID.</ResponseField>
    <ResponseField name="spaceId" type="string">Space UUID.</ResponseField>
    <ResponseField name="userId" type="string">User UUID.</ResponseField>
    <ResponseField name="role" type="string">`"member"`</ResponseField>
    <ResponseField name="status" type="string">`"pending"` or `"active"`</ResponseField>
    <ResponseField name="joinedAt" type="Date">Creation timestamp.</ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `spaceId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid space id: expected a UUID.", "code": "space/invalid-params" }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "space/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "space/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "space/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Space Not Found — 404">
    ```json
    { "error": "Space not found.", "code": "space/not-found" }
    ```
  </Accordion>
  <Accordion title="Banned — 403">
    ```json
    { "error": "You are banned from this space.", "code": "space/banned" }
    ```
    Also returned when the user is banned in a parent of this space; `bannedSpaceIds` lists those spaces:
    ```json
    { "error": "You are banned from a parent of this space.", "code": "space/banned", "bannedSpaceIds": ["…"] }
    ```
  </Accordion>
  <Accordion title="Already a Member — 409">
    ```json
    { "error": "You are already a member of this space.", "code": "space/already-member" }
    ```
  </Accordion>
</AccordionGroup>
