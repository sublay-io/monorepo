---
title: "Send Verification Email"
api: "POST /v8/:projectId/auth/send-verification-email"
description: "Send an email verification token or link to the authenticated user"
---

Sends a verification email to the authenticated user's registered email address. The token or link expires after **5 minutes**.

This is for a signed-in user. When the project requires email verification before sign-in, unconfirmed users with a password can't be signed in; they get their confirmation email from [Sign Up](/v8/api-reference/auth/sign-up) and from a refused [Sign In](/v8/api-reference/auth/sign-in) instead, and that link or code lasts **24 hours**.

Requires a valid user access token, or a service key that names the user in `actingUserId`. Returns `204` at once, sending nothing, if the user is already verified.

## Body Parameters

All parameters are optional.

<ParamField body="mode" type='"code" | "link"' default='"code"'>
  Delivery mode.

  - `"code"` — The email contains a short token the user types into your app. Call the [Verify Email](/v8/api-reference/auth/verify-email) endpoint to complete verification.
  - `"link"` — The email contains a button that opens a Sublay page where the user confirms; confirming verifies the email, then shows a success page that sends them on to `redirectUrl` (or stays there if none was given). See [Verify Email Link](/v8/api-reference/auth/verify-email-link).
</ParamField>

<ParamField body="tokenFormat" type='"hex" | "numeric" | "alpha" | "alphanumeric"' default='"hex"'>
  Character set used to generate the token.

  | Value | Example | Notes |
  |-------|---------|-------|
  | `"hex"` | `a3f9c2...` | 64-character hex string. `tokenLength` is ignored. |
  | `"numeric"` | `048291` | Digits only (0–9). Good for OTP-style inputs. |
  | `"alpha"` | `GXRTPK` | Uppercase letters only (A–Z). |
  | `"alphanumeric"` | `B4KR9Z` | Uppercase letters and digits. |
</ParamField>

<ParamField body="tokenLength" type="number" default="6">
  Length of the generated token. Must be an integer between `4` and `12`. Ignored when `tokenFormat` is `"hex"`.
</ParamField>

<ParamField body="redirectUrl" type="string">
  A URL to redirect the user to after they click the verification link. Only used when `mode` is `"link"`.

  Must be an `https` address on one of your project's **Verified Domains** (Dashboard → Settings → Domains). Each entry covers exactly the host it names, never its subdomains: `example.com` allows `https://example.com/…` on any port, but not `www.example.com`, which needs its own entry. A full address such as `https://app.example.com` covers only that host and port. `localhost` and `*.localhost` are always allowed, over `http` too. Anything else, including a custom-scheme deep link such as `myapp://verified`, is refused with `400 auth/redirect-url-not-allowed` and no email is sent.

  On success `verified=true` is added to its query string. An invalid or expired link shows the hosted error page instead of redirecting.

  If omitted, the server renders a hosted success/error page.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who is sent the verification email. A user token always acts as its own user and must not send it (`400 auth/acting-user-not-allowed`).
</ParamField>

## Response

`204 No Content` with no body whenever the request is processed without a server error, including when the user is already verified.

## Error Codes

| Code | Status | Description |
|------|--------|-------------|
| `auth/redirect-url-not-allowed` | 400 | `mode` is `"link"` and `redirectUrl` isn't an `https` address on one of the project's Verified Domains (or `localhost`). `param` is `redirectUrl`. No email is sent. |
| `auth/not-password-user` | 400 | The authenticated user does not have an email/password account. |
| `auth/missing-user-id` | 400 | A service key sent no `actingUserId`. Error text: `A service key must send actingUserId: the user this request acts as.` |
| `auth/user-not-found` | 404 | A service key named an `actingUserId` that isn't a user in this project (error text: `No user with this actingUserId exists in this project.`), or the access token is valid but no matching user record exists (e.g. the account was already deleted). |
| `auth/acting-user-not-allowed` | 400 | A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as. Error text: `actingUserId is only accepted with a service key. A user's own token always acts as that user.` |
| `auth/unsupported-param` | 400 | The request sent `userId`; on this route the user a service key acts as is `actingUserId`. Error text with a service key: ``"`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`."``; with a user token, or with no credentials: ``"`userId` isn't accepted here: a user's own token always acts as that user."``. The response carries `"param": "userId"`. |
| `auth/email-send-failed` | 502 | The email provider couldn't send the email, so nothing was delivered. Error text: `Failed to send verification email.` Calling again sends a new email. |

<Note>
  Each call generates a new token. A previous unused token remains valid in
  Redis until it either expires or the new one is consumed first.
</Note>
