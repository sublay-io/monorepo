## Overview

`useFetchManyChatMessagesWrapper` is a stateful wrapper around [`useFetchManyChatMessages`](/v8/hooks/chat/messages/use-fetch-many-chat-messages) that manages the message list and cursor pagination for you. It keeps results in local component state — **not** Redux — and never receives socket updates.

Use it for a read-only or **filtered** list of messages that should not be touched by live traffic — for example, a "messages with replies" panel, an admin/moderation view, or any custom message list outside the live conversation stream. For the live canonical conversation view, use [`useLiveChatMessages`](/v8/hooks/chat/messages/use-live-chat-messages) instead.

<Note>This is a point-in-time query: it does not auto-update from socket events. Call `refetch` (e.g. on a refresh button, or on a socket signal of your choosing) to pick up new matches. It does not require `ChatProvider`.</Note>

## Usage Example

```tsx
import { useFetchManyChatMessagesWrapper } from "@sublay/react-js";

function MessagesWithReplies({ conversationId }: { conversationId: string }) {
  const { messages, loading, hasMore, loadMore, refetch } =
    useFetchManyChatMessagesWrapper({
      conversationId,
      filters: { hasReplies: true },
    });

  return (
    <div>
      <button onClick={refetch} disabled={loading}>Refresh</button>
      {messages.map((m) => (
        <div key={m.id}>
          {m.content} · {m.threadReplyCount} replies
        </div>
      ))}
      {hasMore && (
        <button onClick={loadMore} disabled={loading}>Load more</button>
      )}
    </div>
  );
}
```

## Props

<ParamField body="conversationId" type="string" required>
  The ID of the conversation to query.
</ParamField>

<ParamField body="parentMessageId" type="string | null">
  Restrict to thread replies of this message.
</ParamField>

<ParamField body="limit" type="number">
  Page size. Defaults to `50`.
</ParamField>

<ParamField body="sortDir" type='"asc" | "desc"'>
  Sort by creation time. Defaults to `"desc"` (newest first), where `loadMore` fetches older messages. With `"asc"`, `loadMore` fetches newer messages.
</ParamField>

<ParamField body="include" type="ChatMessageListIncludeParam">
  Fields to add to each message, as a single value or an array:
  - `"files"` — the `files` field.
  - `"grants"` — the [reputation-grant summary](/v8/data-models/reputation-grant#grantsummary) at `message.grants`: `{ total, count, viewerTotal }` over positive grants. Populated by the `reputation` bundle; on a project without it the summary comes back zero-filled rather than missing.
</ParamField>

<ParamField body="filters" type="MessageFilters">
  Optional filters. `filters.hasReplies` (boolean): when `true`, returns only messages that have thread replies (`threadReplyCount > 0`); when `false`, only messages with none. Filters by thread replies, not quotings.

  <Note>Threads are one level deep, so `hasReplies: true` together with `parentMessageId` always yields an empty list. This wrapper exposes only `messages`; use the lower-level [`useFetchManyChatMessages`](/v8/hooks/chat/messages/use-fetch-many-chat-messages) if you want the `notice` explaining why.</Note>
</ParamField>

## Returns

<ResponseField name="messages" type="ChatMessage[]">
  The loaded messages. See [ChatMessage](/v8/data-models/chat-message).
</ResponseField>

<ResponseField name="loading" type="boolean">
  `true` while a fetch is in progress.
</ResponseField>

<ResponseField name="error" type="Error | null">
  The last load failure, or `null`. Cleared when the next load starts; `loadMore()` retries it.
</ResponseField>

<ResponseField name="hasMore" type="boolean">
  `true` while `loadMore()` has something to fetch: a next page, or a load that failed.
</ResponseField>

<ResponseField name="loadMore" type="() => Promise<void>">
  Loads the next page in the direction of `sortDir` and appends it: older messages with `"desc"` (the default), newer ones with `"asc"`. Retries the load that failed instead, when there is one. Does nothing while loading or when there is nothing more. Never rejects: a failure lands in `error`.
</ResponseField>

<ResponseField name="refetch" type="() => Promise<void>">
  Reloads the first page (e.g. to pick up new matches). The loaded messages stay until the new first page replaces them. Never rejects: a failure lands in `error`.
</ResponseField>
