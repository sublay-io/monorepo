---
title: "Sign In"
api: "POST /v8/:projectId/auth/sign-in"
description: "Authenticate a user with email and password"
---

Authenticates an existing user by email and password. Returns an access token, refresh token, and the user's profile.

## Body Parameters

<ParamField body="email" type="string" required>
  User's registered email address.
</ParamField>

<ParamField body="password" type="string" required>
  User's password.
</ParamField>

<ParamField body="emailVerification" type="object">
  How the new confirmation email is sent when sign-in is refused because the account's email isn't confirmed. Ignored when the project doesn't require email verification before sign-in. When it's left out, the email uses what the user chose at sign-up (for 24 hours), else a link.
  <Expandable title="properties">
    <ParamField body="mode" type='"link" | "code"'>
      `"link"` emails a **Confirm my email** button; `"code"` emails a 6-digit code, and the `403` carries the `verificationId` to confirm it with.
    </ParamField>
    <ParamField body="redirectUrl" type="string">
      Where the confirmation link sends the user after they confirm. Link mode only. Must be an `https` address on one of your project's Verified Domains (or `localhost`); anything else is refused with `400 auth/redirect-url-not-allowed`.
    </ParamField>
  </Expandable>
</ParamField>

## Email verification required

When the project requires email verification before sign-in (Dashboard → Settings → SDK), an account that has a password must confirm its email before it can sign in. Once the password is confirmed correct, an unconfirmed account is refused with `403 auth/email-not-verified` and sent a new confirmation email (unless one went out in the last 10 minutes). A wrong password or an unknown email still gets the single `401` below, so the new error only appears after a correct password.

Accounts that have no password (they sign in only through a provider) and accounts that sign in through your own login ([external sign-in](/v8/sdk/authentication/external)) aren't affected.

The emails sent to one address are limited to one every 10 minutes and five a day. Past that, sign-in still returns the `403` but sends nothing, and the link or code already in the inbox keeps working.

## Response

<ResponseField name="success" type="boolean">
  `true` on successful authentication.
</ResponseField>

<ResponseField name="accessToken" type="string">
  Short-lived JWT access token. Expires in 30 minutes.
</ResponseField>

<ResponseField name="refreshToken" type="string">
  Long-lived JWT refresh token. Expires in 30 days. Use it to request a new
  access token when the current one expires.
</ResponseField>

<ResponseField name="user" type="object">
  The authenticated user's profile.
  <Expandable title="properties">
    <ResponseField name="id" type="string">Unique user ID (UUID).</ResponseField>
    <ResponseField name="foreignId" type="string | null">External user ID, if set.</ResponseField>
    <ResponseField name="role" type="string">User role.</ResponseField>
    <ResponseField name="email" type="string | null">Email address.</ResponseField>
    <ResponseField name="name" type="string | null">Display name.</ResponseField>
    <ResponseField name="username" type="string | null">Username.</ResponseField>
    <ResponseField name="avatar" type="string | null">Avatar URL.</ResponseField>
    <ResponseField name="bio" type="string | null">Bio text.</ResponseField>
    <ResponseField name="metadata" type="object | null">Public custom data.</ResponseField>
    <ResponseField name="reputation" type="number | null">Reputation score.</ResponseField>
    <ResponseField name="isVerified" type="boolean | null">Whether the user is verified.</ResponseField>
    <ResponseField name="isActive" type="boolean | null">Whether the account is active.</ResponseField>
    <ResponseField name="lastActive" type="string | null">ISO timestamp of last activity.</ResponseField>
    <ResponseField name="suspensions" type="array">Active suspensions on the account.</ResponseField>
    <ResponseField name="avatarFile" type="object | null">Processed avatar file with variants.</ResponseField>
    <ResponseField name="bannerFile" type="object | null">Processed banner file with variants.</ResponseField>
    <ResponseField name="authMethods" type="string[]">List of auth methods (e.g., `["password", "google"]`).</ResponseField>
    <ResponseField name="createdAt" type="string">ISO timestamp of account creation.</ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Credentials — 401">
    ```json
    {
      "error": "Email or password is incorrect.",
      "code": "auth/invalid-credentials"
    }
    ```
    The same answer for an email with no account, an account with no password (e.g. one created through OAuth), and a wrong password, so sign-in never reveals whether an email has an account. To offer "create an account" or "sign in with Google" after a failure, show those options alongside the error rather than choosing between them.
  </Accordion>
  <Accordion title="Email Not Verified — 403">
    ```json
    {
      "error": "Confirm your email to sign in.",
      "code": "auth/email-not-verified",
      "verificationId": "9f2c…"
    }
    ```
    The password is correct, but the project requires email verification before sign-in and the account's email isn't confirmed. A new confirmation email is sent, unless one went out in the last 10 minutes or the per-address limit is reached. In code mode the body carries `verificationId`: send it with the emailed code to [Verify Email](/v8/api-reference/auth/verify-email), then sign in again. When no new email was sent, `verificationId` is the one for the code already sent; if no code is outstanding, it's absent.
  </Accordion>
  <Accordion title="Redirect URL Not Allowed — 400">
    ```json
    {
      "error": "...",
      "code": "auth/redirect-url-not-allowed"
    }
    ```
    `emailVerification.redirectUrl` isn't on the project's Verified Domains. Only checked when the project requires email verification before sign-in.
  </Accordion>
  <Accordion title="Invalid Email Verification Options — 400">
    ```json
    {
      "error": "...",
      "code": "auth/invalid-body",
      "param": "emailVerification"
    }
    ```
    `emailVerification` is malformed. Only checked when the project requires email verification before sign-in.
  </Accordion>
  <Accordion title="Malformed Body — 400">
    ```json
    {
      "error": "...",
      "code": "auth/invalid-body",
      "param": "email"
    }
    ```
    A missing or malformed `email` or `password`. `param` names the field.
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    {
      "error": "Internal server error.",
      "code": "auth/server-error"
    }
    ```
  </Accordion>
</AccordionGroup>

**Rate limit:** 25 requests per 5 minutes per IP. Exceeding it returns `429` `request/rate-limited`, with `Too many sign in attempts, please wait 5 minutes` as `error`.
