---
title: "Upload File"
api: "POST /v7/:projectId/storage"
description: "Upload a generic file without server-side processing"
---

Uploads a file directly to storage without processing. Suitable for PDFs, videos, Office documents, and other non-image assets. The file type is inferred automatically from the MIME type.

This endpoint accepts `multipart/form-data`. Requires an authenticated user.

**Rate limit**: 10 requests per 5 minutes.

## Body Parameters

<ParamField body="file" type="file" required>
  The file to upload. Maximum 50 MB.
</ParamField>

<ParamField body="pathParts" type="array" required>
  JSON-encoded array of path segments. The file is stored under the joined path with a UUID sub-folder appended. Example: `["documents", "user-123"]` → `documents/user-123/<uuid>/<filename>`. A part that is, or contains, a `.` or `..` folder is refused with `400 storage/invalid-body`.
</ParamField>

<ParamField body="entityId" type="string">
  Associates the file with an entity for cascade deletion. Only the entity's author can attach to it (a service key can attach to any entity).
</ParamField>

<ParamField body="commentId" type="string">
  Associates the file with a comment for cascade deletion. Only the comment's author can attach to it (a service key can attach to any comment).
</ParamField>

<ParamField body="spaceId" type="string">
  Associates the file with a space. Only an active admin of the space can attach to it (a service key can attach to any space).
</ParamField>

<ParamField body="position" type="number">
  Display order when a record has multiple attachments, from `0` to `10000`. Defaults to `0`.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data stored alongside the file record.
</ParamField>

<ParamField body="userId" type="string">
  Attribute the upload to a specific user. With a user token the upload is
  already attributed to the caller; only **service keys** may name a
  different user. Omit for a backend/project-owned file (no owning user).
</ParamField>

## Response

```json
{
  "fileId": "uuid",
  "type": "document",
  "relativePath": "documents/user-123/uuid/report.pdf",
  "publicPath": "/internal/files/documents/user-123/uuid/report.pdf",
  "size": 102400,
  "mimeType": "application/pdf",
  "createdAt": "2025-01-01T00:00:00.000Z"
}
```

The `type` field is one of: `image`, `video`, `document`, `other`. It is inferred from the MIME type.

## Error Responses

<AccordionGroup>
  <Accordion title="No File — 400 Bad Request">
    ```json
    { "error": "No file provided", "code": "storage/no-file" }
    ```
  </Accordion>
  <Accordion title="File Too Large — 413">
    ```json
    { "error": "File size exceeds the allowed limit of 50MB", "code": "storage/file-too-large" }
    ```
  </Accordion>
  <Accordion title="Not Allowed To Attach — 403">
    ```json
    { "error": "Not authorized to attach a file to this entity.", "code": "storage/unauthorized" }
    ```
    The caller can't update the record named by `entityId`, `commentId` or `spaceId`: they aren't the entity's or comment's author, or an active admin of the space. The message names the record type. Nothing is stored.
  </Accordion>
  <Accordion title="Record Not Found — 404">
    ```json
    { "error": "Entity not found", "code": "storage/entity-not-found" }
    ```
    The record named by `entityId`, `commentId`, or `spaceId` doesn't exist, or counts as missing: a deleted record, an entity removed by moderation, a comment its author deleted, and a space the caller can't see (a private space they aren't in, for example) all answer 404. The code is `storage/entity-not-found`, `storage/comment-not-found` or `storage/space-not-found`. Nothing is stored.
  </Accordion>
</AccordionGroup>
