---
title: "Publish Entity"
api: "PATCH /v8/:projectId/entities/:entityId/publish"
description: "Publish a draft entity, making it publicly visible"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Publishes a draft entity. After publishing, the entity appears in normal feeds and is visible to all users. The entity's `isDraft` field is set to `false` and `createdAt` is reset to the current time.

**Authentication required.** Only the draft's author may publish it: with their own access token, or with a service key naming them in `actingUserId` — the request then runs exactly as theirs. A draft created through this API always has an author. A draft without one (created through an earlier API version) belongs to your app: only a service key naming nobody may publish it, and a user token gets `403`.

## Path Parameters

<ParamField path="entityId" type="string" required>
  The UUID of the draft entity to publish.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only: the user this publish acts as. Required when the draft has an author: name the author, and the request runs exactly as their own access token's (naming anyone else gets what their token gets, `403`). Leave it out only for a draft with no author, which only an earlier API version could create. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

## Response

Returns the published [Entity](/v8/data-models/entity) object with `isDraft: false`.

<Note>
  Publishing resets `createdAt` to the current time, so the entity appears as "new" in chronological feeds regardless of when the draft was created.
</Note>

<Note>
  Mention notifications are sent when publishing, not when the draft is created. Users mentioned in the entity receive notifications at publish time.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Draft entity not found", "code": "entity/not-found" }
    ```
    Returned when no draft with this ID exists (or the entity is not a draft).
  </Accordion>
  <Accordion title="Unauthorized — 403">
    ```json
    { "error": "Not authorized to publish this draft.", "code": "entity/unauthorized" }
    ```
  </Accordion>
  <Accordion title="Rejected by Validation Webhook — 400">
    ```json
    { "error": "Not now", "code": "entity/webhook-validation-failed" }
    ```
    Returned when your `entity.created` [validation webhook](/v8/webhooks) rejects the publish. `error` carries the `message` your webhook returned. The entity stays a draft.
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId` for a draft that has an author. Name the author: the request then runs exactly as their own.

    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "entity/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
