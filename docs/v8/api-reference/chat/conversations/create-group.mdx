---
title: "Create Group Conversation"
api: "POST /v8/:projectId/chat/conversations"
description: "Create a new multi-member group conversation"
---

Creates a group conversation. The caller is automatically added as an `admin`. All provided `memberIds` are validated to belong to the project and added as `member`.

## Body Parameters

<ParamField body="type" type="string" required>
  Must be `"group"`.
</ParamField>

<ParamField body="name" type="string">
  Display name of the conversation. Maximum 200 characters. Optional.
</ParamField>

<ParamField body="description" type="string">
  Optional description for the conversation. Maximum 1000 characters.
</ParamField>

<ParamField body="memberIds" type="string[]">
  Array of user IDs to add to the conversation. Defaults to `[]`. The caller's own ID is ignored if included — they are always added as admin. All IDs must belong to the same project.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data to attach to the conversation. Optional.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. They create the group and become its `admin`. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns the created [Conversation](/v8/data-models/conversation) object with HTTP `201`.

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Member — 400 Bad Request">
    ```json
    { "error": "User 'abc' does not belong to this project.", "code": "chat/invalid-member" }
    ```
    One or more provided user IDs do not exist in this project.
  </Accordion>
</AccordionGroup>
