---
title: "Get Block Status"
api: "GET /v8/:projectId/users/:userId/block"
description: "Check whether the acting user blocks a specific user"
---

Returns **only the acting user's outbound block state** — whether *I* block `:userId`. This powers a block/unblock toggle in your app's UI.

<Warning>
  This endpoint is **outbound-only by design**. It never reveals the inbound direction (whether `:userId` has blocked the caller). Exposing the inbound state would let a blocked user poll this endpoint to discover a block — the exact disclosure the feature exists to prevent.
</Warning>

<Note>
  **Requires the `moderation` bundle.** A project without the moderation bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the user to check block status against (the target).
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose outbound block state is checked (the blocker). A user token always acts as its own user and must not send it (`400 block/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`.

<ResponseField name="blocked" type="boolean">
  `true` if the acting user blocks the target user; otherwise `false`.
</ResponseField>

<ResponseField name="blockId" type="string">
  ID of the block record. Present only when `blocked` is `true`.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of when the block was created. Present only when `blocked` is `true`.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "Missing user ID",
      "code": "block/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "block/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Self-Check — 400">
    ```json
    {
      "error": "Cannot check block status with yourself.",
      "code": "block/self-check"
    }
    ```
  </Accordion>
</AccordionGroup>
