---
title: "Get Connection Status"
api: "GET /v8/:projectId/users/:userId/connection"
description: "Check the connection status between the authenticated user and another user"
---

Returns the connection status between the authenticated user and the specified user. `isConnected` is `true` only for an accepted connection. Whenever a connection record exists between the two users, pending and declined included, the response also carries it under `connection`; whether a relationship exists at all is shown by the presence of `connection`, not by `isConnected`.

<Note>
  **Requires the `connections` bundle.** A project without the connections bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the other user.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose connection with the user in the path is checked. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`:

<ResponseField name="isConnected" type="boolean">
  `true` only when the two users have an accepted connection. `false` when there is no connection record, and also when there is a pending or declined one.
</ResponseField>

<ResponseField name="connection" type="object">
  The [connection row](/v8/data-models/connection#connectionrow) between the two users, seen from the authenticated user's side. Present whenever a connection record exists (pending, accepted or declined); absent when there is none.
  <Expandable title="properties">
    <ResponseField name="id" type="string">
      ID of the connection record.
    </ResponseField>
    <ResponseField name="user" type="object">
      Public profile of the other user (the user in the path).
    </ResponseField>
    <ResponseField name="type" type="string">
      `"sent"` if the authenticated user sent the request; `"received"` if they received it.
    </ResponseField>
    <ResponseField name="message" type="string | null">
      The note sent with the request, or `null`.
    </ResponseField>
    <ResponseField name="status" type="string">
      `"pending"`, `"accepted"` or `"declined"`.
    </ResponseField>
    <ResponseField name="createdAt" type="string">
      ISO timestamp of when the request was sent.
    </ResponseField>
    <ResponseField name="respondedAt" type="string | null">
      ISO timestamp of when the request was accepted or declined; `null` while pending.
    </ResponseField>
  </Expandable>
</ResponseField>

| State | `isConnected` | `connection` |
|-------|---------------|--------------|
| No connection record | `false` | absent |
| Pending request (either direction) | `false` | present, `status: "pending"`, `type` gives the direction |
| Accepted | `true` | present, `status: "accepted"` |
| Declined | `false` | present, `status: "declined"` |

```json
// A pending request the authenticated user sent
{
  "isConnected": false,
  "connection": {
    "id": "c3d4e5f6-...",
    "user": { "id": "9f8e7d6c-...", "username": "jane", "name": "Jane", "avatar": null },
    "type": "sent",
    "message": "Great meeting you at the event!",
    "status": "pending",
    "createdAt": "2026-03-01T12:00:00.000Z",
    "respondedAt": null
  }
}
```

```json
// No connection record
{ "isConnected": false }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Self-Check — 400">
    ```json
    {
      "error": "Cannot check connection status with yourself",
      "code": "connection/self-check"
    }
    ```
  </Accordion>
</AccordionGroup>
