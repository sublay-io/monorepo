## Overview

Sublay's storage system lets you upload files and images on behalf of authenticated users. Uploaded assets are stored in managed cloud storage and served through a proxy URL so direct storage credentials are never exposed to the client.

<Note>
  **Requires the `files-images` bundle.** File and image uploads are only available when the `files-images` bundle is installed on your project. See [Bundles](/v8/bundles) to add it.
</Note>

A file uploaded with these hooks isn't attached to anything: it has no entity, comment, space or event. A file that belongs to a record is sent with that record's own hook (for example, the images of [`useCreateEntity`](/v8/hooks/entities/use-create-entity)).

## Upload Modes

Sublay provides two hooks for uploading assets:

- **Image upload** — server-side processing with automatic variant generation (resizing, format conversion, EXIF stripping). Returns named variants for responsive display.
- **File upload** — upload for PDFs and JPEG, PNG or WebP images. No server-side processing — the file is stored as-is, and the returned File carries its proxy URL.

## Image Processing Modes

When uploading images, you choose a **processing mode** that defines how variants are generated:

| Mode | Description |
|------|-------------|
| `exact-dimensions` | Each variant has an explicit `{ width, height }`. Use for fixed-size crops. |
| `aspect-ratio-width-based` | All variants share an aspect ratio; you specify widths. Heights are computed. |
| `aspect-ratio-height-based` | All variants share an aspect ratio; you specify heights. Widths are computed. |
| `original-aspect` | Preserves the source aspect ratio; you specify the longest-edge size for each variant. |
| `multi-aspect-ratio` | Picks the ratio in `aspectRatios` closest to the image; one variant per `sizes` entry. |

Every requested size is 1–10000 px, and `dimensions`, `widths`, `heights` and `sizes` take at most 30 entries (one variant each). A variant name can't be empty or `original`, and can't contain `/`, `\` or `..`. The stored original is shrunk to fit `originalMaxSize` on its longest side (50–10000, default 3840). The options are one JSON object, the same on [Upload Image](/v8/api-reference/storage/upload-image) (`file.options`) and on a record's own images (`avatarFile.options`, `images.options`, `coverFile.options`); [Upload Image](/v8/api-reference/storage/upload-image) lists every field.

Both uploads, and every file embedded in a record, return the one [File](/v8/data-models/file) shape.

## File Size Limits

| Upload type | Limit |
|-------------|-------|
| Image upload | 50 MB |
| Generic file upload | 50 MB |

- [Upload Image](/v8/api-reference/storage/upload-image) — `POST /v8/:projectId/storage/images`
- [Upload File](/v8/api-reference/storage/upload-file) — `POST /v8/:projectId/storage`
- [Fetch File](/v8/api-reference/storage/fetch-file) — `GET /v8/:projectId/storage/:fileId`
- [Delete File](/v8/api-reference/storage/delete-file) — `DELETE /v8/:projectId/storage/:fileId`
