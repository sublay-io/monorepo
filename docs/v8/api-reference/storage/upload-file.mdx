---
title: "Upload File"
api: "POST /v8/:projectId/storage"
description: "Upload a generic file without server-side processing"
---

Uploads a file directly to storage without processing. The file must be a PDF, JPEG, PNG or WebP; any other type is refused with `400 storage/unsupported-file-type`. The file type is inferred automatically from the MIME type.

The uploaded file isn't attached to anything: it has no entity, comment, space or event. A file that belongs to a record is sent with that record's own request (for example, the `images` and `files` of [Create Entity](/v8/api-reference/entities/create-entity) or [Create Comment](/v8/api-reference/comments/create-comment), or the cover of [Update Event](/v8/api-reference/events/update-event)).

This endpoint accepts `multipart/form-data`. Requires an authenticated user.

**Rate limit**: 10 requests per 5 minutes.

## Body Parameters

<ParamField body="file" type="file" required>
  The file to upload: PDF, JPEG, PNG or WebP. Maximum 50 MB.
</ParamField>

<ParamField body="file.options" type="string">
  Stringified JSON: `{ "pathParts": [...] }`, the same object as an inline `files.options`. `pathParts` are the folder segments the file is stored under; the new file's id is always added after them, so the file is stored under `<pathParts>/<fileId>/<filename>`. Example: `{ "pathParts": ["documents", "user-123"] }` → `documents/user-123/<fileId>/<filename>`. Each part is slugified. Without `file.options`, or with no or an empty `pathParts`, the file is stored under `files`. `pathParts` is the only key `file.options` takes; any other (an image option such as `mode`, sent here by mistake) is refused with `400 storage/invalid-body`, `param` naming it. A part that is, or becomes, a `.` or `..` folder is refused with `400 storage/invalid-body` and `param` `file.options.pathParts`.
</ParamField>

<ParamField body="metadata" type="string">
  Stringified JSON object of custom key-value data stored on the file. The server adds `originalFilename` alongside, replacing any value of yours under that key. Anything other than a JSON object is refused with `400 storage/invalid-body`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only: the user this request acts as, who owns the uploaded file; the upload runs under that user's own checks. Leave it out to upload an app-owned file with no owning user. A user that doesn't exist returns `404 storage/user-not-found`. A user token always acts as its own user and must not send it (`400 storage/acting-user-not-allowed`).
</ParamField>

## Response

`201 Created` with the [File](/v8/data-models/file), the same shape [Fetch File](/v8/api-reference/storage/fetch-file) returns. The file is stored as uploaded, so `image` is `null`, even for an image.

```json
{
  "id": "uuid",
  "userId": "uuid",
  "entityId": null,
  "eventId": null,
  "commentId": null,
  "chatMessageId": null,
  "spaceId": null,
  "type": "document",
  "originalPath": "https://api.sublay.io/internal/files/documents/user-123/uuid/report.pdf",
  "originalSize": 102400,
  "originalMimeType": "application/pdf",
  "position": 0,
  "metadata": { "originalFilename": "report.pdf" },
  "image": null,
  "createdAt": "2025-01-01T00:00:00.000Z",
  "updatedAt": "2025-01-01T00:00:00.000Z"
}
```

The `type` field is one of: `image`, `video`, `document`, `other`. It is inferred from the MIME type.

## Error Responses

<AccordionGroup>
  <Accordion title="Not signed in — 401 / 403">
    Returned with no JSON body: `401` when no `Authorization` header is sent, `403` when the access token is invalid or expired. Checked before any uploaded file is read, so a request with no credentials gets `401` rather than a body or acting-user error.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "storage/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent a top-level `pathParts`. The folder goes inside `file.options`. Nothing is stored:

    ```json
    {
      "error": "`pathParts` isn't supported in v8. Send it inside `file.options`, as `{ \"pathParts\": [...] }`.",
      "code": "storage/unsupported-param",
      "param": "pathParts"
    }
    ```

    The request sent `position`. A file uploaded here belongs to no record, so it has no place in a list. Nothing is stored:

    ```json
    {
      "error": "`position` isn't accepted: a file uploaded here belongs to no record, so it has no place in a list.",
      "code": "storage/unsupported-param",
      "param": "position"
    }
    ```

    The request sent `entityId`, `commentId`, `spaceId` or `eventId`. A file uploaded here isn't attached to anything, so these fields are refused rather than ignored, and nothing is stored. `param` names the field:

    ```json
    {
      "error": "`entityId` isn't accepted: a file uploaded here isn't attached to anything.",
      "code": "storage/unsupported-param",
      "param": "entityId"
    }
    ```

    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "storage/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "storage/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Body — 400">
    `file.options` or `metadata` was refused. Nothing is stored. `param` names the field.

    `file.options` isn't valid JSON:

    ```json
    { "error": "file.options: Must be a valid JSON string", "code": "storage/invalid-body", "param": "file.options" }
    ```

    A folder in `pathParts` is, or becomes once slugified, `.` or `..`:

    ```json
    { "error": "file.options.pathParts: pathParts can't contain '.' or '..' segments, '?', '#' or encoded slashes", "code": "storage/invalid-body", "param": "file.options.pathParts" }
    ```

    When the folder only becomes `.` or `..` through slugifying, `error` is the message alone, without the `file.options.pathParts: ` prefix.

    `file.options` has a key other than `pathParts`. `param` names the first one:

    ```json
    { "error": "file.options: Unrecognized keys: \"mode\", \"sizes\"", "code": "storage/invalid-body", "param": "file.options.mode" }
    ```

    A `file.options` that isn't a JSON object, a `pathParts` that isn't an array of strings, or `metadata` that isn't a JSON object, gets the same code, with `param` naming the value.
  </Accordion>
  <Accordion title="No File — 400 Bad Request">
    ```json
    { "error": "No file provided", "code": "storage/no-file", "param": "file" }
    ```
  </Accordion>
  <Accordion title="File Too Large — 413">
    ```json
    { "error": "`file` is over the 50 MB per-file limit.", "code": "storage/file-too-large", "param": "file" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project. Checked before the upload.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "storage/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Upload Refused — 400 / 413">
    A file was refused as the body was read: `storage/unsupported-file-type` or `storage/unexpected-file-field`, with `param` naming the field when there is one. A body over 250 MB gets `413 request/body-too-large`; one that can't be read at all gets `request/invalid-multipart` or `request/field-too-large`. See [Upload errors](/v8/api-reference/getting-started#upload-errors).
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Internal server error", "code": "storage/server-error" }
    ```
  </Accordion>
</AccordionGroup>
