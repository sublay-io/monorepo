---
title: "Space Member"
description: "The shape of a SpaceMember object returned by the Spaces membership API"
---

A SpaceMember record represents a user's membership in a specific space. It tracks their role (admin, moderator, or member), membership status (pending, active, banned, or rejected), and join timestamp.

The member actions return this record as their response body: [Join Space](/v8/api-reference/spaces/membership/join-space), [Add Member](/v8/api-reference/spaces/membership/add-member), [Approve Member](/v8/api-reference/spaces/membership/approve-member), [Decline Member](/v8/api-reference/spaces/membership/decline-member), [Ban Member](/v8/api-reference/spaces/membership/ban-member), [Unban Member](/v8/api-reference/spaces/membership/unban-member) and [Update Member Role](/v8/api-reference/spaces/membership/update-member-role).

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | Unique membership record identifier (UUID). |
| `spaceId` | `string` | ID of the space this membership is for. |
| `userId` | `string` | ID of the user who is a member. |
| `role` | `"admin" \| "moderator" \| "member"` | The user's role in the space. |
| `status` | `"pending" \| "active" \| "banned" \| "rejected"` | The user's membership status. |
| `joinedAt` | `Date` | When the membership became active. On a request still awaiting approval, or a declined one, when the request was made. |
| `createdAt` | `Date` | Record creation timestamp. |

## Membership Statuses

| Status | Description |
|--------|-------------|
| `pending` | Join request submitted but awaiting moderator/admin approval. Only applies when the space has `requireJoinApproval: true`. |
| `active` | Full membership granted — user can read and post according to space permissions. |
| `banned` | User has been banned from the space and the spaces under it where they were active. They can't post, comment, react or use the space chat there, and they read only what a non-member reads: an `"anyone"` space they can see, not a `"members"` one (see [Who can read content](/v8/data-models/space#who-can-read-content)). |
| `rejected` | Join request was declined by a moderator or admin. |

## Roles

| Role | Description |
|------|-------------|
| `admin` | Full control: can update the space, manage all members and roles, create rules, and moderate all content. Deleting the space is reserved for its creator, who is always an admin: the creator can't step down, leave, or be banned. |
| `moderator` | Can approve/decline/ban members, moderate content and reports, but cannot change space settings or manage admin accounts. |
| `member` | Regular participant. Can read and post according to the space's `postingPermission` setting: a `"team"` space lets only its admins and moderators post. |

## SpaceMemberWithUser

Returned by the list members and list team endpoints. Includes embedded public user details.

| Property | Type | Description |
|----------|------|-------------|
| `membershipId` | `string` | The membership record ID. Member routes don't take it: they address a member by user id (`user.id`). |
| `role` | `"admin" \| "moderator" \| "member"` | Member's role. |
| `status` | `"pending" \| "active" \| "banned" \| "rejected"` | Member's status. |
| `joinedAt` | `Date` | When the user joined. |
| `user` | [`User`](/v8/data-models/user) \| `null` | The member's public user record (with `spaceReputation` when requested). `null` when the user record no longer exists. |

<Note>Sensitive user fields (email, password hash, `secureMetadata`) are excluded from `SpaceMemberWithUser` responses.</Note>
