---
title: "Count Unread Notifications"
api: "GET /v8/:projectId/app-notifications/count"
description: "Get the number of unread app notifications for the authenticated user"
---

Returns a single integer representing the total number of unread app notifications for the currently authenticated user. Use this to populate notification badge counts in your UI.

<Note>
  This endpoint requires an authenticated user. Include a valid `Authorization: Bearer <accessToken>` header, or use a service key and name the user in `actingUserId`.
</Note>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their unread notifications are counted. A user token always acts as its own user and must not send it (`400 app-notification/acting-user-not-allowed`).
</ParamField>

## Response

Returns HTTP `200` with a plain integer (not a JSON object):

```json
7
```

## Error Responses

<AccordionGroup>
  <Accordion title="Missing token — 401">
    No `Authorization` header was sent. The body is `text/plain`, not JSON:

    ```text
    Unauthorized
    ```
  </Accordion>
  <Accordion title="Expired or invalid token — 403">
    The header was sent but the token failed verification. Refresh the access
    token and retry. The body is `text/plain`, not JSON:

    ```text
    Forbidden
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "app-notification/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "app-notification/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "app-notification/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "app-notification/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "app-notification/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
