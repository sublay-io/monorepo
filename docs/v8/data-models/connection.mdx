---
title: "Connection"
description: "The connection row and connection status shapes for bidirectional user relationships"
---

A connection is a bidirectional relationship between two users that requires mutual acceptance. The connection lifecycle goes through request → accept/decline. Every connection the API returns uses one row shape, seen from one user's side; lists of accepted connections use a shorter version of it.

## ConnectionRow

Returned wherever a connection is read as a request by one of its two users: [Request Connection](/v8/api-reference/users/connections/request-connection), [Accept Connection](/v8/api-reference/connections/accept-connection), [Decline Connection](/v8/api-reference/connections/decline-connection), the [received](/v8/api-reference/connections/fetch-received-pending) and [sent](/v8/api-reference/connections/fetch-sent-pending) pending lists, and the [connection status check](/v8/api-reference/users/connections/get-connection-status).

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | The connection record's ID (UUID). Accept, decline and remove-by-ID take it. |
| `user` | `User` | The other user in the connection (the counterpart of the caller). Public profile fields only. |
| `type` | `"sent" \| "received"` | Whether the caller sent or received the request. |
| `message` | `string \| null` | The note sent with the request, or `null`. |
| `status` | `ConnectionRowStatus` | The connection's state: `"pending"`, `"accepted"` or `"declined"`. |
| `createdAt` | `string` | ISO timestamp of when the request was sent. |
| `respondedAt` | `string \| null` | ISO timestamp of when the receiver accepted or declined; `null` while pending. |

## AcceptedConnectionRow

Returned by the accepted-connection lists, [Fetch Connections](/v8/api-reference/connections/fetch-connections) and [Get Connections](/v8/api-reference/users/connections/get-connections), for every caller. It is the `ConnectionRow` without `type` and `message`.

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | The connection record's ID (UUID). |
| `user` | `User` | The connected user: the caller's counterpart on Fetch Connections, the counterpart of `:userId` on Get Connections. Public profile fields only. |
| `status` | `"accepted"` | Always `"accepted"` in these lists. |
| `createdAt` | `string` | ISO timestamp of when the request was sent. |
| `respondedAt` | `string` | ISO timestamp of when the connection was accepted. |

## ConnectionStatus

Returned by the [connection status check](/v8/api-reference/users/connections/get-connection-status).

```ts
type ConnectionStatus =
  | { isConnected: false }
  | {
      isConnected: false;
      connection: ConnectionRow & { status: "pending" | "declined" };
    }
  | { isConnected: true; connection: ConnectionRow & { status: "accepted" } };
```

`isConnected` is `true` only when `connection.status` is `"accepted"`. A pending or declined request comes back as `isConnected: false` **with** a `connection`, so check for `connection` to tell whether the two users have any connection record; read its `status` and `type` to tell a request you sent from one you received.

## Pagination

Connection list responses include a `pagination` object:

| Property | Type | Description |
|----------|------|-------------|
| `page` | `number` | The current page number. |
| `pageSize` | `number` | The page size used for this response. |
| `totalPages` | `number` | Total number of pages. |
| `totalItems` | `number` | Total number of connections in the list. |
| `hasMore` | `boolean` | Whether more pages exist after this one. |
