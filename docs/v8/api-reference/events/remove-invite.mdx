---
title: "Remove Invite"
api: "DELETE /v8/:projectId/events/:eventId/invites/:userId"
description: "Revoke a user's invite to an event (host-only)"
---

Removes a user's [EventInvite](/v8/data-models/event-invite). **Host-only**: the caller must be the owner or in `hostIds`, and, for an event in a space, an active member of that space who isn't banned in it or a space above it; the space's admins and moderators can't. A service key acts as the host it names in `actingUserId`. Removing the invite **revokes access** to an `invite`-only event. The user's RSVP is deleted (decrementing the matching `rsvpCounts` entry) only when an invite was actually removed and the user can no longer RSVP to the event: on an `invite` event, a host who is an active member of the event's space keeps their RSVP, and anyone else — a space admin or moderator who isn't a host included — loses it. On `public` and `members` events the RSVP is never touched. Everything runs under a row-level lock. Removing a non-invited user is an idempotent no-op success.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event.
</ParamField>

<ParamField path="userId" type="string" required>
  The invitee to remove. A malformed id returns `400 event/invalid-params`.
</ParamField>

## Query Parameters

A DELETE takes no body: every field besides the path goes in the query string.

<ParamField query="actingUserId" type="string">
  Required with a service key: the user this request acts as. It has exactly that user's powers, so it is refused unless they are a host of the event, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Event](/v8/data-models/event) with refreshed `rsvpCounts`.

## Error Responses

<AccordionGroup>
  <Accordion title="Body Not Allowed — 400">
    The request carried a body. A DELETE takes no body: the invitee goes in the path and `actingUserId` in the query string.
    ```json
    {
      "error": "A DELETE request takes no body: send its fields in the query string. Received: `actingUserId`.",
      "code": "event/body-not-allowed",
      "params": ["actingUserId"]
    }
    ```
  </Accordion>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    The event doesn't exist, or the caller can't [see it](/v8/data-models/event#visibility) and isn't one of its hosts.
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden (not a host) — 403">
    The caller isn't a host. The space's admins and moderators can see the invite list but can't change it.
    ```json
    { "error": "Only a host of this event may manage its invites.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Host Not an Active Member — 403">
    The caller is a host, but the event is in a space they aren't an active member of, or they are banned in it or a space above it. One body for every case.
    ```json
    { "error": "Hosts must be active members of this event's space, and not banned from it or a space above it, to do this.", "code": "event/not-space-member" }
    ```
  </Accordion>
  <Accordion title="Unsupported Route — 400">
    `DELETE /v8/:projectId/events/:eventId/invites`, with the invitee in a request body, is not a v8 route. Once the request passes the checks that run ahead of it (such as the bundle check and id validation), it gets this error, with or without a body.
    ```json
    {
      "error": "`DELETE /events/:eventId/invites` isn't supported in v8. Remove an invite with `DELETE /events/:eventId/invites/:userId`, with the invitee's user id in the path.",
      "code": "event/unsupported-route"
    }
    ```
  </Accordion>
</AccordionGroup>
