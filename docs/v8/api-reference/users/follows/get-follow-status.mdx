---
title: "Get Follow Status"
api: "GET /v8/:projectId/users/:userId/follow"
description: "Check whether the authenticated user follows a specific user"
---

Returns the follow status between the authenticated user and the specified user. If the authenticated user is following, the response includes the follow row under `follow`.

<Note>
  **Requires the `follows` bundle.** A project without the follows bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the user to check follow status for.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose follow of the user in the path is checked. A user token always acts as its own user and must not send it (`400 follow/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200`:

<ResponseField name="isFollowing" type="boolean">
  `true` if the authenticated user follows this user; otherwise `false`.
</ResponseField>

<ResponseField name="follow" type="object">
  The [follow row](/v8/data-models/follow#followrow). Present only when `isFollowing` is `true`.
  <Expandable title="properties">
    <ResponseField name="id" type="string">
      ID of the follow record. Pass it to [Delete Follow](/v8/api-reference/follows/delete-follow) to remove the follow.
    </ResponseField>
    <ResponseField name="user" type="object">
      Public profile of the followed user (the user in the path).
    </ResponseField>
    <ResponseField name="createdAt" type="string">
      ISO timestamp of when the follow was created.
    </ResponseField>
  </Expandable>
</ResponseField>

```json Following
{
  "isFollowing": true,
  "follow": {
    "id": "a1b2c3d4-...",
    "user": { "id": "9f8e7d6c-...", "username": "jane", "name": "Jane", "avatar": null },
    "createdAt": "2026-03-01T12:00:00.000Z"
  }
}
```

```json Not following
{ "isFollowing": false }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "follow/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "follow/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "follow/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
