---
title: "ChatMessage"
description: "The shape of a chat message object returned by the Chat API and SDK"
---

A `ChatMessage` represents a single message in a conversation. Messages support text content, GIF attachments, file attachments, @mentions, emoji reactions, threading (replies to a parent message), and quoting.

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | Unique message identifier (UUID). |
| `localId` | `string \| undefined` | Locally-generated UUID echoed by the server. Never stored in the database. Used for optimistic deduplication — matching a temporary local entry to the confirmed server response. |
| `projectId` | `string` | The project this message belongs to. |
| `conversationId` | `string` | ID of the conversation this message is in. |
| `userId` | `string \| null` | ID of the user who sent the message. `null` if the sender's account has since been deleted, and on a [removed message](#deleted-and-removed-messages) for everyone but its author. |
| `user` | `User \| null` | The sender's user profile. `null` when `userId` is `null`. |
| `content` | `string \| null` | Text content of the message. `null` for GIF-only or file-only messages. |
| `gif` | `GifData \| null` | GIF attachment data. `null` if no GIF was attached. |
| `mentions` | `Mention[]` | Array of @mentions embedded in the message. |
| `files` | `File[] \| undefined` | File attachments. On message lists, only populated when `include` contains `"files"`; omitted by default to keep payloads small. A single-message fetch always returns them. |
| `metadata` | `Record<string, any> \| null` | Custom key-value data. Limited to 10 KB. `null` on a [deleted or removed message](#deleted-and-removed-messages). |
| `parentMessageId` | `string \| null` | ID of the parent message if this is a thread reply. Thread replies are excluded from the main conversation stream. |
| `parentMessage` | `ChatMessage \| null \| undefined` | The parent message for thread replies. |
| `quotedMessageId` | `string \| null` | ID of a message being quoted. The message remains in the main stream but renders an inline preview of the quoted content. |
| `quotedMessage` | `ChatMessage \| null \| undefined` | The quoted message, populated one level deep. |
| `threadReplyCount` | `number` | Number of replies in this message's thread. Incremented on reply creation; never decremented. |
| `reactionCounts` | `Record<string, number>` | Emoji reaction counts, keyed by emoji. Computed server-side (e.g. `{ "👍": 3, "❤️": 1 }`). |
| `userReactions` | `string[]` | Emojis the requesting user has reacted with on this message. |
| `editedAt` | `Date \| null` | Timestamp when the message was last edited. `null` if never edited. |
| `userDeletedAt` | `Date \| null` | Timestamp when the sender deleted the message, or when the sender's account was deleted (which deletes all of their messages). A deleted message is returned as a [placeholder](#deleted-and-removed-messages). |
| `moderationStatus` | `"approved" \| "removed" \| null` | Moderation status. A `"removed"` message is returned as a [placeholder](#deleted-and-removed-messages) to everyone but its author. Visible to everyone. |
| `moderatedAt` | `Date \| null` | Timestamp when moderation action was taken. |
| `moderatedById` | `string \| null` | ID of who removed the message: a user ID when `moderatedByType` is `"user"`, the dashboard account's ID when it is `"client"`. Visible only to some requesters — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `moderatedByType` | `"client" \| "user" \| null` | `"user"` when a user removed the message: a space moderator (through a report or directly) or a group conversation admin deleting another member's message. `"client"` when it was removed from the dashboard. A message a space moderator removed through the v7 API also carries `"client"`, with that moderator's user ID (or `null`) in `moderatedById`. Visible only to some requesters — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `moderationReason` | `string \| null` | Optional reason recorded with the moderation action. Visible only to some requesters, including the message's sender — see [Moderation fields](#moderation-fields); `null` for everyone else. |
| `grants` | `GrantSummary \| undefined` | Per-item [reputation-grant](/v8/data-models/reputation-grant) summary — `{ total, count, viewerTotal }` over **positive** grants. Populated when the read asks for grants (`"grants"` in `include`). Zero-filled rather than omitted on a project with no grants, so `undefined` always means "nobody asked". |
| `createdAt` | `Date` | Timestamp when the message was sent. |
| `updatedAt` | `Date` | Timestamp of the last update to this record. |

## Moderation fields

`moderationStatus` is returned to everyone. The other three moderation fields are returned only to some requesters, on every message response; everyone else gets `null`. The requester is the signed-in user, or the user a service key names in `actingUserId` (the key then gets exactly that user's view):

| Requester | `moderationReason` | `moderatedById`, `moderatedByType` |
|---|---|---|
| An active admin or moderator of the space the message's conversation belongs to | ✓ | ✓ |
| A user whose project [`role`](/v8/data-models/user) is `admin` or `moderator` | ✓ | ✓ |
| The message's sender | ✓ | — |
| Anyone else, including other members of the conversation | — | — |

Direct and group conversations have no space, so in them only project-role admins and moderators and the message's sender qualify. A group conversation's admins don't qualify through that role.

Real-time events never carry these three fields, whoever receives them: the `message:created` payload leaves them out (on the message and on its `quotedMessage`), and the other message events don't include them. A message the React SDK adds from `message:created` has them `null`; a message it already holds keeps what it had. Moderators fetch the message to read them. See [Real-time Features](/v8/sdk/chat/real-time).

## Client-only Fields

These fields are never sent by the server. They exist only in the SDK's local state.

| Property | Type | Description |
|----------|------|-------------|
| `sendFailed` | `boolean \| undefined` | Set to `true` by the SDK when a send request fails. Used to render a failed-send indicator on the optimistic message entry. |

## Nested Types

### GifData

The `gif` field uses this shape when a GIF is attached:

| Property | Type | Description |
|----------|------|-------------|
| `id` | `string` | GIF provider ID. |
| `url` | `string` | Landing page URL for the GIF. |
| `gifUrl` | `string` | Direct URL to the animated GIF. |
| `gifPreviewUrl` | `string` | URL to a static preview image. |
| `altText` | `string` | Accessibility description. Required. |
| `aspectRatio` | `string` | Width / height ratio for layout purposes, as a string — e.g. `"1.5"`, not `1.5`. |

All six fields are required when a GIF is attached.

### Mention

Each entry in the `mentions` array is one of:

**UserMention**

| Property | Type | Description |
|----------|------|-------------|
| `type` | `"user"` | Discriminant. |
| `id` | `string` | Sublay user ID. |
| `foreignId` | `string \| null \| undefined` | Your app's user ID, if set. |
| `username` | `string` | The @username at time of mention. |

**SpaceMention**

| Property | Type | Description |
|----------|------|-------------|
| `type` | `"space"` | Discriminant. |
| `id` | `string` | Space ID. |
| `slug` | `string` | The space's slug at time of mention. |

## Deleted and removed messages

A message its author deleted, or that a moderator removed, stays in the conversation as a placeholder: it keeps its place in the list, a deleted or removed parent still anchors its thread replies, and a message quoting it still carries it as `quotedMessage`. Every read returns it this way (list, fetch, and the `quotedMessage` of a message that quotes it).

| Kind | Marker | Who sees the full message | Sender (`userId` / `user`) |
|------|--------|---------------------------|----------------------------|
| Deleted by its author | `userDeletedAt` set | nobody | kept |
| Removed by a moderator | `moderationStatus: "removed"` | its author | `null` |

On a placeholder, `content`, `gif` and `metadata` are `null`, and `mentions` is `[]`, as is `files` when the response carries it. Everything else is kept: `id`, `conversationId`, `parentMessageId`, `quotedMessageId`, `threadReplyCount`, `reactionCounts`, timestamps and the moderation fields (shown as [Moderation fields](#moderation-fields) describes).

A deleted message keeps its sender, so the conversation can show who deleted it. A removed one hides its sender, so a removal doesn't publicly mark the person; its author still sees it in full, with its `moderationStatus`.

Deleting a message clears its content, GIF, mentions and metadata, and deletes its files from storage. Removing one clears nothing, so its author can still read it. Deleting a user turns each of their messages into a deleted message, read back as the same placeholder, and sets their `userId` to `null`.

A removed message's `grants` summary (with `include=grants`) is zero for everyone, its author included, as on [Fetch Many Reputation Grants](/v8/api-reference/reputation-grants/fetch-many-reputation-grants).

Neither can be edited: [Edit Message](/v8/api-reference/chat/messages/edit-message) answers `404 chat/message-not-found`, as for a missing message. To show nothing for them, skip messages with `userDeletedAt` set or `moderationStatus: "removed"` when rendering.
