# Threaded Comments Features

Comprehensive feature overview for Reddit-style threaded comments.

---

## Core Features

### Unlimited Nesting

Comments can be nested infinitely deep. Users can reply to any comment, creating branching conversation threads.

```
Comment 1
  └─ Reply to Comment 1
      └─ Reply to Reply
          └─ Reply to Reply to Reply
              └─ And so on...
```

Visual indicators: indentation, threading lines connecting replies to parents, and clear depth distinction.

---

### Loading Replies

The section loads its first screen in a single request: 10 top-level comments, each with up to 3 replies, 2 levels deep.

- **More replies** — when a comment has more replies than are shown, a "N more replies" button loads the next ones in place.
- **Continue this thread** — comments below the second level show a "Continue this thread" button that loads their replies right there, again with a few levels of nesting. Indentation stops growing after 6 levels.
- **Load more comments** — a button under the list loads the next top-level comments.

Reply counts come from each comment's `repliesCount`; whether a "more" button shows is driven by `hasMore`. To change how much loads up front, edit the `limit`, `replyDepth` and `replyLimit` props passed to `CommentSectionProvider` in `hooks/use-threaded-comments.tsx`.

---

### Blocked Users

When the `moderation` bundle is installed, comments involving a block render as compact rows instead of disappearing, so the replies under them stay in place:

- **"This comment is unavailable"** — the comment's author blocked the user. No author, content, reply or reaction controls are shown. If the user had reacted before, they can still remove their reaction.
- **"Comment from a user you blocked"** — the user blocked this author. The row starts collapsed with a **Show anyway** button; once shown, the comment can be replied to and reacted to as usual.

Edit the row text in `single-comment.tsx`. See [Comment → Blocked authors](/v8/data-models/comment#blocked-authors) for the underlying flags.

---

### Deleted & Removed Comments

A comment its author deleted shows `[deleted]` in place of the author name and the text; a comment a moderator removed shows `[removed]`. The row has no reply, reaction or menu controls, and the replies under it stay in place — and can still be replied to. The author of a removed comment still sees it in full, with a muted note under the text — `Removed by a moderator · only you can see this`, or `Removed by a moderator: <reason> · only you can see this` when the moderator gave a reason. Their row keeps delete, but has no Reply or vote buttons, since the server refuses both. A comment whose author blocked the user shows as **"This comment is unavailable"** instead, even when it is also deleted or removed.

Edit the row text in `single-comment.tsx`. See [Comment → Placeholders](/v8/data-models/comment#placeholders) for the underlying fields.

---

### Upvote/Downvote System

Reddit-style voting with visible vote scores.

- Upvote (▲) and downvote (▼) buttons
- Net score display (upvotes − downvotes)
- Visual feedback on current vote state
- One vote per user per comment
- Change or remove vote at any time
- Can't vote on your own comments

---

### Visual Threading

Clear visual hierarchy with indentation and connection lines.

- Each reply level is indented by 24px, up to 6 levels; deeper replies stay in one column
- One continuous line runs from under a comment's avatar down to its last reply, with a rounded elbow into each reply's avatar
- The "N more replies" / "Continue this thread" row and the inline reply form hang from the same line
- Collapsing a thread removes its lines along with its replies

The geometry is a set of named values at the top of `indentation-threading-lines.tsx`. Every line is derived from them, so changing one keeps the joins intact:

| Value | Default | Controls |
|-------|---------|----------|
| `AVATAR_SIZE` | `24` | Avatar size |
| `INDENT` | `24` | Indentation per reply level (keep it larger than half the avatar) |
| `MAX_INDENT_DEPTH` | `6` | Levels that indent |
| `ROW_PADDING_Y` | `8` | Vertical padding of a comment row |
| `AVATAR_OFFSET_TOP` | `4` | Space between the top of a row's content and its avatar |
| `AVATAR_GAP` | `12` | Gap between the avatar and the comment content |
| `LINE_WIDTH` | `1` | Line thickness |
| `ELBOW_RADIUS` | `12` | Roundness of the elbow |

The line color is set in the same file.

---

### Collapsible Threads

Users can collapse/expand entire comment chains.

- Click `[-]` to collapse a comment and all its replies
- Click `[+]` to expand
- Collapsed state shows reply count
- Useful for navigating long discussions

---

### @ Mentions

Tag other users with `@username`.

- Autocomplete suggestions as you type
- Clickable mentions link to user profiles (via `otherUserClickCallback`)
- Mentioned users receive notifications (if enabled)
- Works in both comments and replies

---

### Highlighted Comments

Deep-link to a specific comment and open the section focused on its thread.

```tsx
<ThreadedCommentSection
  foreignId="post_123"
  highlightedCommentId="comment_abc"
/>
```

While the highlighted comment loads, the section shows its loading skeletons. Once it loads, the component shows only that comment's thread:

1. The highlighted comment's parent at the top, with the highlighted comment under it marked: a subtle background across its whole row, a blue tint on the indentation beside it, and a blue connector line leading into it. A top-level comment is shown on its own, as the top of the thread.
2. The normal replies machinery under them — load more replies, "Continue this thread", voting, replying and deleting work as everywhere else in the section.
3. A **View all comments** button above the thread. It switches to the full comment section: the regular thread from the top, loaded as usual. The highlighted comment is marked there when it is among the loaded comments; a comment deeper in the thread, or further down the list, shows once its thread is loaded. Opening the link again returns to the focused view. Posting a new top-level comment from the focused view switches to the full section too, so the new comment is visible; replies posted inside the focused thread keep the focused view.

If the highlighted comment doesn't exist, the section shows the full comment list. A deleted or removed comment is focused like any other, as its placeholder.

**Use cases:** Notification links, URL params like `?commentId=abc123`.

---

### Edit & Delete

Comment authors can edit or delete their own comments.

**Edit:** Click "Edit" from the action menu, modify text inline, save or cancel. An "edited" indicator is shown.

**Delete:** Click "Delete" from the action menu, confirm. The comment shows as `[deleted]`, keeping its replies in place.

---

### Reporting & Moderation

Built-in reporting for inappropriate content.

**Users:** Click "Report" → select reason → submit.

**Admins:** Reports appear in the [Sublay Dashboard](https://dash.sublay.io) for review. Full moderation toolkit including comment deletion and user banning.

---

### Loading States

Skeleton loaders while fetching comments. Realistic skeleton UI mimics comment structure and prevents layout shift.

**File:** `fetching-comments-skeletons.tsx`

---

### Empty States

Friendly placeholder when no comments exist yet.

**Default message:** "No comments yet" with "Start the conversation." under it.

Customize `no-comments-placeholder.tsx` to change messaging or add illustrations.

---

### Error States

When a load fails, the component shows a retry instead of a wrong or stuck state:

- **First load fails** — "Couldn't load comments" with a **Try again** button, in place of the empty state.
- **"Load more comments" fails** — "Couldn't load more · Try again" in place of the button.
- **"N more replies" or "Continue this thread" fails** — the same "Couldn't load more · Try again" in place of that button, including inside the focused thread view.

**Try again** calls the same `loadMore()` that failed, which re-sends the failed request. Edit the text in `comments-feed.tsx` and `comment-thread/comment-replies.tsx`.

---

### Real-Time Updates

Comments automatically update when other users post. No configuration needed — powered by `@sublay/react-js` subscriptions.

---

### Dark Mode Support

**Inline Styles Variant:**
```tsx
<ThreadedCommentSection
  foreignId="post_123"
  theme={isDark ? 'dark' : 'light'}
/>
```

**Tailwind Variant:**
```tsx
<html className={isDark ? 'dark' : ''}>
  <ThreadedCommentSection foreignId="post_123" />
</html>
```

All colors adapt automatically.

---

### GIF Support (Optional)

Enable a GIF picker in comment forms via the [Sublay Dashboard](https://dash.sublay.io). Add a Giphy API key and GIF search appears automatically — no code changes needed.
