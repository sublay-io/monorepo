---
title: "Fetch File"
api: "GET /v8/:projectId/storage/:fileId"
description: "Retrieve a file and fresh signed links by file ID"
---

Returns a [File](/v8/data-models/file): the same shape [Upload File](/v8/api-reference/storage/upload-file) and [Upload Image](/v8/api-reference/storage/upload-image) return, and the same as a File embedded in any record. For a processed image it includes the image data and every variant.

A file comes back only to a viewer who can see it: a file that belongs to a record goes to whoever can see that record, and a file that belongs to nothing to any signed-in user (see [who can see a file](/v8/data-models/file#file-links)). A file the viewer can't see answers exactly like a missing one, `404 storage/file-not-found`.

Requires an authenticated user, or a service key. A service key sees what the user named in `actingUserId` sees; naming nobody, it sees files that belong to nothing and those anyone can see.

**Rate limit**: 100 requests per 5 minutes.

## Path Parameters

<ParamField path="fileId" type="string" required>
  The UUID of the file to retrieve.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only: the user this read acts as. The answer is exactly what that user's own access token gets. A user token always acts as its own user and must not send it (`400 storage/acting-user-not-allowed`).
</ParamField>

<ResponseField name="id" type="string">
  The file's UUID.
</ResponseField>

<ResponseField name="userId" type="string | null">
  The file's owner: the uploader, or the user a service key named in `actingUserId`. `null` for an app-owned file.
</ResponseField>

<ResponseField name="entityId" type="string | null">
  The entity the file belongs to, or `null`.
</ResponseField>

<ResponseField name="eventId" type="string | null">
  The event the file belongs to, or `null`.
</ResponseField>

<ResponseField name="commentId" type="string | null">
  The comment the file belongs to, or `null`.
</ResponseField>

<ResponseField name="chatMessageId" type="string | null">
  The chat message the file belongs to, or `null`.
</ResponseField>

<ResponseField name="spaceId" type="string | null">
  The space the file is associated with, or `null`. It is set on a space's own avatar and banner; older files (an entity's or event's files, or a `POST /storage` upload associated with a space) may also carry a space.
</ResponseField>

<ResponseField name="type" type="string">
  One of: `image`, `video`, `document`, `other`, from the MIME type.
</ResponseField>

<ResponseField name="originalPath" type="string">
  Signed link to the original file. It stops working at `linksExpireAt`.
</ResponseField>

<ResponseField name="originalSize" type="number">
  Size in bytes of the stored original. For a processed image that is the original as stored, after it is shrunk to its `originalMaxSize`.
</ResponseField>

<ResponseField name="originalMimeType" type="string">
  The stored file's type. For a file stored as uploaded, the uploaded type; for a processed image, `image/<format>` of the stored original (for example `image/webp`).
</ResponseField>

<ResponseField name="position" type="number">
  Display order among the files of the record it belongs to. `0` for a file uploaded through the storage endpoints.
</ResponseField>

<ResponseField name="metadata" type="object">
  Metadata stored at upload time: the uploader's own keys (on `POST /storage` and `POST /storage/images`), plus the server's `originalFilename` and, on an image, `originalFormat` and `originalDimensions` (the uploaded image's own format and size, before processing). Older files may carry other keys.
</ResponseField>

<ResponseField name="image" type="object | null">
  The image data of a processed image; `null` for a file stored as uploaded (an image sent through Upload File or in a `files` list included).

  <Expandable title="image fields">
    <ResponseField name="originalWidth" type="number">
      Pixel width of the stored original (after it is shrunk to its `originalMaxSize`).
    </ResponseField>
    <ResponseField name="originalHeight" type="number">
      Pixel height of the stored original (after it is shrunk to its `originalMaxSize`).
    </ResponseField>
    <ResponseField name="variants" type="object">
      Named variants. Each key maps to `{ publicPath, width, height, size, format }`, `publicPath` being the variant's signed link (it stops working at `linksExpireAt`).
    </ResponseField>
    <ResponseField name="processingStatus" type="string">
      `"completed"` or `"failed"`.
    </ResponseField>
    <ResponseField name="processingError" type="string | null">
      The error when processing failed.
    </ResponseField>
    <ResponseField name="format" type="string">
      The stored file's format (`"webp"`, `"jpeg"` or `"png"`).
    </ResponseField>
    <ResponseField name="quality" type="number">
      Quality setting used during processing.
    </ResponseField>
    <ResponseField name="exifStripped" type="boolean">
      Whether EXIF metadata was removed.
    </ResponseField>
    <ResponseField name="createdAt" type="string">
      ISO 8601 timestamp.
    </ResponseField>
    <ResponseField name="updatedAt" type="string">
      ISO 8601 timestamp.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="linksExpireAt" type="string">
  When every link on this File stops working (ISO 8601), 24 to 48 hours after the read. Get fresh ones from [Refresh File Links](/v8/api-reference/storage/refresh-file-links), or by reading the file or its record again.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO 8601 timestamp.
</ResponseField>

<ResponseField name="updatedAt" type="string">
  ISO 8601 timestamp.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Invalid Id — 400">
    Returned when `fileId` isn't a valid UUID. Checked before sign-in, permissions and the endpoint's other checks.
    ```json
    { "error": "Invalid file id: expected a UUID.", "code": "storage/invalid-params", "param": "fileId" }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    Returned for a query parameter this endpoint doesn't take, or an `actingUserId` that isn't a UUID.
    ```json
    { "error": "...", "code": "storage/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "storage/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "storage/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Returned when no file has this id, or the viewer can't see it.
    ```json
    { "error": "File not found", "code": "storage/file-not-found" }
    ```
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    { "error": "Failed to retrieve file", "code": "storage/server-error" }
    ```
  </Accordion>
</AccordionGroup>
