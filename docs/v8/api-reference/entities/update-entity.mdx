---
title: "Update Entity"
api: "PATCH /v8/:projectId/entities/:entityId"
description: "Update an entity's content and metadata"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Updates the fields of an existing entity. Only the fields you include in the request body are updated — omitted fields are left unchanged. Only the entity's author may update it: with their own access token, or with a service key naming them in `actingUserId` — the request then runs exactly as theirs. An entity with no author belongs to your app: only a service key naming nobody may update it, and a user token gets `403`.

**Authentication required.**

## Path Parameters

<ParamField path="entityId" type="string" required>
  The UUID of the entity to update.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only: the user this edit acts as. Required when the entity has an author: name the author, and the request runs exactly as their own access token's (naming anyone else gets what their token gets, `403`). Leave it out only for an app-owned entity (no author). A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 entity/acting-user-not-allowed`).
</ParamField>

<ParamField body="title" type="string">
  New title for the entity.
</ParamField>

<ParamField body="content" type="string">
  New content body for the entity.
</ParamField>

<ParamField body="attachments" type="object[]">
  Replaces the entity's `attachments` array with the provided value.
</ParamField>

<ParamField body="keywords" type="string[]">
  Replaces the entity's `keywords` array.
</ParamField>

<ParamField body="mentions" type="object[]">
  Replaces the entity's `mentions` array. Each item is:
  - `{ type: "user", id: string, username: string, foreignId?: string }`
  - `{ type: "space", id: string, slug: string }`
</ParamField>

<ParamField body="location" type="object">
  New geographic coordinates:
  ```json
  { "latitude": 40.7128, "longitude": -74.0060 }
  ```
</ParamField>

<ParamField body="metadata" type="object">
  Replaces the entity's `metadata` object entirely.
</ParamField>

## Response

Returns the updated [Entity](/v8/data-models/entity) object, populated with the author's user profile.

<Note>
  If `title` or `content` changed, the entity's semantic search embeddings are automatically re-queued for projects with AI search enabled.
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Entity not found.", "code": "entity/not-found" }
    ```
  </Accordion>
  <Accordion title="Unauthorized — 403">
    ```json
    { "error": "Not authorized to update this entity.", "code": "entity/not-authorized" }
    ```
  </Accordion>
  <Accordion title="Rejected by Validation Webhook — 400">
    ```json
    { "error": "Edits are not allowed", "code": "entity/webhook-validation-failed" }
    ```
    Returned when your `entity.updated` [validation webhook](/v8/webhooks) rejects the request. `error` carries the `message` your webhook returned. The entity is unchanged.
  </Accordion>
  <Accordion title="Missing User ID — 400">
    A service key sent no `actingUserId` for an entity that has an author. Name the author: the request then runs exactly as their own.

    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "entity/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.

    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
</AccordionGroup>
