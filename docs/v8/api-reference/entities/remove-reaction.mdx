---
title: "Remove Entity Reaction"
api: "DELETE /v8/:projectId/entities/:entityId/reactions"
description: "Remove the authenticated user's reaction from an entity"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Removes the authenticated user's reaction from an entity. The entity's `reactionCounts` map is decremented for the removed reaction type.

**Authentication required.**

## Path Parameters

<ParamField path="entityId" type="string" required>
  The UUID of the entity to remove the reaction from.
</ParamField>

## Query Parameters

A DELETE takes no body: every field besides the path goes in the query string.

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, whose reaction is removed. A user token always acts as its own user and must not send it (`400 entity/acting-user-not-allowed`).
</ParamField>

## Blocks

When the `moderation` bundle is installed and the entity's author has blocked the user, the request returns `404 entity/not-found` — identical to a missing entity — and nothing changes. The user's own block on the author doesn't stop them removing their reaction.

## Response

Returns the updated [Entity](/v8/data-models/entity) object with the new `reactionCounts`.

## Error Responses

<AccordionGroup>
  <Accordion title="Body Not Allowed — 400">
    The request carried a body. A DELETE takes no body: send `actingUserId` in the query string.
    ```json
    {
      "error": "A DELETE request takes no body: send its fields in the query string. Received: `actingUserId`.",
      "code": "entity/body-not-allowed",
      "params": ["actingUserId"]
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "entity/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "entity/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId` in the query string. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "entity/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "entity/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    Returned when the entity doesn't exist, or its author has blocked the user (see [Blocks](#blocks)).

    ```json
    { "error": "Entity not found.", "code": "entity/not-found" }
    ```
  </Accordion>
</AccordionGroup>
