---
title: "Verify Email Link"
api: "GET /v8/:projectId/auth/verify-email-link"
description: "Verify a user's email address via a link clicked in an email"
---

Verifies a user's email address when they click the link from a verification email sent with `mode: "link"`. On success, `isVerified` is set to `true` and the token is invalidated.

This endpoint is called automatically by the browser — you do not call it directly from your app. It is the target URL embedded in the verification button in the email.

## Query Parameters

<ParamField query="token" type="string" required>
  The verification token embedded in the link by the server.
</ParamField>

## Behaviour

| Outcome | `redirectUrl` was given | No `redirectUrl` |
|---------|------------------------|------------------|
| Success | Redirect to `{redirectUrl}` with `verified=true` added to its query | Render hosted success page |
| Invalid / expired token | Render hosted error page | Render hosted error page |
| Server error | Render hosted error page | Render hosted error page |

The destination is the `redirectUrl` you passed to [Send Verification Email](/v8/api-reference/auth/send-verification-email), stored with the token when the email was sent. The link itself carries no destination, so a link can only ever lead to the URL your app chose. A failed verification always shows the hosted page, never a redirect.
