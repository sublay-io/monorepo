---
title: "Fetch Many Events"
api: "GET /v8/:projectId/events"
description: "List events with visibility enforcement, filtering, sorting, geo, and free-text search"
---

Returns a paginated list of events. The [server-side visibility predicate](/v8/data-models/event#visibility) is always applied: anonymous callers see only `public` events; authenticated callers additionally see `members` events of spaces they belong to, `invite` events they were invited to, and any event they host. A service key sees exactly what the user it names in `actingUserId` sees, and only `public` events when it names nobody.

Each event includes inline `rsvpCounts`, and—with the `userRsvp` include and an authenticated caller—the caller's own `userRsvp`.

Authentication is optional (`optionalUserAuth`). Several filters interact with the caller's identity (`myRsvp`, `userRsvp`).

## Query Parameters

<ParamField query="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField query="limit" type="number">
  Results per page. Capped at `100`. Defaults to `10`.
</ParamField>

<ParamField query="sortBy" type="string">
  `"startTime"` (chronological) or `"going"` (by going-RSVP count). Defaults to `"startTime"`.
</ParamField>

<ParamField query="sortDir" type="string">
  `"asc"` or `"desc"` (either case). Left out, the sort's natural direction: soonest first for `"startTime"`, most going first for `"going"`.
</ParamField>

<ParamField query="timeWindow" type="string">
  Derived time window: `"upcoming"` (`startTime` in the future), `"ongoing"` (started, has an `endTime`, not yet ended), or `"past"`. Events without an `endTime` become `past` once they start.
</ParamField>

<ParamField query="startsAfter" type="string">
  ISO datetime. Only events starting after this. ANDed with `timeWindow`.
</ParamField>

<ParamField query="startsBefore" type="string">
  ISO datetime. Only events starting before this.
</ParamField>

<ParamField query="spaceId" type="string">
  Restrict to events scoped to this space. Omit for all scopes.
</ParamField>

<ParamField query="hostId" type="string">
  Only events hosted by this user (array containment on `hostIds`).
</ParamField>

<ParamField query="type" type="string">
  Filter by `"online"`, `"physical"`, or `"hybrid"`.
</ParamField>

<ParamField query="status" type="string">
  `"active"` or `"cancelled"`. Defaults to `"active"`.
</ParamField>

<ParamField query="myRsvp" type="string">
  Comma-separated RSVP statuses the caller responded with, e.g. `"going,maybe"`. Requires an authenticated caller (or a service key sending `actingUserId`); otherwise returns `400`.
</ParamField>

<ParamField query="locationFilters" type="object">
  Proximity filter `{ latitude, longitude, radius }` (radius in meters). Uses `ST_DWithin`.
</ParamField>

<ParamField query="titleFilters" type="object">
  Free-text filter on `title`: `{ hasTitle?, includes?, doesNotInclude? }`. `includes`/`doesNotInclude` accept a string or array.
</ParamField>

<ParamField query="descriptionFilters" type="object">
  Free-text filter on `description`: `{ hasDescription?, includes?, doesNotInclude? }`.
</ParamField>

<ParamField query="include" type="string">
  Comma-separated associations to expand: `"user"`, `"space"`, `"files"`, `"userRsvp"`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only: the user to list as. The page is exactly what that user's own access token would get (visibility, `userRsvp`, the `myRsvp` filter). Leave it out for the anonymous view: `public` events only. A user token always acts as its own user and must not send it, and neither may a request with no credentials (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns a paginated response: `{ data: Event[], pagination: { page, pageSize, totalPages, totalItems, hasMore } }`. See [Event](/v8/data-models/event).

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token, or a request with no credentials, sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "event/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="myRsvp Requires Auth — 400">
    ```json
    { "error": "The myRsvp filter requires an authenticated caller (or a service key acting via an actingUserId query param).", "code": "event/my-rsvp-requires-auth" }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    ```json
    { "error": "Limit must be a positive number", "code": "event/invalid-query" }
    ```
  </Accordion>
</AccordionGroup>
