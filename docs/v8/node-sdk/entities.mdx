<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available` for entity calls. See [Bundles](/v8/bundles).
</Note>

Entities are the central content objects in Sublay — posts, articles, products, or any item in your application that users interact with. The `entities` module gives you full server-side control over their lifecycle.

---

### createEntity

Creates a new entity.

```typescript
const entity = await sublay.entities.createEntity({
  foreignId: "post-42",
  title: "My First Post",
  content: "Hello world",
  keywords: ["intro", "welcome"],
  actingUserId: "usr_abc123",
  metadata: { category: "blog" },
});
```

<ParamField body="foreignId" type="string">
  Your application's identifier for this entity. Used for idempotent lookups via `fetchEntityByForeignId`.
</ParamField>

<ParamField body="sourceId" type="string">
  An optional secondary identifier for grouping or filtering entities.
</ParamField>

<ParamField body="spaceId" type="string">
  The space this entity belongs to.
</ParamField>

<ParamField body="title" type="string">
  Title text for the entity.
</ParamField>

<ParamField body="content" type="string">
  Body/content text for the entity.
</ParamField>

<ParamField body="attachments" type="array">
  File or media attachments.
</ParamField>

<ParamField body="keywords" type="string[]">
  Tags or keywords used for filtering and discovery.
</ParamField>

<ParamField body="mentions" type="array">
  User mentions embedded in the entity.
</ParamField>

<ParamField body="location" type="object">
  Geographic coordinates `{ latitude: number; longitude: number }`.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary public metadata.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user the service key acts as, who authors the entity; the create runs under that user's own checks. Omit it to create an app-owned entity with no author, which only your service key naming nobody can later edit, publish or delete. A user that doesn't exist returns `404 entity/user-not-found`.
</ParamField>

<ParamField body="nsfw" type="boolean">
  The entity's own NSFW flag. Defaults to `false`. Effective NSFW also inherits from the entity's space. See [Entity NSFW flagging](/v8/data-models/entity#nsfw-flagging).
</ParamField>

<ParamField body="isDraft" type="boolean">
  When `true`, the entity is created as an unpublished draft. Defaults to `false`. A draft needs an owner, so it requires `actingUserId` (`400 entity/draft-requires-user` otherwise).
</ParamField>

<ParamField body="requireUser" type="boolean">
  When `true`, the request fails with `401 entity/user-required` unless the entity has an author (`actingUserId`).
</ParamField>

<ParamField body="createdAt" type="Date">
  A `Date` used to backdate the entity's creation time. A service key ability, also with `actingUserId` (for imports with original authors and dates).
</ParamField>

<ParamField body="updatedAt" type="Date">
  A `Date` used to backdate the entity's last update time.
</ParamField>

**Returns** — `Promise<Entity>`

### fetchEntity

Fetches a single entity by its Sublay ID.

```typescript
const entity = await sublay.entities.fetchEntity({ entityId: "ent_xyz789" });
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to read as: you get exactly what their own access token would get (their drafts, blocks, `saved`, their own reaction, top comments), and the read counts as their view. Omit it for the anonymous view (drafts return `404`; no view is counted).
</ParamField>

<ParamField body="include" type="string">
  Comma-separated list of associations to populate: `"user"`, `"space"`, `"topComments"`, `"saved"`, `"files"`, `"grants"`. `"topComments"` adds the entity's best top-level comments as full `Comment` objects — see [Top comments](/v8/data-models/entity#top-comments).
</ParamField>

<ParamField body="topCommentsLimit" type="number">
  With `include` containing `"topComments"`: how many top comments per entity. Server default `1`, maximum `5`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

<ParamField body="topCommentsSortByReaction" type="ReactionType">
  With `include` containing `"topComments"`: the reaction whose raw count ranks the top comments. Server default `"upvote"`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

### fetchEntityByForeignId

Fetches an entity by your application's own identifier. Optionally creates it if not found.

```typescript
const entity = await sublay.entities.fetchEntityByForeignId({
  foreignId: "post-42",
  createIfNotFound: true,
});
```

<ParamField body="foreignId" type="string" required>
  Your application's entity identifier.
</ParamField>

<ParamField body="createIfNotFound" type="boolean">
  When `true`, creates a stub entity if no match is found. Defaults to `false`.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to read as: you get exactly what their own access token would get (their drafts, blocks, `saved`, their own reaction, top comments), and the read counts as their view. Omit it for the anonymous view (drafts return `404`; no view is counted). It shapes the read only: an entity made by `createIfNotFound` is always app-owned.
</ParamField>

<ParamField body="include" type="string">
  Comma-separated list of associations to populate: `"user"`, `"space"`, `"topComments"`, `"saved"`, `"files"`, `"grants"`. `"topComments"` adds the entity's best top-level comments as full `Comment` objects — see [Top comments](/v8/data-models/entity#top-comments).
</ParamField>

<ParamField body="topCommentsLimit" type="number">
  With `include` containing `"topComments"`: how many top comments per entity. Server default `1`, maximum `5`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

<ParamField body="topCommentsSortByReaction" type="ReactionType">
  With `include` containing `"topComments"`: the reaction whose raw count ranks the top comments. Server default `"upvote"`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

**Returns** — `Promise<Entity>`

### fetchManyEntities

Fetches a filtered, paginated list of entities. Supports rich filtering by metadata, keywords, location, and more.

```typescript
const { data, pagination } = await sublay.entities.fetchManyEntities({
  spaceId: "spc_abc123",
  sortBy: "hot",
  page: 1,
  limit: 20,
  metadataFilters: { includes: { category: "blog" } },
});
```

<ParamField body="sourceId" type="string">
  Filter by source ID.
</ParamField>

<ParamField body="spaceId" type="string">
  Filter to entities within a specific space.
</ParamField>

<ParamField body="sortBy" type="string">
  Sort order: `"createdAt"` (chronological — honors `sortDir`), `"hot"` (trending), `"top"` (highest scored), or `"controversial"`. A `"metadata.<prop>"` value is also accepted to sort by a metadata field.
</ParamField>

<ParamField body="sortDir" type="string">
  Sort direction: `"asc"` or `"desc"`. Not accepted with `"hot"` or `"controversial"`, which rank one way only.
</ParamField>

<ParamField body="sortType" type="string">
  How to interpret a metadata sort value: `"auto"`, `"numeric"`, `"text"`, `"boolean"`, or `"timestamp"`.
</ParamField>

<ParamField body="sortByReaction" type="string">
  Which reaction `top` ranks by: `"upvote"`, `"downvote"`, `"like"`, `"love"`, `"wow"`, `"sad"`, `"angry"`, or `"funny"`. Defaults to `"upvote"`. Only valid with `sortBy: "top"` — the server rejects it with any other sort.
</ParamField>

<ParamField body="page" type="number">
  Page number (1-indexed). Defaults to `1`.
</ParamField>

<ParamField body="limit" type="number">
  Results per page. Defaults to `20`.
</ParamField>

<ParamField body="include" type="string">
  Comma-separated list of associations to populate: `"user"`, `"space"`, `"topComments"`, `"saved"`, `"files"`, `"grants"`. `"topComments"` adds the entity's best top-level comments as full `Comment` objects — see [Top comments](/v8/data-models/entity#top-comments).
</ParamField>

<ParamField body="topCommentsLimit" type="number">
  With `include` containing `"topComments"`: how many top comments per entity. Server default `1`, maximum `5`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

<ParamField body="topCommentsSortByReaction" type="ReactionType">
  With `include` containing `"topComments"`: the reaction whose raw count ranks the top comments. Server default `"upvote"`. Rejected (`400`) without `"topComments"` in `include`.
</ParamField>

<ParamField body="timeFrame" type="string">
  Time window to restrict results to: `"hour"`, `"day"`, `"week"`, `"month"`, or `"year"`.
</ParamField>

<ParamField body="userId" type="string">
  Author filter: returns only entities authored by this user. Not the viewer: that is `actingUserId`.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to list as: you get exactly what their own access token would get (`followedOnly` and `blockedFilter` for them, their own removed entities when `userId` names them, `saved`, their own reactions, top comments), and the reads count as their views. Omit it for the anonymous view.
</ParamField>

<ParamField body="followedOnly" type='"true" | "false"'>
  When `"true"`, returns only entities from users the viewer (`actingUserId`) follows. Without `actingUserId` it has no effect.
</ParamField>

<ParamField body="keywordsFilters" type="object">
  Filter by keyword tags: `{ includes?: string[]; doesNotInclude?: string[] }`.
</ParamField>

<ParamField body="metadataFilters" type="object">
  Filter by metadata fields: `{ includes?, includesAny?, doesNotInclude?, exists?: string[], doesNotExist?: string[] }`.
</ParamField>

<ParamField body="titleFilters" type="object">
  Filter by title: `{ hasTitle?: "true" | "false"; includes?: string | string[]; doesNotInclude?: string | string[] }`.
</ParamField>

<ParamField body="contentFilters" type="object">
  Filter by content: `{ hasContent?: "true" | "false"; includes?: string | string[]; doesNotInclude?: string | string[] }`.
</ParamField>

<ParamField body="attachmentsFilters" type="object">
  Filter by attachments: `{ hasAttachments?: "true" | "false" }`.
</ParamField>

<ParamField body="locationFilters" type="object">
  Filter within a geographic radius: `{ latitude: string; longitude: string; radius: string }`.
</ParamField>

<ParamField body="nsfwFilter" type='"include-all" | "exclude" | "only"'>
  Filter by effective NSFW (`entity.nsfw OR its space's nsfwEffective`). `"include-all"` (default) adds no predicate; `"exclude"` drops effective-NSFW entities; `"only"` returns only them. See [Entity NSFW flagging](/v8/data-models/entity#nsfw-flagging).
</ParamField>

<ParamField body="blockedFilter" type='"exclude" | "include-outbound-blocked"'>
  How to treat entities authored by users the viewer is [block-edged](/v8/sdk/moderation/overview#blocking) with. `"exclude"` (default) hides them; `"include-outbound-blocked"` re-includes only the viewer's own outbound-blocked authors — never content from users who blocked the viewer. No effect without the `moderation` bundle.
</ParamField>

<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<PaginatedResponse<Entity>>`

### updateEntity

Updates fields on an existing entity, as its author.

```typescript
const entity = await sublay.entities.updateEntity({
  entityId: "ent_xyz789",
  actingUserId: "usr_abc123",
  title: "Updated Title",
  metadata: { featured: true },
});
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID to update.
</ParamField>

<ParamField body="title" type="string">
  New title.
</ParamField>

<ParamField body="content" type="string">
  New content body.
</ParamField>

<ParamField body="attachments" type="array">
  Updated attachments list.
</ParamField>

<ParamField body="keywords" type="string[]">
  Updated keywords list.
</ParamField>

<ParamField body="location" type="object">
  Updated coordinates `{ latitude: number; longitude: number }`.
</ParamField>

<ParamField body="metadata" type="object">
  Replaces the entity's metadata wholesale (not merged).
</ParamField>

<ParamField body="mentions" type="array">
  Updated user mentions list.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user this edit acts as. Required when the entity has an author: pass the author, and the request runs exactly as their own (`400 entity/missing-user-id` without it; anyone else gets `403`). Omit it only for an app-owned entity.
</ParamField>

<ParamField body="nsfw" type="boolean">
  Updated NSFW own-flag (the owner's). A space moderator flagging another user's entity uses `spaces.setSpaceEntityNsfw` instead. See [Entity NSFW flagging](/v8/data-models/entity#nsfw-flagging).
</ParamField>

**Returns** — `Promise<Entity>`

### incrementEntityViews

Increments the view counter on an entity. Call this when a user views content to track engagement. It always acts as your app and takes no `actingUserId`.

```typescript
const entity = await sublay.entities.incrementEntityViews({
  entityId: "ent_xyz789",
  count: 1,
});
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID.
</ParamField>

<ParamField body="count" type="number">
  Number to add to the view counter. Defaults to `1`.
</ParamField>

**Returns** — `Promise<Entity>`

### publishDraft

Publishes a draft entity as its author, making it publicly visible.

```typescript
const entity = await sublay.entities.publishDraft({ entityId: "ent_xyz789", actingUserId: "usr_abc123" });
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID of the draft to publish.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user this publish acts as: the draft's author, and the request runs exactly as their own (`400 entity/missing-user-id` without it; anyone else gets `403`). A draft with no author, which this API never creates, is answered as not found (`404 entity/not-found`).
</ParamField>

### addReaction

Adds a reaction from a user to an entity.

```typescript
const entity = await sublay.entities.addReaction({
  entityId: "ent_xyz789",
  actingUserId: "usr_abc123",
  reactionType: "like",
});
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as: the reacting user.
</ParamField>

<ParamField body="reactionType" type="ReactionType" required>
  One of: `"upvote"`, `"downvote"`, `"like"`, `"love"`, `"wow"`, `"sad"`, `"angry"`, `"funny"`.
</ParamField>

**Returns** — `Promise<Entity>` — the updated entity, as the reacting user sees it: `userReaction` and `reactionCounts` reflect the new reaction.

### removeReaction

Removes a user's existing reaction from an entity.

```typescript
const entity = await sublay.entities.removeReaction({
  entityId: "ent_xyz789",
  actingUserId: "usr_abc123",
});
```

<ParamField body="entityId" type="string" required>
  The Sublay entity ID.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose reaction to remove.
</ParamField>

**Returns** — `Promise<Entity>` — the updated entity, as that user sees it. When the user has no reaction on the entity, the entity comes back unchanged.

If the entity's author has blocked the user, this fails with `404 entity/not-found` and nothing changes.

### getUserReaction

```typescript
});

```

<ParamField body="entityId" type="string" required>

</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the service key acts as, whose reaction is checked.
</ParamField>

**Returns** — `Promise<{ reactionType: ReactionType | null }>`
