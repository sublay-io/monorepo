---
title: "Delete Message"
api: "DELETE /v8/:projectId/chat/conversations/:conversationId/messages/:messageId"
description: "Delete or moderate a chat message"
---

Deletes a message. The behavior differs based on who is deleting:

- **Author self-delete**: The message is soft-deleted. The row is retained as a `[Message deleted]` placeholder — content, GIF, mentions, and metadata are cleared, and `userDeletedAt` is set. File attachments are deleted from storage.
- **Group admin moderation delete**: The message is marked `moderationStatus: "removed"` and excluded from all future queries. Content is not cleared; the record is retained for moderation audit purposes.

The caller must be either the message author or an active group `admin`. An admin who left or was removed can still delete their own messages, but not other members'.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation.
</ParamField>

<ParamField path="messageId" type="string" required>
  The ID of the message to delete.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be the message author or an active group `admin`. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

For author self-delete:
```json
{ "message": "Message deleted.", "userDeletedAt": "2025-01-15T10:30:00.000Z" }
```

For admin moderation:
```json
{ "message": "Message removed by admin." }
```

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403 (not a member)">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Message not found.", "code": "chat/message-not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403 (no permission)">
    ```json
    { "error": "You do not have permission to delete this message.", "code": "chat/forbidden" }
    ```
  </Accordion>
</AccordionGroup>
