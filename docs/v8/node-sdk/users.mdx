The `users` module provides server-side access to user profiles, social graph data (follows and connections), and username availability. All operations use your project API key and do not require a user access token. Reads that depend on who is looking (profiles, suggestions, follower, following and connection lists and counts, comment history) take an optional [`actingUserId`](/v8/node-sdk/overview#acting-on-behalf-of-a-user) to read as that user; without it they return the anonymous view. `updateUser` acts as the user being updated, so it requires `actingUserId` set to that user; `deleteUser` acts as your app and takes no `actingUserId`.

---

### updateUser

Updates a user's profile fields. The update acts as that user: `actingUserId` must be the same user as `userId`, and the request behaves exactly as their own access token would (`403 user/unauthorized` if the two differ).

```typescript
const updatedUser = await sublay.users.updateUser({
  userId: "usr_abc123",
  actingUserId: "usr_abc123",
  name: "Alice Updated",
  bio: "New bio",
  avatar: "https://cdn.example.com/avatar.jpg",
  location: { latitude: 37.7749, longitude: -122.4194 },
});
```

<ParamField body="userId" type="string" required>
  The Sublay user ID to update.
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user the request acts as. Must be the same user as `userId`.
</ParamField>

<ParamField body="name" type="string">
  New display name.
</ParamField>

<ParamField body="username" type="string">
  New username. Must be available.
</ParamField>

<ParamField body="bio" type="string">
  New bio text.
</ParamField>

<ParamField body="avatar" type="string">
  New avatar URL.
</ParamField>

<ParamField body="metadata" type="object">
  Updated public metadata. Merged with existing metadata.
</ParamField>

<ParamField body="secureMetadata" type="object">
  Updated secure metadata. No API response returns it to any user. Users can also write their own, so don't treat it as trusted. Merged with existing values.
</ParamField>

<ParamField body="birthdate" type="string">
  ISO 8601 date string for the user's birthdate.
</ParamField>

<ParamField body="location" type="object">
  Geographic location `{ latitude: number; longitude: number }`.
</ParamField>

**Returns** — `Promise<UserFull>`

### deleteUser

Permanently deletes a user and cascades cleanup across all of their related data — reactions, files, follows, connections, notifications, collections, reports, and mentions are removed, and their entities and comments are stripped of authored content. This mirrors the full-cascade delete performed from the dashboard.

<Warning>
  This is a hard, irreversible delete — the user and their related data cannot be recovered.
</Warning>

```typescript
await sublay.users.deleteUser({ userId: "usr_abc123" });
```

<ParamField body="userId" type="string" required>
  The Sublay user ID to delete.
</ParamField>

**Returns** — `Promise<void>`

### fetchCommentsByUserId

Returns a user's comments — top-level comments and replies alike, across entities — cursor-paginated. See [Fetch Comments by User](/v8/api-reference/users/fetch-comments-by-user-id).

<Note>
  Pass `actingUserId` to read the history as that user: their own moderator-removed comments are included in full, the block rules and `blockedFilter` apply from their perspective (comments on an entity whose author blocked them are left out, except [their own](/v8/api-reference/users/fetch-comments-by-user-id#your-own-comments-on-an-unavailable-entity)), the `isAuthorBlocked` / `isUnavailable` flags are set, `userReaction` is populated, and the [moderation details](/v8/data-models/comment#moderation-fields) are what that user may see. Without it the read is anonymous: deleted and moderator-removed comments are left out, no block rule applies, `isAuthorBlocked` and `isUnavailable` are always `false`, `userReaction` isn't populated, and no moderation details are included.
</Note>

```typescript
const { data, pagination } = await sublay.users.fetchCommentsByUserId({
  userId: "usr_abc123",
  limit: 20,
  include: ["entity"],
});

const next = await sublay.users.fetchCommentsByUserId({
  userId: "usr_abc123",
  limit: 20,
  include: ["entity"],
  cursor: pagination.nextCursor,
});
```

<ParamField body="userId" type="string" required>
  The Sublay user ID whose comments to fetch.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user to read the history as: the result is exactly what their own access token would get. Omit for the anonymous view.
</ParamField>

<ParamField body="entityId" type="string">
  Only comments on this entity.
</ParamField>

<ParamField body="sourceId" type="string">
  Only comments on entities with this `sourceId`.
</ParamField>

<ParamField body="blockedFilter" type='"exclude" | "include-outbound-blocked"'>
  How comments by users `actingUserId` is block-edged with are treated: `"exclude"` (default) leaves them out; `"include-outbound-blocked"` re-includes comments by users they blocked, marked `isAuthorBlocked: true`. No effect without `actingUserId`.
</ParamField>

<ParamField body="limit" type="number">
  Comments per page. Server default `10`, max `100`.
</ParamField>

<ParamField body="cursor" type="string | null">
  `pagination.nextCursor` from the previous response, passed as returned. Omit it, or pass `null`, for the first page. Send the same sort as the request that returned it.
</ParamField>

<ParamField body="sortBy" type='"createdAt" | "top" | "controversial"'>
  Server default `"createdAt"`. `"top"` ranks by the raw count of `sortByReaction`.
</ParamField>

<ParamField body="sortDir" type='"asc" | "desc"'>
  Applies to `"createdAt"` and `"top"`; not accepted with `"controversial"`, which ranks one way only. Server default `"desc"`.
</ParamField>

<ParamField body="sortByReaction" type="ReactionType">
  With `sortBy: "top"` only. Server default `"upvote"`.
</ParamField>

<ParamField body="include" type="CommentIncludeParam">
  Related data to populate: `"user"`, `"entity"`, `"space"`, `"parent"`, `"grants"`.
</ParamField>

<SpaceReputationParams variant="context" field="body" />

**Returns** — `Promise<CursorPaginatedResponse<Comment>>` — `{ data, pagination: { nextCursor, hasMore } }`

## Acting on a user's follows and connections

The functions above are read-only queries about a target user. The functions below **perform an action** on behalf of one user toward another, so they take both:

- `userId` — the **target** of the action (the user being followed, connected with, etc.), taken from the request path.
- [`actingUserId`](/v8/node-sdk/overview#acting-on-behalf-of-a-user) — the user the service key acts as (the follower, the requester, the user whose perspective a status is from).

<Note>
  Listing and managing the acting user's own follow/connection graph by record ID
  lives on the dedicated [`follows`](/v8/node-sdk/follows) and
  [`connections`](/v8/node-sdk/connections) modules.
</Note>

## Acting on a user's blocks

User-to-user **blocking** is part of the trust & safety [moderation bundle](/v8/sdk/moderation/overview#blocking). These functions require that bundle; a project without it returns `403 database/tables-not-available`. Each acts on behalf of one user (the blocker) — pass that user's ID as `actingUserId`.

<Note>
  Blocking severs interaction between two users across every Sublay surface and is **non-disclosing** — the blocked user is never notified. See [Moderation — Blocking](/v8/sdk/moderation/overview#blocking) for the full enforcement behavior.
</Note>

---

### createBlock

Blocks one user on behalf of another. On a new block, existing follows and connections between the pair are torn down (both directions) in one transaction. Idempotent — re-blocking succeeds. Self-block is rejected.

```typescript
const block = await sublay.users.createBlock({
  userId: "usr_target",
  actingUserId: "usr_blocker",
});
```

<ParamField body="userId" type="string" required>
  The user being blocked (the target).
</ParamField>

<ParamField body="actingUserId" type="string" required>
  The user performing the block (the blocker).
</ParamField>

**Returns** — `Promise<Block>` — `{ id, blockerId, blockedId, createdAt }`.

---
