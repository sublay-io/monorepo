---
title: "Storage"
description: "Upload, retrieve, and delete files and images from your server"
---

The `storage` module uploads files and images to managed cloud storage, plus reads and deletes existing files. Both uploads and `getFile` return the one [`File`](/v8/data-models/file) shape, with proxy URLs. Uploads are sent as `multipart/form-data` — pass the file bytes as a `Uint8Array` or a `Blob`.

A file uploaded with this module isn't attached to anything: it has no entity, comment, space or event.

<Note>
  Uploads can be attributed to a user by passing that user's Sublay ID as
  [`actingUserId`](/v8/node-sdk/overview#acting-on-behalf-of-a-user), the user your
  service key acts as. Omit `actingUserId` for a **backend/project-owned** file (no
  owning user).
</Note>

<Warning>
  **Access model.** Reads (`getFile`) are project-scoped — reachable for any file
  in your project. **The owner deletes:** a file with an owner is deleted as that
  user, so pass them as `actingUserId`. Backend-owned files (uploaded without an
  `actingUserId`) are deletable only by your service key naming nobody.
</Warning>

---

### uploadFile

Uploads a file (PDF, JPEG, PNG or WebP) without server-side processing. The file type is inferred from the MIME type.

```typescript
import { readFile } from "node:fs/promises";

const buffer = await readFile("./report.pdf");

const file = await sublay.storage.uploadFile({
  file: new Uint8Array(buffer),
  filename: "report.pdf",
  mimeType: "application/pdf",
  pathParts: ["documents", "usr_abc123"],
  actingUserId: "usr_abc123",
});
```

<ParamField body="file" type="Uint8Array | Blob" required>
  The file bytes to upload. Maximum 50 MB.
</ParamField>

<ParamField body="pathParts" type="string[]">
  The folder segments the file is stored under, sent as `file.options`. The new
  file's id is always added after them, e.g. `["documents", "usr_abc123"]` →
  `documents/usr_abc123/<fileId>/<filename>`. Each part is slugified. Defaults to
  `["files"]`. A folder that is, or becomes, `.` or `..` is refused with
  `400 storage/invalid-body`.
</ParamField>

<ParamField body="filename" type="string">
  Name to store the file under. Defaults to `"upload"`.
</ParamField>

<ParamField body="mimeType" type="string">
  MIME type used when wrapping a `Uint8Array`. Defaults to
  `"application/octet-stream"`. Ignored when `file` is already a `Blob`.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data stored on the file. The server adds `originalName` and
  `uploadedAt` alongside, replacing any values of yours under those keys.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user the service key acts as, who owns the upload. Omit it for a backend/project-owned file. A user that doesn't exist returns `404 storage/user-not-found`.
</ParamField>

**Returns** — `Promise<File>`: the [`File`](/v8/data-models/file), keyed `id`;
`originalPath` is its proxy URL. The file is stored as uploaded, so `image` is
`null`, even for an image.

### uploadImage

Uploads an image, processes it, and stores the original plus all requested variants. The `imageOptions` object is a discriminated union on `mode` — the shape of the other fields depends on the mode you pick. It is sent as one JSON field, `file.options`, the same options a record's own images take (`avatarFile.options`, `images.options`).

```typescript
import { readFile } from "node:fs/promises";

const buffer = await readFile("./avatar.png");

const file = await sublay.storage.uploadImage({
  file: new Uint8Array(buffer),
  filename: "avatar.png",
  mimeType: "image/png",
  imageOptions: {
    mode: "exact-dimensions",
    dimensions: {
      thumbnail: { width: 64, height: 64 },
      card: { width: 400, height: 300 },
    },
    format: "webp",
    quality: 85,
  },
  pathParts: ["avatars", "usr_abc123"],
  actingUserId: "usr_abc123",
});
```

<ParamField body="file" type="Uint8Array | Blob" required>
  The image bytes: JPEG, PNG or WebP. Maximum 50 MB.
</ParamField>

<ParamField body="imageOptions" type="ImageOptions" required>
  Image-processing configuration — a discriminated union on `mode`. The supported
  modes and their required fields:

  | `mode` | Required fields | Notes |
  |--------|-----------------|-------|
  | `exact-dimensions` | `dimensions` (`{ [variant]: { width, height } }`) | Fixed-size crops. |
  | `aspect-ratio-width-based` | `aspectRatio`, `widths` (`{ [variant]: number }`) | Heights computed from the ratio. |
  | `aspect-ratio-height-based` | `aspectRatio`, `heights` (`{ [variant]: number }`) | Widths computed from the ratio. |
  | `original-aspect` | `sizes` (`{ [variant]: number }`) | Preserves source ratio; `fit` limited to `inside`/`outside`. |
  | `multi-aspect-ratio` | `aspectRatios` (`{ width, height }[]`), `sizes` | 1–10 aspect ratios. |

  All modes also accept optional `quality` (1–100, default 85), `format` (`webp` \|
  `jpeg` \| `png` \| `original`, default `webp`; `original` keeps the upload's format when it is JPEG, PNG or WebP, and stores anything else (an AVIF or HEIC, for example) as WebP), `stripExif` (boolean, default
  `true`), `fit` (`cover` \| `contain` \| `inside` \| `outside`, default
  `inside`), `originalMaxSize` (50–10000, default 3840: the longest side the
  stored original is shrunk to) and `pathParts`. Every requested size is
  1–10000 px. See [Upload Image](/v8/api-reference/storage/upload-image) for every field.
</ParamField>

<ParamField body="filename" type="string">
  Name to store the image under. Defaults to `"upload"`.
</ParamField>

<ParamField body="mimeType" type="string">
  MIME type used when wrapping a `Uint8Array`. Ignored when `file` is a `Blob`.
</ParamField>

<ParamField body="pathParts" type="string[]">
  Folder segments for the stored image, sent inside `file.options` (when given, the top-level `pathParts` wins over `imageOptions.pathParts`). The new file's id is always added after them (`<pathParts>/<fileId>/<filename>`, the file name taking the stored format's extension). Defaults to `["images"]`. A folder that is, or contains, `.` or `..` (also written `%2e%2e`), or that contains `?`, `#` or an encoded slash (`%2f`, `%5c`), is refused with a 400.
</ParamField>

<ParamField body="metadata" type="object">
  Custom key-value data stored on the file. The server adds `originalName` and
  `uploadedAt` alongside, replacing any values of yours under those keys.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user the service key acts as, who owns the upload. Omit it for a backend/project-owned file. A user that doesn't exist returns `404 storage/user-not-found`.
</ParamField>

**Returns** — `Promise<File>`: the [`File`](/v8/data-models/file), keyed `id`,
with its `image` data (`originalWidth`, `originalHeight`, `variants`, and the
processing details). Each variant is `{ publicPath, width, height, size, format }`.

### getFile

Fetches a file by ID. For a processed image, its `image` data (variants, processing details) is included. Reads are project-scoped.

```typescript
const file = await sublay.storage.getFile({
  fileId: "fil_abc123",
});
```

<ParamField body="fileId" type="string" required>
  The UUID of the file to retrieve.
</ParamField>

**Returns** — `Promise<File>`: the [`File`](/v8/data-models/file), the same
shape the uploads return. Every owner column (`userId`, `entityId`, `eventId`,
`commentId`, `chatMessageId`, `spaceId`) is present, `null` when unset; `image`
is the image data of a processed image and `null` otherwise.

---

### deleteFile

Deletes a file record and removes all associated storage objects (for images, every generated variant too).

```typescript
await sublay.storage.deleteFile({
  fileId: "fil_abc123",
  actingUserId: "usr_abc123",
});
```

<ParamField body="fileId" type="string" required>
  The UUID of the file to delete.
</ParamField>

<ParamField body="actingUserId" type="string">
  The user this delete acts as. Required when the file has an owner: pass the owner, and the delete runs exactly as their own (`400 storage/missing-user-id` without it; anyone else gets `403`). Omit it only for a backend-owned file.
</ParamField>

**Returns** — `Promise<void>`
