---
title: "Request Connection"
api: "POST /v8/:projectId/users/:userId/connection"
description: "Send a connection request to a user"
---

Sends a connection request from the authenticated user to the specified user. An optional message can be included. A notification is sent to the receiving user.

When a connection between the two users already exists:

- **Your own request is still pending**, or **you are already connected**: `200` with the existing connection row. The stored message is kept (a new `message` is ignored) and no second notification is sent.
- **The other user already sent you a request**: `409 connection/request-received`, with their request in the body as `connection`, so your app can offer to [accept it](/v8/api-reference/connections/accept-connection).
- **A declined request exists between you** (either of you declined the other): `409 connection/request-declined`. A new request is refused while it exists.

When the two users send each other a request through this endpoint at the same time, one request is created: one call gets `201`, the other `409 connection/request-received`.

<Note>
  **Requires the `connections` bundle.** A project without the connections bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the user to send a connection request to.
</ParamField>

## Body Parameters

<ParamField body="message" type="string">
  Optional message to include with the connection request.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who sends the connection request. A user token always acts as its own user and must not send it (`400 connection/acting-user-not-allowed`).
</ParamField>

## Response

Returns HTTP `201` with the created [connection row](/v8/data-models/connection#connectionrow), or HTTP `200` with the existing row when your request is already pending or the two of you are already connected. The body is the same in both cases:

<ResponseField name="id" type="string">
  ID of the connection record. Pass it to [Remove Connection](/v8/api-reference/connections/remove-connection) to withdraw the request.
</ResponseField>

<ResponseField name="user" type="object">
  Public profile of the user the request was sent to (the user in the path). Sensitive fields (email, hash, secureMetadata, etc.) are excluded.
</ResponseField>

<ResponseField name="type" type="string">
  `"sent"` when the authenticated user sent the request, `"received"` when the other user did. Always `"sent"` on a `201`; an existing accepted connection the other user started answers `"received"`.
</ResponseField>

<ResponseField name="message" type="string | null">
  The note sent with the request, or `null`.
</ResponseField>

<ResponseField name="status" type="string">
  `"pending"` for a request not yet answered (always, on a `201`), `"accepted"` for an existing connection.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of when the request was sent.
</ResponseField>

<ResponseField name="respondedAt" type="string | null">
  When the request was accepted, or `null` while it is pending.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "connection/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "connection/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Self-Request — 400">
    ```json
    {
      "error": "A user cannot send a connection request to themselves.",
      "code": "connection/self-request"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    A service key named an `actingUserId` that isn't a user in this project:

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "connection/user-not-found" }
    ```

    Otherwise, the user to connect with doesn't exist, or one of the two users has blocked the other. Both get the same answer:

    ```json
    {
      "error": "One or both users involved in the connection do not exist.",
      "code": "connection/user-not-found"
    }
    ```
  </Accordion>
  <Accordion title="Request Received — 409">
    The other user already sent you a connection request. `connection` is that request, as a [connection row](/v8/data-models/connection#connectionrow) seen from your side (`type: "received"`); accept it with [Accept Connection](/v8/api-reference/connections/accept-connection).
    ```json
    {
      "error": "This user has already sent you a connection request.",
      "code": "connection/request-received",
      "connection": {
        "id": "8f0c…",
        "user": { "id": "…", "username": "…" },
        "type": "received",
        "message": "Hi!",
        "status": "pending",
        "createdAt": "2026-11-18T10:00:00.000Z",
        "respondedAt": null
      }
    }
    ```
  </Accordion>
  <Accordion title="Request Previously Declined — 409">
    ```json
    {
      "error": "Connection request was declined. Only the receiver can initiate a new request.",
      "code": "connection/request-declined"
    }
    ```
  </Accordion>
</AccordionGroup>
