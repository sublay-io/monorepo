# Threaded Comments Props

Threaded comments follow a **minimal props philosophy**. They work with a single prop that identifies the entity and offer optional props for specific needs.

- **React (Web)** — one component, `ThreadedCommentSection`.
- **React Native and Expo** — three components that your screen places: `ThreadedComments`, `ThreadedCommentSection` and `ThreadedCommentInput`. See [React Native and Expo Components](#react-native-and-expo-components).

## Props Interface

<Tabs>
  <Tab title="React (Web)">
    ```tsx
    interface ThreadedCommentSectionProps {
      // Entity identification (provide ONE of these)
      entity?: Entity | undefined | null;
      entityId?: string | undefined | null;
      foreignId?: string | undefined | null;
      shortId?: string | undefined | null;

      // With foreignId: create the entity if it doesn't exist yet
      createIfNotFound?: boolean;

      // Optional features
      isVisible?: boolean;
      highlightedCommentId?: string | undefined | null;
      theme?: 'light' | 'dark';   // Only for the inline styles variant
      children?: React.ReactNode;
    }
    ```
  </Tab>
  <Tab title="React Native / Expo">
    ```tsx
    // Wraps the screen
    interface ThreadedCommentsProps {
      // Entity identification (provide ONE of these)
      entity?: Entity | undefined | null;
      entityId?: string | undefined | null;
      foreignId?: string | undefined | null;
      shortId?: string | undefined | null;

      // With foreignId: create the entity if it doesn't exist yet
      createIfNotFound?: boolean;

      // Optional features
      highlightedCommentId?: string | undefined | null;
      theme?: 'light' | 'dark';
      children?: React.ReactNode;  // Your screen
    }

    // Sort by and the comments
    interface ThreadedCommentSectionProps {
      children?: React.ReactNode;  // Replaces the "no comments yet" view
    }

    // The comment box
    interface ThreadedCommentInputProps {
      containerClassName?: string;            // Tailwind variant
      containerStyle?: StyleProp<ViewStyle>;  // Inline styles variant
    }
    ```
  </Tab>
</Tabs>

| Prop | React (Web) | React Native / Expo |
|------|-------------|---------------------|
| `entity`, `entityId`, `foreignId`, `shortId` | `ThreadedCommentSection` | `ThreadedComments` |
| `createIfNotFound` | `ThreadedCommentSection` | `ThreadedComments` |
| `highlightedCommentId` | `ThreadedCommentSection` | `ThreadedComments` |
| `theme` | `ThreadedCommentSection`, inline styles variant only | `ThreadedComments`, both variants |
| `children` | `ThreadedCommentSection`: replaces the "no comments yet" view | `ThreadedComments`: your screen. `ThreadedCommentSection`: replaces the "no comments yet" view |
| `isVisible` | `ThreadedCommentSection` | — (don't render `ThreadedCommentInput` instead) |
| `containerClassName` / `containerStyle` | — | `ThreadedCommentInput` |

The examples below use the web component. On React Native and Expo, pass the same props to `ThreadedComments`.

## Entity Identification

**Provide one of these** to identify which entity the comments belong to:

### `entity`

**Type:** `Entity | undefined | null`

A complete Entity object.

```tsx
<ThreadedCommentSection
  entity={{
    id: "0b9d5a3e-6c1f-4f7a-9d2e-8a4c1b7e5f30",
    projectId: "proj_456",
    foreignId: "post-789",
    // ... other entity fields
  }}
/>
```

**Use when:** You already have the full entity object from `useFetchEntity` or similar hooks.

---

### `entityId`

**Type:** `string | undefined | null`

The Sublay entity's own `id` (a UUID), as returned by the SDK and the API.

```tsx
<ThreadedCommentSection entityId="0b9d5a3e-6c1f-4f7a-9d2e-8a4c1b7e5f30" />
```

**Use when:** You have the entity's Sublay ID but not the entity object.

---

### `foreignId`

**Type:** `string | undefined | null`

Your external/custom ID for the entity. The component finds the Sublay entity that has this `foreignId`. It creates one only when [`createIfNotFound`](#createifnotfound) is also set.

```tsx
<ThreadedCommentSection foreignId="blog-post-789" />
```

**Use when:** You identify the entity by an ID from your own system.

---

### `shortId`

**Type:** `string | undefined | null`

A short, human-readable identifier (if you've set one on the entity).

```tsx
<ThreadedCommentSection shortId="my-first-post" />
```

**Use when:** You have the entity's short ID, for example from a URL.

<Note>
**You only need ONE of these props.** Use whichever fits your data model best.
</Note>

---

### `createIfNotFound`

**Type:** `boolean` — **Default:** `false`

Used with `foreignId`. When set, the entity is created the first time the section is shown if no entity with that `foreignId` exists yet.

```tsx
<ThreadedCommentSection foreignId="blog-post-789" createIfNotFound />
```

Without it, the section only finds an existing entity. When there is none, it shows its ["Couldn't load comments" state](/v8/components/components/threaded/features#error-states) instead of the comments.

The created entity has no author, so the project's **Who can create entities without an author** setting decides who may create it. The default, **Everyone**, lets any visitor's section create it. Under **Signed-in users only** a visitor with no session can't, and under **No one from the client** only a service key can (create the entity from your backend first). A refused section shows the same "Couldn't load comments" state. See [Fetch Entity by Foreign ID](/v8/api-reference/entities/fetch-entity-by-foreign-id).

It has no effect with `entity`, `entityId` or `shortId`.

The other examples on this page pass `foreignId` alone, for an entity that already exists.

## Optional Props

### `isVisible`

**Type:** `boolean` — **Default:** `true`

**React (Web) only.** Whether the comment box is shown. When `false`, the section shows Sort by and the comments, without the box.

```tsx
<ThreadedCommentSection
  foreignId="post_123"
  isVisible={canComment}
/>
```

On React Native and Expo, the comment box is its own component: to hide it, don't render [`ThreadedCommentInput`](#threadedcommentinput).

---

### `highlightedCommentId`

**Type:** `string | undefined | null`

ID of a specific comment to highlight when the section loads. The section opens focused on that comment's thread — its parent (if it has one) with the highlighted comment marked under it, and their replies — with a **View all comments** button that switches to the full comment section. If the comment doesn't exist, the full comment section shows. See [Highlighted Comments](/v8/components/components/threaded/features#highlighted-comments).

```tsx
<ThreadedCommentSection
  foreignId="post_123"
  highlightedCommentId="comment_456"
/>
```

**Use cases:** Deep-linking from notifications, jumping to a comment via URL param.

---

### `theme`

**Type:** `'light' | 'dark'` — **Default:** `'light'`

Sets the color theme for the entire comment section. On React (Web) it is **only for the inline styles variant**. On React Native and Expo both variants use it; it goes on `ThreadedComments`.

```tsx
<ThreadedCommentSection
  foreignId="post_123"
  theme={isDark ? 'dark' : 'light'}
/>
```

<Tabs>
  <Tab title="Inline Styles Variant">
    Uses the `theme` prop to conditionally render dark or light colors:

    ```tsx
    style={{ backgroundColor: theme === 'dark' ? '#1F2937' : '#FFFFFF' }}
    ```
  </Tab>

  <Tab title="Tailwind Variant">
    On React (Web), the section has no `theme` prop. It uses Tailwind's dark mode system instead — add a `dark` class to a parent element:

    ```tsx
    <html className={isDark ? 'dark' : ''}>
      <ThreadedCommentSection foreignId="post_123" />
    </html>
    ```

    Requires Tailwind's dark mode to follow the `dark` class: `darkMode: 'class'` in `tailwind.config.js` (Tailwind CSS 3), or `@custom-variant dark (&:where(.dark, .dark *));` in your CSS (Tailwind CSS 4). On React Native and Expo, the Tailwind variant takes `theme` like the inline styles variant.
  </Tab>
</Tabs>

---

### `children`

**Type:** `React.ReactNode`

Content shown in place of the "no comments yet" view, when the entity has no comments. On React Native and Expo, this is the `children` of `ThreadedCommentSection`; the `children` of `ThreadedComments` is your screen.

```tsx
<ThreadedCommentSection foreignId="post_123">
  <div className="text-center text-gray-500 my-4">
    Be the first to comment!
  </div>
</ThreadedCommentSection>
```

## React Native and Expo Components

On React Native and Expo, threaded comments are three components, installed together by `npx @sublay/cli add comments-threaded --ref v8` and all exported from the component's `index.ts`. Your screen places them:

```tsx
import { KeyboardAvoidingView, Platform, ScrollView } from 'react-native';
import {
  ThreadedComments,
  ThreadedCommentSection,
  ThreadedCommentInput,
} from './components/comments-threaded';

function EntityScreen() {
  return (
    <ThreadedComments foreignId="post_123" theme="dark">
      <KeyboardAvoidingView
        style={{ flex: 1 }}
        behavior={Platform.OS === 'ios' ? 'padding' : undefined}
      >
        <ScrollView keyboardShouldPersistTaps="handled">
          <YourEntity />
          <ThreadedCommentSection />
        </ScrollView>
        <ThreadedCommentInput />
      </KeyboardAvoidingView>
    </ThreadedComments>
  );
}
```

The entity above the section scrolls away with the comments, and the comment box stays pinned below the scroll view. Keyboard handling is up to your screen: use `KeyboardAvoidingView` as above, or the keyboard library your app already uses. Give the scroll view `keyboardShouldPersistTaps="handled"`, so tapping Reply, a vote or **Sort by** while the keyboard is open works on the first tap instead of only closing the keyboard.

### `ThreadedComments`

Wraps the screen. It takes the entity props, [`createIfNotFound`](#createifnotfound), [`highlightedCommentId`](#highlightedcommentid), [`theme`](#theme), and `children`: your screen, which holds `ThreadedCommentSection` and `ThreadedCommentInput`.

It holds the state the other two share, and it renders the sheets — Sort by, the comment menu, the menu for your own comment, and the report form — over the view it wraps. That view is an invisible `flex: 1` view, so wrap the whole screen to have the sheets cover the screen. The navigation header your navigator draws stays outside it.

### `ThreadedCommentSection`

The **Sort by** button and the comments. It has no scrolling of its own: put it inside your screen's `ScrollView`, so content above it (the entity) scrolls away with the comments.

| Prop | Type | Description |
|------|------|-------------|
| `children` | `React.ReactNode` | Replaces the "no comments yet" view |

It throws an error when it is rendered outside `ThreadedComments`.

### `ThreadedCommentInput`

The comment box, with the **"Replying to"** bar above it. Place it anywhere inside `ThreadedComments`, typically pinned below the `ScrollView`. Tapping Reply on a comment focuses it. It never focuses itself when the screen opens.

| Prop | Variant | Type | Description |
|------|---------|------|-------------|
| `containerClassName` | Tailwind | `string` | Classes for the view around the box |
| `containerStyle` | Inline styles | `StyleProp<ViewStyle>` | Style for the view around the box |

By default, the view around the box has a top border, on the section's background color. Passing either prop replaces that default.

```tsx
<ThreadedCommentInput containerClassName="border-t border-gray-200 bg-white pb-4" />
```

To hide the comment box, don't render `ThreadedCommentInput`. It throws an error when it is rendered outside `ThreadedComments`.

## Complete Examples

### Minimal Usage

```tsx
<ThreadedCommentSection foreignId="blog-post-123" createIfNotFound />
```

---

### With Dark Mode (Inline Styles)

```tsx
function BlogPost({ post }) {
  const [isDark, setIsDark] = useState(false);

  return (
    <>
      <button onClick={() => setIsDark(!isDark)}>Toggle Theme</button>
      <ThreadedCommentSection
        foreignId={post.id}
        theme={isDark ? 'dark' : 'light'}
      />
    </>
  );
}
```

---

### With Highlighted Comment

```tsx
import { useSearchParams } from 'react-router-dom';

function BlogPost({ post }) {
  const [searchParams] = useSearchParams();

  return (
    <ThreadedCommentSection
      foreignId={post.id}
      highlightedCommentId={searchParams.get('commentId')}
    />
  );
}

// URL: /blog/my-post?commentId=comment_abc123
// → opens focused on comment_abc123's thread, with "View all comments" above it
```

---

### Full Example (Web)

```tsx
function BlogPost({ postId }) {
  const [searchParams] = useSearchParams();
  const [isDark, setIsDark] = useState(false);
  const { user } = useUser();
  const { data: entity } = useFetchEntity({ foreignId: postId });

  return (
    <ThreadedCommentSection
      entity={entity}
      isVisible={!!user}
      highlightedCommentId={searchParams.get('commentId')}
      theme={isDark ? 'dark' : 'light'}
    >
      <div className="text-center text-sm text-gray-500 my-2">
        No comments yet. Be respectful in the discussion.
      </div>
    </ThreadedCommentSection>
  );
}
```

---

### Full Example (React Native / Expo)

```tsx
function EntityScreen({ entityId, commentId, isDark }) {
  const { user } = useUser();

  return (
    <ThreadedComments
      entityId={entityId}
      highlightedCommentId={commentId}
      theme={isDark ? 'dark' : 'light'}
    >
      <KeyboardAvoidingView
        style={{ flex: 1 }}
        behavior={Platform.OS === 'ios' ? 'padding' : undefined}
      >
        <ScrollView keyboardShouldPersistTaps="handled">
          <YourEntity />
          <ThreadedCommentSection>
            <Text>No comments yet. Be respectful in the discussion.</Text>
          </ThreadedCommentSection>
        </ScrollView>
        {user ? <ThreadedCommentInput /> : null}
      </KeyboardAvoidingView>
    </ThreadedComments>
  );
}
```
