---
title: "Add Entity Reaction"
api: "POST /v8/:projectId/entities/:entityId/reactions"
description: "Add or update a reaction on an entity"
---

<Note>
  **Requires the `entities` bundle.** A project without the entities bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

Adds a reaction of the specified type to an entity. If the user already has a reaction on this entity, it is replaced with the new type. The entity's `reactionCounts` map is updated accordingly. Sending the reaction the user already has changes nothing: the response is the same `200` with the entity, counts stay as they are, and no notification is sent.

**Authentication required.**

## Path Parameters

<ParamField path="entityId" type="string" required>
  The UUID of the entity to react to.
</ParamField>

## Body Parameters

<ParamField body="reactionType" type="string" required>
  The type of reaction to add. One of: `upvote`, `downvote`, `like`, `love`, `wow`, `sad`, `angry`, `funny`.
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who the reaction is attributed to. Useful for backfilling reactions from an external system. A user token always acts as its own user and must not send it (`400 entity/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Entity](/v8/data-models/entity) object with the new `reactionCounts` map.

<Note>
  The entity owner receives an in-app notification when someone reacts to their entity. Milestone notifications are also sent at reaction count thresholds (e.g., 10, 50, 100 reactions).
</Note>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    ```json
    { "error": "Missing user ID", "code": "entity/missing-user-id" }
    ```
    Returned when a service key sends no `actingUserId`.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "entity/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "entity/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Entity not found.", "code": "entity/not-found" }
    ```
  </Accordion>
</AccordionGroup>
