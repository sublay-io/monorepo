---
title: "Delete Event"
api: "DELETE /v8/:projectId/events/:eventId"
description: "Permanently or soft-delete an event and clean up its children (the owner or the space's admins and moderators)"
---

Deletes an event. Allowed for the event's **owner** (also when they are no longer an active member of its space) and for an active admin or moderator of the event's space. Other hosts can't delete an event that has an owner. When the owner's account was deleted, any of its hosts may delete it — for an event in a space, only while an active member of that space (an event kept after the `spaces` bundle was uninstalled counts as having no space here). A service key acts as the user it names in `actingUserId`, with that user's powers. The event's child `EventRsvps` and `EventInvites` are cleaned up, and—depending on settings—its files.

Deletion honors the project's `eventDeletion` settings:

- `softDelete` (default `false`) — when `true`, the event is soft-deleted (a `deletedAt` timestamp is set) and drops out of listings while the row is retained.
- `preserveFilesOnSoftDelete` (default `true`) — on a soft delete, keep the event's files. On a hard delete, files are always removed.

## Path Parameters

<ParamField path="eventId" type="string" required>
  UUID of the event to delete.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Required with a service key: the user this request acts as. It has exactly that user's powers, so it is refused unless they are the event's owner, an active admin or moderator of its space, or (on an event with no owner) one of its hosts, and it is recorded as theirs. A user token always acts as its own user and must not send it (`400 event/acting-user-not-allowed`).
</ParamField>

## Response

Returns `204 No Content` on success.

## Error Responses

<AccordionGroup>
  <Accordion title="Missing Acting User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "event/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Acting User — 400">
    `actingUserId` is not a user id.
    ```json
    { "error": "actingUserId must be a user id.", "code": "event/invalid-query" }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "event/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Body Not Allowed — 400">
    The request carried a body. A DELETE takes no body: send `actingUserId` and every other field in the query string.
    ```json
    {
      "error": "A DELETE request takes no body: send its fields in the query string. Received: `actingUserId`.",
      "code": "event/body-not-allowed",
      "params": ["actingUserId"]
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "event/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    The event doesn't exist, or the caller can't [see it](/v8/data-models/event#visibility) and isn't one of its hosts.
    ```json
    { "error": "Event not found", "code": "event/not-found" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    The caller isn't the owner or an admin or moderator of the event's space (other hosts included), and the event has an owner — or the event has no owner and the caller isn't one of its hosts.
    ```json
    { "error": "Only the event's owner or an admin or moderator of its space may delete it.", "code": "event/forbidden" }
    ```
  </Accordion>
  <Accordion title="Host Not an Active Member — 403">
    On an event with no owner, the caller is a host, but the event is in a space they aren't an active member of, or they are banned in it or a space above it. One body for every case.
    ```json
    { "error": "Hosts must be active members of this event's space, and not banned from it or a space above it, to do this.", "code": "event/not-space-member" }
    ```
  </Accordion>
  <Accordion title="Already Deleted — 404">
    ```json
    { "error": "Event not found or already deleted.", "code": "event/delete-failed" }
    ```
  </Accordion>
</AccordionGroup>
