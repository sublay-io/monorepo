## Overview

`useJoinSpace` returns a callable function for joining a space. If the space has `requireJoinApproval: true`, the membership is created with `status: "pending"` until approved by a moderator or admin. Otherwise, it is immediately `active`. A private space can't be joined: joining a space the user can't see answers `404 space/not-found`, and its moderators and admins add members with [`useAddMember`](/v8/hooks/spaces/use-add-member).

<Note>When using `SpaceProvider`, call `joinSpace` from `useSpace` — it then fetches the space again, so the space's `memberPermissions` and member count reflect the change.</Note>

## Usage Example

```tsx
import { useJoinSpace } from "@sublay/react-js";

function JoinButton({ spaceId }: { spaceId: string }) {
  const joinSpace = useJoinSpace();

  const handleJoin = async () => {
    const result = await joinSpace({ spaceId });
    console.log(result.status); // "pending" or "active"
  };

  return <button onClick={handleJoin}>Join</button>;
}
```

## Parameters

<ParamField path="spaceId" type="string" required>
  UUID of the space to join.
</ParamField>

## Returns

Resolves with the user's membership record, as a [SpaceMember](/v8/data-models/space-member) object: `id`, `spaceId`, `userId`, `role` (`"member"`), `status` (`"pending"` or `"active"`), `joinedAt` and `createdAt`. A new membership (also a join after a declined request) answers HTTP `201`. Joining again as an active member, or with a request already awaiting approval, is not an error: it answers HTTP `200` with the existing membership, unchanged. A banned user gets `403 space/banned`.

The response carries no permissions. To read what the user may do in the space now, fetch the space again: its `memberPermissions` describe them (a request awaiting approval reports `status: "pending"` and `isMember: false`). `joinSpace` from `useSpace` does this for you.
