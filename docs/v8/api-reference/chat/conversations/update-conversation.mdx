---
title: "Update Conversation"
api: "PATCH /v8/:projectId/chat/conversations/:conversationId"
description: "Update a group or space conversation's name, description, avatar, or posting permissions"
---

Updates one or more fields on a conversation. Only `group` and `space` conversations can be updated — direct conversations return a 400.

**Authorization:**
- `group` conversations: caller must be an active `admin` member.
- `space` conversations: caller must be an active `admin` or `moderator` of the parent Space (a banned admin or moderator can't).

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation to update.
</ParamField>

## Body Parameters

All fields are optional. Only provided fields are updated.

<ParamField body="name" type="string">
  New display name for the conversation. Maximum 200 characters.
</ParamField>

<ParamField body="description" type="string">
  New description. Maximum 1000 characters.
</ParamField>

<ParamField body="avatarFileId" type="string | null">
  ID of an uploaded [File](/v8/data-models/file) to use as the conversation avatar. Pass `null` to remove the current avatar. If a previous avatar exists, it is deleted from storage automatically.
</ParamField>

<ParamField body="postingPermission" type="string">
  Who can post messages. Only valid for `space` conversations. Accepted values: `"members"` (any active member), `"admins"` (only space admins and moderators).
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be allowed to update the conversation (see **Authorization** above). A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns the updated [Conversation](/v8/data-models/conversation) object, with `avatarFile` populated if set.

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Conversation not found.", "code": "chat/not-found" }
    ```
  </Accordion>
  <Accordion title="Cannot Update DM — 400 Bad Request">
    ```json
    { "error": "Direct conversations cannot be updated.", "code": "chat/cannot-update-dm" }
    ```
  </Accordion>
  <Accordion title="Invalid Field — 400 Bad Request">
    ```json
    { "error": "'postingPermission' can only be set on space conversations.", "code": "chat/invalid-field" }
    ```
  </Accordion>
  <Accordion title="Forbidden (group) — 403">
    ```json
    { "error": "Only group admins can update this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Forbidden (space) — 403">
    ```json
    { "error": "Only space admins and moderators can update the space conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
</AccordionGroup>
