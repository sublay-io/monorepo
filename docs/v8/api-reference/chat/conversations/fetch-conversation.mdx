---
title: "Fetch Conversation"
api: "GET /v8/:projectId/chat/conversations/:conversationId"
description: "Fetch a single conversation by ID"
---

Returns a [Conversation](/v8/data-models/conversation) object with the caller's membership row and active member count included. The caller must be a member of the conversation, current or former; for a space chat, an active member of the space can fetch it before opening it for the first time.

## Path Parameters

<ParamField path="conversationId" type="string" required>
  The ID of the conversation to fetch.
</ParamField>

## Query Parameters

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Must be a member of the conversation. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

Returns a [Conversation](/v8/data-models/conversation) with two additional fields:

<ResponseField name="currentMember" type="ConversationMember | null">
  The calling user's membership row for this conversation. `null` if the user has no membership record.
</ResponseField>

<ResponseField name="memberCount" type="number">
  Number of currently active members.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "Missing user ID", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Forbidden — 403">
    ```json
    { "error": "You are not a member of this conversation.", "code": "chat/not-a-member" }
    ```
  </Accordion>
  <Accordion title="Not Found — 404">
    ```json
    { "error": "Conversation not found.", "code": "chat/not-found" }
    ```
  </Accordion>
</AccordionGroup>
