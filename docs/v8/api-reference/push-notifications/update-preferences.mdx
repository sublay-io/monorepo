---
title: "Update Notification Preferences"
api: "PUT /v8/:projectId/push-notifications/preferences"
description: "Set the authenticated user's disabled push notification types"
---

Upserts the acting user's push notification preferences. The request **replaces** the whole disabled-types set — send the complete set you want stored, not a delta. Duplicates are collapsed; only valid event type names are accepted.

Requires authentication. **Acting-user-scoped:** an end-user token (`Authorization: Bearer <accessToken>`) writes its own preferences. A service key acts on behalf of a named user via the body `actingUserId` — a service key without `actingUserId` is rejected, and an end-user token must not send it. Requires the `push` bundle.

## Body Parameters

<ParamField body="disabledTypes" type="string[]" required>
  The complete set of event types to disable for push. Each value must be one of the server's exact event type names (see the [event palette](/v8/notification-preferences#the-event-palette)) — unknown names are rejected. Pass `[]` to re-enable everything (all-on).
</ParamField>

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their preferences are written. A user token always acts as its own user and must not send it (`400 notification-preferences/acting-user-not-allowed`).
</ParamField>

## Response

Returns `200` with the stored set (deduplicated).

```json
{ "disabledTypes": ["comment-mention"] }
```

## Error Responses

<AccordionGroup>
  <Accordion title="No Credential — 401">
    Plain-text `Unauthorized`, with no JSON body and no `code`. Returned when the
    request carries no `Authorization` header at all.
  </Accordion>
  <Accordion title="Rejected Credential — 403">
    Plain-text `Forbidden`, with no JSON body and no `code`. Returned when the
    access token is malformed, has the wrong signature, or has **expired** — the
    common case, since access tokens live 30 minutes. Refresh the access token
    and retry.
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "notification-preferences/acting-user-not-allowed" }
    ```
    Returned when a user token sends `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
  </Accordion>
  <Accordion title="User Not Found — 404">
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "notification-preferences/user-not-found" }
    ```
    Returned when a service key names an `actingUserId` that isn't a user in this project.
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "notification-preferences/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "notification-preferences/unsupported-param",
      "param": "userId"
    }
    ```
    Returned when the request sends `userId`. On this route the user a service key acts as is `actingUserId`.
  </Accordion>
  <Accordion title="Missing User ID — 400">
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "notification-preferences/missing-user-id" }
    ```
    Returned when a service key omits the required `actingUserId` (it has no implicit session user).
  </Accordion>
  <Accordion title="Invalid Body — 400">
    ```json
    { "error": "...", "code": "notification-preferences/invalid-body" }
    ```
    Returned when `disabledTypes` contains a value that is not a recognized event type name.
  </Accordion>
  <Accordion title="Bundle Not Installed — 403">
    ```json
    {
      "code": "database/tables-not-available",
      "missingTables": ["PushProviderConfigs", "PushDevices", "NotificationPreferences"],
      "dashboardUrl": "https://…/<projectId>/database"
    }
    ```
    Returned when the `push` bundle is not installed for this project.
  </Accordion>
  <Accordion title="Bundle Provisioning — 503">
    ```json
    {
      "code": "database/tables-provisioning",
      "missingTables": ["PushProviderConfigs", "PushDevices", "NotificationPreferences"],
      "bundleId": "push"
    }
    ```
    Returned while the `push` bundle is mid-install. Retry shortly.
  </Accordion>
  <Accordion title="Server Error — 500">
    ```json
    {
      "error": "Internal server error.",
      "code": "notification-preferences/server-error"
    }
    ```
  </Accordion>
</AccordionGroup>

**Rate limit:** 50 requests per 5 minutes per IP. Exceeding it returns `429` with a plain-text message and no `code`.
