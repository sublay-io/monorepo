---
title: "Fetch Blocked Users"
api: "GET /v8/:projectId/blocks"
description: "Get the acting user's own paginated list of blocked users"
---

Returns a paginated list of the users the acting user has blocked (their **outbound** blocks), each row carrying a public summary of the blocked user. This is the private "manage / way back to unblock" surface.

<Warning>
  A block list is **private** — only the blocker can read their own list. It exposes only the caller's outbound blocks; there is no way to read who has blocked the caller.
</Warning>

<Note>
  **Requires the `moderation` bundle.** A project without the moderation bundle returns `403 database/tables-not-available`. See [Bundles](/v8/bundles).
</Note>

## Query Parameters

<ParamField query="page" type="number" default="1">
  Page number for pagination.
</ParamField>

<ParamField query="limit" type="number" default="20">
  Number of results per page. Max `100`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their own block list (as the blocker) is returned. A user token always acts as its own user and must not send it (`400 block/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `200` with a paginated response:

<ResponseField name="data" type="array">
  Array of block entries.
  <Expandable title="item properties">
    <ResponseField name="id" type="string">
      ID of the block record.
    </ResponseField>
    <ResponseField name="blockedUser" type="object">
      Public profile of the blocked user. Sensitive fields (email, hash, salt, secureMetadata, etc.) are excluded. May be `null` if the user is unavailable.
    </ResponseField>
    <ResponseField name="createdAt" type="string">
      ISO timestamp of when the block was created.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="pagination" type="object">
  Pagination metadata.
  <Expandable title="properties">
    <ResponseField name="page" type="number">
      Current page number.
    </ResponseField>
    <ResponseField name="pageSize" type="number">
      Number of items per page.
    </ResponseField>
    <ResponseField name="totalItems" type="number">
      Total number of blocked users.
    </ResponseField>
    <ResponseField name="totalPages" type="number">
      Total number of pages.
    </ResponseField>
    <ResponseField name="hasMore" type="boolean">
      Whether there are more pages after the current one.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "Missing user ID",
      "code": "block/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "block/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.
    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "block/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
</AccordionGroup>
