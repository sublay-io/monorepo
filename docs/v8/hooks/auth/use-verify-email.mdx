## Overview

`useVerifyEmail` returns a function that submits a verification code to the server. It confirms two kinds of code:

- a code from `useSendVerificationEmail` with `mode: "code"`, sent to the signed-in user. On success, `user.isVerified` is updated immediately in the local Redux store.
- a sign-up code, sent when the project requires email verification before sign-in and you passed `emailVerification: { mode: "code" }` to `signUpWithEmailAndPassword` or `signInWithEmailAndPassword`. Pass the `verificationId` they returned. The account being confirmed isn't signed in, so the signed-in user (if any) is left untouched; sign the user in afterwards. See [Require Email Verification](/v8/sdk/authentication/built-in#require-email-verification).

## Usage Example

<CodeGroup>
```tsx React
import { useVerifyEmail } from "@sublay/react-js";
import { useState } from "react";

function VerifyCodeForm() {
  const verifyEmail = useVerifyEmail();
  const [code, setCode] = useState("");
  const [error, setError] = useState("");

  const handleSubmit = async (e: React.FormEvent) => {
    e.preventDefault();
    setError("");
    try {
      await verifyEmail({ token: code });
      // user.isVerified is now true locally
    } catch (err: any) {
      setError(err.response?.data?.error ?? "Verification failed.");
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      {error && <p>{error}</p>}
      <input
        value={code}
        onChange={(e) => setCode(e.target.value)}
        placeholder="Enter verification code"
      />
      <button type="submit">Verify</button>
    </form>
  );
}
```

```tsx React Native
import { useVerifyEmail } from "@sublay/react-native";

function VerifyCodeScreen({ code }: { code: string }) {
  const verifyEmail = useVerifyEmail();

  return (
    <Button
      title="Verify"
      onPress={() => verifyEmail({ token: code })}
    />
  );
}
```
</CodeGroup>

## Parameters

The returned function accepts:

<ParamField path="token" type="string" required>
  The code entered by the user. Must match the code from the email exactly.
</ParamField>

<ParamField path="verificationId" type="string">
  The `verificationId` returned with a sign-up code. Required to confirm one; leave it out for a code from `useSendVerificationEmail`. A sign-up code allows 5 wrong tries. If the ID is lost, signing in again returns it (or a new code's, if the last email is more than 10 minutes old); after the tries run out, signing in again can send a new code with a new `verificationId` (at most one email every 10 minutes).
</ParamField>

## Returns

The hook returns an async function. That function resolves to:

<ResponseField name="success" type="boolean">
  `true` when verification succeeded.
</ResponseField>

<Note>
  On success without a `verificationId`, `user.isVerified` is optimistically set
  to `true` in the local Redux store immediately — no need to refetch the user.
  With a `verificationId`, the local store is left as it is.
</Note>
