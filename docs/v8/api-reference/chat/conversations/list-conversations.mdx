---
title: "List Conversations"
api: "GET /v8/:projectId/chat/conversations"
description: "Get the current user's conversations, ordered by most recent activity"
---

Returns a cursor-paginated list of `ConversationPreview` objects for the acting user. Only active memberships are included. A space chat is included only while the acting user is an active member of its space and can see it ([visibility](/v8/data-models/space#visibility)); a pending, rejected or banned member, or someone who left the space, doesn't get it even while they still hold a conversation membership. Results are ordered by `lastMessageAt` descending (conversations with no messages appear last), then by `createdAt` descending, then by `id`, so every conversation has one place in the order and no page skips or repeats one.

<Note>
  A `direct` conversation stays out of both parties' lists until it has a first message, so an opened-but-never-sent DM is invisible to the other side. A DM whose messages were later [deleted or removed](/v8/data-models/chat-message#deleted-and-removed-messages) stays listed, its last message the placeholder. `group` and `space` conversations appear from creation.
</Note>

To fetch a single conversation in this same shape — one that was paginated out, or just created — use [Fetch Conversation Preview](/v8/api-reference/chat/conversations/fetch-conversation-preview). Both endpoints are served by the same query, so the shapes stay identical.

## Query Parameters

<ParamField query="types" type="string">
  Only conversations of these types. Allowed values: `direct`, `group`, `space`, matched exactly (lowercase). Send a comma-separated list (`types=direct,group`) or repeat the parameter (`types=direct&types=group`). Omitted or empty, all types are returned. Any other value, such as `DIRECT` or `dm`, returns `400 chat/invalid-query`.
</ParamField>

<ParamField query="cursor" type="string">
  Continue after the last conversation of a previous response. Leave it out on the first request, then pass `pagination.nextCursor` from the previous response, unchanged. The cursor is opaque: don't build or parse it. One that can't be read returns `400 chat/invalid-cursor`. Keep `types` the same across the pages of one list.
</ParamField>

<ParamField query="limit" type="number">
  Number of conversations to return per page. Defaults to `20`. Maximum `50`.
</ParamField>

<ParamField query="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as. Their conversations are listed. A user token always acts as its own user and must not send it (`400 chat/acting-user-not-allowed`).
</ParamField>

## Response

<ResponseField name="data" type="ConversationPreview[]">
  Array of conversation preview objects. Each item is a [Conversation](/v8/data-models/conversation) extended with the following fields:

  <Expandable title="ConversationPreview fields">
    <ResponseField name="unreadCount" type="number">
      Number of unread messages in this conversation for the acting user.
    </ResponseField>

    <ResponseField name="memberCount" type="number">
      Number of active members.
    </ResponseField>

    <ResponseField name="mutedUntil" type="string | null">
      ISO timestamp until which the acting user has muted this conversation. `null` when the conversation is not muted, and also when it is muted forever.
    </ResponseField>

    <ResponseField name="mutedForever" type="boolean">
      Whether the acting user has muted this conversation indefinitely. A forever mute returns `mutedForever: true` with `mutedUntil: null` — the far-future storage sentinel is never exposed as a date. Read the boolean; never string-match a date.
    </ResponseField>

    <ResponseField name="lastMessage" type="ChatMessage | null">
      The most recent top-level [message](/v8/data-models/chat-message) in the conversation (thread replies are never the last message), or `null` if there is none. A [deleted or removed](/v8/data-models/chat-message#deleted-and-removed-messages) last message is shown as its placeholder, by the same rules as everywhere else: `content`, `gif` and `files` are empty, and a removed one's `userId` and `user` are `null` unless it's the viewer's own. A preview with only the fields below, not the full message the `message:created` socket event delivers: `content` is cut to 100 characters, `user` is set only in group and space conversations, and fields such as `mentions`, `quotedMessage`, `reactionCounts` and `parentMessageId` are not included. Its timestamps are UTC ISO strings ending in `Z`.

      <Expandable title="lastMessage fields">
        <ResponseField name="id" type="string">
          UUID of the message.
        </ResponseField>
        <ResponseField name="conversationId" type="string">
          UUID of the conversation the message belongs to.
        </ResponseField>
        <ResponseField name="content" type="string | null">
          Message text, **truncated to 100 characters** for list performance. Fetch the message itself for the full content.
        </ResponseField>
        <ResponseField name="gif" type="object | null">
          Attached GIF, if the message carries one.
        </ResponseField>
        <ResponseField name="userId" type="string | null">
          UUID of the sender. `null` when the sender's account was deleted, and on a removed message for everyone but its author.
        </ResponseField>
        <ResponseField name="userDeletedAt" type="string | null">
          Set when the message was deleted (by its author, or when their account was deleted).
        </ResponseField>
        <ResponseField name="moderationStatus" type="string | null">
          `"removed"` when a moderator removed the message.
        </ResponseField>
        <ResponseField name="createdAt" type="string">
          ISO timestamp of when the message was sent.
        </ResponseField>
        <ResponseField name="files" type="File[]">
          Attached [files](/v8/data-models/file), with proxy URLs and image variants resolved. Empty array when the message has no attachments.
        </ResponseField>
        <ResponseField name="user" type="object | null">
          Sender identity (`id`, `name`, `username`, `avatar`, `reputation`) — populated for `group` and `space` conversations only. Always `null` for `direct` conversations, where the counterparty is already in `otherMembers`.
        </ResponseField>
      </Expandable>
    </ResponseField>

    <ResponseField name="otherMembers" type="object[]">
      Up to 5 active members of the conversation other than the acting user, each with public user fields (`id`, `name`, `username`, `avatar`). Populated for `direct` and `group` conversations only — a DM/group has no `name`, so the counterparty is how a client renders the title and avatar. Capped at 5 (a preview avatar stack needs a few, not all — use `memberCount` for the full group total). Always an empty array (`[]`) for `space` conversations, whose membership can be large and which carry their own `name`. Ordered by member join time.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="pagination" type="object">
  <Expandable title="pagination fields">
    <ResponseField name="nextCursor" type="string | null">
      Pass it as `cursor` to get the next page. `null` when `hasMore` is `false`.
    </ResponseField>
    <ResponseField name="hasMore" type="boolean">
      Whether more conversations exist beyond this page.
    </ResponseField>
  </Expandable>
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    { "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.", "code": "chat/acting-user-not-allowed" }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    Returned when a service key names an `actingUserId` that isn't a user in this project.
    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "chat/user-not-found" }
    ```
  </Accordion>
  <Accordion title="Unsupported Parameter — 400">
    The request sent `userId`. On this route the user a service key acts as is `actingUserId`.

    With a service key:

    ```json
    {
      "error": "`userId` was renamed to `actingUserId`: send the user this service key acts as in `actingUserId`.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```

    With a user token, or with no credentials:

    ```json
    {
      "error": "`userId` isn't accepted here: a user's own token always acts as that user.",
      "code": "chat/unsupported-param",
      "param": "userId"
    }
    ```
  </Accordion>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    { "error": "A service key must send actingUserId: the user this request acts as.", "code": "chat/missing-user-id" }
    ```
  </Accordion>
  <Accordion title="Invalid Cursor — 400">
    `cursor` isn't a `pagination.nextCursor` the server gave out.
    ```json
    {
      "error": "Invalid `cursor`. Pass `pagination.nextCursor` from a previous response unchanged, or leave `cursor` out to start from the beginning.",
      "code": "chat/invalid-cursor",
      "param": "cursor"
    }
    ```
  </Accordion>
  <Accordion title="Invalid Query — 400">
    For example a `types` value other than `direct`, `group` or `space`, a `limit` above 50, or `cursorCreatedAt` (not accepted; pass `pagination.nextCursor` as `cursor`). `error` starts with the field name.
    ```json
    { "error": "types: Unknown type `DIRECT`. Allowed: direct, group, space.", "code": "chat/invalid-query" }
    ```
  </Accordion>
</AccordionGroup>
