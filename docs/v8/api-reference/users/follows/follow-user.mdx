---
title: "Follow User"
api: "POST /v8/:projectId/users/:userId/follow"
description: "Follow a user by their ID"
---

Creates a follow relationship from the authenticated user to the specified user. A notification is sent to the followed user.

## Path Parameters

<ParamField path="userId" type="string" required>
  The Sublay user ID (UUID) of the user to follow.
</ParamField>

## Body Parameters

<ParamField body="actingUserId" type="string">
  Service key only, and required with one: the user this request acts as, who follows the user in the path. A user token always acts as its own user and must not send it (`400 follow/acting-user-not-allowed`).
</ParamField>

## Response

On success, returns HTTP `201` with the created follow record:

<ResponseField name="id" type="string">
  Unique follow record ID (UUID).
</ResponseField>

<ResponseField name="followerId" type="string">
  ID of the user who followed (the authenticated user).
</ResponseField>

<ResponseField name="followedId" type="string">
  ID of the user being followed.
</ResponseField>

<ResponseField name="createdAt" type="string">
  ISO timestamp of when the follow was created.
</ResponseField>

## Error Responses

<AccordionGroup>
  <Accordion title="Missing User — 400">
    A service key sent no `actingUserId`.
    ```json
    {
      "error": "A service key must send actingUserId: the user this request acts as.",
      "code": "follow/missing-user-id"
    }
    ```
  </Accordion>
  <Accordion title="Acting User Not Allowed — 400">
    A user token sent `actingUserId`, even naming its own user. Only a service key names the user it acts as; a user token always acts as its own user.
    ```json
    {
      "error": "actingUserId is only accepted with a service key. A user's own token always acts as that user.",
      "code": "follow/acting-user-not-allowed"
    }
    ```
  </Accordion>
  <Accordion title="Self-Follow — 400">
    ```json
    {
      "error": "A user cannot follow themselves.",
      "code": "follow/self-follow"
    }
    ```
  </Accordion>
  <Accordion title="User Not Found — 404">
    A service key named an `actingUserId` that isn't a user in this project:

    ```json
    { "error": "No user with this actingUserId exists in this project.", "code": "follow/user-not-found" }
    ```

    Otherwise, the user to follow doesn't exist:

    ```json
    {
      "error": "One or both users involved in the follow do not exist.",
      "code": "follow/user-not-found"
    }
    ```
  </Accordion>
  <Accordion title="Already Following — 409">
    ```json
    {
      "error": "Follow relationship already exists.",
      "code": "follow/already-exists"
    }
    ```
  </Accordion>
</AccordionGroup>
